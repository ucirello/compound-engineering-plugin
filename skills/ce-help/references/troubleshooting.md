# Troubleshooting RocketClaw

`docs/` and `README.md` paths are public pages. `SKILL.md` gives their URLs.

| What the user sees | What to tell them |
|---|---|
| A skill is missing, or behaves the old way after an update | Check the installed RocketClaw OpenCode package and its registration using `README.md#install` and `docs/install/upgrading.md`, then start a new session. Do not apply another harness's marketplace commands. |
| An old copy of a skill keeps running after an update | An earlier Bun install may be shadowing the plugin. `docs/install/upgrading.md` has the cleanup command. |
| The agent will not start a skill it recommended | The skill is manual-only, so the user has to type it. `references/skill-map.md` marks these. |
| The slash command is not recognized | Use `/skill-name` in OpenCode and check that the installed package registered that command. Do not use another harness's invocation syntax. |
| A skill says a tool is missing | `ce-setup` reports which tools are missing and how to install them. Install only what the workflow needs. |
| A cross-model pass or oracle peer did not run | The run's report says why. `ce-setup` reports missing tools, and the `ce-pov` guide page lists what peers need. Config can also turn the automatic review pass off, so check `docs/guides/configuration.md`. |
| Delegation or a model override failed | Distinguish capacity limits from nesting depth, permission denial, unavailable native tools, and rejected model arguments. Check the global depth prerequisite in `references/starting-and-running.md`. Use native subagents and `opencode.models`, not removed dispatch bridges. Model-override permission is separate from delegation authorization; inherit a suitable model when allowed and disclose missing required independent coverage. Never bypass restrictions through shell or another harness. |
| Workspace creation or cleanup stopped | Keep existing isolation and native harness ownership. New workspaces require a verified base, `jj workspace add --colocate`, and colocation verification in the new absolute root. `ce-worktree` uses one local YYYYMMDD plus a meaningful slug, collision-checked against registrations and disk, with stable numbered suffixes. Unsupported naming or colocation is a blocker. Removal requires explicit exact ownership/name/path authorization, stopped workers and moved sessions, recovery references and copied/read-back evidence outside the target, plus tracked/conflicted/ignored/untracked inspection. From a surviving absolute root use guarded `jj workspace remove`, verify deregistration and directory removal, and treat warnings as blockers. `jj workspace forget` only unregisters and preserves files; a snapshot does not protect ignored or untracked data. Never force-delete or fall back to Git. |
| Context pressure interrupted `ce-compound` | Full mode uses a fresh native noninteractive, full-depth subagent with the shell-read source session ID, absolute workspace root, existing learning document and topic. Export source evidence with supported OpenCode session export/API into local `.tmp`, not the database; the source session is primary evidence. The parent relays the result without a second Full pass. Lightweight fallback is only for actual unavailability, denial, or depth failure, reported explicitly; retry the same source session later. Interactive discoverability and pack steps still require consent. |
| Plans or learnings are not where the user expected | `docs_root` in `.rocketclaw/config.yaml` moves every RocketClaw artifact folder. Format options can also change ideation, brainstorm, and plan files from `.md` to `.html`. |
| `ce-compound` wrote nothing | It captures only what the final code, tests, standards, and docs do not already show, so skipping a routine fix is correct. If a lesson was missed, run it again and say what the lesson was. |
| Learnings are captured only when the user asks | A standing instruction fixes this. `ce-setup` offers one when the repo tracks its learnings. |
| New plans ignore past learnings | Check that `<root>/solutions/` holds learnings and that `ce-plan` ran in this repo. A `ce-compound` refresh handles learnings that have gone stale. |
| A hands-off run stopped before merging | That is expected. Merging normally stays with the user. The `lfg` guide page covers where a run ends. |
| The agent's last reply made no sense | `wtf` explains it plainly. |
| A session is out of context, or the work has to move to another agent | `ce-handoff` writes a handoff, and a new session can resume from it. |
