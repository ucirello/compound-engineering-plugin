# Managed stacks: posture, verification, transitions, maintenance, landing

Run JJ from the absolute target workspace root, repository-scoped `gh` with `GIT_DIR=$(jj git root)` exported there, and store all receipts/topology under local `.tmp/rocketclaw/`. Never invoke Git or a working-tree stack manager for mutations. CLI recipes and topology schema: `references/stack-commands.md`.

## Posture (one per run)

| Posture | Behavior |
| --- | --- |
| `target` | Only the named PR. Stop at looks-ready; offer stack-wide once on a confirmed multi-layer stack. Never merges. |
| `stack-ready` | Advance downstack-to-upstack when the active layer is quiescent: zero actionable threads/comments/CI, no human/red/stack/currency residual, and no delegate in flight. CI may still run and settle may remain. Lower layers stay probed; return to the lowest reopened layer. Never merges. |
| `stack-land` | Same traversal, but explicitly authorizes landing the bottom-most open settled layer after all Step 3 or pipeline success gates. Quiescence alone never authorizes landing. |

One PR without stack language defaults to `target`; ask once whether to carry a confirmed stack. Explicit whole-stack intent selects `stack-ready`; explicit land intent selects `stack-land`. Re-state posture on every continuation. Pipeline never asks or expands supplied scope. A declined whole-stack offer preserves target-only monitoring. Drafts are opt-in; never skip a draft or human-blocked layer to reach higher work.

## Discovery and ownership

Accept either (a) an explicitly handed-off native JJ topology whose exact identities and graph are freshly verified, or (b) existing manager-owned membership proven by read-only `gh stack view --json` or GitHub stack metadata. `pr_chain.manager_status == "confirmed"` is required for cross-PR continuation. `manager_source == "native-jj"` distinguishes the native route; it does not imply membership in an external manager. Mere parent/head branch adjacency is a manual dependency chain, never native ownership or stack-wide authority.

For native handoff, materialize the caller's complete explicit topology using the schema in `stack-commands.md` before bootstrap; never invent omitted layers, remotes, heads, or parent boundaries. Export its absolute `BABYSIT_TOPOLOGY_FILE` on every snapshot/watch/mark call, including re-arms and layer transitions. The helper independently verifies PR identities, current remote API heads, mapped JJ remote repositories, order, and JJ ancestry on each poll. Fetch exact named remote bookmarks first and verify OIDs. A moved head, missing object, ambiguous mapping, malformed file or failed probe yields `probe-error`, not absent or confirmed. Refresh the receipt only after reconciling verified authorized progress; never edit it merely to silence divergence. Pass it unchanged through resumption and bounded callers.

Existing external managers retain ownership: preserve their recorded order, membership, identifiers, PR bases and metadata. Native JJ executes only graph changes already authorized by that ownership contract. Do not import/reinitialize the stack, invent topology, transfer ownership, or mutate its files through a Git-backed manager. If its metadata update cannot be performed through a supported non-working-tree API without violating ownership, report the exact metadata residual and do not claim full maintenance. Read-only discovery is still permitted. A schema-unavailable stack response means absent only after a successful default-branch probe; auth/rate/transport/malformed failures remain uncertainty. Without confirmed membership, preserve ordinary manual parents/dependents and target-local behavior, including readiness relative to an open parent.

## Continuation and shared budget

Inspect the verified ordered entries once. Under accepted stack-wide scope begin at the lowest unsettled non-draft layer, otherwise keep the requested target and offer once to start lower. When target-only settles, offer once to continue to its immediate open dependent. No repeated approval is needed for already accepted scope, routine clean-head alignment, or authorized monitoring.

Keep one writer and watcher. At each transition stop the watcher, await in-flight delegates, revalidate ownership/order/heads/downstack quiescence, and align the clean workspace to the next exact PR head via `references/setup.md`. An empty `@` directly above it is aligned. Preserve tracked, conflicted, ignored and untracked work; dirty or uncertain state stops the invocation, never resets/discards. Continue that layer's state with `--continue-invocation`, the original `--invocation-id`, `--session-started-at`, `--invocation-budget-seconds`, plus `--continue-dead-time-seconds <prior-layer-invocation_dead_time_seconds>` and the same posture. Never renew budget per layer. Loss of positive ownership confirmation ends continuation, not a downgrade to manual-chain rewriting.

Arm with `--downstack-pr <N>` for every open lower layer. `downstack-actionable` returns to the lowest reopened eligible layer after current delegate completion. Recheck lower layers at every transition, before target mutation and at readiness. A standing residual keeps the interactive watch active around independent streams, blocks readiness/advancement, and is returned immediately in pipeline once autonomous work is exhausted.

## Pre-push baseline and authorized upstack propagation

Before any delegate can push the target, capture a recoverable exact baseline: ownership/order, target and every open dependent's repository/remote/bookmark, local and remote OIDs, immediate parent's old OID, complete owned layer change sets, and draft/PR base metadata. Retain recovery bookmarks and evidence outside disposable isolation. Require a clean workspace and still-confirmed target membership. Failure stops the active invocation in every mode: no delegate, further tick or re-arm; report the residual and resume invocation.

After a delegate reports a pushed target, independently fetch and verify its exact local bookmark, API head and remote bookmark all equal that pushed OID. Keep the target fixed throughout propagation: never rebase it or trunk. Revalidate all dependent baseline heads before changing anything. Select only the first open dependent and its owned upper layers in recorded dependency order; no manual-chain or unrelated descendant changes. For each layer, rebase exactly its captured owned revision set from its captured old immediate-parent head onto its verified new immediate-parent head using scoped `jj rebase -r <owned-layer-revset> -d <verified-new-parent>`. Do not use an unbounded descendant rebase. Verify no out-of-scope revisions moved, original layer intent/coverage survived, and the target stayed unchanged. An immutable boundary or semantic conflict is a residual, not permission to bypass policy. Stop at the first conflict, preserve recovery, and reverse only this run's proven disposable unpublished operations when safe; never global undo or discard user work.

Only after validation, move each owned layer bookmark to its exact rewritten tip and publish bottom-to-top with `jj git push --remote <verified-remote> --bookmark <layer>`. Expected-remote protection is mandatory; do not refetch-and-overwrite a concurrent head or force. Re-probe after every success or failure: publication is not assumed atomic. Record exact successful PR URLs/old/new OIDs, first rejected/divergent layer and remaining unpublished tips. Preserve already published progress and recovery references; resume only after reconciling that exact partial state, never blindly replay. Target's intentional push is not dependent divergence. Refresh verified topology receipts and supported metadata only for observed changes; unresolved metadata or graph state blocks full stack readiness. Scope is maintenance inherited from babysitting a confirmed managed layer, not delegation permission to rebase or force-push; propagation stays with this skill.

## Landing and post-merge synchronization

Under `target`/`stack-ready`, final merge remains human-owned: report the exact ownership-appropriate command, never execute it. Under explicit `stack-land`, identify the bottom-most open settled PR after full gates. For native JJ topology, use repository GitHub final merge `gh pr merge <verified-URL> --squash --match-head-commit <verified-head>`; do not delete branches. For an existing GitHub-managed stack, retain its server-side `gh stack merge <bottom-most-open-settled-PR> --yes --squash` protocol only if verified to preserve ownership without workspace mutation. Never merge an upper endpoint that would land an unsettled prefix, and never substitute `gh pr merge` for an external manager's required protocol. An unavailable safe merge protocol is a truthful blocker, not a policy exception.

Re-probe PR state: successful enqueue is not MERGED. Keep watching (or return a queued pipeline residual) until actual MERGED; never advance or report land success while OPEN. Only this run's verified authorized merge is a continuation transition; externally observed MERGED/CLOSED remains a terminal stop. On merge failure, do not synchronize or retry through another merge route.

After actual merge, fetch and verify the new base/trunk OID and GitHub's next PR base metadata. Squash landing requires dropping precisely the landed parent's changes, not rebasing them into trunk again. Rebase the next layer's exact captured owned range from the old landed parent onto the verified new base using the same scoped propagation, coverage checks and expected-remote publication above, then propagate higher owned layers. Update a PR base only when required by the captured topology and authorized landing, preserving manager-owned metadata via supported APIs. Never run `gh stack sync` or its working-tree rebase/push bridge. If retargeting, ancestry, ownership or partial-publication evidence is uncertain, preserve state and return the exact residual. Continue only after graph, metadata, review and CI are re-proven on current heads. Pipeline `stack-land` never returns success before actual merge and verified synchronization (or an explicit residual).
