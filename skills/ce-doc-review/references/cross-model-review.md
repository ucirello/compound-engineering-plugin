# Cross-Model Judgment Pass

This skill explicitly requests an OpenCode-native peer subagent for each activated `adversarial-document-reviewer`, `product-lens-reviewer`, or `security-lens-reviewer`, plus **one** `whole-doc` sweep whenever the pass runs. Coherence, feasibility, scope, and design do not run cross-model. Use the same classification and reviewer brief as the local review; pass the same slice to each twin on unified artifacts and the full document on legacy artifacts. The sweep uses `references/personas/whole-doc-reviewer.md` and always gets the full document. It has no local twin.

The pass is additive and non-blocking. A skipped or failed peer never makes a successful local review fail, but the missing cross-model coverage must be visible. Only verified independence can promote agreement.

**Checkout egress policy comes first.** `cross_model_review_mode` is `auto` (default) or `off`. When `off`, record **disabled by checkout config** before route discovery or disclosure. Only an explicit live user request for this peer pass overrides `off`; a configured target or project preference does not. A live prohibition still wins. Do not start peers if higher-priority rules prohibit egress.

Resolve the target by live user preference, `cross_model_peer`, active project instructions (from context), then the first eligible different-family target in `codex → claude → grok → antigravity`. Cursor default and Composer are opt-in only. Once an explicit target is resolved, its unavailability is not a reason to fall through to the next target. Determine the host's actual serving provider/family from the OpenCode session's runtime model record; do not infer it from the product name, inherited environment, a request or a model's own claim. An unattested host family skips automatic different-family selection. Keep requested **target**, actual **OpenCode route**, serving **provider/family**, and **actual served model** separate.

Use `opencode.models` (chat) to look up the configured or preferred identifiers and variants by provider; include older versions when checking an exact pin. Resolve one native OpenCode provider/model/effort combination for the entire document. The target keys and editorial mapping below describe desired models, not permission to invoke their former harnesses:

Live model and effort instructions outrank `cross_model_model` and `cross_model_effort`. Validate pins against the target family, native discovery, and supported tool fields; an explicit pin must run exactly or be reported unavailable. A legacy harness-specific route (e.g. explicitly requesting Grok through Cursor, Cursor Auto, or the Pi session default) is not identical to a native provider route. If the exact route or preset is unavailable in OpenCode, say so and do not invoke that harness or silently replace the route. Family aliases may resolve to an exact discovered native identifier; do not guess. For unpinned editorial defaults only, an observed obsolete/unavailable model permits one same-target, same-family replacement, preferring the listed fallback where present. A rejected editorial Codex effort may be omitted once if there is no explicit effort pin; record it as unapplied. Resolve replacements for the whole document, never mix models across the legs. Do not silently change any explicit model, effort, recipient or intermediary.

**Permission and isolation are separate gates.** Apply `dispatch.md` and `subagent-model.md`: a permitted user-or-skill delegation rule accepts this explicit request; an unconditional prohibition or a missing/denied native tool still blocks it. An explicit peer request is not necessarily an explicit model request under the host's policy. Do not pass `model` or an effort override unless permitted. Inherit only if the runtime can attest that the inherited selection meets the fixed route and different-family contract; same-model reviewers never count. Distinguish effective nesting depth, active-slot capacity, an override/action denial, argument rejection, unavailable routing and missing tooling by the actual evidence. Shell may only inspect local settings, stage private evidence or write receipts; it cannot replace a missing/denied subagent or evade a model or depth restriction.

Use a native fresh context constrained to the embedded brief, with enforceable read-only (or tool-less) execution, no repository context, no outside reads, no edits, no web or MCP, and no nested dispatch. Use an empty private run subdirectory as the peer working directory when the supported native tool exposes that scoping. Grant no extra permissions or network escape. A prompt saying "read-only" is not an enforced boundary; if effective permissions and scoping cannot provide this isolation, retain the local reviewers and report the peer route unavailable.

## 2. Disclose before sending

`CROSS_MODEL_PEERS`, if nonempty, is a comma-separated egress restriction on the target and **every** actual provider/intermediary receiving the document. Resolve the actual native provider route first. Keep the target-key allowlist aliases: `codex` for OpenAI, `claude` for Anthropic, `grok` for xAI, `antigravity` for Google (`gemini` alone does not admit it), and `composer` or `cursor` for a Cursor intermediary; `cursor` is required for Cursor Auto itself. For generic `opencode` or `pi` target keys, the target key does not itself authorize an otherwise unsanctioned serving provider. `grok` alone never sanctions Cursor as an intermediary. Unset or empty means unfiltered, not that the user's or host's rules can be bypassed.

Honor `CROSS_MODEL_MAX_PEERS=0` as disabled and `CROSS_MODEL_MAX_DOC_CHARS` (default 200000 bytes) per leg before announcing what will be sent. Never truncate an over-limit slice or sweep silently; name the coverage loss.

- **Interactive:** before dispatch, put a prominent cross-model line by the team announcement. Name the target, **requested** concrete model and reasoning level, the OpenCode route and all actual egress recipients. State which legs will send the full document (the sweep and legacy focused lenses) and which will send only a slice (unified focused lenses). Do not present the requested model as the served model or claim verified independence before receipt. If no route runs, use a short skip line with the observed reason.
- **Non-interactive:** do not announce in chat. Before starting, use the permitted shell to write a one-line stderr disclosure per send (lens, scope, route, recipients, requested model and effort). Keep that disclosure with the dispatch record under the private run directory. The invoking request plus disclosure are sufficient only where actual policy allows this egress; use the same eligibility and allowlist checks as interactive. If dispatch fails, distinguish the preflight disclosure of intended egress from evidence of actual egress.

Keep the requested wording in later mentions as well. Add a serving caveat if a receipt disagrees or if no model was requested (`serving model unverified`). A receipt-less pinned request is still a request, not evidence of identity.

## 3. Dispatch, bound, and collect

For each eligible leg, inline the allowlisted persona, `references/findings-schema.json`, and relevant `references/subagent-template.md` instructions, including `<context-slots-rules>` and `<output-contract>`. Supply the same `document_type`, `origin_path` provenance, and document scope as its local twin, using the short lens labels `adversarial`, `product-lens`, `security-lens`, and `whole-doc`. The remote brief uses round-one framing even on later rounds; do not send the accumulated decision primer, local files or pack constraints. Let synthesis enforce R29/R30. Keep slices and evidence under the private run directory defined in `references/synthesis-and-presentation.md`.

Launch all eligible legs in the same dispatch wave as the local reviewers, subject to the native active-slot limit. Record each attempt's lens, native handle/session when returned, fixed route, requested model/effort, start and deadline. Use native bounded wait/status/result/cancel/release capabilities only when exposed. Constrain calls to the shared `CROSS_MODEL_HARD_SECS` budget (default 1200 seconds), measured from the first peer launch, without extending it for retries. Use an idle cap of 480 seconds if the native tool supports idle tracking. If the available native tool cannot provide a bounded lifecycle, do not launch an unbounded peer. Collect all started or possibly-started attempts before return; cancel pending peers when the result is no longer needed or the deadline expires, then use one bounded final status check (up to 10 seconds) if supported. Record unresolved handles and blockers; do not report unsupported cleanup as done or reap arbitrary OS processes.

- **Preflight or positive no-start evidence:** identify checkout disablement, unknown host family, unsanctioned recipient, missing tooling, unavailable isolation/route, model-argument rejection, delegation or override denial, or exhausted depth separately. Do not fabricate a started terminal state. Active slots alone permit queueing and retry once a slot frees, within budget.
- **Recoverable infrastructure failure:** distinguish it from an intentional skip. Recover once on the same disclosed route, with the same model, permissions and payload scope, only when the tool positively shows the leg did not start and a correction is possible. Never retry an actual denial, nesting limit, unresolved dispatch whose egress may already have occurred, or missing tool via another transport. If shared failure removes the cross-model pass, name the whole-doc broad-read loss, not merely a quiet skip.
- **Provider/model failures:** report observed quota, auth, timeout, or failure; account auth needs evidence from a provider-capable dispatch, not a sandbox-shaped error. Do not automatically retry quota or ordinary provider failures. A native receipt showing transient overload (`529` / `overloaded`) permits one same-route, same-model retry within the shared deadline. A refused unpinned editorial default can use the Step 1 replacement once only if no leg has run on the original model; re-resolve and disclose the whole route before any send. A fixed pin or a policy rejection cannot be swapped or retried.
- **Started outcome:** distinguish `failed`, `timeout`, `died-without-result`, malformed findings, and unverified collection. No valid output is not an empty findings array. An empty validated array means the peer found no additional issues.

## 4. Verify receipts and report

Validate findings against `findings-schema.json`. The coordinator writes a private `<reviewer-name>-<provider>.json` only for a schema-shaped return collected from the recorded native dispatch, overriding its `reviewer` name and downgrading `safe_auto` to `gated_auto`. Attach the recorded native session/dispatch receipt and separate `cross_model_target`, `cross_model_harness` (`opencode`), `cross_model_route`, `model_requested`, `model_actual` (or `unverified`), `effort_requested`, and any actual effort recorded by the runtime. Never infer model served from the request or trust the peer's own identity claim. If the tool exposes an identity record, confirm its session and actual model against the dispatched handle. Mark `independence_verified: true` only for a fresh, isolated context whose served model and family are verified different from the host and whose required route, model and effort are met; otherwise `false`. A schema-valid return with unverified independence may be retained as attributed evidence, not as completed cross-model coverage or agreement promotion.

Settle and classify each leg before reading fold-in results. Read back only verified, run-owned files in the private run directory, and retain findings, receipts and actual failure evidence for Coverage/resume. Remove only consumed, disposable peer scratch after collection when authorized; if cleanup/collection cannot complete, preserve evidence and name the blocker. No fixes or synthesis if the local review took the incomplete-stop path.

Use the exact Coverage and non-interactive `peer.outcome` rules in `references/synthesis-and-presentation.md`; in-process twins cover their own lenses when a peer is unavailable, not the broad sweep or different-family corroboration. A merged finding advances by one anchor step only under synthesis's one-fix test and verified independence rule.
