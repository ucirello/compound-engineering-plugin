# Discoverability check

After the report, apply the **Discoverability Check** section of `references/refresh-and-discoverability.md`. It defines what a reader must learn, the smallest addition and its tone, the consent step, and the `CONCEPTS.md` variant. Follow its interactive Full path in an interactive refresh, with these differences:

- **Instruction files:** look for the project's root agent-instruction surface, whatever this project uses (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, or an equivalent). If there is none, skip the check.
- **Questions:** ask as `references/refresh/modes.md` describes under Blocking questions.
- **Non-interactive:** emit a "Discoverability recommendation" line in the report instead of editing instruction files. The scope of a non-interactive refresh is doc maintenance, not project config.
- **Late edit:** if this check edited an instruction file after Commit already ran, fold only this check's owned instruction-file changes into the verified refresh change with path-scoped `jj squash --into <verified-refresh-change> -- <owned-paths>` (same bookmark, not yet pushed), or create a small path-scoped follow-up with `jj commit <owned-paths>`. Delegate all message composition or revision to the complete standards in `references/refresh/commit.md`: read that step and apply its strongest instruction, full Go guide, comparison of several recent full JJ subjects and bodies at the actual verified history anchor, and repository-local syntax precedence; no fixed message syntax is prescribed here. Run JJ from the absolute target workspace root. If the bookmark was already pushed, push the exact verified bookmark with `jj git push --bookmark <verified-bookmark>` so an open PR includes the edit. Preserve unrelated work and include only owned changes. If the user chose "don't commit", leave the edits uncommitted alongside the rest.
