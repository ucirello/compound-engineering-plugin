# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the host permits the override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the host permits the override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, that is the intended route instead of the default tier above, subject to actual model-selection permissions. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier. Resolve permitted model choices with `opencode.models` and dispatch through native OpenCode subagents, never another harness's dispatcher.

**Permission and depth.** This skill explicitly requests source-fetch and media-analysis delegation. Under a host rule permitting user OR skill-requested delegation, that satisfies the skill-requested exception without a second approval. An unconditional prohibition, unavailable tool or actual denial still applies. Delegation permission does not grant model-selection permission: if the host requires an explicit user model request, omit the optional model argument unless one exists. Use suitable inherited-model agents, disclose unmet configured tiers, and never describe same-model agents as cross-model independence. Verify effective nesting depth from OpenCode's supported configuration inspection; permission does not establish available depth.

**Degradation rule.** When per-agent model selection is unavailable or forbidden, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on a suitable inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When delegation itself is unavailable, denied or depth-exhausted, run the source fetch and media analysis inline only if host permissions allow that work, with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths. If a required route or independence cannot be satisfied, report incomplete coverage, not completion.

Classify dispatch failures from the actual error: distinguish missing tool, permission denial, model-argument rejection, and nesting depth/capacity exhaustion. Correct an allowed pre-launch argument error once; never retry a denial or evade a depth limit through shell or another harness. Leave capacity-limited work queued or use the permitted inline degradation above; preserve the more specific unavailable-state rule in the persona file for that source.
