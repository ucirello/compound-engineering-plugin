# Opt-in native JJ stack construction and submission

Load only when the user requests a PR stack or a standing preference wants one. Before ordinary Step 3, run Probe, Topology and Construction only. Step 5 exclusively owns publication and post-submit descriptions. All JJ subprocesses use the absolute target workspace root as cwd; all repository gh calls use Context's `GIT_DIR=$(jj git root)` preamble. Read `references/gh-stack-cli.md` for verified metadata, exact-ref, manager and landing boundaries.

## Probe and topology

Verify gh availability, authentication and repository support, plus existing managed-stack metadata where applicable. Classify missing tool, unavailable stacks, ambiguous parent and failed authentication separately. Required intent (explicit demand or forcing preference) stops on an unavailable required stack route; soft intent may report the residual and use ordinary single-PR creation. When the user did not request a stack and the work is one logical change or only artificial slices exist, use one PR; explicit stack intent is not refusable on that ground.

Capture original bookmark and exact tip, complete working changes, exclusions and recovery references before classification. Classify parent by explicit PR number when available, verifying owner, repository and headRefOid; bare names only prove local state. Classification must not move the working copy. Preserve existing managed topology. A named parent is authoritative: never silently move to another top layer. Ambiguous/shared/non-top managed parents stop with the topology residual, not a command to jump to the top. A standalone parent serves as untouched trunk unless adoption as bottom is authorized and authored by the current user. Unknown is not standalone.

Resolve the authoritative parent tip after fetch: verified current remote tip when it represents the confirmed layer; otherwise verified local parent when its newest work has not been published. Do not hardcode origin or default-base creation for upstack layers. If no parent was named and starting on default, follow `references/branch-creation.md`, including the local-only-commit decision. For an existing feature bookmark resolve the verified base tip without misclassifying feature commits as default-bookmark local work. Preserve the original tip under a recovery bookmark before any rewrite.

## Construction

Inspect the complete captured range plus tracked and intended new working files. Derive the smallest linear set of coherent, independently reviewable layers, foundation first; no layer may depend on an upstack layer. Use whole files or existing commit boundaries, never force a hunk split. A clear safe topology proceeds under stack authorization. Materially different reasonable topologies require a concise bottom-to-top proposal; pipeline mode returns it as a residual. Hunk partitioning or published history rewriting requires explicit approval; pipeline mode stops with the required confirmation instead. Never rewrite published history merely because stack intent exists.

Every commit composition, including layer messages, follows the full Go-guide read, several historical subjects/bodies and repository-first runtime standards in `references/commit-and-push.md`. Include a known plan unit semantically using repository-compatible syntax; omit unclear/spanning units, and never hunt for a plan.

For existing boundaries create/reuse one nonconflicting bookmark at each exact planned tip through `jj bookmark create <layer> -r <verified-tip>`. Reuse the original feature bookmark only when its unchanged tip is a planned tip. For working whole-file groups, commit only the layer's owned paths via `(cd "$workspace_root" && jj commit <layer-paths> -m "<message composed from the standards above>")` and attach its bookmark to that exact committed revision. Start each next layer from its immediate parent, retaining all prerequisites. If native reordering is needed, preserve recovery refs and use only authorized owned changes; do not rewrite foreign history.

Excluded paths belong to no layer: never save, move, restore, track or commit them. Preserve tracked, ignored and untracked work before any revision movement; if safe movement without colliding with exclusions cannot be proven, stop with the exact residual rather than stashing/removing/discarding files. Keep saved owned work and recovery references until the final top's complete diff against the captured base equals the original intended change set minus exclusions. Verify exact layer order, ancestry, heads and complete coverage before submission.

## Submit — Step 5 only

Apply the Project publishing gate to every exact state being published. Resolve teaching archive configuration and invocation override first. Archive-on is a residual before publication until a stack-aware archival route exists; never silently disable it or add an unplanned post-submit commit. User may rerun with `archive:off`.

Inspect all existing PR layers and draft status. Never mark an existing draft ready unless explicitly authorized this run. Create new layers ready/non-draft when authorized, using explicit head and immediate parent base; preserve existing drafts. A draft-only outcome is a hard residual before babysit when babysit is on, never successfully shipped ready work.

Push each verified layer bookmark explicitly through `(cd "$workspace_root" && jj git push --remote <verified-remote> --bookmark <layer>)`, adding `--allow-new` only for authorized new bookmarks. Re-query matching owner/head PR presence immediately before each create. Match each resulting explicit PR URL to its head and immediate parent; verify topology and publication receipts. Partial publication retains recovery state and reports exact completed/pending layers, never claims complete coverage.

For each new PR pass its explicit URL to ordinary PR-mode description composition and apply the result with `gh pr edit <url>` and a workspace-local body file. Never select by an ambient bookmark. Existing layer bodies/titles remain unchanged unless this invocation explicitly requests rewriting or authorized factual maintenance applies; pipeline defaults to no optional rewrite. Declining optional rewriting must not block otherwise-authorized alignment or monitoring.

Report bottom open non-draft URL and hand off through `references/apply-and-handoff.md`: default `posture:stack-ready`, `posture:stack-land` only with explicit landing intent, with stack-wide scope for pipeline submit. Preserve manager-aware landing boundaries from `references/gh-stack-cli.md`; never merge members independently.
