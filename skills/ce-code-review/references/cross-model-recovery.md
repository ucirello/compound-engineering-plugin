# Cross-model recovery and coverage

Read at Stage 3d for a failed native launch or at fold-in for a missing/unusable result. Keep target, requested model/effort, exact base/head IDs, read-only constraints, adversarial brief and the original shared deadline fixed for a same-route retry. Never recover through a shell model launcher, another harness, relaxed permissions, or delegation hidden behind tools.

## Classify the actual failure

- **Delegation denied:** host/user policy forbids subagents. Do not retry via another mechanism. Parent analysis is attributed non-independent evidence; disclose lost persona, validator and cross-model coverage. Follow the degraded path, never claim full completion.
- **Model override denied:** distinct from delegation denial. Ordinary suitable reviewers may inherit the session model. A required cross-model pass is missing unless a permitted native route really serves an attestably different family; inherited same-family coverage is only the local lens.
- **Depth exhausted:** an actual nesting-depth error is not a concurrency limit, model rejection or policy denial. Stop trying deeper children; perform only work allowed at this depth, report the exact missing independent review/validation, and never evade via CLI or another harness. Lowering the requested task depth does not grant a forbidden model override.
- **Active-agent capacity:** queue the selected reviewer, collect/release active owned work, then retry through native tools. Do not drop roster members, label them failed, or shrink full to lite. If no active work or supported release can restore capacity, record a degraded/no-subagent result.
- **Native tool missing / collector unavailable:** explicitly name the missing capability. Stop any already launched owned work. No fake launch receipt, detached substitute, polling or silent parent-as-independent review.
- **Model/effort argument rejected or model unavailable:** availability/argument mismatch is not delegation denial. For ordinary local reviewers follow `subagent-model.md`: once without overrides, inherited model, with the rejected choice disclosed. For a configured/user-pinned cross-model model do not substitute; report the missing configured coverage and use local adversarial coverage if possible. For an unpinned default only, one closest compatible same-family replacement from `opencode.models` may be selected, disclosed and launched within the original deadline. Never cross families silently.
- **Pre-launch infrastructure failure:** correct a concrete invocation/path mistake, retry the same permitted native route only while each failure is new and plausibly recoverable and time remains. Repeated failure or spent deadline ends recovery. No-job-ID recovery occurs before finalizing the roster; do not later revive a peer after the local fallback has received its brief.
- **Started then failed/timeout/no output:** record launch ID, observed terminal state, and bounded diagnostics. Never treat a start acknowledgement as completed review, or malformed/absent output as zero findings. A schema/trust failure stays degraded. Unknown whether a review happened means uncertain coverage, not a clean skip.
- **Authentication-shaped diagnostic:** attribute credentials only with positive evidence of provider-capable dispatch and the provider response. Otherwise it is an execution-context failure, not proof the user's account is logged out. Either way no review means the lens still needs coverage.
- **Provider rate limit/capacity, max-turn exhaustion:** do not endlessly restart or rotate recipients. At most one observed transient overload retry on the same permitted route within the deadline; if still no review, restore the local adversarial lens. Name loss of cross-model corroboration.

## Replacement and local fallback

For a first proven no-review outcome, one replacement recipient is allowed only when the failed recipient was not an explicit live user preference, another attested-different native installed/available and allowlisted target remains, host model permissions permit it, and shared time remains. Resolve it, announce every changed recipient/model before egress, and launch natively. Config/default preference is not a live user pin, but configured model choices must still be honored; do not change a pinned model under the guise of changing routes. No third peer and no hidden recipient changes.

Otherwise dispatch exactly one native local `adversarial-reviewer`, with the original exact-range brief, collected by ordinary bounded rules. Stop/collect any outstanding peer first so both never concurrently review the same brief. Coverage: `adversarial lens: in-process fallback (cross-model peer not run: <observed reason>)`; record `peer.outcome: in-process-fallback`. Same-model separate context covers the lens, not verified cross-model corroboration. If that fallback cannot run, say the lens is uncovered; focused verdict is Not ready, and a full report explicitly names missing required coverage instead of claiming full completion.

Disabled by checkout config, prohibition, unverified host family, remote scope, allowlist mismatch or unavailable target before launch are **not run** reasons. A successfully started peer that fails is a **started failure**, even when local fallback later covers the lens. Keep both facts. A valid empty schema result is **ran, no additional issues**. A result without independence receipts can contribute evidence but cannot promote confidence or skip validators.

Reconcile all native launches before returning, preserving receipts and normalized evidence under local `.tmp/`. Never delete unrelated artifacts or native session state. Cleanup/lifecycle warnings are reported, not hidden as success. The parent owns recovery and disclosure; merge/report leaves only consume the recorded outcome.
