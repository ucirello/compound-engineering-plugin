# Managed stacks: posture, discovery, transitions, upstack maintenance, landing

## Posture (full text)

Hold one run posture `posture:target|stack-ready|stack-land`, distinct from watch/checkpoint/pipeline/duration. Restate it at every `--continue-invocation` alongside the existing budget flags.

| Posture | Behavior |
| --- | --- |
| `target` | Only the named PR, stop at looks-ready; never merge. May offer confirmed-stack scope once; decline preserves target-only. |
| `stack-ready` | Automatically traverse to the immediate open non-draft upstack layer needing work once the active layer is quiescent, even with CI running or settle incomplete. Quiescent means zero actionable threads/comments/CI, no needs-human, blocked-failing, stack-blocked, open/claimed currency item or delegate in flight. Never merge. Lower layers remain under the watcher probe; lowest reopened layer pulls the walk back. |
| `stack-land` | Same traversal, plus run-level land authorization. Only a **settled** bottom-most open layer passing full Step 3 gates may land, through the SHA-guarded GitHub API land and native JJ post-land synchronization in `stack-commands.md`. Quiescence alone never authorizes landing. |

User names one PR without stack intent: default target, ask once when confirmed multi-layer membership merits whole-stack readiness. Own/finish stack intent selects stack-ready; land/merge-when-green intent selects stack-land. Explicit babysit-managed-stack intent counts as stack-ready acceptance, no redundant question. Prefer intent to keywords. Pipeline uses supplied posture/scope and never asks.

## Discovery and continuation

Automatically classify every target's chain on first snapshot and every poll. Use repository-scoped `gh api` GraphQL manager metadata with `GIT_DIR=$(jj git root)` from the target absolute workspace root. Do not invoke local Git-based managers, even for discovery. Accept membership only when ordered manager metadata contains the target PR. Successful null stack means absent; the specific stack-schema-unavailable response means absent only after a separate successful default-branch lookup. Auth, transport, rate-limit, malformed/other GraphQL errors or failed default-branch lookup mean probe-error. With no confirmed manager, ordinary PR head/base relations distinguish independent PRs from manual chains; neither authorizes stack-wide continuation. Discovery never imports/adopts/changes a stack or switches workspaces.

Only a fresh `manager_status == "confirmed"` activates continuation or managed maintenance. Probe-error stays target-local and mutation-conservative until positive confirmation. Every babysit still discovers membership regardless of posture. Native topology validates the ordered metadata, never substitutes for it.

Inspect ordered entries once before choosing the active layer (not multi-PR monitoring). Resolve posture before review/CI work. Under target, a requested middle layer with unsettled lower layers gets the one-time offer to begin at the lowest unsettled non-draft layer and walk upward; never silently redirect. With stack-wide posture, begin there without asking; if all lower layers are settled begin at the requested PR. When the originally requested PR looks ready under target, offer once to continue to the immediate open non-draft upstack candidate needing work. Acceptance selects stack-ready for the run; it is not a suggestion to create/adopt stacks. Pipeline without supplied stack-wide authority reports that candidate as a residual.

One active PR and one watcher. At every transition revalidate manager membership/order and lower-layer quiescence, stop the old watcher, align clean JJ state to the exact next head following `stack-commands.md`/`setup.md`, and initialize that PR's snapshot with `--continue-invocation`. Preserve `--invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS"`, plus `--continue-dead-time-seconds <prior layer invocation_dead_time_seconds>` and the same posture. The anchor is session-started-at, not invocation-started-at. Layer state accumulates its own dead time; carrying it prevents prior suspension counting as active time. Never renew the run budget per layer.

Never skip past/enter an out-of-scope draft or advance past needs-human. Stop at draft outside scope, human-blocked layer, end, budget or user stop. A human-blocked active layer keeps watching independent streams under interactive rules, but cannot advance. Loss of manager confirmation ends continuation with a classification residual, never manual-chain degradation.

## Pre-push baseline

Before a delegate may push the active managed layer, save a recoverable fresh manager order of target plus open dependents, exact head/base repository/ref identities, fetched remote and local bookmark OIDs, layer commit boundaries/sets and JJ operation/recovery IDs under local `.tmp/`, as specified in `stack-commands.md`. Require clean conflict-free JJ state and positive membership at the verified active head (empty `@` directly above it is aligned). Failure is a true invocation stop in every mode: no delegate, tick or watcher re-arm; state the residual and host-rendered resume invocation. Missing atomic multi-ref proof is not itself a blocker: explicit leased JJ bookmark pushes and mandatory post-push verification preserve recoverability without assuming all-or-none.

## Step 7: upstack maintenance after an authorized target push

After a delegate-reported target-head push, preserve the upstack before resuming watch. This caller-owned propagation is implicitly authorized managed maintenance, not arbitrary history editing or delegate authority. Freshly confirm metadata, clean state and exact target local/remote SHA after fetch; moved target is a residual, never rebased/overwritten. No open dependent means no cascade. Otherwise execute `stack-commands.md`'s exact-set native JJ propagation, beginning strictly above the target, reconciling descendants JJ may already have rewritten. Prove the full rewrite closure belongs to confirmed open dependents, exclude target and unrelated trunk/workspaces, verify diffs/ancestry/bookmarks, and publish only exact dependent bookmarks with fetched-ref leases and original-baseline race comparisons.

After success or rejection fetch and re-probe target and every baseline open dependent. Compare dependent old/expected new heads; do not mistake the intentional target push for divergence. Already-updated remotes are observed progress, not grounds to roll back. Name the first rejected/divergent dependent and recoverable retry boundary. Never declare readiness with stranded dependents. Conflict/uncertain topology is needs-human/stack residual with recovery IDs, not a guessed import, force-push or blind rollback. Keep independent streams progressing where safe while a maintenance residual blocks readiness and conflicting mutations. All mechanical maintenance stays in this skill, never with review/CI delegates.

During accepted continuation arm the single watcher with repeated `--downstack-pr <N>` for each open lower manager layer. A `downstack-actionable` wake carries downstack_prs when a lower layer gains a thread, comment, failing check or head beyond arm-time baseline. Stop watcher and return to the **lowest** reopened eligible non-draft layer, carry invocation/posture/budget, handle it, cascade then walk back up. Wait for any active delegate to finish before returning; never mutate two review/CI targets concurrently. Recheck lower quiescence and manager order at transitions, immediately before active-target mutation and at looks-ready. Loss of confirmation ends continuation.

## Layer transitions and stack-land

Stack-ready advances on quiescence, not settle; no standing residual qualifies. Report one line per departed layer (quiescent/CI running or ready-as-next), freshly verify each already-quiescent layer passed through, and let settle proceed under downstack probing. Final report gives each layer's freshly probed settled/quiescent state. Target-only decline ends at looks-ready. Out-of-scope draft and needs-human boundaries remain intact.

Under stack-land, before plain advance, land the bottom-most open settled PR after interactive Step 3 settle or pipeline success gates. Never land an upstack PR while lower PRs remain open. Follow `stack-commands.md`'s expected-head-guarded GitHub API squash merge/queue and native JJ synchronization of surviving layers; no local Git-based stack manager or `gh pr merge`. Follow change-description guidance for any composed squash description. A failed/denied merge is a residual and never triggers synchronization. Queued OPEN is not MERGED: keep watching (pipeline returns queued residual), never declare success or advance. Only actual MERGED plus verified post-land synchronization permits the run-owned layer transition, with old watcher stopped, fresh manager order and the same continue invocation/posture/budget. Inability to synchronize metadata, bases or dependent bookmarks is a recoverable stack residual, not success. This run's own land is a layer transition; externally observed MERGED/CLOSED stays a true Terminal stop. Pipeline stack-land cannot report success on a green prefix without completing actual merge and synchronization, and after successful transition continues on the next layer within the same bound.
