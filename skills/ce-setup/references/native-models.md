# Check native delegation readiness

OpenCode V2 deep delegation needs an effective `experimental.subagent_depth` of at least `3`. Tell users to merge `"experimental": { "subagent_depth": 3 }` into `~/.config/opencode/opencode.json`, or use `opencode debug paths` / `opencode debug paths config` to locate their global config directory and edit the existing JSON/JSONC. Preserve unrelated settings, sibling `experimental` fields, and any higher integer value; never replace the file or create a competing config. Check the [configuration precedence](https://opencode.ai/v2/docs/config) for the target project and report any higher-precedence value below `3`. The package-local `opencode.json` alone does not affect a consuming project. Report what the user needs to do; do not edit global configuration or claim depth is verified if effective config is not visible.

Read `.rocketclaw/config.yaml` and `.rocketclaw/config.local.yaml` to check routes; `.rocketclaw/config.example.yaml` documents choices, not active settings. Keep the existing precedence (local ordinary keys override shared ones; structured work-engine lists and effort maps replace, not merge; only the OpenCode entry applies to `review_subagents`). Resolve configured aliases/providers to exact available IDs and advertised variants with `opencode.models`. Legacy route labels and configured defaults retain their model-family/effort meaning, not a different harness to run. If the intended default is unknown or unavailable, report it; do not pick a replacement. No adapter installation, cache warm, or test dispatch is required for setup.

When a consuming workflow calls for best-effort or required delegation, execute only through permitted native OpenCode subagents (or a native OpenCode shell surface only when the workflow and permissions explicitly allow it, never as a bypass). A loaded skill explicitly requesting dispatch satisfies a user-or-skill permission rule; an unconditional prohibition, actual denial or unavailable tool still applies. Model overrides have their own permission: if not permitted, inherit only when the inherited model satisfies the route. Same-model reviewers do not establish cross-model independence. Diagnose depth exhaustion, permission denial, model-argument rejection and a missing tool separately. Do not retry denied operations. Only take a fallback the consuming workflow allows; disclose an unmet required model, variant, fixed route or independence requirement as incomplete, even when work continues on an allowed fallback.
