# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers the reviewers' model, what happens when the harness is full, how review agents are released, and the permission mode.

**Delegation permission.** This skill explicitly requests reviewer subagents. When the host allows delegation requested by the user OR a loaded skill, that satisfies the skill-requested exception without another approval. Merely loading a skill without such a request would not suffice. Respect unconditional higher-priority prohibitions, unavailable tools, and actual permission denials; never bypass them through shell or another harness.

**Model selection.** Use `opencode.models` to resolve the configured balanced mid-tier model and OpenCode's native subagent tool to dispatch it, only when model selection is permitted. Preserve configured models and tiers as intent. Permission to delegate is not permission to override the model: if the host requires an explicit user model request, omit the optional `model` argument unless that request exists. Otherwise inherit the parent model when it can meet the review requirements. Task wording alone does not select a different model. Disclose an unmet tier or route; same-model reviewers are separate reviewers, not cross-model independence. If a required different-model pass cannot run, report that coverage as incomplete.

Subject to the model-selection permission above, if the user's or project's active instructions or the live prompt name a model for this subagent, use that model instead of the default tier above. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. When a dispatch cannot recover through active work, supported release, or a corrected invocation, run that pass inline using the same prompt asset and disclose the substitution.

**Nesting depth and coverage.** Verify effective delegation depth through OpenCode's supported configuration discovery; do not infer available capacity from permission or the package-local configuration. Distinguish an actual nesting/depth failure from concurrency exhaustion, a permission denial, a rejected model argument, and a missing tool using the returned error. Do not retry denied operations or evade depth limits with another harness. This skill permits the same-rubric inline fallback, but disclose that it is not an independent reviewer and report any unmet independence or required-model coverage as incomplete rather than fully verified.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.
