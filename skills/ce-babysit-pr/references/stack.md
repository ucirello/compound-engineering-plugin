# Managed stacks: posture, discovery, transitions, upstack maintenance, landing

Run JJ from the verified absolute workspace root, and apply the repository-scoped `gh` preamble from `references/setup.md` to every Stacks REST request.

## Posture (full text)

Hold exactly one posture for the run. It is written as `posture:target|stack-ready|stack-land` — distinct from `watch` / `checkpoint` / `mode:pipeline` / duration. Re-state the same posture on every managed-stack layer `--continue-invocation` transition alongside the existing budget flags.

| Posture | Behavior |
| --- | --- |
| `target` | Only the named PR. Stop at looks-ready. May offer stack-wide once when a confirmed multi-layer managed stack needs work; decline keeps the target-local stop. Never merges. |
| `stack-ready` | Once the active layer is **quiescent** — zero actionable backlog (`counts.threads/comments/ci == 0`), **no standing residual** (no open `needs-human`, no `blocked-failing` — `has_failing_checks` with nothing left to dispatch — no `stack-blocked`, no open or claimed currency item), and no delegate work in flight — automatically continue to the next open non-draft upstack layer that needs work, even while the quiescent layer's CI is still running or its settle window has not elapsed. Lower layers stay under the watcher's downstack probe; the lowest one that re-opens pulls the walk back. Never merges. Persist for the run; do not re-ask each layer. |
| `stack-land` | Like `stack-ready` for traversal. Selecting or handing off `posture:stack-land` **is** run-level land authorization. Landing still requires **settled**, not merely quiescent: submit only the bottom-most open settled layer via the async merge API, then prove landing and reconcile remote topology before continuing. |

**Selection:** the user named one PR with no stack language → default `target`, but if it is a confirmed multi-layer managed stack, ask once (only this PR vs whole stack to ready). Intent to own/finish the stack → `stack-ready`. Intent to land/merge when green → `stack-land`. Prefer intent over keyword matching. An explicit "babysit the managed stack" request selects `stack-ready` (or `stack-land` when land intent is also clear). In `mode:pipeline`, use only the posture/scope already supplied on the invocation — never ask.

When a confirmed managed stack is in play and you need CLI recipes, read `references/stack-commands.md`.

## Discovery and continuation

**Classify from remote evidence.** The snapshot binds the target's repository and exact pushed head to the Stacks REST membership and bottom-to-top order in `references/setup.md`. Only `manager_status == "confirmed"` with `manager_source == "stacks-rest"` identifies an authorized managed stack. Reconfirm the exact stack ID, number, and membership for each transition and mutation; neither local bookmarks nor ordinary PR dependencies establish membership. REST order is not an ancestry or per-layer freshness verdict; prove both separately when acting.

**Only when the fresh snapshot has `manager_status == "confirmed"` may stack-wide continuation activate; no other classification authorizes it.** A manual dependency chain never activates stack-wide continuation: keep it target-local even when its base/head topology resembles the manager's ordered branches. `probe-error` also stays target-local and mutation-conservative until a later snapshot positively confirms the manager. Discovery still runs for every babysit — posture does not disable confirmed-manager detection or Step 7 upstack maintenance.

For a confirmed managed stack, inspect the manager's ordered entries once before choosing the active layer; this is a read-only look at the order, not multi-PR monitoring. Resolve **posture** per the table above before any review/CI work. If posture is still `target` and the requested middle PR has an unsettled downstack layer, offer once to begin at the lowest unsettled non-draft layer and proceed upward (`stack-ready`), with target-only as the alternative; do not silently redirect review/CI work to another PR. If posture is already `stack-ready` or `stack-land` and the requested PR has an unsettled downstack layer, begin at the lowest unsettled non-draft layer without asking (downstack-to-upstack). If all downstack layers are settled, begin on the requested PR. When the requested PR already looks ready or later settles under `target`, offer once to continue to the immediate open non-draft upstack layer if it needs work (accepting selects `stack-ready` for the rest of the run). That one-time offer expands the babysit scope on an already confirmed managed stack — it is **not** a proactive suggestion to create or adopt PR stacks. An explicit request to babysit the managed stack counts as `stack-ready` acceptance, so do not ask redundantly. In `mode:pipeline`, which cannot ask, continue beyond the requested PR only when the invocation already supplied `posture:stack-ready`, `posture:stack-land`, or equivalent stack-wide scope; otherwise return the next candidate as a residual.

Once `stack-ready` or `stack-land` is in effect, that posture authorizes babysitting each layer of the confirmed managed stack in turn without asking again at each layer. Keep one active PR target and one watcher. At each transition: revalidate manager membership and ordered state, stop the old watcher, switch/check out the next immediate layer, then initialize its own snapshot state with `--continue-invocation` and the same three recorded values on the flags the first snapshot used — `--invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS"` (the anchor flag is `--session-started-at`, not `--invocation-started-at`) — plus `--continue-dead-time-seconds <prior layer's `invocation_dead_time_seconds`>` so the shared active-time budget carries the suspended time already excluded on earlier layers (each layer's state dir accumulates its own dead time, so without this the new layer would count that prior suspend as active) — **and re-state the same `posture:` value on the continue invocation**. The invocation budget is not renewed per layer. Never skip past a draft or enter it unless the user explicitly included that draft; never advance past a layer with a `needs-human` blocker. Stop at the first draft outside scope, human-blocked layer, end of the stack, budget, or user stop. Reconfirm `manager_status == "confirmed"` before every cross-PR transition — loss of positive confirmation ends stack-wide continuation rather than degrading into manual-chain behavior.

## Pre-push baseline

**Managed-stack pre-push baseline.** Before invoking a delegate that may push the active target, apply the clean JJ alignment gate and record a recoverable receipt from fresh REST and exact JJ remote bookmark evidence (`references/stack-commands.md`). Include the target and every open dependent above it, with exact direct-parent identity, and reconcile any earlier unresolved propagation or land receipt. If the baseline or workspace cannot be proved, this is a true stop in every mode: no delegate, new tick, or watcher re-arm; report the residual and resume invocation. Do not assume propagation will be atomic.

## Step 7: upstack maintenance after an authorized target push

7. **After an authorized target-head push in a confirmed managed stack, preserve the upstack before resuming the watch.** Retain the delegate's verified pushed OID. Prove from fresh REST and exact JJ remote bookmarks that only the target moved as intended since the receipt, and require clean verified alignment. No open dependent means no cascade. Otherwise use the dependent-only JJ recipe in `references/stack-commands.md`, preparing the complete proven child series before leased pushes. Never rebase the target or trunk, or treat an unexpected target move as authority to overwrite. Stop at a conflict, moved ref, denied/unknown authority, out-of-scope layer, or incomplete receipt; report observations and any confirmed progress with a recoverable residual. Manual chains and delegated target fixers never use this step.

During accepted managed-stack continuation there is one watcher and one mutated target, but the watcher probes below: arm it with `--downstack-pr <N>` for every open lower layer in verified REST order. It wakes `downstack-actionable` for changed work, head, or stack evidence. Re-read exact REST evidence; stop the watcher and return to the **lowest** re-opened verified non-draft layer via `--continue-invocation` only if that transition still satisfies the scope and quiescence rules. Recheck order and downstack quiescence before every transition, active-target mutation, and looks-ready decision. Never mutate two layers concurrently: wait for the in-flight delegate. If confirmation disappears or the new topology is not covered by the receipt, end continuation and report the residual.

## Layer transitions and the stack-land land step

For any layer transition, align via the verified clean JJ head gate in `references/setup.md`; manager state does not authorize discarding work or bypassing the gate. Apply `references/envelope.md`'s factual refresh before the authorized land step when this run made the description stale.

**A confirmed managed-stack layer stop may be a run transition.** Under `stack-ready` the transition condition is quiescence (table above; a layer carrying any standing residual is not quiescent, so the walk never leaves a red or human-blocked layer behind), not settle. When the active layer has nothing actionable, report its state in one line ("quiescent, CI running" / "ready as next"), revalidate the manager and downstack, then advance to the immediate next open non-draft layer that needs work without asking again; pass through already-quiescent non-draft layers only after freshly confirming each one. Its settle window keeps running under the downstack probe; the final report states each layer's settled/quiescent state from a fresh probe. Under `stack-land`, run the land step below **before** any plain advance once the bottom-most open layer is settled (do not skip merge and walk upstack while a settled prefix is still OPEN); a merely quiescent bottom layer may be walked past but not landed. Stop before a draft unless the user explicitly included that draft in scope. Under `target`, if no continuation decision has been made and this is the originally requested PR, use Step 1's one-time offer. A decline makes the target-local looks-ready result the final stop. A `needs-human` layer remains the active layer — keep watching its independent streams, but do not advance upstack. These transition rules apply only while a fresh probe still reports `manager_status == "confirmed"`; independent PRs, manual chains, and probe errors always use the target-local stop.

**`stack-land` land step (after settle / pipeline green gates, before any plain advance).** The active layer must be the **bottom-most open settled** PR in a fresh exact REST stack observation and must pass the existing interactive settle or pipeline success gates on the exact submitted SHA. Use `references/stack-commands.md` to submit once with that expected SHA, retain and poll the receipt, and verify landing and topology. Pending or enqueued is not success: keep the target active without writing a new head or advancing, or return the appropriate bounded pipeline residual. If this run's receipt proves the PR actually merged and the subsequent ref/topology reconciliation succeeds, stop the watcher and `--continue-invocation` on the next open non-draft layer needing work under the same posture and budget. A just-landed layer is a transition, not Terminal; external `MERGED`/`CLOSED` without a matching run receipt is Terminal as usual. Reconcile a recorded in-flight land before applying the ordinary Terminal check so its confirmation is not lost. Failure or inconsistent reconciliation is a stack residual, not authorization for another merge mechanism.
