# Cross-model recovery

Use only on a native start failure or when fold-in has no usable review. Keep exact captured base/head, read-only permissions, fixed recipient/model and brief. No fallback ever invokes Git or another harness.

- **Permission, depth/capacity, model-argument rejection, missing tool:** distinguish from the actual error. Never retry denied delegation or evade nesting with shell. If delegation is allowed but model override is forbidden, omit the optional model argument and use a suitable inherited reviewer. This covers a separate-reader lens, not a required cross-model/fixed-route pass; report that requirement incomplete.
- **Infrastructure failure before a native job ID:** recover the same route only for a new plausibly recoverable error within the shared 1210-second deadline. Stop on a repeated error/deadline; keep local adversarial in the roster if no peer started. Do not retry again at fold-in after that fallback has received the brief.
- **Started then failed infrastructure:** await/cancel the failed native job before bounded same-route recovery. Do not switch model, broaden scope or relax trust. Report the adversarial lens degraded, not simply lost cross-model corroboration, if recovery is the only attempted cover.
- **Transport unavailable before egress:** no content was reviewed or sent. Report not-run and scope/reason accurately. Shared native-tool failure rules out all routes. A route-specific unavailable model is not a user authentication failure.
- **Authentication-shaped text:** attribute user credentials only with positive provider-capable launch/provider-response evidence. Otherwise report execution-context failure, never prescribe account login based solely on peer text. Either way no review occurred.
- **Provider overload:** at most one same-route retry for a positively observed overload (e.g. HTTP 529), owned by the orchestrator, within the original deadline. If it still yields no review, dispatch local adversarial; do not change recipients.
- **Max-turn exhaustion:** local adversarial fallback, no peer retry or recipient switch.
- **Model refused:** preserve a configured or user-named model; do not silently swap it. Only a default model may consume the one replacement attempt on the same route with the closest advertised same-family native model, announced before egress and allowed by model-selection policy. Report the rejected model and configuration remediation. A rejected optional model argument is a host-policy error, not provider refusal.
- **Quota or other established no-review outcome:** one replacement recipient only when the original was not an explicit user preference, another attested-different allowed native route exists, and the shared deadline remains. Announce the new recipient; never switch invisibly inside a worker. No third peer. Otherwise use local adversarial.
- **Ran, no usable output / unknown diagnostic:** report exactly that, with observed terminal state (`failed`, `timeout`, or missing result), not a clean pass. An unknown diagnostic does not prove a no-review outcome; do not invent one. Collect bounded native error/log evidence before cleanup.

The did-not-run fallback dispatches one permitted generic `adversarial-reviewer` with the same brief. Coverage uses `adversarial lens: in-process fallback (cross-model peer not run: <reason>)` and `peer.outcome: in-process-fallback`. This means a separately dispatched inherited-model context, not cross-model proof. Never label it `harness-native fallback` (that is the caller's signal for skipping this skill). An inline or parent-coordinator fallback is allowed only where the review contract permits: focused requires a usable independent read and is **Not ready** if it cannot obtain one. Any required independence, fixed route or cross-model coverage left unmet remains incomplete even if a local lens ran. Genuine prohibitions remain respected; a skill-requested delegation exception does not override them.

Use native lifecycle controls; cancel/await started jobs before retry or cleanup. Retain durable receipts and bounded diagnostic evidence in workspace-local `.tmp/`. Do not remove files of running, ambiguously owned, or still-referenced jobs. No filesystem deletion substitutes for a native cancellation acknowledgement.
