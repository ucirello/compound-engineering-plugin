# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the cheapest capable available model when an override is permitted. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when an override is permitted.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

When model selection is allowed, resolve the requested or configured choice with native `opencode.models` and pass an exact available model to the native OpenCode subagent tool; never guess an ID or dispatch through another harness. When allowed, an explicit model in active instructions takes precedence over the role model in the resolved RocketClaw config, which takes precedence over the tier default. A role or tier in config is intent, not permission to pass a model override.

**Permission and degradation.** Phase 2 explicitly requests these subagents, satisfying a user-or-loaded-skill delegation rule without further approval. An unconditional prohibition or actual denial still applies. Delegation permission is separate from model override permission. If no override is permitted or resolvable, use the inherited model when suitable and keep the read budgets and output caps; disclose any required fixed route you cannot meet. When dispatch is unavailable, run source fetch and media analysis inline where permitted, honoring the same persona, read and write boundaries, and budgets. Still download media to the scratch path and write each finding to its scratch artifact; the summary and plan reconciliation read those paths. If an inline source read is also unavailable, use the matching persona's skip/degrade result; if media analysis cannot run, report `needs_analysis` rather than claiming coverage.

Check effective OpenCode V2 depth and distinguish exhausted nesting depth, temporary capacity, explicit denial, missing tools, model-override rejection, and an actual launched-worker failure by the observed result. Queue temporarily capacity-limited work; do not retry a denial or evade a depth limit. For a correctable pre-launch argument error, correct it once; when the rejected argument is an optional model, omit it only if inherited execution is permitted and suitable. Apply the inline degradation above only for unavailable dispatch, not to retry denied connector actions. A launched media-worker failure retains the media and records `needs_analysis`; apply the source's unavailable-state rule if a launched source worker cannot return results.
