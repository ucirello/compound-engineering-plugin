# Cross-Model Execution Contract

Read when `execution-engines.md` selects a configured route or recovery. The OpenCode host owns the controller protocol below using native `opencode.models`, subagents, and shell tools; no external harness dispatcher or workspace bridge is used. Durable records, not a worker's prose or exit alone, establish completion.

## Resolve intent without changing authority

Preserve current-task, session, caller-binding, project, and configuration precedence. A live preference is `prefer`; unambiguous strict intent is `require`. Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `config.yaml`; a present local list/map replaces that whole key, including empty values. Mode is `off | prefer | require`. Entries retain `harness: codex | claude | grok | cursor | opencode | antigravity` and optional exact `model`; effort remains a per-harness map in its configured levels. Configuration remains desired behavior, not executable shell syntax or authority to change recipients.

Preserve ordered candidates, exact model pins, and effort. Route tokens remain `codex`, `claude`, `grok-cli`, `cursor`, `composer`, `grok-cursor`, `opencode`, `antigravity`; Composer and Grok via Cursor retain intermediary `cursor`. Cursor model presets remain exact data (including `composer-2.5[fast=true]` and `grok-4.7[context=256k,reasoning_effort=high,fast=true]` defaults). An unpinned Antigravity preference retains ordered intent `gemini-4-argon`, then `gemini-3.8-flash`; exact pins never become another model. Resolve available native model IDs with `opencode.models`. A native model with the same family does not prove a configured intermediary, serving route, or effort was satisfied. If that route cannot be represented natively, record it unavailable; never invoke its CLI to evade the host.

Delegation permission, model-selection permission, and depth are separate checks. This skill explicitly requests bounded implementation subagents, satisfying a host user-OR-loaded-skill exception where one exists; unconditional prohibitions, missing tools, and actual denials still apply. If model overrides need an explicit user model request, do not supply the optional model argument solely on configuration authority. An inherited-model worker is eligible only when it satisfies the unit's requirements; disclose unmet configured intent. Same-model workers do not establish cross-model independence. Inspect effective `experimental.subagent_depth` through `opencode debug config` and its sources (`opencode debug paths`); permission alone does not imply remaining capacity. Classify actual launch errors as permission, model argument, missing tool, or depth/capacity. Never evade a denial/depth limit through shell or another harness.

Preflight in configured order without exposing content. Skip only an equivalent current-host default or an evidenced unavailable candidate. Disclose requested versus actual route/model, effort, receipt status, and each fallback reason. `prefer` and `require` both continue natively on the current session model after all candidates prove unavailable; strict intent never authorizes another unrequested recipient. Once an attempt starts, it must become authoritatively terminal or reaped before any retry/fallback. Required independent/different-model coverage that cannot be supplied remains incomplete, never fully verified.

## Sanction, source, and isolation

Before egress, record binding source, fixed recipient/provider/route/intermediaries, bounded material exposed, caller restrictions, enforced versus cooperative restrictions, and permission posture. Isolation is not an OS security sandbox; native permissions are inherited, never automatically approved or broadened. A required restriction the native tools cannot enforce makes the route unavailable.

Create durable private run state under the canonical workspace's ignored `.tmp/rocketclaw/ce-work/<run-id>/`, with an owner-only directory. `CE_WORK_RUNS_ROOT`, when set, denotes the parent containing run IDs and must resolve under local `.tmp/`; never use OS temporary storage, including fallback/error paths. Record repository identity, absolute canonical root, selected bookmark, verified base commit ID, source kind/digest, fixed engine/model/effort, and every transition atomically in a manifest with receipts. Keep packet/result/log paths and SHA-256 digests. Once initialization records READY, engine selection is locked: overhead, latency, or triviality cannot reopen native authoring.

A plan may be the sole canonical dirt: make a disclosed, owned-plan-only checkpoint through the message standards in `implementation-loop.md`, recording its commit and digest. Unrelated dirt blocks this route, never implicit checkpointing. A prompt brief needs a clean canonical state. Write it directly under local run state, not as tracked repository content: Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, Units. Use conservative P1 unless discovery proves distinct goals/dependencies/files/checks. Missing goal, bounded scope, or authoritative verification returns to clarification. Store a private copy and SHA-256; caller source paths cease being authoritative.

Detect existing isolation first. Reuse verified existing isolation without renaming/recreating or silently enforcing colocation. Ordinary synchronous units stay in the active checkout and ordinary native isolation remains harness-owned. For a cross-model unit needing isolation, use the harness's supported colocated JJ capability and lifecycle if available. Unsupported required capabilities are blockers, not permission to bypass ownership. If host-managed creation is authorized, use `ce-worktree` with one local date captured once and one identity `YYYYMMDD-<meaningful-task/pr/revision-slug>` for both registered workspace name and destination basename. Normalize supplied names without double-prefixing; check registrations and destinations, append `-2`, `-3`, etc. on collision, and retain the identity through retries/resumes/midnight. Existing isolation and source/PR bookmarks stay unchanged. From the source absolute root:

```sh
(cd "$workspace_root" && jj workspace add --colocate --name "$dated_identity" --revision "$verified_base" "$absolute_owned_destination")
(cd "$absolute_owned_destination" && jj git colocation status)
```

Keep destinations in the owned local `.tmp/` layout. Verify registered name, path, base commit ID, and colocation before edits. Move the active harness session using its supported session-move facility if adopting that workspace. Never silently repair an incompatible harness workspace. JJ reference: https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace . All JJ commands run with cwd at the target workspace's absolute root, never merely `jj -R`. Repository-scoped `gh` uses `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`; never execute Git directly.

## Host-owned unit transaction

Use separate visible host tool calls for state-changing transitions; never hide start-through-integration in a shell loop. Persist evidence before each next transition. Each unit/attempt gets a fixed recipient and fresh handle; a handle may recover that unit only, never another unit.

1. **Prepare.** Recheck canonical identity/bookmark/base/cleanliness. Record run/unit/attempt IDs, expected files, base, dependencies, wave fields, packet path/digest, and restriction posture. Packet includes only Goal Capsule, Definition of Done, active unit, relevant Verification Contract rows, cited R/F/AE/KTD excerpts, Product Contract Key Decisions whose `Governs R…` links match the unit's R-IDs, inherited restrictions, prototype citations with locality/availability/authority qualifications, and matching Compound Pack rules from `work-intake.md`. For prompts include only the matching P-unit. No transcript or full source by default. Workers inspect accessible explicitly cited prototype decisions/screens, even in another workspace, but edit/test only their own workspace. Expected scope is not permission to expand it.
2. **Start fixed author.** Bind native handle and actual model metadata to authorization containing run/unit/attempt, route/intermediaries, recorded effort, packet digest, workspace and bounded authority. Record dispatch before considering any fallback. Worker has no canonical commit, push, PR, shipping, peer-scheduling, recipient-switch, or expansion authority. Keep output as working-copy changes; JJ automatic snapshots are not canonical commits. Use the implementation-worker prompt. Never claim a served model/effort is verified without native evidence.
3. **Observe.** Use supported native status/wait facilities, at most 60 seconds per wait; report unit/route/elapsed/latest activity/state. Preserve a 7200-second hard limit and a 600-second progress-reset idle window only for trustworthy incremental activity. For hard-only activity disable idle expiry; silence alone does not justify fallback. If the native API cannot enforce required supervision, report the unmet capability before dispatch. Loss of contact stays live until authoritative terminal evidence or explicit supported termination/reap; retain workspace and receipts.
4. **Terminalize and inspect.** Snapshot completed output with JJ, record exact base and final commit/tree, and retain a recovery bookmark. Require one recorded base parent and the complete final tree; no partial file-only transport. In a later call inspect actual diff, all paths, binary/mode/rename/deletion changes, result evidence, expected scope, and expansion requests. Generated byproducts and unexplained scope block integration. Process completion is not integration or verification.
5. **Acquire and preflight.** Record an exclusive integration lock and exact canonical pre-fold commit/tree/bookmark, tracked inventory/conflicts, and ignored/untracked metadata. Reject unknown canonical movement or unrelated dirt. Record expected post-apply tree and changed paths. Integrate the isolated delta using native JJ rebase/squash operations only after proving base and owned scope; preserve transport/recovery references. Never replace a reviewed range or integrate a transport commit directly as the canonical commit. Any conflict is a stop, not permission to discard files.
6. **Verify and reconcile.** Run the authoritative Verification Contract command in the canonical absolute root, capturing its exit status directly and keeping logs in run state, with Python bytecode disabled where relevant. Use explicit `bash -o pipefail -c` for shell syntax; direct argv never expands substitutions. Reconcile exact expected tracked state before recording verified. Inventory ignored entries by metadata before/after; disclose changed/removed/created counts with bounded path samples as `ignored_state`, never copy/restore/delete them. Ignored caches/databases/`.env` and untracked content are not protected by tracked snapshots; empty ignored directories need not be inventoried.
7. **Commit or recover.** Only a verified, reconciled unit gets a host-owned owned-path canonical commit, using `implementation-loop.md`'s runtime message standards. Record its exact commit/tree and verification receipt. On any failed pre-commit transition or check, stop, retain the lock, and restore only proven run-owned tracked changes through native JJ recovery from the recorded snapshot; prove exact pre-fold equality before releasing the lock or allowing retry/sibling/fallback. If restoration is uncertain, retain all state and report blocked. Never overwrite unknown work. A crash after a canonical commit is reconciled from parent/tree evidence, never redispatched.
8. **Clean and release.** Cleanup is not implied by completion: require existing authorization and prove integration (or explicit abandonment naming the exact transport commit/terminal handle). Stop workers, leave target, move any active session to a surviving workspace, verify exact registered name/absolute path/run ownership, inspect tracked conflicts plus ignored/untracked content, and preserve recovery references. Copy required packets/receipts/logs outside the target and read them back. Non-disposable, unrelated, ambiguous, or still-referenced content blocks removal. Respect harness lifecycle authority. From the surviving absolute root use `jj workspace remove <verified-workspace-name>` for authorized deletion. Verify deregistration AND directory disappearance; warnings can leave files. Retain remaining state and report failures, never force-delete or use Git. `jj workspace forget` is only for unregistering while preserving files. Bookmark deletion is separate; keep archive/best/recovery and needed references.
9. **Verify run.** After all units are terminal, run source-wide authoritative checks from a clean canonical snapshot with exit/log/ignored-state evidence and exact tracked reconciliation/restoration safeguards above. A failed check blocks shipping/return even after cleanup. A successful durable RUN_VERIFIED receipt is required for complete status.

## Parallel waves

Apply `execution-strategy.md`'s Safety Check across dependencies, paths, shared contracts, migrations, lockfiles, generated/config surfaces, environment singletons and merge cost. Cap at 3–5. Record one clean wave base; isolate every concurrent worker. Terminalize every worker before the first fold and inspect all actual inventories. Same-path/semantic collisions block the wave. Integrate sequentially in dependency order; reverify scope and semantics against the advancing tree even after a clean apply. While holding the lock, record each host commit whose parent is the exact pre-fold canonical commit and allow only those exact earlier wave commits for later siblings. Clean/release before the next integration. Failed apply/check/commit requires proven restoration before another sibling/retry/fallback; affected dependents stay queued. Repeated collision or broad edits disables waves; preserve unaffected results rather than discarding them.

## Recovery and exactly-once fallback

Recovery runs before input classification, with no new dispatch/route/source discovery or shipping. A supplied safe run ID is authoritative. Without one, plan discovery may match only canonical repository identity/bookmark and selected plan digest; multiple unfinished matches require a decision listing matching IDs/recovery paths, never a guessed run or third run. Prompt-backed runs require their disclosed ID. Unsafe or foreign-mode manifests block recovery.

Reconcile durable manifest, native terminal metadata, exact base/final tree, expected post-apply inventory, and canonical parent/tree before adopting one matching unbound handle or continuing terminalization/restoration/commit reconciliation. Unknown dirt blocks; live contact loss never authorizes duplicates. Already-complete runs with successful source-wide verification are observation-only: return stored receipts, never rerun tests/builds/install/generation/shipping merely to reconfirm them. Missing required evidence is a blocker.

After authoritative failure/timeout/died-without-result and any required exact restoration, abandonment cleanup, and lock release, durably claim fallback once for that unit. Refuse while a job is live or successful output is unreconciled. Both `prefer` and `require` may claim current-session native fallback after disclosing unavailability; neither may substitute an unrequested recipient. An existing claim means do not execute again. Record accepted native canonical commit, SHA-256 verification-evidence digest and summary as native-completed; require source-wide RUN_VERIFIED afterward. Retrying an external unit retains scalar run ID, previous receipts, dependency/wave/base contract and fixed engine, with a fresh attempt ID. Report every transition, blocker and recovery path to the user/caller.

## Tail ownership and receipts

Record `implementation_engine_binding` (mode/target/model/source), requested/actual routes and intermediaries, requested/actual model and served-model receipt status, requested effort or null (served effort unverified absent evidence), fallback reason, source kind/digest, run ID, plan checkpoint, per-unit process/integration/verification/canonical-commit/cleanup receipts, blockers and recovery path. No worker summary can replace actual evidence. Standalone resumes its shipping reference only after these gates; return-to-caller returns implementation/local verification with `standalone_shipping_skipped: true`, never simplify/review/PR/CI. Engine choice never transfers canonical or tail authority.
