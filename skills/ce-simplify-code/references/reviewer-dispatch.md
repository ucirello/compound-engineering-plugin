# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers the reviewers' model, what happens when the harness is full, how review agents are released, and the permission mode.

**Model selection.** Resolve available model IDs with native `opencode.models`; use native OpenCode subagents or supported native shell dispatch, never a bridge or another harness dispatcher. Preserve the existing configured reviewer role/tier, defaulting to balanced mid-tier only when no applicable configuration exists. Apply an override only when the dispatch primitive supports it and host policy permits it; task wording alone does not select a model. If host policy requires an explicit user model request, omit the optional model argument absent that request, use a suitable inherited reviewer, and disclose the unmet configured route. Delegation permission does not itself authorize a model override.

If the user's or project's active instructions or the live prompt name a model for this subagent, use that model instead of the default tier above. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. Distinguish actual permission denial, unavailable tools, model selection errors, nesting-depth limits, and capacity errors; do not treat any one as evidence of another. Bound retries to recovery through active work, supported release, or one corrected invocation; do not loop on unchanged failures. When dispatch cannot recover, run that pass inline using the same prompt asset and disclose the substitution, provided inline review is permitted. A genuine higher prohibition or tool denial must not be bypassed through shell or another harness. Return each required persona's terminal outcome or explicitly mark its coverage incomplete; never proceed to fixes with missing mandatory review coverage. Same-model separate reviewers provide separate passes, not cross-model independence.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** This loaded skill's explicit request for reviewers satisfies the user-or-loaded-skill delegation exception; do not ask for redundant approval. Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply. Effective nesting depth and available slots are separate from permission; neither grants permission nor proves denial. Preserve configured permissions and do not alter host configuration during this review.
