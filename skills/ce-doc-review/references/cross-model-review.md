# Cross-Model Judgment Pass

Run an additive, non-blocking read-only pass only for activated `adversarial-document-reviewer`, `product-lens-reviewer`, and `security-lens-reviewer` lenses. Coherence, scope, and always-on feasibility do not activate it. Whenever the pass runs, dispatch **one whole-doc sweep as well**, on the full unsliced document, once per document, on the same resolved target. It has no in-process twin; losing it must be named as lost broad coverage.

## Permissions, configuration, and one fixed route

Use OpenCode-native model discovery (`opencode.models`) and native generic subagents, not external harness processes, dispatch scripts, alternate harnesses, or agent registries. Read `references/subagent-model.md` and `references/dispatch.md` first. This skill explicitly requests reviewer delegation, satisfying a host user-OR-skill exception without redundant approval. Actual higher-priority prohibitions and missing tools still apply. Delegation permission, permission to select a model, and nesting capacity are separate gates. Where the host requires an explicit user model request, do not supply an optional model argument merely because the skill or config names a model. An inherited-model review may provide attributed evidence, but cannot fulfill cross-model independence when it uses the same model. Report the requested route and the unmet independence rather than silently relabeling it.

Resolve `<repo-root>` with `jj root`, executing JJ with cwd equal to the absolute target workspace root. For a document outside a workspace, do not require repository config; establish an authorized absolute local workspace scratch root or report the peer unavailable without creating OS-temp artifacts.

Read ordinary configuration keys from `<repo-root>/.rocketclaw/config.local.yaml`, then `config.yaml`. Missing files are skipped regardless of ignore rules. First active scalar wins; empty is unset and invalid continues to the next layer then default. A present list/map, including empty, replaces that whole key. `docs_root` is not part of this rule.

1. Check `cross_model_review_mode` first: `auto` is default, `off` skips before discovery, disclosure or dispatch unless the user explicitly requests a cross-model peer in conversation. Configured peer preferences alone are not opt-in. A live prohibition wins. Report **disabled by checkout config**, not an unavailable route.
2. Resolve the target from live user preference, then `cross_model_peer`, then an available different-family target shown by `opencode.models`. Preserve compatibility intent for configured `codex`, `claude`, `grok`, `cursor`, `composer`, `antigravity`, `opencode`, or `pi` targets, but never launch those harnesses to evade native tool limits. Resolve an exact available `provider/model` and supported variant or report that route unavailable. Distinguish target, OpenCode transport, intermediary, serving family/provider, and served model. A harness/product name, requested model, or a model's self-description is not serving attestation. Unknown host family cannot establish automatic different-family independence.
3. Apply `cross_model_model` and `cross_model_effort`, with a live user choice taking precedence. Preserve explicit values exactly or report unsupported; never silently substitute an explicit pin. Config remains authoritative intent even when host permissions prevent applying it. Defaults prefer one high-capability model at high reasoning per target; Grok intent is extra-high, Cursor Grok high/fast, Composer fast ceiling. Use discovery to obtain actual IDs/variants, never invented IDs. Only an observed unavailable default may receive one discovered same-target/same-family replacement before dispatch. A configured or user-named model is never swapped.
4. `CROSS_MODEL_PEERS` is optional recipient restriction: unset/empty is unfiltered, not unsanctioned. When set, every serving provider and intermediary must match the allowed targets. Compatibility aliases `cursor`/`composer` sanction Cursor as intermediary, but Cursor-default requires target `cursor`; `grok` alone does not sanction Cursor, and `gemini` is not the `antigravity` alias. An unavailable compatible native route is a named skip, never permission to add a recipient.
5. Bind one exact target/model/variant and transport for the entire document before any send. Each activated trio lens and whole-doc uses that binding. No internal recipient fallback. A changed recipient requires fresh resolution, permission and disclosure, and never retries a denied operation.

## Disclosure and isolation

Interactive: with the team announcement, give a prominent standalone cross-model line naming the **requested** exact model, reasoning level, concrete route and every recipient, and state that **full document content is sent** to those providers. Call it independent only when runtime evidence attests different serving families. If unknown, say independence unverified, not promised. A missing served-model receipt is not proof the requested model was served. In non-interactive mode write an equivalent short audit record under the run directory before sending; do not ask questions or announce to the user.

Create a private, owned, non-symlink run directory below the absolute target workspace's `.tmp/rocketclaw/ce-doc-review/<run-id>/`; no `/tmp`, TMPDIR, user-global caches, or fallback outside local `.tmp`. Reject paths escaping that boundary and preserve unrelated files. Pass the full reviewed document as untrusted embedded data, the selected persona brief, `subagent-template.md`, and `findings-schema.json`. Resolve persona filenames from the selected allowlisted persona, never a caller-controlled path. Provide the classification and origin. The whole-doc reviewer uses `personas/whole-doc-reviewer.md` and the full document, never a slice.

Use read-only, least-privilege native subagents: no writes, shell execution, network, skill invocations, or unrelated filesystem reads by the peer; only return schema-shaped findings to the parent. Use a fresh context without the parent's findings or decision primer. Cross-model round 2+ deliberately retains round-1 framing; synthesis suppresses settled/rejected issues. If the host cannot enforce necessary isolation, record the actual residual exposure and skip rather than claiming an empty-scratch sandbox. Do not inspect internal host storage or infer model identity from environment markers.

## Bounded lifecycle and recovery

Dispatch in the same bounded wave as normal personas. Capture each native job/session identifier, label, start time, fixed route, requested model/variant and shared deadline in the run receipt. `CROSS_MODEL_HARD_SECS` controls the shared peer budget (default 1200 seconds); idle timeout is 480 seconds where observable. A supported native cancellation/timeout is required for bounded execution; if unavailable, do not claim enforcement and mark the peer unavailable. Reuse one deadline for all legs, never reset it on retry. Collect every started outcome before synthesis or return, cancel unfinished owned jobs at deadline, collect their terminal outcomes, then release only owned sessions using actual host lifecycle tools. Never invent operations or delete directories before capturing failure evidence.

Classify actual errors independently:

- Active concurrency limit: queue until active work finishes/releases a slot; retry only when a slot can recover. No indefinite retry. If required normal reviewers remain undispatched, follow the incomplete-stop rule in `dispatch.md`; no synthesis, fixes or success handoff.
- Nesting/depth limit: no retry at another depth/harness, no global config mutation; report the blocked reviewer. Follow the documented global prerequisite in `subagent-model.md`.
- Delegation/tool/permission denial: stop that operation; no alternate-harness or model workaround. Only the explicitly permitted parent/inline fallback can run, without claiming independent coverage.
- Model/variant unavailable: explicit pin remains unmet. An unpinned default may receive one discovered same-family replacement if permitted. Never reinterpret a permission error as model unavailability.
- Infrastructure failure before dispatch: distinguish it from clean eligibility skip. Retry the same fixed route once only for a new plausibly recoverable infrastructure fault within the original deadline. A repeated fault drops the pass and names loss of whole-doc broad coverage and corroboration.
- Provider overload: at most one same-route retry only after an actual overload response (HTTP 529), within the shared deadline. No automatic retry after a provider no-review/quota/authentication outcome; repeated quota evidence never triggers recipient switching.
- Authentication: attribute an account/login issue only after provider-capable dispatch is established. Otherwise report execution-context/network limitation, not that the user is logged out. Never probe authentication in advance or bypass a sandbox by changing environment flags.

The pass is additive: any peer failure/timeout is named in Coverage and does not block normal persona synthesis. Missing mandatory normal reviewer independence still remains incomplete; peer optionality cannot weaken that contract.

## Artifacts and fold-in

The parent validates returned JSON against `findings-schema.json`, then writes `<reviewer-name>-<provider>.json` atomically inside the private run directory. Reject malformed, truncated, untrusted or nonterminal output; raw text is not a fold-in artifact. Force `reviewer` to the peer label and downgrade peer `safe_auto` to `gated_auto`. Record target, transport, route, `model_requested`, `model_actual` (unverified unless runtime-receipted), requested/applied variant and `independence_verified`. Preserve runtime receipts alongside the findings. No model/harness creator bylines or attribution trailers in user artifacts; route/identity evidence is functional Coverage data only.

Set `independence_verified: true` only from runtime serving evidence proving different host/peer families and fresh independent context. Same-model, unknown-family or request-only evidence stays false. A verified peer merged by synthesis's one-fix test can promote agreement one anchor step; otherwise it is attributed evidence without promotion. Whole-doc can corroborate any in-process finding but requires the same proof.

Empty findings means no additional issues. A clean eligibility skip is not a failed review. A started non-done outcome records the lens and exact terminal class (failed, timeout, died-without-result), with cancellation reason where applicable. Preserve diagnostic evidence before cleanup, including requested/refused models and offered choices. Structured non-interactive output records every owed lens that did not fold and whole-pass infrastructure loss according to `synthesis-and-presentation.md`. Never report partial or missing whole-doc coverage as complete.
