# Native peer recovery and coverage

Classify actual errors separately: unavailable tool, unconditional permission prohibition/denial, forbidden model argument, nesting depth, temporary active-agent capacity, provider overload/rate limit, authentication, malformed output, timeout or infrastructure crash. Do not call a depth error a permission denial. Permission does not prove remaining nesting capacity; inspect the effective OpenCode configuration/depth evidence when exposed. Never modify host configuration or evade a limit through shell/another harness.

- Before launch, correct one malformed invocation if permitted. Model override denial means omit `model` and use a suitable inherited reviewer; required different-model coverage remains incomplete. Never retry an actual permission denial. Capacity backpressure queues until active workers release slots; exhausted nesting is not that queue.
- A no-launch infrastructure failure is recovered before finalizing the local roster. Retry only the same disclosed route, model, scope and read-only brief while each error is newly recoverable and the shared 1210-second deadline remains. Repeated errors end recovery. If no peer starts, retain local adversarial, with lost cross-model coverage explicit.
- Once a launch exists, persist its receipt, collect terminal state and stop/release it before any retry. Use the same deadline, never reset it. One same-route overload retry is allowed only on observed provider overload (HTTP 529); do not duplicate automatic provider retries. Max-turn exhaustion and ordinary provider no-review outcomes restore the local adversarial lens without claiming cross-model success.
- Authentication diagnoses require a provider-capable launch or provider response. A login-shaped sandbox error alone does not establish that the user's account is logged out. Preserve bounded diagnostics before cleanup.
- For a quota failure, a different recipient is allowed only when the original selection was automatic and another eligible allowlisted different-family native route exists. Resolve and disclose the new route before sending. Explicit recipients do not switch. Otherwise run the local fallback and record `adversarial lens: in-process fallback (cross-model peer not run: <reason>)` with `peer.outcome: in-process-fallback`.
- Terminal crashes may use bounded same-route recovery, preserving exact captured scope. A recovered pass after local dispatch is degraded lens coverage; never run two adversarial reviewers on the same brief accidentally. A late timeout cannot be labeled a completed pass. If fallback is prohibited/unavailable, report the lens incomplete, not fully verified.

Never label the local fallback `harness-native fallback` (that is the caller's separate skipped-skill signal). Never promote findings without attested different-model independence. Native launch receipts, terminal errors, artifact validation and actual serving identity govern the outcome; a job ID, progress update, requested model or an empty artifact does not prove a successful review. Retain diagnostic and receipt files under local `.tmp/`; cleanup means stopping/releasing owned workers, not deleting evidence.
