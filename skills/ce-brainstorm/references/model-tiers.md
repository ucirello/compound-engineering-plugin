# Model Tiers

Read this when dispatching a sub-agent (the Phase 1.1 grounding scout, the Phase 2.6 claim verifier, or the opt-in Slack researcher). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** — the grounding scout: retrieval and quoting work. Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec — escalate to the generation tier when the repo is large or the stack obscure.
- **Generation tier** — the claim verifier: evidence-driven mechanical verification. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** — the dialogue itself. Questions, approaches, synthesis, and the requirements-only unified plan run in the main conversation on the orchestrator's model; nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, use that model instead of the default tier above. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier.

**Degradation rule.** If native dispatch does not accept a model override, dispatch the scout and verifier on the inherited model with the same read budgets and output caps. If native dispatch is unavailable, scan the topic inline, writing the grounding dossier when local scratch is available, and verify claims inline before the Phase 3 write. For requested Slack research, search inline only when the same Slack tools are available; otherwise report the blocker. Installation requires OpenCode's effective `experimental.subagent_depth` to be at least `3`. If the host reports a depth limit, point the user to that setting; do not edit their configuration.

Use OpenCode's native generic subagent primitive and the native model catalog (`opencode.models` where exposed) for exact model overrides. Pass the absolute workspace or starting directory. Issue independent dispatches together and announce what can proceed in parallel; wait only when the next action needs a result. Classify a rejected native dispatch by whether an agent launched: correct a pre-launch argument rejection once, leave capacity-limited work queued without duplicates, and send any other failure to the inline degradation above. Do not report a worker's coverage until its result is actually available.
