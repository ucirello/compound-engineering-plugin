# Native Cross-Model Execution Contract

The host is the controller. Use `opencode.models`, native subagents and shell, not a bundled work engine, detached runner, workspace bridge, or another harness dispatcher. Controller references in this skill mean this protocol. Keep durable atomic run records under `<absolute-workspace-root>/.tmp/rocketclaw/ce-work/<run-id>/`, with one host writer and exclusive integration ownership. Never claim cooperative instructions are enforced confinement.

## Route selection and permissions

Follow `execution-engines.md` authority precedence. Resolve `work_engine_mode` (`off | prefer | require`), ordered `work_engine_preferences` objects (`harness`, optional `model`), and harness-keyed `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `config.yaml`. Present local lists/maps including empty ones replace the team key. Invalid scalars continue to the next layer. Off disables standing preferences, not live intent. Preserve typed binding provenance, model/provider choices and tiers as intent. Intent names include codex, claude, grok, cursor, composer, opencode and antigravity; a fixed harness/intermediary requirement cannot be silently relabeled as native execution.

Use `opencode.models` to resolve exact available provider/model IDs and variants without exposing repository material. Traverse candidates in order and record every rejection. Never substitute an explicit pin or effort. Configuration is not permission to override a model: if the host requires an explicit user model request, omit the optional subagent model argument and use suitable inherited-model workers only where allowed. Separate delegation permission, model-selection permission, and nesting capacity. Skill-requested dispatch satisfies a user-or-skill rule, not an unconditional prohibition. Verify effective nesting capacity (deep chains require `experimental.subagent_depth` at least 3; installation alone does not establish it). Classify actual errors as permission denial, model rejection, capacity/depth, or missing tool. Correct one pre-launch argument error once; never retry denials or evade limits through shell/another harness.

Preserve existing route intent: `grok-cli` means native Grok and `grok-cursor` means Grok through Cursor, with that intermediary recorded; Composer means a Composer-family model through Cursor. Explicit Cursor preset IDs remain exact requested model data, not shell syntax. When those legacy routes omit a pin, preserve `grok-4.7[context=256k,reasoning_effort=high,fast=true]` for grok-cursor and `composer-2.5[fast=true]` for Composer as requested intent. Antigravity serves only the requested Gemini family here; an unpinned candidate retains the ordered defaults `gemini-4-argon`, then `gemini-3.8-flash`. Native availability must be established through the catalog, not another harness's CLI, and a required intermediary that OpenCode cannot satisfy stays unavailable. Resolve effort independently even for live/caller candidates; a present local map replaces the team map. An invalid non-map requests nothing and is disclosed once; an unsupported requested effort makes the candidate unavailable. Native fallback uses session effort and reports that the configured effort was not applied.

Same-model workers are separate workers, not cross-model independence. Required different-model/exact-route coverage remains incomplete when unavailable. Both prefer and require disclose exhausted candidates and continue on the current session model without expanding authority or claiming the requested route ran. Collapse same-host/default candidates without a redundant job. Once dispatch starts, do not change recipient or fall back while it is live or unreconciled.

## Source, authorization and receipts

Use safe run IDs matching `^[A-Za-z0-9._-]{1,128}$`, not all periods. Record repository identity, absolute canonical root, bookmark, verified base commit, source kind/digest, binding/source, requested and actual route/provider/model/intermediaries/effort, identity receipt status, fallback reason, blockers and recovery path. Served identity/effort remain unverified unless actual runtime evidence establishes them. Before dispatch disclose recipient, exposed material, inherited authority and enforced versus cooperative restrictions. JJ workspace isolation is not an OS sandbox; required confinement that cannot be enforced makes the route unavailable.

Copy and hash the selected plan or bounded prompt brief into private local run state. A brief contains Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units (one conservative P1 by default). Missing goal/scope/verification returns to triage. Never include raw conversation, unrelated context or credentials. A selected plan that is the sole canonical dirt may be checkpointed by the host using the dynamic message standards in `implementation-loop.md`; disclose that exact checkpoint. Unrelated dirt is not checkpointed. Ignored inventory size alone never blocks the route.

Per unit/attempt record packet path/digest, dependencies/wave/base, workspace/name, worker handle, start/activity/terminal evidence, actual changed paths, result, integration, verification exit/log/digest, canonical commit, ignored-state divergence, cleanup and fallback claim. Follow `implementation-result-schema.json`. Worker summaries and process exits are not integration proof.

## Unit transaction

1. Re-read source digest, canonical repository/bookmark/base and cleanliness. Record a selected-engine lock; overhead or speed cannot silently unlock it. Prepare the bounded packet in `execution-strategy.md`, including reverse-linked Product Contract decisions, prototype locality/citations, evidence strategy, expected files and exclusions. Grant one fixed model, one unit and workspace, no canonical commit/push/PR/shipping/peer scheduling/scope expansion.
2. Detect isolation first; reuse existing isolation under its verified existing name without recreation or lifecycle changes. Prefer supported harness-owned colocated JJ isolation. Otherwise this selected isolated route may use `ce-worktree` under its authorization rules. Capture the local creation date once; derive `YYYYMMDD-<meaningful-kebab-case-slug>` from task/PR/revision, normalize caller names without double-prefixing, persist it across retries/resumes/midnight. Check registrations and destinations; suffix collisions `-2`, `-3`, etc. Name equals destination basename under local `.tmp/`; preserve source/PR bookmarks. Unsupported harness naming/colocation is a compatibility blocker. From the absolute source root run `(cd "$workspace_root" && jj workspace add --colocate --name "$name" --revision "$verified_base" "$absolute_destination")`. From the absolute destination verify `jj git colocation status`, root and actual base before editing; stop on mismatch.
3. Dispatch a fresh native subagent with the exact hashed packet, absolute cwd, base and permitted model/variant. Bind its handle to this unit only. Record start before observation. Observe through separate supported waits capped at 60 seconds, with a 7200-second hard bound and a progress-reset 600-second idle bound only when incremental activity is trustworthy; otherwise disable idle (`hard-only`). If native lifecycle cannot guarantee required bounds, report the limitation and block, not invent an adapter. Missing activity/contact is not termination. Never duplicate live work; record confirmed stop/reap through supported lifecycle authority.
4. On authoritative terminal completion, snapshot and pin the full final JJ change with the exact recorded sole base parent. In a separate host step inspect exact base-to-result paths/diff, binary/mode/rename/delete evidence, worker result and scope requests. Unexpected paths/generated byproducts block before integration. Preserve recovery references. Workers leave results for the host; no canonical commits.
5. Acquire the single host integration lock; record exact canonical pre-integration change/tree/bookmark/status and recovery revision. Revalidate dependencies and advancing base. Use native JJ operations to rebase/integrate only the accepted unit, inspecting conflicts and semantic compatibility. Run authoritative verification from the absolute canonical root and capture the actual exit directly (shell expressions require an explicit pipe-failing shell). Reconcile tracked state exactly before committing. Record ignored/untracked metadata before/after, counts and bounded samples of changed/created/removed entries; do not silently copy/restore/delete ignored files. Empty ignored directories are not inventoried and local databases/secrets are not snapshot-protected.
6. Failed verification or unexpected tracked mutation forbids commit. Restore only positively attributed integration changes from recorded JJ recovery revisions, preserving unrelated state. Prove exact pre-integration equality before releasing the lock, retrying, falling back or continuing siblings. If proof fails retain lock/workspace/refs/evidence and return blocked. After success the host makes the owned-path canonical commit with the full dynamically composed message, records exact parent/tree/commit/evidence and releases the handle. Reconcile a crash-after-commit from evidence, never redispatch it.
7. Once all units are terminal, run source-wide authoritative gates with direct exit capture, exact tracked reconciliation, ignored-state disclosure and durable logs. Failed gates block return/shipping even after cleanup.

All JJ commands use the target workspace's absolute root as cwd, never `jj -R` as a substitute. Repository-scoped GitHub calls use `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. No direct Git executable use, including history, review or transport. All scratch/failure logs live under local `.tmp/`. Latest JJ references: https://docs.jj-vcs.dev/latest/git-experts/ ; https://docs.jj-vcs.dev/latest/git-command-table/ ; https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace .

## Waves, recovery and exactly-once fallback

Apply the full independence check in `execution-strategy.md`, bounded 3–5 concurrency, disjoint ownership and one clean recorded wave base. Launch ready calls together; terminalize and inspect all results before the first fold. Integrate sequentially, record exact canonical parent/tree/commit, and revalidate later siblings against the advancing base. Shared paths/contracts stop affected units even if application is clean. Failure requires proven restoration and lock release; stale/colliding results require explicit resolution or fresh attempts. Repeated collisions disable waves; preserve unaffected results and queue dependents.

Recovery uses the supplied safe run ID before triage without dispatch. Without one, discover only a unique unfinished plan run matching repository/bookmark/source digest; prompt runs require the disclosed ID. Multiple matches or unsafe/foreign records block selection. Reconcile handles, terminal output, pinned parent/tree and canonical receipts. Unknown dirt blocks, never destructive restoration. Completed recovery is observation-only: return stored unit and plan-wide receipts, never rerun tests/build/install/generation or either shipping tail. Missing receipts block success.

After confirmed failure/timeout/termination, exact restoration and lock release, the single host writer records one fallback claim before native work. Refuse an existing claim/completion, live attempt or successful unreconciled output. Both modes may continue on the current session model, never another unrequested recipient; report unmet cross-model requirements. Corrected retries use fresh attempt IDs under the same scalar run ID, preserving prior receipts and dependency/wave/base contracts. Complete fallback only with accepted canonical commit, local verification digest/summary and successful final gate receipt.

## Cleanup and tail ownership

Completion alone does not authorize deletion. Respect cleanup authorization and harness lifecycle. Stop workers; leave the target and move any active harness session to a surviving workspace. Verify exact registration/name/absolute path/run ownership, prove integration, preserve recovery/best/archive bookmarks and copy/read back required evidence outside the target. Inspect tracked changes/conflicts and ignored/untracked files; snapshots do not protect ignored/untracked content. Never remove ambiguous, unrelated, still-referenced or non-disposable content. From a surviving absolute root use `jj workspace remove <verified-workspace-name>` only when authorized. Verify both deregistration and directory disappearance; partial deletion/warnings retain state and report blockers, never force-delete or use Git cleanup. `jj workspace forget` is unregister-only, preserving files. Bookmark deletion is separate.

Standalone runs resume `shipping-workflow.md`; return-to-caller returns receipts with `standalone_shipping_skipped: true`, never simplify/review/PR/CI. Workers inherit neither tail. Report every route/checkpoint/dispatch/activity/terminal/integration/restoration/verification/commit/cleanup transition and blockers/recovery paths.
