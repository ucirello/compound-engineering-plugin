# Resolve the target and arm monitoring

Use JJ and GitHub CLI from the workspace's absolute root. Every repository-scoped `gh` call uses `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. Inspect `jj git remote list` and require successful `gh repo view`; non-GitHub or unresolved repositories stop with a clear GitHub-only report.

Resolve an explicit PR number/URL first. Otherwise inspect bookmarks on `@` and their remote tracking. **If `@` is an empty working-copy change, also inspect `@-`, its bookmarks, remote branch, and associated open PR before deciding no PR exists.** Continue for an eligible parent PR. Ambiguous identities require a decision, not a guessed target.

For automatic handoffs, read draft state before creating a new invocation or superseding any watcher. A draft is excluded unless the user explicitly included it. Respect standing monitoring opt-outs before bootstrap. Description-only requests stay draft-only.

Verify `headRefName`, `headRefOid`, head repository/owner, host, remote, and direct push authority with fresh API and JJ evidence. Fetch the exact verified remote/bookmark with JJ. Inspect tracked changes, conflicts, ignored and untracked content before alignment; preserve unrelated work. An empty `@` directly above the verified head is already aligned. Otherwise a clean workspace can use `jj new <verified-head>` and an explicitly verified bookmark as the later push target. Do not use Git checkout, reset, discard, or infer push destination from the working-copy tip. Clean exact-head alignment needs no repeat approval; dirty/conflicted state, uncertain identity, denied permission, or unknown authority stops safely.

Classify stacks read-only using `gh stack view --json` only when its ordered list contains this PR, otherwise use GraphQL stack data. Only a successful null result, or a schema-unavailable stack field plus a successful independent default-branch lookup, means absent. Auth, transport, malformed data, rate limits, or failed probes mean `probe-error`. Ordinary open-PR base/head relationships identify manual dependencies, not managed stacks. Discovery never imports or switches a stack.

Only positively confirmed manager membership permits stack-wide continuation. Under `target`, offer once to expand scope to `stack-ready` when lower or upper layers need work; do not silently redirect. Explicit stack-wide or landing requests already choose `stack-ready` or `stack-land`, so never ask again at each layer. Pipeline cannot ask and stays target-local absent supplied stack-wide authority. Never skip an excluded draft or needs-human layer. See `stack.md` for transitions and manager compatibility.

Default to authorized in-session monitoring using native OpenCode shell/wait capabilities to run and await the retained `scripts/pr-snapshot watch` helper. Build snapshots and journal transitions through its actual `snapshot` and `mark` CLI (`tick.md`), preserving its locked recovery and receipt semantics instead of manual state writes. Re-arm without asking after ordinary ticks. Honor checkpoint requests and monitoring opt-outs; if native waiting cannot sustain a watch, report paused checkpoint mode rather than promising unattended continuation. Pipeline uses bounded ticks (`pipeline.md`). Never create an unmanaged detached watcher or fake progress with foreground sleep.

Persist consequential decisions under the workspace's ignored `.tmp/rocketclaw/babysit-pr/<host>-<owner>-<repo>-<N>/`. No global temporary fallback. Resume syntax is `/ce-babysit-pr <url>` plus the same non-target `posture:` token; use dollar-prefixed syntax only on a host documenting it. A durable scheduler requires supported native scheduling and the existing authorization; do not silently introduce another harness or start opted-out monitoring.
