# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers what happens when the harness is full, how review agents are released, and the permission mode.

**Delegation permission.** This skill explicitly requests reviewer subagents. Under a host rule permitting delegation when the user OR a loaded skill requests it, this request suffices; do not require a second approval solely because the user did not separately request subagents. A skill without an explicit dispatch request grants no such permission. An unconditional higher-priority prohibition, missing tool, or actual permission denial still applies. Never bypass it through shell or another harness. Use an allowed inline pass with the same prompt asset when independence is not required, and disclose the substitution and any incomplete coverage.

**Bounded dispatch and nesting.** Check effective remaining nesting capacity using the host's supported runtime information; do not infer it from delegation permission or configured depth alone. Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. Distinguish that from a nesting-depth limit, permission denial, model-argument rejection, or missing tool using the actual error. Do not retry denied operations or evade depth limits through shell or another harness. When dispatch cannot recover through active work, supported release, or a permitted corrected invocation, run that pass inline or return it to the parent coordinator only where the review contract permits, using the same prompt asset and disclosing the substitution. Preserve required independence; report unmet required coverage as incomplete, not verified.

**Model permission.** Permission to delegate does not grant permission to override models. Resolve permitted model choices through `opencode.models`; preserve configured routes and tiers as intent. If the host requires an explicit user model request, omit the optional native `model` argument without that request and use suitable inherited-model reviewers. Report unmet tier or route requirements. Separate same-model reviewers are not cross-model independence; a required different-model pass that cannot run remains incomplete.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.
