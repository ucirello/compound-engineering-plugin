Derive a meaningful kebab-case slug from task, PR, or revision, normalize caller names without double-prefixing, and use `YYYYMMDD-<slug>` for both registered workspace name and destination basename: e.g. `20261008-optimize-ranking-exp-001`, `20261008-pr-214`, or `20261008-review-efcb657`. Preserve existing PR/source bookmarks. Keep the absolute destination under the source workspace's `.tmp/` layout. Preserve the chosen date/name across retries, resumes, and midnight boundaries.

```sh
(cd "$workspace_root" && jj workspace add --colocate --name "$workspace_name" --revision "$verified_base" "$absolute_destination")
(cd "$absolute_destination" && jj git colocation status)
```

Verify registration, absolute destination, base, and colocation before editing. If harness isolation creates a new workspace, request and verify the same required identity and colocation; unsupported naming or colocation is a compatibility blocker through the workflow's safe decision path. Adopt the workspace through the harness session mechanism when making it the primary workspace. Never silently change existing isolation. Copy only declared shared resources and required environment files, preserving repo-relative paths, without overwriting unrelated content; parameterize ports and separate databases, lock files, and output paths. Never reset an existing experiment workspace to reuse it.

## Retiring run-owned isolation

Completion alone does not authorize deleting a user or harness-owned workspace. Respect the existing cleanup authorization and lifecycle authority. Stop workers, leave the target, and move any active harness session to a surviving workspace first. Verify the exact registered name, absolute path, and run ownership. Inspect tracked changes, conflicts, and ignored/untracked content; removal snapshots working-copy state but does not protect ignored files or files left untracked. Preserve recovery references and copy/read back result markers, logs, and required evidence outside the target before removal. For integrated winners, prove the exact winning revision is reachable from the optimization bookmark. Never remove unrelated, ambiguously owned, still-referenced, or non-disposable content.

From a surviving workspace's absolute root, run `jj workspace remove <verified-workspace-name>`. Verify both deregistration with `jj workspace list` and directory disappearance: deletion failures may be warnings despite successful exit. On incomplete cleanup preserve remaining state and report the blocker; no force deletion or Git fallback. Use `jj workspace forget` only for unregistering while preserving files. JJ owns colocated Git metadata cleanup. Bookmark deletion is separate; preserve best/archive/recovery bookmarks and all still-needed references.
