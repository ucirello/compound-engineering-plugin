# Cross-Model Judgment Pass

Run only the activated conditional judgment lenses: adversarial, product-lens, and security-lens. Coherence, scope-guardian, and feasibility do not gain new activation triggers. Each peer receives the same persona brief, document type, origin, and reviewer-specific slice as its in-process twin; legacy documents remain full-document reviews. Whenever the pass runs, also dispatch exactly one `whole-doc` reviewer with the full document in the same wave. It has no twin and its loss must be named separately in Coverage.

## Resolve and disclose the fixed model route

Attest the host serving family from runtime evidence, not harness branding. Unknown host family cannot establish automatic same-family exclusion: skip automatic dispatch. Read ordinary keys from `.rocketclaw/config.local.yaml`, then `config.yaml`, using the first active valid scalar; empty is unset, invalid continues to the next layer. Present lists/maps replace the whole key, including empty ones. `docs_root` remains `config.yaml` only. Resolve the absolute repository root with `jj workspace root` from the target workspace. See https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace .

Evaluate `cross_model_review_mode` first: `off` disables automatic egress unless the user explicitly requests a cross-model peer in conversation; a configured preference alone is not opt-in. Live prohibitions win. Resolve `cross_model_peer` by conversation, config, active project instructions, then first available attested-different family in `codex → claude → grok → composer`. Cursor default/Auto is explicit-preference only and cannot imply independence.

Use `opencode.models` to resolve the selected family and exact model to an available provider/model ID and reasoning variant. Execute with OpenCode-native subagents, or a documented OpenCode shell invocation when native subagent model selection is unavailable; never invoke another harness's dispatcher. Configured `cross_model_model` and `cross_model_effort` remain authoritative, with conversation overrides first. Preserve preferred mappings: codex `gpt-6-luna` at extra-high (`xhigh`), claude `claude-opus-5-5` at high, native Grok `grok-4.7` at extra-high; intentional compatibility mappings are Grok-via-Cursor `grok-4.7-xhigh` and Composer `composer-2.5-fast` (fast is its ceiling). These compatibility examples do not authorize a cross-harness launch. Cursor default requests no specific model. If OpenCode cannot supply the required model/tier or sanctioned intermediary, name the capability skip rather than substitute silently. Only an observed unavailable/obsolete/incompatible default permits a closest same-family replacement; never silently change an explicit model.

Bind one concrete OpenCode route for all peers. `CROSS_MODEL_PEERS`, when set, restricts every target and intermediary; unset means invocation plus disclosure sanctions egress. Compatibility alias policy: cursor or composer sanctions Cursor as intermediary, but only cursor selects its default voice; grok alone does not sanction Grok-via-Cursor. Changing recipients requires fresh resolution and disclosure. Do not authentication-probe before provider-capable dispatch.

Before sending content, prominently disclose requested model, reasoning tier, route, and every recipient, and that document content leaves the machine. Call it independent only when serving families are attestably different. Name requested models as requests, never proof of service; caveat only a conflicting receipt or a route with no requested model. Non-interactive mode emits no user-facing prose but records one bounded egress audit line per send in the local run log. A skipped automatic pass records its reason, distinguishing checkout policy from unavailable or non-independent routes.

## Dispatch, isolation, and bounded recovery

Create a private, owner-controlled, non-symlink run directory under `$(jj workspace root)/.tmp/rocketclaw/ce-doc-review/<run-id>`; outside JJ use local `.tmp/rocketclaw/ce-doc-review/<run-id>`. All prompts, slices, logs, result files, fallback and error files stay there. Embed reviewed content and the allowlisted persona brief plus `findings-schema.json` in the prompt. Use an empty scratch working directory with no project context. Deny writes, network tools, MCP, and further delegation; use tool-less execution where supported. If the runtime retains read-only tools, disclose that residual and restrict reads to embedded material; inability to enforce least privilege is a named skip, not permission to widen access. Provider transport itself is the disclosed egress. Request only the narrow permission required for that fixed connection; denial creates no job and preserves in-process coverage.

Dispatch peers alongside in-process reviewers respecting capacity/backpressure and lifecycle rules in `dispatch.md`. Do not send the accumulated decision primer on round 2+: peers retain round-1 framing and synthesis suppresses resolved/rejected duplicates.

Record each started task ID, fixed route, requested model/tier, launch timestamp and outcome. Await every started task before synthesis or return using bounded waits of at most 30 seconds and runtime-supported cancellation. Keep one shared budget: `CROSS_MODEL_HARD_SECS`, default 1200 seconds for progress-observable routes and 600 for hard-only non-streaming routes. `CROSS_MODEL_IDLE_SECS` defaults to 480 seconds where genuine output progress is observable; do not mistake reasoning silence for completion. Supervisor backstop is `max(1230, configured hard budget + 30)` and orchestrator deadline is configured hard budget + 10 from the final launch, shared by all legs. Do not turn an unset knob into an explicit override that erases the hard-only default. Stop unfinished tasks at the deadline, then collect terminal evidence with a final bounded 10-second grace. Never invent unavailable cancellation operations; preserve and report unresolved tasks.

Repeat the identical route once only for exact provider-overload 529, within the remaining shared deadline. No internal recipient fallthrough. Infrastructure failure before dispatch is not a clean skip: recover the same fixed route, model, embedded read scope and empty-scratch isolation while each failure is new and plausibly recoverable and budget remains; stop on a repeated failure or exhausted deadline. Never automatically retry a provider no-review outcome, or repeat a quota/usage-limit route after repeated evidence in this session. Any different recipient requires new disclosure and sanction.

## Collect, validate, and synthesize

Read only owner-controlled, non-symlink bounded result files; validate JSON against `findings-schema.json`. Normalize reviewer to `<reviewer-name>-<target>`, with allowlisted names `adversarial`, `product-lens`, `security-lens`, `whole-doc`; downgrade peer `safe_auto` to `gated_auto`. Record `cross_model_target`, `cross_model_harness` (OpenCode), `cross_model_route`, `model_requested`, `model_actual`, and `independence_verified`. Never infer actual service from a requested ID. Independence requires actual serving-family evidence different from the attested host; receipt-less/default routes remain false. Only verified independence permits one-anchor agreement promotion after synthesis's one-fix merge test, not string matching.

Classify every started outcome before cleanup: usable output, empty findings, failed, timeout, died-without-result, or unreadable/untrusted output. Only usable validated files fold into synthesis, and only if review proceeds there; incomplete review reports outcomes without applying findings. Raw leftovers never count. Clean eligibility skips are not review failures; an empty valid findings list means no additional issues. Started failures and trust/read failures are non-blocking but named degraded coverage, never silent skips. Infrastructure loss must name both whole-doc broad-read loss and lost corroboration; each trio retains its in-process twin.

Inspect bounded failure evidence before deleting consumed task artifacts. Name observed quota, capability or authentication failures. Account-login remediation requires positive evidence that provider-capable dispatch occurred; authentication-shaped sandbox text alone does not establish logout. Preserve unresolved evidence and blockers rather than claiming cleanup. Collect final outcomes and release only agents this review created using supported lifecycle operations before returning.
