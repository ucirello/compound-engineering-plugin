# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers what happens when the harness is full, how review agents are released, and the permission mode.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Delegation permission.** This skill explicitly requests reviewer subagents. Under a host rule allowing delegation when the user OR a loaded skill requests it, that request suffices; do not require a second user approval. An unconditional higher-priority prohibition, unavailable capability, or actual denial still applies. Never bypass one through shell or another harness. Delegation permission does not grant model-selection permission; apply Step 2's separate model rules.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. Verify the effective nesting capacity using available runtime configuration discovery and the installation prerequisite of `experimental.subagent_depth >= 3`; package-local configuration alone does not enable this in consuming projects. Do not mutate host configuration. Classify an actual failure as depth/capacity, permission denial, model-argument rejection, or missing tool from its real error, rather than assuming they are interchangeable. Do not retry a denied operation or evade a nesting limit through another harness. When a dispatch cannot recover through active work, supported release, or a corrected invocation, run that pass inline using the same prompt asset only if permitted, and disclose the substitution. Inline review cannot satisfy required independent or different-model coverage: report any unmet requirement as incomplete.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.
