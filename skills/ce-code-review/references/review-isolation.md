# Faithful mutation-test isolation

Read-only reviewers stay in the shared workspace. A mutation-test reviewer may mutate only a faithful isolated snapshot of the exact reviewed revision, under the granted review/probe authority; never the shared tree.

1. Detect existing harness/JJ isolation first and reuse it under its existing verified name. Do not rename, recreate, or change colocation merely to enforce new-creation rules. Verify the snapshot's full `commit_id`, file contents, conflicts, and relevant local changes equal the captured reviewed head; a default-branch or primary-checkout snapshot is not faithful.
2. Prefer the harness's supported colocated JJ isolation and adoption/lifecycle capability when available. Required naming/colocation that it cannot provide is a compatibility blocker, not permission for a Git worktree fallback or a policy workaround. Otherwise use `ce-worktree`'s native JJ instructions with a verified base and absolute owned destination beneath the existing workspace-local `.tmp/` parent.
3. For a newly selected name, capture local `YYYYMMDD` once. Normalize the task/PR/revision/caller slug without double-prefixing; choose `YYYYMMDD-review-<meaningful-slug>`. Use exactly that identity for workspace name and directory basename, checking registrations and destination collisions and suffixing `-2`, `-3`, etc. Preserve it over retries/resume/midnight, existing isolation names, and all PR/source bookmarks; no PID/random/timestamp naming.
4. From the source workspace's absolute root, create explicitly: `(cd "$workspace_root" && jj workspace add --colocate --name "$dated_name" --revision "$verified_head" "$absolute_owned_destination")`. From the created absolute root verify `jj git colocation status` and the captured parent/tree before mutation. The new working copy may be empty directly above the verified head; compare its tree and parent IDs, not merely a mutable bookmark name. Use a faithful local `.tmp/` scratch copy instead if supported isolation cannot capture the reviewed tree, including eligible local changes; never silently test another revision.
5. Respect harness ownership and explicit cleanup authority. Completion alone does not authorize deleting a user's workspace. Before retiring a disposable run-owned JJ workspace, stop/collect all workers, leave the target and move active sessions to a surviving workspace, verify exact registered name/path/run ownership, prove required integration, preserve recovery references, and copy/read back necessary artifacts outside the target. Inspect tracked changes/conflicts **and** ignored/untracked content; snapshots do not protect ignored/untracked files. Ambiguously owned, referenced, or non-disposable content blocks removal.
6. From a surviving absolute workspace root use `jj workspace remove <verified-name>`. Verify both deregistration and directory disappearance; warnings or residual directories are blockers. Preserve state and report failures, never force-delete, use Git cleanup, or pair `workspace forget` with deletion. `workspace forget` is unregister-only when intentionally preserving files. Bookmark deletion is separate; retain archive/best/recovery refs still needed. Harness-owned isolation uses its authorized lifecycle rather than bypassing it.

All JJ commands run from the actual absolute target root. Repository-scoped `gh` runs there with `GIT_DIR=$(jj git root)`. See https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace.
