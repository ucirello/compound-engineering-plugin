# Committing the refresh

Skip if no files changed. Check the current bookmark (`jj log -r @ -T 'bookmarks.join("\n")' --no-graph` or `jj bookmark list -r @`), whether the working copy has unrelated changes (`jj status` / `jj diff --summary`), and recent change-description style (`jj log -n 10 --no-graph -r ::@`). Limit the change to **only** the files this refresh modified (named filesets; JJ has no index). Based on https://go.dev/wiki/CommitMessage and on past commit messages that you can see in `git log`, compose commit messages adherent to the present standards. Repo-local syntax from project instructions and `git log` ALWAYS wins when it differs from Go guidance. Apply compatible Go guidance to quality/clarity/structure without replacing repo-local syntax. Semantic constraint: the composed message summarizes the refresh (what was updated, consolidated, replaced, or deleted). Then run `jj commit -m "<message composed from the standards above>"` with those filesets.

Non-interactive defaults: on the repo's default bookmark (main, master, or whatever `trunk()` / the remote designates) → `jj bookmark create` a bookmark named for what was refreshed (e.g., `docs/refresh-auth-learnings`), `jj commit` the refresh filesets, attempt a PR with `GIT_DIR=$(jj git root) gh` from the workspace root (if PR creation fails, report the bookmark name); on a feature bookmark → separate change on that bookmark; jj failures → put the recommended commands in the report and continue.

Interactive: ask (per Blocking questions), with the recommended option first. On the default bookmark: bookmark+commit+PR (recommended; specific bookmark name) / commit directly to the current bookmark / don't commit. On a clean feature bookmark: commit to it (recommended) / separate bookmark / don't commit. On a dirty feature bookmark: `jj commit` only refresh filesets / don't commit.
