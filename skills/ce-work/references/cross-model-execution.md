# Cross-Model Execution Contract

Read when `execution-engines.md` selects a configured route, or when recovering a run. Execute through OpenCode-native model discovery and subagents, with shell only for local JJ and verification operations. There is no external-harness adapter, detached runner, or workspace controller. The host owns the durable run record and must prove every transition; a worker response is not integration or verification evidence.

## Resolve configuration and capability before dispatch

Keep the authority ordering in `execution-engines.md`. Live route intent is preference-strength unless unambiguously strict; resolve `prefer` or `require`. A typed binding is one fixed candidate, not permission to widen the recipient list. Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `config.yaml`; present local lists/maps, including empty values, replace the team key. Modes are `off | prefer | require`. Preserve the existing preference objects (`harness`, optional `model`) and harness-keyed effort map as desired behavior, not executable commands.

Use `opencode.models` to resolve configured model names to exact available provider/model IDs. Preserve configured order, explicit pins, tiers, and effort intent. Operational provider/harness names such as Codex, Claude, Grok, Cursor, Composer, OpenCode, and Antigravity remain configuration vocabulary; do not invoke their dispatch CLIs. A requested intermediary or harness-specific route that native OpenCode cannot actually provide is unavailable, not silently equivalent to a similarly named model. Omitted model means the configured default only if it can be established. Never guess a model or effort mapping or put configuration strings into shell commands.

This skill explicitly requests native implementation subagents. Under a host rule allowing user-OR-loaded-skill-requested delegation, that satisfies the skill-requested exception without another approval. An unconditional higher-priority prohibition, actual denial, or missing tool still applies. Delegation permission does not authorize a model override: if the host requires an explicit user model request, omit the optional model argument and use a suitable inherited model only where the contract permits it. Record requested versus actual identity; same-model workers do not prove cross-model independence. A required different-model pass or fixed route that cannot be met remains incomplete.

Check effective nesting capacity separately from permissions; use the installation/configuration discovery procedure from `ce-setup` (depth at least 3, adopted by the consuming configuration, not assumed from the plugin package). Classify the actual launch error as permission, model-argument rejection, missing tool, or depth/capacity. Correct a pre-launch argument error once; queue capacity-limited units. Never retry a denial, escape through shell/another harness, or claim permission guarantees depth. Inline or parent-coordinator fallback is allowed only when it preserves the unit's requirements and independence.

Preflight candidates without exposing repository material. Skip an equivalent current-session default and record why. Before dispatch, disclose and record authorizing source, requested and actual provider/model/route, intermediaries, effort, material exposed, inherited restrictions, and enforced versus cooperative boundaries. JJ workspace isolation is not an OS security sandbox. A required boundary the native tool cannot enforce makes the candidate unavailable. Never broaden permissions to reach a route.

When all candidates are unavailable before dispatch, both `prefer` and `require` disclose attempted candidates and observed reasons once, then continue natively on the current session model, without inventing another external recipient. Report unmet route/effort/independence requirements, not fully verified cross-model coverage. After dispatch starts, no fallback or second author starts until the recorded author is terminal and integration/restoration is reconciled. Latency or convenience is not unavailability.

## Durable source, isolation, and bounded packets

Create private run state under the canonical workspace's ignored `.tmp/rocketclaw/ce-work/<safe-run-id>/`; all packets, logs, message files, and error-path artifacts stay under local `.tmp/`. Never use OS-global temp storage. Record absolute canonical root, repository identity, task bookmark, exact base commit, source kind/digest, ownership, and pre-work tracked/untracked/ignored inventory. Preserve pre-existing work. A selected plan that is the sole dirt may receive a disclosed plan-only checkpoint using `implementation-loop.md`'s message standards; unrelated dirt makes isolated integration unavailable rather than implicitly checkpointed. A bare prompt requires a bounded brief with Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units (one conservative P1 unless evidence supports decomposition). Store the private copy and SHA-256 before dispatch; omit raw conversation, credentials, and unrelated context.

Detect existing isolation first. Reuse it under its verified existing name; never rename or recreate it to enforce new conventions. For harness-owned isolation, request its supported colocated JJ capability and verify its absolute root, registered name, base, and `jj git colocation status`; never bypass its ownership/lifecycle contract. If required colocation cannot be supplied, use the safe shared/serial path only when allowed, otherwise report a compatibility blocker.

For newly needed caller-owned isolation, use `ce-worktree` and its naming/lifecycle contract. Capture local `YYYYMMDD` once; derive a meaningful task/PR/revision kebab slug, normalize caller names without double-prefixing, and persist the selected identity across retries, resumes, and midnight. Use one `YYYYMMDD-<slug>` identity for workspace name and destination basename beneath the local `.tmp/` layout. Check both registrations and paths; append `-2`, `-3`, etc. on collision, never overwrite or use timestamps/PIDs/random naming substitutes. Existing source/PR bookmarks stay unchanged. From the source absolute root:

```sh
(cd "$workspace_root" && jj workspace add --colocate --name "$selected_name" --revision "$verified_base" "$absolute_owned_destination")
(cd "$absolute_owned_destination" && jj git colocation status)
```

Request and verify compliant naming for newly created harness-owned `ce-worktree` isolation too; unsupported naming is a blocker, not permission to create a noncompliant workspace. Adopt the workspace with the harness's native session-move facility where needed; do not leave the session pointing at another root. Every JJ command runs with cwd set to its target absolute workspace root, not `jj -R`. See https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace and https://docs.jj-vcs.dev/latest/git-experts/ .

Persist one attempt binding: run/unit/attempt IDs, base, dependencies, wave, fixed model/effort intent, native worker handle, absolute workspace, packet path and SHA-256. A prepared binding locks the unit's engine until a recorded terminal/fallback decision. Send only Goal Capsule, Definition of Done, active unit, relevant Verification Contract rows, cited R/F/AE/KTD excerpts, governing Product Contract Key Decisions, expected files, evidence strategy, restrictions, and exclusions. Workers may narrow but never broaden authority. They cannot schedule peers, switch recipients, integrate, make canonical commits, push, open PRs, or execute either shipping tail. Native workers receive the fresh-context and evidence requirements in `execution-strategy.md`.

## Serial host-owned transaction

1. Record prepared state before launch, then the actual native handle and launch outcome before supervision. Use separate tool calls for launch, observation, terminal inspection, and integration; never hide a run in a shell loop or background dispatcher. Bound each available wait to 60 seconds and publish unit, elapsed time, meaningful activity, route, and terminal state. Use a 7200-second hard budget and a 600-second progress-reset idle budget only when native activity is trustworthy; otherwise record hard-only activity and disable idle inference. If the tool cannot enforce a budget, disclose that limit and use its supported stop mechanism; never infer termination from silence.
2. A live or unreachable worker remains authoritative. Stop/reap only with the native lifecycle tool and record observed termination; no duplicate or fallback while liveness is uncertain. Retain the workspace and recovery evidence.
3. After authoritative completion, capture the entire final tree as an isolated JJ change based on the recorded base. Verify the sole parent and complete tree with native JJ facts, and preserve a recovery bookmark. Inspect exact base-to-result diff, actual paths, binary/mode/rename/delete changes, worker result, expected scope, and scope-expansion requests. Unexpected generated output is still unexpected scope; preserve and resolve it before integration. Worker summaries and process success alone prove neither scope nor completion.
4. Acquire one host-owned integration lock in durable state. Re-read canonical base/head/bookmark and cleanliness; unknown movement blocks. Preserve a recovery reference and exact pre-fold tree/path inventory. Use native JJ change integration (for example, `jj rebase` of the pinned isolated result onto the verified advancing canonical base followed by inspection) only after preserving the original result. Conflicts or ambiguous ownership stop; do not discard user work or blindly accept a clean textual apply as semantic compatibility.
5. Run authoritative verification in the target absolute canonical root, capturing direct exit status and private logs (disable Python bytecode where applicable). Simple commands use direct argv; shell expressions require an explicit shell with pipe-failure handling. Record pre/post tracked trees, conflicts, paths, and bookmarks. Verification must not mutate tracked output unnoticed. Inventory ignored entries by metadata before and after and report changed/removed/created counts plus bounded path samples; ignored data, `.env` files, and databases are not protected by JJ snapshots. Never copy, restore, or delete ignored files as a side effect of reconciliation.
6. Only after scope, checks, and exact-state reconciliation pass, create the host-owned canonical change using the full message composed under `implementation-loop.md`, limited to owned paths. Persist accepted commit, parent, tree, verification receipt, and integration state before releasing the lock. A post-commit crash is resumable, never authorization to redispatch.
7. On failed apply, check, or pre-commit transition, forbid the canonical commit and restore only proven run-owned changes using preserved JJ recovery evidence. Prove exact pre-fold equality before releasing the lock or allowing retry, sibling, or fallback. Do not use a repository-wide undo/reset that could affect unrelated work. If exact restoration cannot be proved, retain lock, isolated result, references, and recovery path and return blocked.
8. After all units reach canonical completion, run the plan-wide Verification Contract or prompt acceptance checks as a separate recorded host-owned gate from a clean snapshot. Capture exit status, log, tracked reconciliation, and ignored-state divergence. A failed gate blocks completion even if workspace cleanup succeeded.

## Waves, recovery, and exactly-once fallback

Apply the Parallel Safety Check before each wave, cap at 3–5 workers, and bind all isolated members to one recorded wave base. Dispatch independent ready units together. Wait for every member to terminalize and inspect every actual path inventory before the first fold-in. Same-path or semantic contention stops integration for host resolution. Integrate sequentially in dependency order under the lock, recording each exact accepted parent/tree/commit as the advancing wave base. Revalidate each later result against it. No sibling advances while restoration is unresolved. Repeated collision, unplanned edits, or unprovable restoration disables further waves without discarding unaffected output.

Resume a supplied safe run id (`^[A-Za-z0-9._-]{1,128}$`, at least one non-period character) from its durable record, never from directory order. Without an id, discover only a single plan-backed unfinished record matching repository identity, bookmark, and selected plan digest; multiple matches block selection. Prompt-backed recovery requires the disclosed id. Foreign/unsafe records block. Recover native handles and recorded JJ facts read-only first. Do not redispatch, reapply, recommit, or enter either shipping tail. Reconcile an interrupted apply/commit only by exact recorded parent/tree/path evidence. Unknown dirt is not permission to restore destructively. If every unit and the final gate already have successful receipts, report those receipts without rerunning tests/builds/formatters/installers/generators. Missing receipts remain a blocker, not fabricated evidence.

After authoritative failure/timeout/termination, with exact restoration proven and lock released, record one atomic host-owned fallback claim for that unit before native authoring. Refuse a second claim or any claim while a worker is live or successful output is unreconciled. Both modes permit the current-session fallback, never a new unrequested recipient. Record its accepted commit and verification-evidence digest; preserve all earlier attempts under the same scalar run id. A corrected retry requires a fresh attempt id with unchanged dependency/wave contract and no live earlier author. Stop when native tools cannot establish these guarantees rather than pretending the deleted controller enforced them.

## Receipts, cleanup, and tail ownership

Persist and return `implementation_engine_binding`, authorizing source, requested/actual route and intermediaries, requested/actual model, served-model receipt status (`unverified` without trustworthy evidence), requested effort and actual effort status, fallback reason, source kind/digest, scalar run id, per-unit attempt/process/integration/verification/canonical-commit/cleanup receipts, disclosed plan checkpoint, blockers, and recovery path. Record actual tool outcomes, not expected transitions. Identity and effort are not verified merely because requested. A required cross-model pass that did not run remains incomplete.

Cleanup is separate from success and requires existing authorization and lifecycle ownership. Stop workers; leave the target and move active harness sessions to a surviving workspace. Verify exact registered name, absolute path, run ownership, integration, tracked changes/conflicts, and ignored/untracked content. Preserve recovery references; copy required packets/logs/receipts outside the target and read them back before removal. Never remove unrelated, ambiguous, still-referenced, or non-disposable state. For authorized caller-owned disposal, from a surviving absolute root use `(cd "$surviving_root" && jj workspace remove "$verified_workspace_name")`. Verify both deregistration and directory disappearance; warning-only deletion failure is incomplete cleanup. Retain remaining state and report blockers, never force-delete or fall back to Git. `jj workspace forget` is only unregistering while preserving files. Bookmark deletion is separate; retain best/archive/recovery references still needed. Harness-owned cleanup uses only its supported lifecycle authority.

Standalone execution resumes its Phase 3–4 tail after implementation. Return-to-caller returns receipts with `standalone_shipping_skipped: true` and never runs caller-owned final simplify/review/PR/CI. Engine selection changes who authors, not tail ownership.
