# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

**Native dispatch and permissions.** Resolve configured tier intent with `opencode.models` and use OpenCode-native subagents/shell, never another harness's dispatcher. This skill explicitly requests the fetch and analysis subagents above: when host policy permits user OR skill-requested delegation, no second approval is needed. An unconditional prohibition, unavailable tool, or actual denial still applies. Delegation permission is separate from model-selection permission: if model overrides require an explicit user model request, omit the optional model argument and use a suitable inherited model, preserving configured routes as intent and disclosing any unmet tier requirement. Same-model agents are not evidence of cross-model independence.

**Degradation rule.** When model selection is unavailable or forbidden, dispatch permitted source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on a suitable inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. Check remaining runtime nesting capacity separately from permission. When delegation is forbidden, unavailable, or depth-limited, run source fetch and media analysis inline only within the same read/write boundaries and budgets; report the reduced coverage and any unmet required independence. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths. Never bypass policy or nesting limits through shell or another harness.

Classify a rejected native dispatch by actual evidence: permission denial, model-argument rejection, missing tool, and depth/capacity limits are distinct. Correct an allowed malformed pre-launch argument once; never retry a denied operation. Leave capacity-limited work queued or use the permitted inline fallback above. Follow a source persona's more specific unavailable-state rule when applicable, and never report an unavailable required pass as completed.
