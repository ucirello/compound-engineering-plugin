# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Use OpenCode-native subagents and `opencode.models` for permitted model discovery, not another harness dispatcher. Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, that model takes precedence over the default tier above, subject to actual host model-selection permissions. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier. Configuration remains authoritative intent, not permission to override host policy. When model overrides require an explicit user request, omit the optional model argument and use a suitable inherited model; disclose unmet tier or route requirements.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

This skill explicitly requests the source and media subagents. Under a host rule permitting user-OR-loaded-skill requests, this satisfies delegation permission without another approval. An unconditional prohibition or actual denial still controls. Delegation permission, model-selection permission and nesting capacity are separate. Verify effective runtime nesting depth from discovered OpenCode configuration; package-local defaults do not prove the consumer adopted them. Classify an actual dispatch failure as missing tool, permission denial, model-argument rejection, or depth/capacity exhaustion. Correct a permitted pre-launch argument error once, never retry a denial or evade depth through shell/another harness. Leave capacity-limited work queued or use the permitted inline degradation, preserving budgets, artifacts and source-specific unavailable-state rules. Report inline versus delegated completion and any unmet coverage; same-model agents are separate agents, not cross-model independence.
