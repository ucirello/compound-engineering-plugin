# Model Tiers

Read this when dispatching a sub-agent (the Phase 1.1 grounding scout, the Phase 2.6 claim verifier, or the opt-in Slack researcher). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** — the grounding scout: retrieval and quoting work. Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec — escalate to the generation tier when the repo is large or the stack obscure.
- **Generation tier** — the claim verifier: evidence-driven mechanical verification. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** — the dialogue itself. Questions, approaches, synthesis, and the requirements-only unified plan run in the main conversation on the orchestrator's model; nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, treat that as the desired model instead of the default tier above. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier. Resolve available names through `opencode.models`. Pass a model override only when host policy permits it; configuration or skill intent does not satisfy a host requirement for an explicit user model request. Otherwise use the suitable inherited model and disclose unmet tier or route intent.

**Degradation rule.** This skill explicitly requests scout and verifier delegation. Under a user-or-loaded-skill delegation rule, those requests suffice without second approval; unconditional prohibitions and actual denials still apply. Check effective nesting depth separately from delegation and model permissions. Classify dispatch errors accurately as depth/capacity, permission, model rejection, or missing tool; never bypass through another harness. When model selection is unavailable or forbidden, use a suitable inherited model and retain budgets and caps. When native delegation cannot start, do the topic scan inline at Phase 1.1, still writing its grounding dossier for downstream consumers, and verify claims inline before Phase 3 with the same budgets. Disclose the fallback and any lost independent coverage; inline or same-model work is not proof of required cross-model independence.

Classify a rejected native dispatch by whether an agent launched: correct a pre-launch argument rejection once, leave capacity-limited work queued, and send any other failure to the inline degradation above.
