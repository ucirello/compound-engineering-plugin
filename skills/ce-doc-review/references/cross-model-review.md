# Native cross-model document review

This additive, non-blocking pass covers each activated conditional judgment lens (`adversarial-document-reviewer`, `product-lens-reviewer`, `security-lens-reviewer`) and one `whole-doc` sweep per document. The whole-doc sweep always receives the full document and has no in-process twin. Each lens uses its normal persona brief and `findings-schema.json`; reviewer identities remain `<reviewer-name>-<provider>`.

## Resolve policy and route before dispatch

Read `.rocketclaw/config.local.yaml`, then `config.yaml` at the absolute JJ workspace root (`jj workspace root`). The first valid ordinary key wins; missing or invalid values continue to the next layer. `cross_model_review_mode: off` skips this pass as **disabled by checkout config**, unless the user explicitly requests it in conversation. A live prohibition always wins. `auto` is the default. Resolve the target from the user's request, then `cross_model_peer`, then applicable project instructions and an available different-family route. Respect `CROSS_MODEL_PEERS` when set; unset means unfiltered. Preserve configured `cross_model_model` and `cross_model_effort`, with conversational choices taking precedence. Never silently change a recipient, explicit model, effort, or fixed route.

Use `opencode.models` to resolve available provider/model IDs and effort variants, then native OpenCode subagents, not another harness's CLI or a dispatcher script. Preserve the desired tier: high reasoning, except Codex and native Grok extra-high; Composer fast is its accepted ceiling. Preferred identities are GPT-6-luna, Claude Opus 5.5, Grok 4.7, Composer 2.5-fast, and Gemini 4 Argon. These are route intent, not permission to override the host's model policy. A configured fixed intermediary that native execution cannot honor is unavailable coverage, not permission to substitute. Only an unpinned default observed unavailable may be resolved to a disclosed same-family compatible replacement; explicit user/configuration models run exactly or skip.

Apply `dispatch.md`'s separate delegation, model-selection, and nesting-depth checks. If model overrides are forbidden, use suitable inherited-model reviewers for ordinary lenses; that does not complete a required different-model pass. Never use shell or another harness to bypass a denial or depth limit.

Attest the host serving family from runtime-published identity, not environment markers, product branding, requested IDs, or model self-report. Keep requested target, provider, route, requested model, served-model evidence, and effort separately recorded. Unknown host identity cannot establish different-family independence. A same-model separate context is a separate reviewer, not cross-model independence.

## Disclosure, isolation, and execution

Before sending content, interactive runs prominently announce the requested model, effort, provider/route, and that **full document content is sent to that provider**. Name a requested model as requested, not as proven served. Non-interactive runs retain an auditable egress record in local run evidence. Changed recipients require fresh resolution, sanction, and disclosure. Do not widen scope or permission to obtain a peer.

Create private, owner-controlled run evidence under `<absolute-workspace-root>/.tmp/rocketclaw/doc-review/<run-id>/` (local `.tmp/` outside repositories). Reject symlinked or untrusted evidence paths. Dispatch all activated lenses and the single whole-document sweep in the same bounded wave as local reviewers, respecting host capacity. Give each peer only its embedded document, persona, schema, origin, and round-1 framing: no peer findings, accumulated decision primer, repository tools, writes, or network access beyond the sanctioned model transport. Use supported native read-only/tool restrictions; if they cannot enforce this boundary, skip with the isolation limitation recorded.

Track each native job ID and deadline. `CROSS_MODEL_HARD_SECS` controls the common peer window (default 1200 seconds); validate a positive integer, capture it once, and use one shared deadline rather than resetting it per leg. Await every started job, collect terminal results and bounded diagnostics, and stop outstanding jobs using supported lifecycle operations at the deadline. Never invent cancellation support or leave workers unaccounted for. Classify `done`, `failed`, `timeout`, and `died-without-result` distinctly. Persist schema-valid results as `<reviewer-name>-<provider>.json`; malformed, partial, or untrusted artifacts never fold in.

## Recovery and coverage

An infrastructure error before any dispatch is not a clean skip. While time remains, correct a new plausibly recoverable invocation failure and retry the **same** route with the same model, recipients, embedded scope, and isolation. Stop when the failure repeats or the deadline expires. Do not retry permission denials or evade depth limits. A positively identified overload may receive one same-route retry within the original deadline. Provider quota/authentication/no-review outcomes do not trigger automatic recipient changes or repeated retries. Identify authentication as an account problem only with provider-capable launch or provider-response evidence; otherwise describe the execution-context failure without instructing account login.

Collect diagnostics before cleanup and retain recovery evidence. Read back each artifact, validate the findings schema, and record requested/served model provenance. Set `independence_verified: true` only with evidence of a separate reviewer context and attestably different serving families. An unknown or mismatched served identity remains attributed evidence without agreement promotion. An empty findings array is a completed review with no additional issues, not a skipped pass.

Fold usable artifacts under the ordinary one-fix synthesis rules. Missing peers never erase local-lens coverage or fail the additive pass, but name every owed lens that did not fold and the whole-doc broad-read loss separately. Required different-model coverage that could not run remains incomplete; do not label it fully verified. Follow `synthesis-and-presentation.md`'s structured `peer.outcome` and per-lens coverage contract. Preserve peer-only fix restrictions: another model's finding alone never authorizes silent application. Stop/release all run-owned reviewers before cleaning disposable scratch; retain required evidence and never delete user documents.
