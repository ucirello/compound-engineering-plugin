# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Use native OpenCode subagents and `opencode.models` to resolve permitted model choices; do not invoke another harness or a dispatch script. Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, prefer that model over the default tier above, subject to actual model-selection permissions. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier.

Delegation permission, model override permission and remaining nesting depth are separate checks. This skill explicitly requests source and media subagents, satisfying a host rule that permits delegation when user OR skill requests it; no second approval is needed under that rule. Never override a genuine higher-priority prohibition. If an explicit user model request is required and absent, omit the optional model argument and use a suitable inherited model. Configuration remains authoritative intent; report any unmet tier or independence requirement, and never count same-model reviewers as cross-model coverage. Check effective remaining nesting capacity independently of permission.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Classify a rejected native dispatch using the actual error: missing tool, genuine permission denial, model-argument rejection, exhausted nesting depth/capacity, or launched-agent failure. Correct a fixable pre-launch argument rejection once; do not retry denied operations or evade depth through shell/another harness. Leave capacity-limited work queued or use the permitted inline degradation with identical budgets, accurately reporting the limitation. Send other failures to inline degradation or the more specific unavailable-state rule in the persona file. Preserve required independence and mark any unavailable required cross-model coverage incomplete.
