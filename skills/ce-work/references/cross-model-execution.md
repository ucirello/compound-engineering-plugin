# Cross-Model Execution Contract

Read when `execution-engines.md` resolves an implementation route, or when recovering its durable run. Execute with OpenCode-native `opencode.models`, `subagents`, and `shell`; do not invoke another harness, dispatcher, work-engine controller, or workspace bridge. Configuration remains the source of desired behavior, not executable shell syntax.

## Route intent, authority, and preflight

Resolve `work_engine_mode` (`off | prefer | require`), `work_engine_preferences` (ordered objects with `harness` and optional `model`), and `work_engine_effort` (harness-to-effort map) independently from `.rocketclaw/config.local.yaml`, then `config.yaml`. A present local list/map, including an empty one, replaces the team value. Invalid scalar values continue to the next layer. `off` disables standing intent only, not a live request or validated caller binding. Preserve caller provenance and the authority order in `execution-engines.md`.

Live intent is preference-strength unless it unambiguously requires an exact route. Preserve ordered candidates; a typed four-field caller binding is a single candidate, not permission to broaden to a list. Keep configured route tokens (`codex`, `claude`, `grok-cli`, `cursor`, `composer`, `grok-cursor`, `opencode`, `antigravity`), intermediaries, model pins, and effort tiers as requested identity. Historical defaults include Composer `composer-2.5[fast=true]`, Grok-through-Cursor `grok-4.7[context=256k,reasoning_effort=high,fast=true]`, and Antigravity's ordered `gemini-4-argon`, then `gemini-3.8-flash` when no pin exists. They are intent, not permission to launch those harnesses or substitute model families.

Discover available native models with `opencode.models`. Verify exact model, provider, route, effort capability, and required restrictions before sending content. A provider/model available through OpenCode does not prove the requested intermediary route is available. An unsupported fixed route, exact pin, or effort is unavailable, with the concrete reason recorded; never claim it was honored. Skip a candidate equivalent to the current host/model, recording that native execution already supplies it. Never switch recipients after dispatch starts.

Delegation permission, model-selection permission, and remaining nesting depth are separate checks. This skill explicitly requests implementation workers; under a host user-or-skill delegation rule that satisfies the skill-requested exception without another approval. It cannot override an unconditional prohibition or denial. If model overrides require an explicit user model request, omit the optional `model` argument unless that requirement is met. Use a suitable inherited model for permitted native work, recording unmet route/tier intent. Same-model workers are separate contexts, not cross-model independence. Inspect effective OpenCode configuration/depth and classify actual launch errors as capacity/depth, permission, model-argument rejection, or missing tool; do not evade them through shell or another harness.

Before any dispatch, disclose and durably record the authorizing source, requested recipient/provider/intermediary/model/effort, actual native route, bounded material exposed, inherited authority, enforced versus cooperative restrictions, and the fact that workspace isolation is not an OS sandbox. If mandatory restrictions cannot be enforced, the route is unavailable. Do not broaden permissions to make it reachable.

For both `prefer` and `require`, exhaust only authorized pre-egress candidates, disclose every unavailable candidate once, then continue natively on the current session model. `require` keeps identity fixed while viable; it never permits a different unrequested recipient. Report unmet required cross-model coverage as incomplete. After a job starts, no retry or fallback may begin until that job is authoritatively terminal and integration/restoration has been reconciled.

## Durable source and receipts

Store private run state beneath the absolute canonical root's `.tmp/rocketclaw/ce-work/<run-id>/`, including briefs, packets, evidence, logs, and recovery records. Never use OS-global temp storage. A prompt brief includes Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and conservative Units (one P1 unless discovery proves decomposition). Do not initialize or dispatch if goal, scope, or authoritative verification is missing. Include only necessary repository content, never unrelated conversation, credentials, or speculative scope.

Record source kind and SHA-256 digest, repository identity, source root, bookmark, exact base commit, run/unit/attempt identity, dependencies and wave base, packet digest, requested versus actual route/model/effort, served-model receipt status, fallback reason, native worker handle, terminal status, complete output revision, actual paths, authoritative verification, host canonical commit, cleanup, blockers, and recovery path. Served identity is unverified unless native evidence proves it; requested effort is not proof of served effort. Retain old attempts on retry and keep one scalar run ID. Record ignored-state changed/removed/created counts and bounded path samples separately from tracked-state reconciliation; ignored caches/databases and empty directories are not protected by a JJ snapshot.

A repository plan may be checkpointed only when it is the sole canonical dirt, with its exact path/digest and host commit disclosed. Unrelated dirt blocks isolated integration, never authorizes an implicit checkpoint. Prompt runs need an already-clean baseline. Re-read canonical identity, bookmark, exact commit and source digest before preparing each unit.

## Native unit transaction

Use separate visible tool calls for state-changing transitions, stopping on any failure. Do not hide start, wait, integration, or multiple units inside a shell loop. All JJ commands run with cwd set to the relevant absolute workspace root. Use https://docs.jj-vcs.dev/latest/cli-reference/ and https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace for native operations; no direct Git executable, including transport/history fallbacks. Repository-scoped `gh` requires `GIT_DIR=$(jj git root)` from that root.

1. **Prepare.** Persist one immutable packet for one unit: goal, Definition of Done, relevant Verification Contract, dependencies, files, inherited restrictions, settled decisions (including reverse-linked Product Contract decisions), cited accessible prototypes, matched pack rules, evidence strategy, exclusions, and the Build what was asked / Plan IDs stay out rules from `implementation-loop.md`. Workers may narrow authority, never broaden it; they cannot push, ship, schedule peers, change recipients, or create canonical commits.
2. **Isolate detect-first.** Inspect existing isolation and native harness lifecycle first. Reuse verified existing isolation under its existing name; never rename/recreate it for compliance. Use supported harness-native colocated JJ capability where available, verify exact base commit and colocation without bypassing ownership. If explicit run-owned isolation is needed and authorized, use `ce-worktree`: capture local YYYYMMDD once, normalize the meaningful task/PR/revision slug without double-prefixing, and preserve the chosen identity across retries/resumes/midnight. Workspace name and absolute destination basename are the same dated name under local `.tmp/`; check both registrations and paths, adding `-2`, `-3`, etc. on collision, never timestamps/PIDs/random substitutes. From the absolute source root run `(cd "$workspace_root" && jj workspace add --colocate --name "<selected-dated-name>" --revision "<verified-base>" "<absolute-owned-destination>")`; verify `(cd "<absolute-owned-destination>" && jj git colocation status)`, and adopt the workspace through the supported session interface. Unsupported required naming/colocation is a compatibility blocker, not permission for Git-only isolation. Ordinary synchronous native work stays in the active workspace; these instructions grant no blanket isolation creation permission.
3. **Dispatch.** Use one fresh native subagent per unit and bind the handle to that unit only. Fix a pre-launch argument mistake once; never retry a denial. Persist handle/packet identity before accepting output. Keep workers within owned paths and prevent canonical state writes. Use shell only for non-model commands and authoritative verification, not for harness dispatch.
4. **Observe.** Report unit, actual route, elapsed time, latest meaningful activity, and terminal state. Bound each wait to 60 seconds where the native interface supports it, a trustworthy progress idle window to 600 seconds, and total authoring to 7200 seconds. Untrustworthy incremental activity uses hard-only supervision, not idle-failure inference. If native controls cannot enforce required bounds, disclose the limitation before dispatch. A temporarily unreachable job remains live: no duplicate work or fallback. Confirm termination before reaping and retain inspectable state.
5. **Terminalize and inspect.** Process completion is not implementation success. Snapshot the entire output with JJ, retain its exact revision and recovery bookmark, and inspect the exact base-to-output diff, paths, binary/mode/rename/delete changes, generated byproducts, expected scope, result schema, and verification evidence. Output must be attributable to the recorded base. Unexpected scope stops integration for explicit host resolution. A transport snapshot is not a canonical commit.
6. **Integrate fail-stop.** Acquire one host integration lock only after inspection. Record the canonical pre-fold revision/tree, bookmark, tracked/conflict state, and ignored/untracked inventory outside the target workspace. Verify the recorded canonical head has not moved. Use native JJ rebasing/squashing of the accepted owned change into a dedicated host integration change, retaining both original output and pre-fold recovery references. Never blind-merge on a conflict-free apply. Inspect actual scope again, run the authoritative Verification Contract command with direct argv (or explicit `bash -o pipefail -c` for shell syntax), disable Python bytecode where applicable, capture its exit status directly, and reconcile tracked state against the accepted post-apply tree. Any unexplained revision/bookmark/path/conflict movement blocks committing. Disclose ignored-state divergence without deleting or restoring those files.
7. **Commit or recover.** Only the host creates the owned-path canonical commit, using `implementation-loop.md`'s runtime message standards. Record its exact commit ID and parent/tree evidence before marking the unit committed. Failed apply/verification/commit forbids continuation; preserve output and restore only run-owned changes to the recorded pre-fold state using JJ recovery, proving exact equality. If equality cannot be proven without touching user work, retain lock, workspace, evidence and recovery references and return blocked. Never reset/discard unrelated work. A crash after a matching canonical commit is reconciled, not redispatched.
8. **Clean safely.** Stop workers; move out of the target and move any active harness session to a surviving workspace. Honor harness lifecycle authority and existing cleanup authorization. Verify registered name, absolute path and run ownership, prove integration, preserve recovery references, and copy/read back required receipts outside the target. Inspect tracked changes/conflicts plus ignored and untracked content; snapshots do not protect ignored or still-untracked files. Never remove unrelated, still-referenced, ambiguously owned or non-disposable content. For authorized file deletion run `(cd "<surviving-absolute-root>" && jj workspace remove "<verified-name>")`; verify both deregistration and directory disappearance. Warnings or incomplete deletion retain state and become blockers, never force-delete or fall back to Git. `jj workspace forget` is unregister-only, preserving files. Bookmark deletion is separate; retain recovery/archive/best references and any still needed.
9. **Verify the run.** After all units are canonical, perform source-wide Verification Contract gates from a clean recorded canonical snapshot, capture direct exit status and logs, reconcile tracked state, disclose ignored divergence, and persist the run-verification receipt. Failure blocks return/shipping even if cleanup succeeded. Never report complete based on worker declarations alone.

## Independent waves, resume, and one fallback

Apply `execution-strategy.md`'s Parallel Safety Check to dependencies, actual files, interfaces, migrations, lockfiles, generated/config/registry surfaces, singleton resources, and expected merge cost. Use at most 3–5 independent workers, each with distinct isolated output and one recorded wave base. Start all ready units together; terminalize and inspect every result before the first fold-in. Integrate sequentially, authoritatively verify each against the advancing tree, record the exact canonical advance, and revalidate remaining results. Semantic collision, scope expansion, or failure stops affected work; no sibling starts while restoration/lock release is unresolved. Repeated collision disables further waves, without discarding unaffected results.

A supplied `implementation_run:<safe-id>` selects durable state before input classification and never authorizes fresh work. Otherwise discover a single unfinished plan run by exact repository, bookmark and plan digest; prompt runs require the disclosed ID. Ambiguous matches or unsafe/foreign state block selection. Do not choose by directory order or mint another run to escape ambiguity. Reconcile native worker handles, live/terminal status, output revisions, locks, canonical parent/tree evidence, and interrupted cleanup. Do not redispatch, reapply, recommit, rerun successful gates, or invoke either shipping tail during observation-only recovery. Missing required receipts remain blockers.

Only after authoritative terminal failure/timeout, exact restoration or exact abandonment, and lock release may the host persist an atomic one-time fallback claim under the same run/unit. A live job or successful unreconciled output forbids fallback. Both `prefer` and `require` then permit exactly one native current-session implementation, with requested-versus-actual identity and reason disclosed; no second recipient or duplicate claim. Record its host commit and local-verification digest, then the source-wide successful receipt. Retries receive new attempt IDs and retain the same source/dependency/wave contract and earlier evidence.

Standalone execution resumes `ce-work`'s quality and shipping tail only after successful run verification. `mode:return-to-caller` returns implementation/local-verification receipts and `standalone_shipping_skipped: true`; the caller owns simplify/review/PR/CI. Workers inherit neither tail. Once a unit has a recorded selected route and dispatch preparation, do not abandon it for convenience: advance this protocol or report blocked with recovery evidence.
