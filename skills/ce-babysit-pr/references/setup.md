# Step 1 detail: forge check, PR resolution, chain classification, checkout, watch mode

## Prerequisites

The loop runs `gh`, JJ, and bundled Python helpers against a local JJ workspace with filesystem access. A harness without those cannot run this skill — say so and stop rather than half-running. See [JJ's Git-user guide](https://docs.jj-vcs.dev/latest/git-experts/) and [command reference](https://docs.jj-vcs.dev/latest/cli-reference/).

Resolve the absolute workspace root with `jj workspace root`. Every JJ operation runs with that root as its working directory. In this skill and all its references, **every repository-scoped `gh` command** uses this preamble, with the root re-supplied on separate shell calls; keep explicit host/repo selectors where specified (they select the remote repository, not the local workspace):

```bash
(cd "$workspace_root" && GIT_DIR="$(jj git root)" && export GIT_DIR && gh <arguments>)
```

Verify workspace-local `.tmp/` is ignored (normally a `/.tmp/` rule in `.gitignore`) before creating state or isolated work there. If it is not, honor repository policy on setting up the ignore rule; do not silently track scratch data or move it to OS-global temp.

## Step 1: Confirm GitHub, resolve the PR, pick an execution mode

**GitHub only.** This skill and everything it delegates to speak GitHub's API (`gh`, review threads, Actions). First confirm the repo is on GitHub: `gh repo view` succeeding is the positive signal (it also covers GitHub Enterprise that `gh` is configured for). If it fails, inspect `jj git remote list` for the relevant remote URL. On any non-GitHub forge, or if `gh` cannot resolve the repo at all, **stop and tell the user ce-babysit-pr is GitHub-only** and that GitLab/other forges are not yet supported. Do not proceed into `gh` calls that will produce confusing errors.

Resolve the PR from the supplied number or URL, or from the JJ workspace. Without an explicit ref, examine `@` and, when it is empty, `@-` (`jj log`, `jj bookmark list --all`, `jj git remote list`). Resolve the parent's bookmarks to the verified head repository and its remote branch, then look up the open PR by that head, preserving fork owner and host. A bare `gh pr view` can depend on a branch checkout and is not proof that no PR exists. An empty `@` alone is neither the absence of a PR nor the absence of babysitting work. Continue when the parent resolves to one eligible PR; if none exists or the target is ambiguous, report and stop, never guess.

Honor an explicit or standing monitoring opt-out. For an automatic calling-skill handoff without an explicit user watch-mode token, check the resolved PR's draft state with the plain scoped `gh pr view <ref> --json isDraft` read, before any bootstrap — never `snapshot --start-invocation`, which could supersede an explicitly authorized watch on that draft. A draft target reports its draft status and stops before starting a watcher unless the user opted in. On user-invoked runs the first snapshot's emitted `pr_is_draft` serves as the ongoing signal.

**Check auto-merge expectations before watching CI.** When a check or caller expects auto-merge, verify remote stack membership first using the read-only procedure below. GitHub does not support auto-merge for a managed stack, regardless of the repository setting: report that mismatch, never try to enable it, and do not treat that request as implicit `stack-land` authorization. For a PR proved outside a managed stack, read `gh api repos/<base-owner>/<base-repo> --hostname <host> --jq .allow_auto_merge`. If false, report that Settings > General > Pull Requests > "Allow auto-merge" is off and stop before bootstrap. In `mode:pipeline` return `status: "needs-human"` with one residual naming the blocker. Changing the setting is the user's call. Once enabled, a previously failed auto-merge job still needs a rerun as in Step 5.

**Classify the target with GitHub Stacks REST, not a local manager.** Each snapshot validates the exact PR, repository and head against `GET repos/<owner>/<repo>/pulls/<PR>`, then verifies its declared stack against `GET repos/<owner>/<repo>/stacks/<stack-number>`, using the stack ID, number, target position and ordered heads. An explicit null membership means `absent`. If the preview field is omitted, use the PR-filtered list; an empty list is `absent`, as is the documented preview-unavailable 404 when the exact non-preview PR and repository/default branch are independently readable. A missing declared stack, contradictory evidence, other auth/transport errors or malformed responses mean `probe-error`. When no stack is confirmed, ordinary base/head relationships distinguish an independent PR from a manual dependency chain. Discovery makes no writes and never infers a managed stack from topology alone.

**Only when the fresh snapshot has `manager_status == "confirmed"` may stack-wide continuation activate; no other classification authorizes it.** A manual dependency chain never activates stack-wide continuation: keep it target-local even when its base/head topology resembles the manager's ordered branches. `probe-error` also stays target-local and mutation-conservative until a later snapshot positively confirms the manager. Discovery still runs for every babysit — posture does not disable confirmed-manager detection or Step 7 upstack maintenance.

For a confirmed managed stack, inspect the manager's ordered entries once before choosing the active layer; this is a read-only look at the order, not multi-PR monitoring. Resolve **posture** per the table in `references/stack.md` before any review/CI work. If posture is still `target` and the requested middle PR has an unsettled downstack layer, offer once to begin at the lowest unsettled non-draft layer and proceed upward (`stack-ready`), with target-only as the alternative; do not silently redirect review/CI work to another PR. If posture is already `stack-ready` or `stack-land` and the requested PR has an unsettled downstack layer, begin at the lowest unsettled non-draft layer without asking (downstack-to-upstack). If all downstack layers are settled, begin on the requested PR. When the requested PR already looks ready or later settles under `target`, offer once to continue to the immediate open non-draft upstack layer if it needs work (accepting selects `stack-ready` for the rest of the run). That one-time offer expands the babysit scope on an already confirmed managed stack — it is **not** a proactive suggestion to create or adopt PR stacks. An explicit request to babysit the managed stack counts as `stack-ready` acceptance, so do not ask redundantly. In `mode:pipeline`, which cannot ask, continue beyond the requested PR only when the invocation already supplied `posture:stack-ready`, `posture:stack-land`, or equivalent stack-wide scope; otherwise return the next candidate as a residual.

Once `stack-ready` or `stack-land` is in effect, that posture authorizes babysitting each layer of the confirmed managed stack in turn without asking again at each layer. Keep one active PR target and one watcher. At each transition: revalidate manager membership and ordered state, stop the old watcher, switch/check out the next immediate layer, then initialize its own snapshot state with `--continue-invocation` and the same three recorded values on the flags the first snapshot used — `--invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS"` (the anchor flag is `--session-started-at`, not `--invocation-started-at`) — plus `--continue-dead-time-seconds <prior layer's `invocation_dead_time_seconds`>` so the shared active-time budget carries the suspended time already excluded on earlier layers (each layer's state dir accumulates its own dead time, so without this the new layer would count that prior suspend as active) — **and re-state the same `posture:` value on the continue invocation**. The invocation budget is not renewed per layer. Never skip past a draft or enter it unless the user explicitly included that draft; never advance past a layer with a `needs-human` blocker. Stop at the first draft outside scope, human-blocked layer, end of the stack, budget, or user stop. Reconfirm `manager_status == "confirmed"` before every cross-PR transition — loss of positive confirmation ends stack-wide continuation rather than degrading into manual-chain behavior.

**Old-PR intake comes before the checkout gate.** On a fresh invocation, run `references/intake.md` here. Its assessment only reads, so a PR you cannot push to still gets a verdict; a Rework or Close verdict stops (or returns, in `mode:pipeline`) before any snapshot or watcher. A user request to take the PR over goes to `references/takeover.md` instead of the gate below.

**Verify the PR's exact pushed head before any delegated mutation.** Read the resolved PR's head repository, owner, name and OID (`headRepository`, `headRepositoryOwner`, `headRefName`, `headRefOid`, `isCrossRepository`). Verify the named remote's fetch and push identity, fetch the exact head bookmark with `jj git fetch --remote "exact:$head_remote" --branch "exact:$head_bookmark"`, and require the remote bookmark and open PR to agree on the pushed OID. Prove push authority independently; ownership, confirmed write access, or a permitted maintainer edit on a fork can establish it. In a clean workspace, track that verified remote bookmark if the matching local bookmark is absent; don't retarget a divergent bookmark. Require the resulting tracked remote bookmark, local bookmark, and open PR to agree before passing the workspace, bookmark, remote and OID to delegates. The same OID under a different bookmark or remote does not by itself identify the push target.

An empty, conflict-free `@` with the verified head as its sole parent is aligned. Otherwise, once the workspace is clean and alignment will not displace unrelated tracked or ignored work, align with `jj new "$verified_head_oid"` from the workspace root; neither moving to the proven head nor starting/re-arming already-authorized monitoring needs a second approval. For a confirmed stack, also verify fresh REST membership, exact layer identity and any unresolved transaction receipt (`references/stack-commands.md`) before mutation. Stop and report dirty/conflicted work, a divergent bookmark, an ambiguous target, denied permissions, or unproven push authority; never reset, discard, or guess. Offer takeover when push access blocks the work.

Then decide **how the watch sustains itself** — a skill can't be re-invoked by magic once its turn ends, so *you* set up the loop. **The default is a self-sustaining, in-session watch: you do not do one tick and hand back a resume command.** Read `references/watch-loop.md` once here for the mechanics; later steps cite its sections rather than re-reading it. Then:

**User-runnable resume syntax.** Whenever this skill prints or copies a resume invocation, default to `/ce-babysit-pr <url>` and, when the run posture is not `target`, append the same `posture:stack-ready` or `posture:stack-land` token so checkpoint / durable / session re-entry keeps stack scope. Use `$ce-babysit-pr <url> [posture:…]` only when the active host is Codex or explicitly documents dollar-prefixed skill invocation. Render only the invocation as inline code and output one form only.

- **Self-sustaining in-session watch (default).** Keep monitoring until a stop condition is met. By default, run `pr-snapshot watch`, the deterministic change detector, and wait for its `BABYSIT_WAKE` output using the harness's tools. When host instructions dictate how PR waits work, the host's mechanism replaces the detector (`references/watch-loop.md`, **Choosing the wake source**). The detector polls without agent tokens; each wake returns control to this agent for one tick of judgment and sub-skill calls. The detector exits on each wake, so re-arm it after the tick. Never collapse those judgments into a shell script. `references/watch-loop.md` defines scheduling and wake handling.
- **Checkpoint.** Use checkpoint mode only when the user requests it or nothing can wake this agent. Run exactly one tick, persist, report, and print the resume invocation. Say monitoring is paused. Never fake a loop with a foreground `sleep`, or end the turn promising to continue with no wake source armed.
- **Pipeline** (`mode:pipeline`, set by an orchestrator like `lfg`) — run **bounded synchronous ticks in-line**: the orchestrator is the scheduler, so loop ticks yourself (snapshot → act → re-snapshot) until the **pipeline stop** (Step 3), then return. Fully non-interactive. See `references/pipeline.md` for what differs — a different stop condition, residuals returned in the structured result, and a structured return — and read `references/watch-loop.md` for its bound.

**Durability.** The in-session watch is session-bound; if the session closes, resume in the same workspace so the local `.tmp/` state is available. `references/watch-loop.md` owns authorized OpenCode background and durable monitoring. If the user passed a mode, honor it; otherwise pick per available capability, state it in one line, and proceed.
