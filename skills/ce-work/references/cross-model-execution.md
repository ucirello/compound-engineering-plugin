# Cross-Model Execution Contract

Read this only when `references/execution-engines.md` selects a configured route or an existing run needs recovery. The host implements this protocol with OpenCode-native `opencode.models`, subagents, shell, and durable local records. There is no bundled controller, adapter, detached runner, acpx transport, or other-harness dispatcher. A worker response never substitutes for independently inspected JJ state and authoritative verification.

## Resolve intent without changing authority

Preserve the authority order in `references/execution-engines.md`. Live preference is `prefer` unless the user unambiguously requires a route (`require`). Read `work_engine_mode`, ordered `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `config.yaml`; present lists/maps, including empty ones, replace the whole key. `off` disables standing preference only. A typed caller binding remains one candidate with its original provenance.

Configuration remains the source of desired model choices and tiers. Candidate objects retain `harness` (`codex | claude | grok | cursor | opencode | antigravity`), optional `model`, and per-harness requested effort. These are intent data, not instructions to launch those harnesses. Preserve operational provider identities and requested intermediary routes in receipts. Do not turn Composer through Cursor, Grok through Cursor, or a specified Antigravity route into a supposedly equivalent native route. Use `opencode.models` to discover exact available provider/model IDs and supported variants. Resolve candidates in order before exposing content, without running another harness's CLI. An exact required intermediary unavailable through native OpenCode is unavailable, not silently satisfied by the same model through another route. No model pin or effort is silently substituted.

Delegation, model selection, and nesting depth are separate constraints. This workflow explicitly requests unit subagents where permitted. A host rule allowing user-OR-skill-requested delegation therefore needs no second user approval; an unconditional prohibition still wins. If the host allows delegation but requires an explicit user model request for overrides, omit the optional `model` argument unless that request exists. Use inherited-model workers only when they satisfy the unit's requirements; disclose unmet configured tiers/routes. Same-model workers are not cross-model independence. Check effective nesting capacity using the host's supported capability/error evidence; do not infer capacity from permission. Classify actual failures as permission denial, model-argument rejection, missing capability, or depth/capacity exhaustion. Never evade a denial or depth limit through shell or another harness.

When all candidates are unavailable before dispatch, disclose each reason once and continue natively on the current session model for either `prefer` or `require`, preserving `fallback_reason` and incomplete cross-model coverage. A viable required identity remains fixed. Required model independence or a fixed-route review must never be reported complete when unavailable. Do not elevate permissions, guess a model, or silently substitute a recipient. A same-host default with no distinct model collapses to native execution and is recorded as such.

Before dispatch disclose and record binding source, requested and actual provider/model/route/intermediary, packet contents and digest, scope, inherited restrictions, requested effort, and restriction posture. Isolation is not an OS sandbox: record which restrictions the native tool actually enforces and which remain cooperative. A required restriction that cannot be enforced makes the route unavailable. Do not promise another harness's sandbox or approval settings. Never broaden permissions to make a route work.

## Durable source, records, and receipts

Use a private run root under the canonical absolute workspace root: `.tmp/rocketclaw/ce-work/<run-id>/`. Verify `.tmp/` is ignored before writing; if not, arrange the authorized ignore update before dispatch. All briefs, packets, logs, lock records, message files, verification output, fallback paths, and error artifacts stay under local `.tmp/`, never OS temporary storage. Restrict access to private records and never include credentials or raw conversation history. The host owns the manifest and writes each transition atomically using a same-directory temporary file plus rename, with read-back before the next transition. Workers cannot edit authoritative records. Serialize host manifest writes; acquire an exclusive integration lock before canonical mutation and retain its owner and recovery path on ambiguity.

Record the repository identity, canonical absolute root, active bookmarks, exact canonical revision/tree, source kind and SHA-256 digest, scalar stable `run_id`, selected binding, and state. Preserve these return fields:

- `implementation_engine_binding`: `mode`, `target`, `model`, `source`;
- `requested_route`, `actual_route`, all intermediaries, `requested_model`, `actual_model`, and served-model receipt status (unverified when not observable);
- `requested_effort` or null; served effort remains `unverified` without independent evidence;
- `fallback_reason`, `source_kind`, source digest, and `run_id`;
- per-unit `unit_receipts` separating authoring terminal state, transport/scope inspection, integration, authoritative verification, host canonical revision, cleanup, attempt and job IDs;
- disclosed `plan_checkpoint`, `blockers`, `recovery_path`, verification evidence and plan-wide verification receipts.

A repository plan may be checkpointed only when it is the sole canonical change and its selected digest is verified. Use the dynamically composed, path-limited JJ commit procedure in `references/implementation-loop.md`, disclose the checkpoint, and record its resulting revision. Unrelated dirt makes this route unavailable; it is never checkpointed implicitly. For prompt work, write a private brief containing Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units. Use one conservative P1 unless discovery proves distinct bounded units. Missing goal, scope, or authoritative verification returns to clarification. Copy and hash the accepted brief into run state; that copy, not the caller's temporary path, becomes authoritative. Record source digest and re-read it before preparing each unit.

## Isolated workspace contract

Detect existing isolation first and preserve harness ownership. Ordinary synchronous native units stay in the active workspace; ordinary native worker isolation remains harness-managed per `references/execution-strategy.md`. This cross-model protocol may create run-owned sibling JJ workspaces only for its isolated attempts. Reuse verified existing isolation under its existing name, even if undated or noncolocated; do not rename, recreate, or silently modify it. If the harness owns creation/lifecycle, use its supported colocated JJ capability, request the required name, and verify it. Unsupported colocation/naming is a compatibility blocker through the safe route-unavailable decision path, not permission for Git-only isolation or a permission workaround.

For creation through `ce-worktree` or its naming contract, capture local creation date once and persist it before attempting creation. Normalize a meaningful task/PR/revision or caller-supplied slug, stripping an existing date prefix rather than double-prefixing; examples are `20261008-fix-email-validation`, `20261008-pr-214`, and `20261008-review-efcb657`. Use the same `YYYYMMDD-<meaningful-kebab-case-slug>` identity for workspace name and destination basename beneath the absolute local `.tmp/` parent. Check both `jj workspace list` registrations and filesystem destinations; append `-2`, `-3`, etc. on collision without overwriting state. No timestamps, PIDs, or random naming substitutes. Persist the selected date/name/path across retries, resumes, and midnight. Existing PR/source bookmarks remain unchanged.

From the source workspace's absolute root, verify the intended base revision and create explicitly:

```bash
(cd "$workspace_root" && jj workspace add --colocate --name "$workspace_name" --revision "$verified_base" "$absolute_owned_destination")
(cd "$absolute_owned_destination" && jj git colocation status)
```

Verify registered name/path, repository identity, clean state, and exact base ancestry/tree before editing; JJ may place an empty working-copy change above the base, so do not equate `@` with the base blindly. Give workers absolute roots and repository-relative paths such as `src/example.py`, never `.tmp/.../workspace/src/example.py`. Every JJ invocation runs from the target absolute root, e.g. `(cd "$workspace_root" && jj status)` or Python `subprocess.run(["jj", ...], cwd=workspace_root)`; `jj -R` alone is insufficient. Repository-scoped GitHub CLI uses `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`.

JJ references: https://docs.jj-vcs.dev/latest/git-experts/ , https://docs.jj-vcs.dev/latest/git-command-table/ , https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace . Prefer JJ; a Git fallback is allowed only for an operation JJ cannot perform, never workspace lifecycle.

## Serial unit transaction

Advance one state-changing transition per host tool call through terminal scope inspection. Record and read back each transition before continuing. Do not generate a shell script that spans dispatch, waiting, and integration. A nonzero command ends that call and enters recovery, never automatic continuation.

1. **Initialize and prepare.** Prove clean canonical state, record source/checkpoint, repository/bookmarks, exact base and complete tracked tree, expected paths, packet digest, unit dependencies, attempt ID, workspace ownership, result location and selected native route. Re-read canonical state before dispatch; unrelated changes or a moved base stop preparation. Ignored dependencies, virtual environments, and caches do not themselves disqualify a clean canonical workspace.
2. **Bind before egress.** Durably bind exactly one native worker handle/job to the attempt, route/model/effort, absolute workspace, immutable packet path/digest, expected scope and result location. If the tool returns the handle only after launch, write pending authorization first, record the returned handle immediately, and never launch a second job to repair missing metadata. A missing/ambiguous binding blocks further egress until reconciled. No caller-supplied shell recipient, ambient override, or worker-selected fallback is accepted. Workers inherit only the bounded unit packet in `references/agents/implementation-worker.md`: no canonical commit, push, PR, shipping, peer scheduling, fallback, or scope expansion authority.
3. **Observe without steering.** Use native status/wait mechanisms and separate host calls, bounded to 60 seconds where supported. Report unit, actual route, elapsed time, meaningful activity/kind, and terminal state. Preserve a 7200-second hard deadline. Apply the 600-second progress-resetting idle window only when incremental activity is trustworthy; otherwise use `hard-only` with idle detection disabled. No missing output alone proves failure. A live or temporarily unreachable job remains authoritative; do not duplicate or fall back. Stop/reap only through supported native lifecycle actions and retain its workspace/evidence.
4. **Terminalize and inspect.** After authoritative completion and worker termination, snapshot the complete JJ result as a transport change and preserve it with a recovery bookmark. Require the recorded base as sole parent and the complete final tree. The host alone owns transport snapshots; they are not canonical commits. In a later call inspect actual diff/path inventory, untracked candidates, binary/mode/rename/delete evidence, worker result, scope-expansion requests, and packet scope. Unexpected generated or unexplained changes stop integration and retain all evidence. Worker `completed` proves authoring only.
5. **Acquire and preflight.** Acquire the canonical integration lock; verify exact canonical pre-fold revision/tree/bookmarks and allowed wave progression, source digest, transport parent/tree and approved path inventory. Record a durable pre-fold snapshot/recovery bookmark and expected post-apply tree/path set before any mutation. Dirty/conflicted/ambiguous state blocks. Use JJ change operations (for example a host-owned copy of the transport via `jj duplicate`, then `jj rebase` onto the verified canonical base) only after checking their current help and exact revision targets. Never move the retained transport/recovery revision or treat a clean textual application as semantic compatibility. Inspect conflicts and actual resulting tree before canonical verification; use `jj edit` only when the canonical working copy is proven clean and the target is the verified host-owned integration change.
6. **Verify and reconcile.** Run the exact authoritative Verification Contract argv, capturing its exit status directly and private log, with Python bytecode disabled. For shell syntax use explicit `bash -o pipefail -c '<verification command>'`, not literal unexpanded argv. Record before/after tracked revision/tree/bookmarks and status-visible inventory; any verification mutation fails reconciliation. Separately inventory ignored entries by metadata and disclose `ignored_state` changed/removed/created counts plus a bounded sample in every verification receipt/return. Ignored state is not part of tracked equality, empty ignored directories are not inventoried, and no ignored file is copied/restored/deleted automatically. Caches, `.env` files and local databases are not protected from the verification command. Preserve newly created ignored content.
7. **Commit once or restore exactly.** Only after passing verification and exact reconciliation may the host describe/finalize one canonical change using the complete runtime-composed message from `references/implementation-loop.md`. Record exact canonical revision, parent, tree, scope and verification digest before cleanup/release. Do not truncate messages. A failed apply, verification or pre-commit step forbids canonical commitment. Restore only this run's attributed tracked changes using the recorded JJ recovery snapshot/operation evidence; never reset, discard user changes, or blindly undo unrelated/concurrent operations. Prove exact pre-fold revision/tree/bookmark and status equality before releasing the lock or starting fallback/retry/sibling. If proof is impossible retain lock, transport, workspace and recovery path and return blocked. A crash after the canonical change is evidence to reconcile, not permission to commit again.
8. **Clean and release.** Apply the removal safeguards below only after reconciled integration and any required authorization. Record cleanup outcome and release the lock. Preserved workspaces stay disclosed; success never authorizes deleting a user's workspace.
9. **Verify the run.** Once every unit is terminal (`cleaned` or `native-completed`), acquire the same verification ownership boundary, start from a clean canonical snapshot, and run every plan-wide Verification Contract gate (or authoritative prompt check). Capture status/log and durable receipts directly; inspect/reconcile tracked equality and ignored divergence exactly as above. If a check mutates tracked state, restore only attributable changes and prove exact equality. A failure or missing receipt blocks completion even if cleanup succeeded. Do not hide failure behind a later successful command.

Report source kind, route, checkpoint, dispatch, activity, terminal result, transport/scope inspection, integration, restoration, verification, canonical change, cleanup, blockers, and recovery path. A durably initialized selected engine cannot be abandoned as trivial or for speed: finish this protocol or report blocked, unless fallback is explicitly claimed below.

## Parallel waves

Use `references/execution-strategy.md`'s Parallel Safety Check before any wave; cap at 3–5. Record one wave ID and base from clean canonical state, distinct isolated workspaces, fixed dependency order and exclusive files. Dispatch all ready native calls concurrently. Terminalize all results and inspect all actual inventories before integrating any. Same-path changes stop the wave; shared-interface contention requires host resolution even without overlap.

Integrate sequentially under the lock. The first unit requires the wave base; later units accept only the exact earlier host-owned canonical revisions recorded in this wave. Record each wave advance with its exact parent/tree before cleanup/release. Unknown movement blocks. Reinspect scope, semantic compatibility and authoritative verification on the advancing canonical tree, with one host-owned change per unit. Never merge a transport directly. On conflict/failure restore exactly under lock before another unit, retry, or fallback. Recompute readiness; unaffected siblings may continue after release, dependents stay queued. Repeated collision, broad edits, or inability to prove restoration disables more waves while retaining unaffected outputs.

## Resume and exactly-once fallback

A caller's `implementation_run:<safe-id>` is authoritative. Otherwise discover a plan run only by exact repository identity, active bookmarks and selected plan digest, not by guessing from arbitrary directory listings or conversation text. Prompt runs require the disclosed ID. Multiple matching unfinished runs block selection and report their IDs/recovery paths; never start a third. Unsafe or foreign manifests block rather than being skipped.

Resume is read-only reconciliation before ordinary triage and never dispatches, reapplies, recommits or runs either shipping tail automatically. Adopt at most one exactly matching unbound job, monitor a recorded live worker, terminalize authoritative completed output, continue an interrupted attributed restoration, or reconcile an already-created canonical revision only when its parent/tree match durable evidence. A transport bookmark written before its row is reusable only with the exact base parent and final tree. Expected post-apply tree/path evidence may reconcile an interrupted apply; unknown dirt blocks without destructive restoration.

When every unit is terminal and a successful plan-wide receipt exists, completed recovery is observation-only: return stored receipts without rerunning tests/builds/format/install/generation or verification. A missing receipt is a recovery blocker, not permission to improvise a check. Losing contact never makes a recorded job terminal; require authoritative terminal evidence or explicit supported termination. Cleanup is idempotent and verifies remaining state. Abandonment requires the exact transport revision, or exact terminal job ID when no transport exists.

After authoritative failure, timeout, died-without-result, or exact restoration and lock release, durably claim native fallback once for this unit/attempt before writing. Record requested versus actual route/model and reason. Both `prefer` and `require` allow one current-session fallback when unavailable, but a live job or successful unreconciled output forbids it. An existing claim never authorizes a duplicate. If integration began, exact restoration and snapshot equality are prerequisites. After fallback, record accepted canonical revision, local verification evidence SHA-256 and bounded summary, then close only that unit as `native-completed`. Preserve earlier receipts. A corrected redispatch uses the same scalar run ID, a new attempt ID, and unchanged dependency/wave/base contract; never silently redispatch or use a list of run IDs. Final completion still requires the stored plan-wide successful receipt.

## Retiring a run-owned workspace

Stop workers first. Verify exact registered name, absolute path and run ownership, integration proof when required, tracked changes, conflicts and ignored/untracked content. Keep recovery/transport/best/archive bookmarks and references still needed. Copy required receipts/logs/evidence outside the target and read them back before deletion. JJ removal snapshots working-copy state, but ignored and left-untracked content is not protected: never remove unrelated, ambiguous, still-referenced or non-disposable content. Completion alone grants no cleanup authority; respect user authorization and harness-owned lifecycle.

Leave the target directory and move any active harness session to a verified surviving workspace before removal. From that surviving absolute root run:

```bash
(cd "$surviving_workspace_root" && jj workspace remove "$verified_workspace_name")
```

Then verify BOTH deregistration via `jj workspace list` and directory disappearance. A successful exit can hide deletion warnings. On failure or incomplete cleanup retain remaining state and report the blocker, never force-delete or fall back to Git cleanup. `jj workspace forget` is reserved for unregistering while intentionally preserving files, not retirement/deletion. Bookmark deletion is a separate authorized action and must preserve recovery and still-needed references.

## Preserve tail ownership

Standalone execution resumes `ce-work`'s quality/shipping workflow only after implementation and local verification. `mode:return-to-caller` returns receipts and `standalone_shipping_skipped: true`, never simplify/review/PR/CI steps owned by the caller. Workers inherit neither tail.
