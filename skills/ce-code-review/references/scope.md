# Determining the reviewed diff and scope

Read at Stage 1. Resolve scope before the Review depth gate. Apply `dispatch-capabilities.md` before PR triage or any other launch. All JJ commands below run from the reviewed workspace's **absolute root**: `(cd "$workspace_root" && jj ...)`; `-R` alone does not set cwd. Paths in inventories must be repository-relative (`src/example.py`), never workspace-prefixed. See https://docs.jj-vcs.dev/latest/git-experts/ and https://docs.jj-vcs.dev/latest/cli-reference/ .

## Stage 1: Resolve endpoints without changing the working tree

Discover `workspace_root` with `jj workspace root`; thereafter set tool cwd to that absolute path. Repository-scoped GitHub calls always run `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. Verify exact repositories, remotes, bookmarks, and immutable commit IDs; do not guess `origin`, `main`, or a same-named fork bookmark. Read-only review scope does not authorize `jj edit`, checkout, reset, discard, push, or creating a workspace.

- **Explicit `base:`:** reject combination with a PR/bookmark target. Verify the supplied revision, then resolve its unique common ancestor with `@` using `jj log -r 'heads(::@ & ::<verified-base>)' --no-graph -T 'commit_id ++ "\n"'`. An unresolved/ambiguous endpoint is an error, not permission to guess. The reviewed head is `@`; diff base to `@` includes all snapshotted working-copy changes.
- **PR number/URL:** use scoped `gh pr view <target> --json state,title,body,files` first. Closed/merged stops with `PR is closed/merged; not reviewing.` Drafts are reviewed normally. This skill explicitly requests a lightweight native triage child for automated/trivial changes. Apply actual delegation/model/depth permissions; prefer the cheapest capable tier only when overriding is permitted, otherwise inherit. Give it title/body/paths; uncertainty means not trivial. If unavailable, continue with the limitation recorded rather than inventing a skip. A real triviality judgment may stop with `PR appears to be a trivial automated PR; not reviewing. Run without a PR argument to review the current bookmark, or pass base:<ref> if review is intended.`
- Fetch PR metadata without checkout via scoped `gh pr view <target> --json title,body,baseRefName,headRefName,headRefOid,isCrossRepository,url,files,reviews,comments`. Compute `hasPriorComments` from existing review submissions/comments. Keep `BASE:pr:<target>` as the logical scope marker while separately resolving real `PR_BASE_REF` and `PR_HEAD_REF` commit IDs.
- **Local alignment:** require a verified same-repository head, the expected local bookmark association, and proof that the exact PR head is an ancestor of `@`. A clean empty `@` directly above that head is aligned; an identical bookmark name alone is not. If any check is uncertain, choose `pr-remote`. Local aligned diff uses the unique common ancestor of verified PR base and `@` through `@`, including local changes; never append remote hunks to it.
- **Remote PR:** `FILES:` comes from metadata; `DIFF:` comes from scoped `gh pr diff <target> --color=never`. Failure stops with an actionable error, never checkout fallback. Best-effort `jj git fetch --remote <verified-remote> --branch <verified-bookmark>` from the workspace root may obtain each endpoint. For forks resolve the actual head repository/remote, not a same-named branch on the base repository. Set `PR_HEAD_REF` only when its immutable ID equals `headRefOid`; if fetching fails or the head moved, omit it and record diff-only coverage. Resolve a separate verified base commit as `PR_BASE_REF`; absent base means file-level/schema diffs use hunks only and never assume main.
- **Bookmark target:** if it is the verified current reviewed revision, use standalone scope. Otherwise scoped `gh pr view <bookmark> --json baseRefName,url,headRefName` may resolve a PR and use that path. If none exists, resolve/fetch the exact remote/local bookmark with JJ, determine the verified default base, and diff their unique common ancestor through the immutable target as `branch-remote`. Failure to resolve is an error; never switch the workspace.
- **No target:** resolve an associated PR via verified bookmarks/repository, checking `@-` as well when `@` is an empty child of a pushed head. Otherwise resolve the verified default base through remote metadata/bookmarks. If no base can be resolved, stop; diffing only `@-` would silently omit committed work.

For real endpoints set `DIFF_A` to the verified ancestor/base and `DIFF_B` to `@` in local scope or the immutable reviewed remote head. Produce `FILES:` with `jj diff --from "$DIFF_A" --to "$DIFF_B" --name-only` and `DIFF:` with `jj diff --from "$DIFF_A" --to "$DIFF_B" --git --context 10`. Set `BASE:` to the real base except the PR logical marker. Inspect `jj status` and ignored/untracked content: JJ normally tracks nonignored files automatically, unlike a staged/unstaged index. Files deliberately left untracked remain excluded and are listed in `UNTRACKED:`/Coverage; do not change tracking merely to review them.

Pass scope mode (`standalone`/`local-aligned`/`pr-remote`/`branch-remote`), head/base revisions, file inventory and diff to every reviewer/validator. Remote scope never Reads/Greps changed workspace paths: use `jj file show -r <verified-head> <path>` or the diff hunks, and scope provenance to that same revision. A missing verified remote head means hunks-only coverage, not permission to inspect stale local files.

## Stage 1b: Deterministic signals

Validate both endpoints before computing facts. Use the retained `scripts/review-scope.py` with `--base <real-base> --head <reviewed-head> --docs-root <root>` for remote scope and `--base <real-base> --docs-root <root>` for local scope, from the absolute workspace root. Resolve a working Python interpreter in the same shell call. The helper performs numeric/path classification only, never harness dispatch; if inspection fails or endpoints are missing, fail closed rather than estimating or comparing a remote base to a local tree. Read the returned JSON once.

`hard_block_full` forces full for migration/schema path classes, uncounted files, or at least 200 executable non-test changed lines. `silent_pass_classes` (including CI workflow paths) prohibit lite, not automatically focused/full; consequence decides. Signals are heuristics, not automatic reviewers or permission to award lite. Use `test_files_changed`, `agent_surface`, `has_learnings_corpus`, and `declared_packs` as selection inputs. Local configured packs are checked without cloning/resolution; remote config is not inferred from the local checkout. If declared-packs status is unknown, inspect local config explicitly where scope allows. Apply the Review depth gate before later spine references.

## Stage 1c: Map criteria and create the run directory

Enumerate `CODING_STANDARDS.md`, `CLAUDE.md`, and `AGENTS.md` in the **reviewed tree**, paired with changed descendants. Root files govern all descendants; scoped files govern only their subtree. Apply all governing CODING_STANDARDS files. Instruction files supply criteria only for files without any governing CODING_STANDARDS file; no file is graded against both kinds. Declared packs remain separate learnings sources. A successful empty mapping is valid; uncertainty/search failure is not an empty result and must be named for the depth gate and standards reviewer.

Create the private run directory under `$workspace_root/.tmp/rocketclaw/code-review/<run-id>` (local `.tmp` if no repository exists). Verify `.tmp/` is ignored, refuse symlink/foreign-owned scratch locations, use mode 0700/umask 077, and stop on failure; never fall back to OS temporary storage. Every path writes artifacts there, including lite/focused.

## Stage log and visibility

Use retained `scripts/run-log.py event --run-dir <absolute-run-dir> --start scope`, then its `--end <stage> --start <stage>` boundaries, with reviewer/candidate/token counts only when known. It is bookkeeping, not dispatch. Lite/focused stages are scope, review, receipt (peer overlaps focused review); full stages are scope, select, dispatch, validate, merge, report (peer overlaps dispatch). Finish with its summarize contract in `modes-and-output.md`. Fold bookkeeping into existing calls rather than a separate turn. When supported, task tracking shows review outcomes, not persona mechanics; unavailable tracking does not require simulated chat tasks.
