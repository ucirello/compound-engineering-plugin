# Cross-Model Implementation

Load this for a selected cross-model candidate or recovery. OpenCode is the only dispatcher; JJ owns the workspace lifecycle. The orchestrator, not the worker, owns the run record, canonical verification and commits. A worker's exit or reported result is not proof of integration.

## Resolve one fixed author

Use the authority ordering in `references/execution-engines.md`. Ordinary “use X” is `prefer`; explicit strict intent (“only X”) is `require`. Follow an authorized ordered list as written; a typed caller binding is one candidate, with its original provenance. Resolve standing `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently under the two-file config rule; a present local list/map (even empty) replaces its team counterpart. Preserve the existing configuration and caller vocabulary: `codex`, `claude`, `grok`, `cursor`, `composer`, `opencode`, `antigravity`, `pi`. Standing preferences are ordered `{harness, model?}` objects; effort is a map keyed by harness. For example, `{harness: cursor, model: composer}` expresses a Composer model request, not permission to run Cursor. Keep operational provider labels and model pins as input data, never executable flags.

Use `opencode.models` to resolve an exact available `provider/model` and variant for each candidate before sending any work. If a legacy harness label unambiguously expresses a model family (such as Claude or Composer), use only an actually available equivalent family and disclose the mapping. A true non-OpenCode harness requirement, a model-less request without an unambiguous OpenCode mapping, an unavailable exact pin, or an unsupported requested effort is unavailable, not permission to choose a different provider/model or launch another CLI. Resolve a requested effort against the selected model's supported variants; an invalid effort map supplies no request and is reported once. Do not change the session model. Equivalent current-host/default candidates do not start an isolated worker; skip redundant standing candidates when searching a list, and collapse a single redundant binding to native with the requested/actual distinction reported.

Check delegation permission, model-override permission, and remaining nesting capacity independently. Under a user-or-skill delegation rule this reference explicitly requests its selected OpenCode worker; an unconditional prohibition or actual denial still controls. An inherited or already-configured model is eligible only if it satisfies the selected binding. Never bypass a denial, rejected model argument, or depth limit through shell or another harness. Before the first launch, try only the next authorized candidate if preflight proves this one unavailable; `require` never authorizes an unrequested recipient. If none qualify, explain the attempted routes and observed reasons once and continue on the current OpenCode session model. This fallback applies to both `prefer` and `require`, does not request elevated permission, and never invents a fulfilled model requirement.

Prefer a fresh native OpenCode subagent that can actually adopt the assigned workspace and selected model through the live tool schema. Verify both capabilities, not merely the availability of a subagent action. When workspace/model selection needs a separately authorized OpenCode session and no higher-priority rule forbids it, the shell can run `opencode run --model "$model" --format json --title "$attempt_id" --file "$packet" "<bounded instruction>"` with CWD set to the already-created absolute JJ workspace. Pass the model as one exact `provider/model[#variant]` argument, the packet as an absolute path, and retain the tool/session handle and events. Do not pass `--worktree`, `--auto`, or change permissions. Use this native CLI surface only when the shell and session launch are allowed in their own right and the selected permissions can be honored; an actual native dispatch denial or exhausted nesting may not be worked around. If no supported surface can prove assignment, treat the route as unavailable before sending a packet. See [OpenCode agents](https://opencode.ai/v2/docs/agents) and [JJ workspaces](https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace).

## Establish the durable run and sanction egress

Before changing the repository or sharing a packet, resolve the absolute canonical workspace with `jj workspace root`, then run each JJ command with that workspace as CWD (or the explicit worker workspace for its own commands). Preserve the workspace/bookmark, starting `@` change and commit IDs, sole parent, exact clean/dirt status, full checked source digest and accepted base. The canonical checkout must be clean and conflict-free for isolation, except a selected plan that is verified as the only dirty path may receive a disclosed path-limited checkpoint under `references/implementation-loop.md`. Unknown dirt is never checkpointed or silently discarded. A prompt source requires cleanliness and a bounded brief (request, goal, scope, acceptance and verification, constraints/exclusions, and normally one P1 unit) before a run starts. Copy that brief into private run storage, hash it and use the saved copy; never store a transcript or credentials.

Use `<canonical-workspace>/.tmp/rocketclaw/ce-work/<safe-run-id>/` for the run, packets, logs, evidence, locks, and preserved state; ensure `.tmp/` is ignored and not already tracked. Create an owned, private directory (0700 on POSIX) and write private receipt files atomically. Reject symlinks, foreign ownership or unsafe paths; do not overwrite existing run IDs or fall back to OS temp. Use a durable manifest with full source digest and kind, canonical root and repository identity, starting and current accepted revisions, `run_id`, fixed binding (`mode`, `target`, `model`, `source`), requested and actual route/model, model receipt status, requested effort or null (actual effort `unverified`), restrictions, checkpoint, blockers, and recovery path. Each unit records dependencies, optional wave/base, exact expected paths, and append-only attempts with packet digest, workspace identity, launch handle, terminal evidence, transport, restoration, integration, verification, commit, fallback and cleanup receipts. Store output and evidence outside the worker workspace.

Disclose and record provenance, requested and actual route (including any intermediary), fixed recipient/provider/model, material exposed (including checkout contents, matched pack rules and explicitly cited prototypes), and caller restrictions before dispatch. Workspace separation is cooperative, not an OS sandbox. A required restriction that cannot be enforced makes the route unavailable. Without trustworthy served-model evidence record `actual_model: unverified`; never infer that a renamed, substituted, or configured model actually served the request. Once the selected run is recorded as ready, latency or convenience is not route unavailability: use this route or return its durable blocker. Do not silently resolve a different recipient mid-run.

## Prepare and observe

1. For each ready unit, create a private packet with only its goal, definition of done, unit and verification evidence strategy, relevant requirement/decision excerpts (including explicitly governing links), expected files, exclusions and inherited restrictions. Include applicable pack rules with citation, following `references/work-intake.md`, and relevant prototype citations and locality qualifications. Do not send the whole plan/brief or conversation by default. Read and include `references/agents/implementation-worker.md` and `references/implementation-result-schema.json`. The worker may edit and self-check only the assigned workspace; it may read only explicitly cited prototype material outside it. It cannot commit, integrate, push, ship, dispatch peers, expand scope or select a fallback. Record the packet path and SHA-256 before dispatch.
2. Detect existing isolation first. Do not rename, recreate or clean up a harness-owned or user workspace. For a new run-owned worker workspace, capture the local date once and record a unique `YYYYMMDD-<meaningful-kebab-case-slug>` name (e.g. `20261008-validate-email-u3`) matching its absolute destination basename under the run's `workspaces/` directory. Normalize caller-provided names without double-prefixing; check registrations and destination paths and use `-2`, `-3`, etc. on collisions. Reuse the recorded name on retrying creation; give a genuinely new attempt a fresh dated identity without changing the saved run date. From the canonical root:

   ```bash
   (cd "$workspace_root" && jj workspace add --colocate --sparse-patterns full --name "$name" --revision "$verified_base" "$absolute_destination")
   (cd "$absolute_destination" && jj git colocation status)
   ```

   Verify the exact registry entry, same repository, empty `@` and sole parent equal to the frozen base, and confirm colocation from the new workspace. Use full checkout scope (do not inherit sparse patterns that would hide paths). A harness-managed isolated workspace is eligible only if it meets the same base/colocation checks and supported adoption, with its own ownership rules; no enforcement by rewriting it. Canonical ignored content is neither copied nor a preflight blocker. Abort a launch on unverified workspace assignment rather than allowing the worker to write to the canonical checkout.
3. Record a launch intent with attempt ID, packet digest, workspace and recipient before dispatch. Recheck the digest and recorded assignment, then bind exactly one fresh OpenCode session/tool handle to that attempt; record the handle returned by OpenCode, not one invented by the worker. Keep each lifecycle transition a separate fail-stop tool call; do not script dispatch, waiting and fold-in as one command or chain units in the worker. On interruption between start and receipt, adopt only a unique match from authoritative OpenCode session/tool evidence, never infer non-launch from a missing handle. Observe in separate bounded calls (at most 60 seconds each), giving the user elapsed time, actual progress and observed state. Keep a two-hour hard deadline and, only with trustworthy incremental telemetry, a ten-minute stall limit measured from actual progress. At a limit request sanctioned cancellation and verify terminal state before proceeding; missing telemetry, lost contact, or a stalled tool without confirmed terminal state never authorizes a duplicate, fallback, integration, or deletion.
4. Once terminal, preserve native lifecycle evidence and the worker's structured result. For `completed`, snapshot the worker's complete `@` using JJ and record its exact commit ID, sole parent equal to the recorded base, and conflict-free state. Pin the transport with an explicitly run-owned recovery bookmark if needed (never move another bookmark). Inspect `jj diff --from "$verified_base" --to "$transport" --summary` and the exact `jj diff --from "$verified_base" --to "$transport" --git`, including both rename paths, deletions, binary/mode/type changes and unexplained outputs. Inventory ignored/unsnapshotted content separately by local metadata without following symlinks; do not copy or remove it as part of integration. Compare actual paths with the packet and structured result. Stop on unexpected writes, a malformed result, or a scope-expansion request and preserve the workspace. A transport snapshot remains noncanonical even when the author reports success.

## Integrate one unit at a time

Acquire an exclusive integration lock for the canonical workspace, scoped to the run/unit and held through transaction, verification and receipt. Use exclusive creation of a private lock directory in `.tmp/rocketclaw/ce-work/`; write ownership with a unique token. An existing lock, including one with missing ownership evidence, is a recovery signal, not something to replace. Under the lock re-read canonical workspace identity, JJ change/commit IDs, bookmark, parent, conflict state and exact tracked working tree. Freeze the pre-fold baseline and expected post-fold state before writing. Stop if the canonical revision or tree does not match the recorded base or an exact earlier accepted dependency/wave commit, or if user/ignored content could be overwritten.

- Rebase the transport **without touching canonical files** when the canonical accepted parent advanced, e.g. `jj duplicate --onto "$accepted_parent" "$transport"` in the canonical repository. Record that new candidate's exact commit ID, sole parent and tree; reject conflicts and recheck its exact paths and semantics against the accepted parent. If no rebase is needed, use the transport itself. Preserve candidate and transport until reconciliation. Verify canonical `@` is empty above the expected parent and untouched, then apply it with `jj restore --from "$candidate" --into @ -- "${owned_filesets[@]}"`, using a nonempty list of exact `root-file:` filesets (both sides of renames). Read back exact expected tree equality before verification. Never merge, squash the unreviewed transport, or promote the transport bookmark to shipping.
- Run the unit's authoritative checks in the canonical workspace with runtime byproducts directed under ignored `.tmp/` where supported and Python bytecode disabled. Capture actual exit status, command, and log. Take exact JJ snapshots before/after, checking canonical workspace identity, working-copy change, parent, bookmark, conflict state and tracked tree, and keep a bounded before/after metadata inventory of ignored or unsnapshotted files (`ignored_state`: created/removed/changed counts and path samples; distinguish unknown from zero; exclude the run's own receipts). Do not copy, restore, or delete those files; commands that mutate caches or local data may cause real side effects. A failed check or tracked mutation fails the unit even if testing output sounds successful.
- Only after success and exact reconciliation, persist the verification receipt and intended message against the candidate and commit just the owned paths as in `references/implementation-loop.md`. Record canonical commit ID, sole parent, exact tree, verified result and new working-copy ID before unlocking or cleaning. A valid canonical commit whose receipt is missing is crash-reconciliation evidence, not permission to apply or commit again. If the unit is already satisfied and no changes are needed, prove it against the current accepted canonical revision and record that verification without making an empty commit.
- On pre-commit failure restore **only proven run-owned changes** from the frozen baseline using path-limited `jj restore --from "$pre_fold_snapshot" --into @`, and prove pre-fold tree, parent, change and bookmark equality; never reset the repository or roll back global JJ operations. If concurrent or unowned dirt is possible, or proof fails, retain the lock, workspace and references and block later integration, retry and fallback. On proven restoration persist the receipt and release only the same owned lock. A lock released after successful canonical integration records that exact accepted revision as the only permitted next baseline.

After all required units reach accepted state and their required cleanup is reconciled, run the plan-wide Verification Contract (or prompt-wide checks) under the same canonical lock and clean-snapshot discipline. Capture status, log, exact before/after reconciliation and ignored-state disclosure; restore only proven tracked mutations and block when they occur or the check fails. Write a durable successful run-wide receipt before reporting completion or handing off. Never rerun a stored successful gate merely because a recovery request arrived.

### Independent waves

Keep dependency order and use the Parallel Safety Check in `references/execution-strategy.md`. Cap a cross-model wave at 3–5 independent workers and use separate verified isolated workspaces from one recorded base. Wait for all transports and compare actual inventories before the first integration, including same paths, shared contracts/migrations/configuration, and semantic collisions even when files differ. Fold in sequentially under the canonical lock. Only exact prior accepted host commits advance the wave; unexpected movement, failed checks, scope expansion and conflicts block affected units and their dependents. Stop new waves after repeated collisions or uncertain restoration. Preserve unaffected terminal work and resume it only after proving the new baseline and rechecking the independent scope.

## Recover without repeating work

Resolve recovery before ordinary input. Use the exact supplied ID, or on an ordinary plan-backed continuation match the private manifest to canonical repository/workspace, accepted branch/bookmark and exact source digest. Zero matches permit a new authorized run; multiple matches block and disclose IDs/paths. Unsafe or inconsistent manifests block rather than being silently skipped. Prompt-backed recovery requires its recorded ID. For legacy bridge records without sufficient OpenCode/JJ evidence, preserve them and report what cannot be reconciled; never invoke removed helpers or translate a legacy ID into a guessed native session.

Inspect stored receipts, verified JJ revisions, exact tree evidence, and the recorded native handle with OpenCode. For a recorded CLI session, use `opencode session export "$session_id"` from its assigned workspace if a persisted transcript is needed; write the export inside the ignored run root. A transcript alone is not terminal lifecycle evidence. Recovery alone never redispatches, applies a pending output, recommits, reruns verification or enters either shipping tail. It can observe a live attempt, adopt a uniquely matched post-launch session, seal proven terminal output, recognize an interrupted apply only when it exactly matches its recorded expected tree and paths, finish proven restoration, record an already-landed canonical commit matching the frozen parent/tree and intended description, or finish already-authorized cleanup. If the completed manifest has accepted unit and run-wide receipts, return those read-only. A missing required receipt is a blocker, not authorization to fabricate or repeat the step.

Post-start fallback is available exactly once per unit, for either mode, only after authoritative failure/cancellation (or a rejected integration with proven restoration), no live or unreconciled successful worker, and verified canonical state with the integration lock released. Atomically record one fallback claim before any native edits; a pre-existing claim prevents another start. Disclose the observed reason and use only the current session model. Record the accepted native commit and SHA-256 of verification evidence, then perform cleanup. An explicitly authorized corrected retry uses the same run ID, fresh attempt ID and workspace, after exact restoration and safe abandonment; preserve earlier receipts and do not widen dependency/base rules. Unknown or live state cannot be reaped by assumption: use native cancellation only when authorized and verify termination.

## Retire only owned workspaces

Stop the worker and prove its terminal state. Move any active OpenCode session out to a surviving verified workspace and respect any harness-owned lifecycle contract. Confirm the exact registration, absolute path, canonical relationship and run ownership. Prove integration for accepted work; explicit abandonment instead requires the exact transport revision or, if no transport exists, the exact terminal session/attempt identity and approval. Inspect tracked, conflicted, ignored and unsnapshotted files before deletion; preserve all non-disposable or ambiguous content and do not delete a referenced workspace. Copy/read back the receipts and evidence outside the target first. From the surviving workspace:

```bash
(cd "$surviving_workspace_root" && jj workspace remove "$verified_name")
```

Verify both deregistration and directory disappearance, even if the command returned success. Incomplete removal retains evidence and blocks cleanup rather than forcing deletion. `jj workspace forget` is for unregister-only behavior, never a prelude to deleting files. Keep temporary bookmark deletion separate and preserve any reference still needed for recovery. A recovery retry of cleanup must not repeat integration or delete unrelated paths. Report unit intake, dispatch/activity, terminal state, scope, restoration, verification, accepted commit, cleanup, and any blocker with its recovery path; use `references/return-to-caller.md` for the same facts in structured form.
