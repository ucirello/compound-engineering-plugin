# Cross-model adversarial pass

Run only for a selected adversarial lens (including focused depth) when the local tree is the reviewed head. Remote scopes retain the local persona with verified reviewed-revision context. The peer reads the same `references/personas/adversarial-reviewer.md` and returns `references/findings-schema.json`; it is not a whole-diff generalist. Use native OpenCode `opencode.models`, `subagents`, and read-only `shell` inspection, never a dispatcher from another harness or a detached bridge script.

## Resolve policy, permission, and one fixed route

Read ordinary configuration from `<absolute-workspace-root>/.rocketclaw/config.local.yaml`, then `config.yaml`: first active valid scalar wins, empty is unset; present lists/maps replace the whole key. `docs_root` remains config.yaml-only. Resolve `cross_model_review_mode` (`auto` default or `off`) before dispatch. `off` needs a live user opt-in; an explicit prohibition always wins. Resolve target from user preference, `cross_model_peer`, loaded project instructions, then the first available attested-different family in `codex → claude → grok → composer`. Preserve these target families as configuration intent and resolve their available provider/model IDs using `opencode.models`; do not invoke their harness CLIs. Unknown host serving family cannot establish automatic independence. `CROSS_MODEL_PEERS`, when present, restricts every disclosed recipient; absence is not a missing approval.

This skill explicitly requests reviewer subagents. If the host permits delegation when the user OR an applicable loaded skill requests it, this instruction satisfies that exception: do not demand a second user approval. Loading a skill without a dispatch instruction would not suffice. An unconditional higher-priority prohibition, missing tool, or actual denial still applies. Never evade it with shell or another harness.

Model permission is separate. Resolve requested `cross_model_model` and `cross_model_effort` (user overrides configuration); preserve configured routes and editorial intent: Claude Opus high, Codex/native Grok extra-high, Grok-through-Cursor high/fast and Composer fast ceiling. Resolve current concrete IDs and supported variants with `opencode.models`, not stale IDs or another harness's defaults. Only pass the optional subagent `model` argument when the host permits it; if an explicit user model request is required, skill/config tier preference is not that request. A suitable inherited-model reviewer may cover the adversarial lens, but cannot satisfy a required different-model or fixed-route pass. Disclose unmet model/tier/route intent and mark cross-model coverage incomplete. Never silently substitute families or claim same-model reviewers prove cross-model independence.

Verify effective nesting capacity from the runtime's discovered project configuration and actual tool context before dispatch. Use the authenticated native CLI `opencode api get '/api/config?location%5Bdirectory%5D=<URL-encoded-absolute-project-root>'` when available, storing captures under local `.tmp`. This returns a top-level source-entry array, not a post-plugin effective-config envelope: verify types, identify the exact project document and `info.experimental.subagent_depth`, and inspect higher-precedence discovered settings under https://opencode.ai/v2/docs/config. Combine the winning configured value with the current runtime nesting level/tool capability; missing evidence is uncertainty, not proof of remaining capacity. The shipped package sets depth at least 3 only when used as a project; plugin installation does not merge it into a consuming project. Do not mutate host/global configuration or raise depth to bypass a limit. Distinguish actual nesting/depth errors from temporary active-agent capacity, permission denial, model-argument rejection and missing tool; never retry denials or evade depth through shell/another harness.

Bind a concrete provider/model route before egress. Disclose recipient, requested model/effort, and that reviewed code leaves the machine (record in run audit rather than user prose in mode:agent). This is notice, not extra confirmation, within actual permissions. Call it independent only when host and served peer families are attested different; a request is never proof of the served model. A route failure never silently switches recipients.

## Dispatch and collect

Before local dispatch, write private run files under `<absolute-workspace-root>/.tmp/rocketclaw/ce-code-review/<run-id>/`: `adversarial-review-constraints.md` holds host-vetted applicable criteria, max 32 KiB (`none` when absent), and `adversarial-review-brief.md` holds untrusted intent, 2–8 material risk divisions (one on a simple change), representative paths, generated-repetition coverage and cross-division interactions, max 32 KiB. Never combine trusted constraints with review data or copy raw user text into constraints. Stage exact `full.diff` and `files.txt`; large diffs are read selectively by path, never truncated or mechanically sharded.

Launch the fixed native read-only reviewer, persist its launch receipt, scope, route and start epoch, then collect with native bounded in-turn result delivery. A start acknowledgement is not lens coverage or a final result. The peer may overlap local reviewers only when native dispatch provides a reliable bounded collector. Otherwise collect it before the local batch; do not detach shell work or poll jobs. Idle bound is 480 seconds; shared hard budget is `CROSS_MODEL_HARD_SECS` (default 1200 seconds), with collection deadline budget +10. Never let a short native wait truncate the aggregate budget, or begin a wait past the remaining deadline. Stop/release outstanding native work before returning, including on finish failure. No persisted process may be abandoned.

Only after successful peer launch remove the local adversarial persona from the initial roster. A failed launch leaves it as fallback under `cross-model-recovery.md`; a later no-review outcome may restore it. Never run two usable adversarial reviews on the same brief. A fallback always obeys the delegation/model/depth rules above.

## Normalize, attest, and fold once

Validate a terminal artifact before fold-in; save `<run-dir>/adversarial-<provider>.json`, force `reviewer` to that value and downgrade peer `safe_auto` to `gated_auto`. Read only bounded, non-symlink files owned by this run; reject uncertain ownership or malformed schema. Keep receipt fields `cross_model_route`, `cross_model_target`, `cross_model_harness` (`opencode`), `model_requested`, `effort_requested`, `receipt_supported`, `model_actual`, `effort_actual`, and `independence_verified`. Derive actual identity from native runtime evidence, never the requested model or persona label. Missing identity is literally `unverified`; only an attested different serving family sets `independence_verified: true`.

Findings are attributed evidence even when identity is unverified. Agreement promotes only when `independence_verified: true`; same-model or inline fallback agreement never promotes. Preserve receipt fields and unmet requirements in Coverage and `finish-input.json`. Empty findings in a valid artifact means no additional issues; a failed, denied, depth-limited, or malformed pass is not that outcome. Cross-model failure is non-blocking for the full review but leaves cross-model coverage incomplete; focused review still requires its separately dispatched adversarial read or returns Not ready. Read recovery before selecting any replacement. Fold once, retain consumed findings/receipts for the report, and clean up only disposable run-owned peer scratch after terminal collection, never unrelated evidence or repository files.
