# Native JJ experiment isolation

This is a shell/tool procedure, not a helper-script API. Keep the spec's backend and model/security configuration authoritative; native tools implement that intent. Preserve all measurement protocols, paired comparisons, cache keys, receipts, recovery markers, and independent confirmation requirements.

## Establish and create

1. Detect existing harness isolation and session ownership before creating anything. Adopt supported existing isolation without renaming it, even if its name is nonconforming. Never reset, recreate, or clean it to make an experiment fit. Unsupported harness naming or colocation is a compatibility blocker.
2. Resolve the absolute source workspace root and verify the exact base revision with `jj log` there. Record its full commit ID and history head in the run ledger. Reject missing or ambiguous bases rather than substituting another ref.
3. For new isolation use `ce-worktree`'s native procedure. Capture YYYYMMDD once per run and persist it across resume, retries, and midnight. Choose one `YYYYMMDD-optimize-<spec>-exp-<NNN>` identity for both registered name and destination basename. Normalize an already dated caller without adding a second date. Check both `jj workspace list` registrations and filesystem collisions; choose `-2`, `-3`, etc. only for a new identity, then persist it. A retry verifies the recorded registration, path, base, and ownership; it never resets an existing workspace. Preserve source/PR bookmarks.
4. Create only an absolute destination under the source workspace's local `.tmp/`, with basename equal to the persisted `$identity` selected above. From the absolute source root run `jj workspace add --colocate --name "$identity" --revision "$verified_base" "$absolute_destination"`. From the new absolute root run `jj git colocation status` and verify colocation before dispatch. Failure blocks the experiment without forced cleanup.
5. Record exact name, path, run owner, session, base, and disposable status outside the destination. Copy configured shared files only after containment and symlink checks; preserve relative layout, never overwrite unrelated files. Keep ignored databases and other shared resources in the evidence inventory. Apply configured port/environment parameterization. Count registered workspaces plus active owned destinations for the budget rather than inferring membership from directory names.

## Integrate without destructive resets

Describe and retain the candidate's mutable-scope changes as an identified JJ revision, excluding `result.yaml` and scratch. Compose descriptions using SKILL.md's runtime standards. Keep the exact candidate and baseline IDs in the ledger. For a winner use native JJ merge/rebase operations from the optimization workspace; for a runner-up apply its identified change with `jj rebase` onto the verified new baseline in disposable isolation, resolving no conflict silently. Preserve the pre-integration baseline and candidate recovery references. Measure the combined snapshot independently as the loop requires. If combination fails, restore the optimization bookmark to its verified pre-combination revision without discarding unrelated working-copy changes; retain the rejected candidate/evidence. Never use hard resets or broad clean operations. Remote transport uses `jj git fetch` / authorized `jj git push`, exact refs, `jj file show`, and `jj diff`; validate the remote result topology and mutable scope exactly as in the loop. Do not substitute missing refs or push without existing authorization.

## Retire only verified disposable isolation

Completion is not removal authorization. Stop workers and ensure no pending receipt references the target. Leave the target directory and move any active session to a surviving absolute workspace root using native session controls. Verify exact registration/name/path/run ownership and explicit disposable authorization. For kept work, verify integration and preserve baseline, best, archive, and recovery references. Copy results, raw measurements, logs, and recovery markers outside the target, read them back, and record their destinations before removal.

Inspect `jj status`, conflicts, diffs, and a separate inventory of ignored/untracked content including copied databases. Do not infer safety from clean JJ status: ignored data still matters. Preserve any unrelated, ambiguous, dirty, conflicted, non-disposable, or session-owned content and report the blocker. Once every safeguard passes, from the surviving absolute workspace root run `jj workspace remove "$verified_name"`. Verify BOTH deregistration with `jj workspace list` and actual directory disappearance. Warnings or incomplete removal retain state and require a report, never force deletion, filesystem cleanup, or fallback to forget. `jj workspace forget` is only for explicit unregister-and-preserve-files requests. Bookmark deletion is a separate authorized action; never delete best/archive/recovery refs as part of retirement.

Removal snapshots working-copy state, but ignored files and files left untracked are not protected by that snapshot. Copy/read back any required or still-referenced contents first; retain the workspace when disposability is uncertain.
