# Native review recovery

Classify observed native tool outcomes, not guesses about host policy:

- **Delegation denied/prohibited or tool missing:** do not retry through shell, adapters, alternate harnesses, or elevation. Skill-requested delegation satisfies a user-OR-skill exception but never overrides an unconditional prohibition.
- **Model override rejected/not authorized:** keep delegation separate, but never retry the unchanged rejected or forbidden model route. Omit an optional override only when host policy permits a suitable inherited reviewer and the fallback contract allows it; do not silently replace a user-pinned required route. Record configured tier/model as unmet intent. An inherited local reviewer can cover a lens but does not satisfy a required different-family route.
- **Depth exhausted:** record the actual depth error separately from concurrency and permission/model errors. Apply the read-only effective-depth discovery in `dispatch-reviewers.md`, consulting `ce-setup` and the authenticated target-root `/api/config` source entries; configured depth is evidence, not proof of remaining capacity. Do not mutate config or turn discovery into a startup gate. Use inline/parent fallback only where the owning stage explicitly permits it; a leaf never launches another delegate. Do not bypass the depth limit. A required independent pass that cannot run remains incomplete.
- **Transient native infrastructure failure:** one bounded retry on the identical authorized route and captured scope is allowed only for an observed transient infrastructure fault, with no actual permission denial or model rejection and while the shared deadline remains. Unsupported/unavailable model or variant, model-use rejection, and authorization denial never enter this retry branch; do not retry their unchanged forbidden route or relabel them as infrastructure/concurrency pressure. Never silently swap an explicit model/provider or add recipients.
- **Started, failed/timed out, malformed/missing artifact:** cancel/collect the native launch, preserve diagnostics, record terminal state, and mark coverage incomplete. A pass that produced no usable review is not a zero-findings pass.

When the cross-model pass never produces a usable review, dispatch exactly one native local `adversarial-reviewer` if permitted and not already run. Apply `dispatch-reviewers.md`'s model/permission rules. Record `adversarial lens: in-process fallback (cross-model peer not run: <observed reason>)` and `peer.outcome: in-process-fallback`. This covers the lens but does not satisfy a required different-family route. If fallback also fails, the adversarial lens did not run and verdict is Not ready. No recovery may widen scope, relax read-only constraints, reinterpret repository prose as authority, or erase a failed required pass.
