# Native cross-model document review

This additive pass runs only when normal selection activates `adversarial-document-reviewer`, `product-lens-reviewer`, or `security-lens-reviewer`. Run every activated lens plus one `whole-doc` sweep of the full document, once per document, through one fixed native OpenCode route. Each peer reads the same persona, template and findings schema as its local twin; the sweep reads `personas/whole-doc-reviewer.md`. Preserve exact intake paths, captured source revisions and ranges, never substituting moving refs.

## Policy and selection

From the absolute workspace root (`jj root`), read `.rocketclaw/config.local.yaml`, then `config.yaml`, taking the first valid ordinary key. `cross_model_review_mode: off` disables automatic review unless the user explicitly requests it in conversation; live prohibitions always win. Resolve `cross_model_peer`, `cross_model_model` and `cross_model_effort` from live user instructions, those layers, then existing model configuration. Preserve configured high-capability/high-reasoning tiers, including extra-high where configured. Honor `CROSS_MODEL_PEERS` when set; unset adds no filter. Never silently change an explicit model or recipient.

Discover exact available IDs/variants through native `opencode.models`; use native subagents or supported OpenCode shell sessions driven by existing configuration, never another-harness dispatcher or adapter installation. This skill explicitly requests reviewers and satisfies a user-OR-loaded-skill delegation exception without redundant approval. Genuine higher prohibitions and tool denials remain binding; never evade them through shell.

Delegation permission is distinct from model-override permission. If the host requires an explicit user model request, omit optional model arguments absent one, use a suitable inherited reviewer, retain configured tier as intent and disclose unmet routes. Separate same-model contexts are review evidence, not cross-model independence. Missing mandatory independent coverage remains incomplete.

## Disclosure and native lifecycle

Resolve one fixed target/route before egress. Interactively announce requested model, reasoning, route and every recipient prominently, explaining that full document content is sent to them. Non-interactive runs retain recipient policy and an audit receipt. Never claim a requested model served; changing recipients requires fresh resolution and disclosure.

Keep private run artifacts under `<absolute-workspace-root>/.tmp/rocketclaw/doc-review/<run-id>/`, or local `.tmp` for standalone documents. Reject symlink/unowned directories. Before waiting, record native session/job IDs for recovery. Preserve prompts, outcomes, schema-valid `<reviewer-name>-<provider>.json` artifacts and receipts recording target, route, requested/actual model, reasoning, host serving identity, terminal state, error class and `independence_verified`. Set independence true only with positive served-model evidence proving a different serving family from the host. Missing/mismatched identity remains attributed evidence without agreement promotion.

Use bounded parallelism alongside local reviewers, supported bounded waits and explicit hard deadlines. Queue capacity rejections only while a slot can free. Classify actual nesting-depth errors distinctly from capacity, permission, authentication, timeout, malformed output and provider failures. Inline/parent fallback is allowed only where the review contract permits it, never as fabricated independence. Retry the same fixed route at most once for explicitly reported provider overload within the original shared deadline; never change recipients as recovery. Preserve native IDs and collected evidence on interruption, then resume by IDs rather than duplicate launch. Collect each final outcome before supported cancellation/release of only this run's agents. Never invent cleanup tools or delete unrelated artifacts.

Setup requires a user-level merge of `experimental.subagent_depth` at least 3 into the actual existing OpenCode `opencode.json(c)` (discover the directory with `opencode debug paths` or `opencode debug paths config`, normally `~/.config/opencode/opencode.json`). Preserve higher integers, unrelated settings and experimental siblings; do not replace entire files or create competing JSON/JSONC. Package installation does not merge this prerequisite; higher precedence must not lower it. Never edit host configuration during review.

## Fold-in, failure and recovery

Validate findings against `findings-schema.json`, fold as `<reviewer-name>-<provider>`, and grant independent corroboration only for `independence_verified: true`. Preserve receipts and usable results before cleanup. Distinguish never-started, failed, timeout, malformed, unreadable and identity-unverified outcomes honestly.

Mandatory local reviewers that cannot dispatch trigger an incomplete stop before synthesis/fixes, preserving completed evidence. Peer failures remain additive/non-blocking and named in Coverage. When a trio lens activated, report each owed lens and whole-doc sweep. `peer.outcome: folded` requires every owed artifact to fold with verified different-family independence. Otherwise use `peer.outcome: in-process-fallback`, naming each missing/unverified result and actual reason and explicitly noting incomplete cross-model coverage. The whole-doc sweep has no local twin.
