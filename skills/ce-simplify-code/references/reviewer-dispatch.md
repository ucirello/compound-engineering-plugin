# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers what happens when the harness is full, how review agents are released, and the permission mode.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. Inspect effective nesting depth through supported configuration discovery; classify actual errors separately as depth/capacity, permission denial, model rejection, or missing tool. When a dispatch cannot recover through active work, supported release, or a corrected invocation, run that pass inline using the same prompt asset only if the caller's review contract permits it, and disclose the substitution. Never claim missing independent coverage complete or evade a denied or depth-limited operation through another harness or shell.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.

This skill's explicit reviewer dispatch authorizes native subagents under a user-or-applicable-skill delegation policy without a second approval. Loading an unrelated skill is not authorization. Unconditional prohibitions and tool denials still apply. Model override permission is separate from delegation permission and actual nesting capacity; when an override requires a user model request that is absent, omit the optional model argument and disclose an unmet configured tier.

For setup, document that deep delegation requires merging `experimental.subagent_depth` of at least `3` into the existing OpenCode user configuration. Discover the actual config directory with `opencode debug paths` / `opencode debug paths config`; update the existing `opencode.json` or `opencode.jsonc`, preserving sibling fields and any higher integer. Do not create a competing config or replace the whole file. Package-local configuration or plugin installation alone does not enable this, and higher-precedence configuration must not lower the depth. Never modify the host configuration automatically.
