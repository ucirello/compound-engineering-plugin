# Cross-Model Execution Contract

Read after engine selection or before recovering an existing run. The OpenCode host owns scheduling, integration, verification, descriptions, recovery and shipping; use `opencode.models`, native `subagents` and `shell`, never another harness dispatcher or a workspace bridge script.

## Resolve and authorize one fixed recipient

Resolve live intent, typed bindings and `.rocketclaw/config.local.yaml` / `config.yaml` under `execution-engines.md`, preserving ordered choices, model pins and `work_engine_effort` tiers. Compatibility target values remain `codex`, `claude`, `grok`, `cursor`, `composer`, `opencode`; legacy route values remain `codex`, `claude`, `grok-cli`, `cursor`, `composer`, `grok-cursor`, `opencode`. These values express requested identity, not permission to launch those harnesses. Query `opencode.models` for the configured provider/model and supported variants. Native execution must faithfully satisfy the requested model, tier and restrictions; a harness-specific requirement not enforceable natively makes the route unavailable. Never silently substitute a model, provider or tier. Preserve provider references and disclose compatible aliases. Keep target, requested harness/intermediaries, actual OpenCode route, requested model, served model and receipt status separate; unverified served identity or effort remains `unverified`.

Preflight ordered candidates without sending repository content. Skip equivalent current-model candidates or proven unavailable candidates and record reasons; lock the first qualified recipient before dispatch. `prefer` and `require` both disclose an unavailable route once and continue on the current session model when no qualified candidate remains. `require` forbids unrequested external substitutions, not native fallback. Never elevate permissions to make a route reachable. After start, no recipient change or fallback is allowed while a job is live, unreachable, or successful but unreconciled.

Before egress durably record binding provenance, fixed recipient/provider/intermediaries, exposed material, inherited authority, enforceable versus cooperative restrictions, requested effort, and isolation limitations. JJ workspaces are not OS security sandboxes. A restriction the native tool cannot enforce makes the route unavailable.

## Durable source, packets and receipts

From the canonical workspace's absolute root, use `jj workspace root`, `jj status`, `jj diff`, and `jj log` to record repository identity, bookmark, base change/commit and pre-work state. All shell JJ commands run as `(cd "$workspace_root" && jj ...)`; `-R` alone does not set cwd. Repository-scoped GitHub commands run as `(cd "$workspace_root" && export GIT_DIR=$(jj git root); gh ...)`. Use https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace and https://docs.jj-vcs.dev/latest/git-command-table/; Git fallback is allowed only for an operation JJ cannot perform.

Store run state, packets, logs, error paths and fallback evidence in ignored local `.tmp/rocketclaw/ce-work/<run-id>/`; outside JJ use local `.tmp/`. Retain `CE_WORK_RUNS_ROOT` / `CE_PEER_JOBS_ROOT` compatibility only when they resolve to local `.tmp/`, otherwise report the invalid override. Ensure `.tmp/` is ignored. Preserve scalar safe run ids and reject unsafe or foreign-mode manifests.

Copy the selected source into private run state and hash it with SHA-256. A selected plan that is the sole pre-work change may receive a disclosed plan-only checkpoint; unrelated dirt is never checkpointed implicitly. Prompt-backed runs require a clean canonical state and a bounded brief with Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units. Use one conservative P1 unless evidence proves distinct units. Never include raw conversation, credentials or speculative scope. Missing goal, bounded scope or acceptance returns to clarification before dispatch.

For each attempt record run/unit/attempt ids, base, dependencies, wave id, packet path/digest, fixed recipient, restrictions and activity kind. A plan packet contains only Goal Capsule, DoD, active unit, relevant verification rows, cited R/F/AE/KTD excerpts and governing Product Contract decisions; prompt packets contain only the matching unit. Both include expected files, evidence strategy and exclusions. Workers may narrow but never broaden authority; no canonical commit, push, PR, shipping, peers, fallback or recipient switch. Do not permit workers to mutate JJ repository state. Host snapshots their complete output. Require their terminal result to conform to `references/implementation-result-schema.json`; validate all required fields and scope-expansion evidence before accepting completion. Socket binds, OS permissions and peer-credential probes remain host-owned: sandbox EPERM is not proof the host lacks a capability.

Receipts retain `implementation_engine_binding`, requested/actual routes and models, served identity status, requested effort and unverified served effort, fallback reason, source kind/digest, scalar `run_id`, `unit_receipts`, disclosed `plan_checkpoint`, blockers and recovery path. Per-unit receipts distinguish dispatch, live/terminal process state, scope inspection, integration, authoritative verification, canonical commit and cleanup. A tool result alone is not completion.

## Native serial protocol

1. Establish durable source and clean canonical snapshot, then record the engine lock. Cost or latency never unlocks the selected engine.
2. Create a controller-owned isolated JJ workspace using `jj workspace add <absolute-local-.tmp-path> -r <recorded-base>` from the absolute canonical root. Verify the worker base before edits. Ordinary synchronous native units remain in the active checkout; isolated cross-model workspaces are the exception, not general permission to create workspaces.
3. Dispatch one fixed-model native subagent with only its recorded packet and workspace. Use shell only for bounded commands, never another harness dispatcher. Record tool handle and actual available identity evidence. If callable model-pinned subagents are absent, record route unavailability rather than inventing a tool.
4. Observe without steering. Each host wait is at most 60 seconds; publish unit, route, elapsed time, last activity and terminal state between waits. Preserve a universal 7200-second hard cap; use a progress-resetting 600-second idle bound only for trustworthy incremental activity, otherwise disable idle timeout (`hard-only`). Silence alone is not failure. Explicitly terminate and confirm terminal/reaped status before fallback; retain evidence on loss of contact.
5. On authoritative completion, host snapshots the complete worker change and verifies recorded base parent and final tree. In a separate host call inspect `jj diff`, actual paths, binary/mode/rename/delete evidence, result schema, expected scope and expansion requests. Unexpected output blocks before integration; never trust reported paths alone.
6. Acquire a single durable canonical integration lock. Record pre-fold commit, complete tracked tree and expected applied paths/tree; reject unknown canonical movement. Apply only the accepted unit with native JJ operations (for example host `jj rebase` of the isolated change onto the accepted canonical base, then select the accepted result), inspecting conflicts before further mutation. Do not overwrite user work. Verify exact expected tree before proceeding.
7. Run authoritative verification with direct argv, or explicit `bash -o pipefail -c` for shell syntax. Capture exit status directly, disable Python bytecode, and retain logs. Any unexpected tracked-state mutation fails reconciliation. Inventory ignored entries by metadata before/after and report created/changed/removed counts with bounded samples; never copy, restore or delete ignored caches, databases or secrets. Ignored-state divergence is disclosure, not a clean-state proof.
8. Only after scope, verification and reconciliation pass, compose the description under `implementation-loop.md` and record the host-only canonical commit. Verify its parent/tree and record it before cleanup and lock release. Transport changes never count as canonical completion by themselves.
9. On failed apply, verification or pre-commit step, forbid commit and restore only host-attributed integration to the exact pre-fold snapshot. Use guarded JJ operation recovery only if no unrelated operation intervened; otherwise preserve state and block. Prove exact tracked equality before lock release, retry, sibling or fallback. Never rewind shared user/worker operations. Failed proof retains lock, workspace, transport change and recovery path. A crash after commit reconciles evidence instead of redispatching.
10. After all units finish, execute source-wide Verification Contract checks from a clean recorded canonical snapshot, capturing each exit and durable receipt. Restore only check-attributed tracked changes, prove equality, disclose ignored-state divergence. A failing check retains logs and blocks completion even if cleanup succeeded.

Report every transition, including restoration, blocker and recovery path, directly or in the structured return.

## Parallel waves

Use only proven-independent ready units: check dependencies, actual/declared files, shared interfaces, migrations, lockfiles, generated/registry/config files, environment singletons and merge cost. Uncertainty selects serial. Cap at 3–5 workers, each isolated at one recorded clean wave base. Dispatch all ready native calls concurrently. Workers cannot schedule peers or broaden dependencies.

Require all workers terminal and all complete output inventories inspected before the first fold. Same-path or semantic contention stops the wave. Integrate sequentially in dependency order under the lock, verifying and committing each result separately. Record each exact host-owned advancing commit and revalidate remaining siblings against it; clean textual application is not semantic compatibility. Unknown movement blocks. Failure requires exact restoration and lock release before any sibling proceeds. Affected dependents stay queued; unaffected siblings may continue only after readiness is recomputed. Repeated collision, broad edits or unprovable recovery disables waves while preserving every inspectable result.

## Recovery and exactly-once fallback

An explicit validated run id is authoritative. Otherwise discover only one unfinished plan run matching repository, bookmark and source digest; never choose by listing the shared root. Ambiguous matches block with ids/recovery paths. Prompt runs require their disclosed id. Resume never dispatches, selects another route, re-applies, recommits or runs either shipping tail. It may adopt exactly one matching unbound native handle, observe live work, snapshot terminal output, continue guarded recovery, or reconcile an already-created canonical commit by exact parent/tree evidence. Unknown dirt blocks without destructive restoration.

A completed run with all units terminal and a successful source-wide receipt is observation-only: return stored evidence without rerunning commands. Missing required receipts are blockers. Cleanup is idempotent and requires confirmed integration; abandonment requires the exact transport change or failed/reaped handle. A corrected retry retains the scalar run id and earlier receipts, uses a fresh attempt id and cannot change recorded dependency/base contracts.

Before fallback atomically record one durable claim only after authoritative failure/timeout/reap and exact restoration plus lock release when integration began. Live or successful unreconciled output refuses the claim. An existing claim forbids duplicate implementation. Both `prefer` and `require` permit exactly one fallback on the current session model; record accepted canonical commit, SHA-256 of verification evidence and summary on completion. No run is complete until every unit is terminal and successful source-wide verification is durably recorded.

## Tail ownership

Standalone resumes the quality/shipping workflow only after implementation gates. Return-to-caller emits implementation and verification receipts with `standalone_shipping_skipped: true`, never the caller's simplify/review/PR/CI tail. Workers inherit neither tail.
