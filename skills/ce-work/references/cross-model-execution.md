# Native routed implementation contract

Read this after execution-engines selects a configured or requested route, and during recovery. OpenCode native subagents replace the former controller, detached runner, and harness adapters; never launch another harness to bypass permissions.

## Resolve and record before dispatch

Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `.rocketclaw/config.yaml`. Modes remain `off | prefer | require`; a present local list/map (including empty) replaces that key. Preserve candidate order, harness/provider/model pins and requested effort. Live narrower intent and typed binding provenance outrank standing defaults. Harness compatibility values `codex | claude | grok | cursor | opencode | antigravity | pi` remain intent, not authorization to run external CLIs. Never invent aliases or substitute a pinned model.

Use `opencode.models` to discover exact available model IDs, then native subagents. Model permission is separate from delegation permission: if the host requires an explicit user model request, omit the optional model argument unless that request exists. Record configured intent and any unmet route/effort/independence requirement. An inherited same-model worker is not cross-model. A required unavailable route remains disclosed as unavailable; native fallback is permitted only within inherited authority and the caller's contract, never reported as satisfying missing independence. A host prohibition or denied operation is not permission to try another harness or retry the denial. Classify actual depth, permission, model, and tool errors separately. Capacity limits may queue work; they do not prove model unavailability.

Before content crosses to a worker, persist a receipt under `<absolute-workspace-root>/.tmp/rocketclaw/ce-work/<run-id>/`: binding mode/target/model/source; requested and actual route, provider/intermediaries/model/effort; identity verification status; fallback reason; source kind and SHA-256; verified history/base commit; unit/attempt/dependency/wave identities; packet digest; workspace identity; dispatch/session ID; progress, terminal outcome, integration, authoritative checks, host commit and cleanup receipts; blockers and recovery path. Never claim an unverified served identity. Isolation is not an OS sandbox. A restriction that cannot be enforced must be disclosed; if enforcement is required, block before dispatch.

## Workspace and source lifecycle

Detect existing isolation first and preserve its name. Prefer harness-owned isolation and session adoption; unsupported required naming or colocation is a compatibility blocker, not a reason to bypass lifecycle. Explicit creation runs from the surviving absolute source root: `jj workspace add --colocate --name <dated-identity> --revision <verified-base> <absolute-destination>`. Run `jj git colocation status` with cwd equal to the created absolute root before writing. All destinations and scratch are under the source workspace's absolute `.tmp/rocketclaw` tree. Capture one local YYYYMMDD once and persist it with a meaningful task/PR/revision kebab slug. Caller names obey the same normalization without duplicate date prefixes. Registration and destination basename share that identity. Check both registrations and disk destinations, allocating `-2`, `-3` collisions. Reuse the captured identity across retries/resumes and midnight; no PID/random/timestamp names. Preserve existing isolation and source/PR bookmark names.

For a plan retain its exact digest and bounded cited sections. A selected plan that is the sole dirty path may receive a disclosed host-owned plan-only checkpoint; unrelated dirt must never be checkpointed. Prompt work needs a concrete goal, bounded scope, acceptance checks, exclusions and conservative units; otherwise return to clarification. Persist its brief under local scratch, not OS temp. Packets contain only the active unit, relevant goal/requirements/decisions/verification, prototype citations, matched pack rules and inherited exclusions; no raw conversation, credentials or unrelated plan sections. Record packet bytes and digest before dispatch. Native workers may edit/test their assigned workspace only, never commit, push, ship, change recipients or schedule peers.

## Bounded execution and integration

Use one native author per bounded unit and one writer per file. After dispatch, lock the recorded route: latency or convenience does not authorize duplicate/native implementation. Observe in separate calls, with waits bounded to 60 seconds where supported. Preserve a 7200-second hard cap and a 600-second progress-reset idle window only when actual progress is observable; otherwise disable idle timeout and disclose hard-only observation. Never infer death from silence or loss of contact. Stop/reap through native lifecycle and retain evidence before retry or fallback.

On authoritative terminal success, inspect complete `jj status` and exact base-to-worker-head `jj diff --from <base> --to <head> --git`, including untracked, ignored, conflicts, binaries, modes, renames and deletions. Reported paths are only hints. Capture exact final revision and preserve recovery refs; unexpected scope or unexplained generated artifacts block integration. Never label partial output complete.

Integrate in a separate host step under a recorded exclusive integration lease. Record canonical pre-fold revision, complete owned path inventory and recovery refs, then apply only accepted unit changes using JJ. Run authoritative checks with cwd equal to the canonical absolute root, preserving real exit status and full local logs. Shell syntax needs an explicit shell with pipe-failure handling; never hide check failure behind another command. Reconcile exact tracked state and conflicts; inventory ignored/untracked created/changed/removed entries separately. Snapshots do not protect ignored files, secrets or local databases. Do not silently restore/delete those entries. Failed verification forbids a host commit; restore only owned tracked changes to the recorded pre-fold state, prove equality, and retain lock/evidence on uncertainty. Compose the full message under implementation-loop standards and commit only owned paths; persist accepted commit before releasing the lease. A crash after that commit is reconciled, not redispatched.

Parallel waves require the full execution-strategy independence check, one recorded wave base, disjoint ownership and at most 3–5 workers. Terminalize and inspect every member before any integration. Fold sequentially in dependency order, checking semantic compatibility and authoritative verification against each advancing canonical head. Only exact earlier accepted host commits may advance later siblings. Collision, unexpected head movement or failure stops affected dependents; preserve unaffected outputs, restore exactly before another fold, and disable further waves on repeated contention.

## Recovery, fallback and cleanup

Recovery is observation-first: require the supplied run ID, or exactly one plan-digest/repository/bookmark-matching unfinished receipt. Never guess by listing arbitrary state. Ambiguous, unsafe or foreign receipts block. Reconcile recorded native sessions and exact revision evidence without redispatching, rerunning completed checks, recommitting or entering either shipping tail. A missing receipt is a blocker. Retry gets a fresh attempt under the same run ID and fixed unit/dependency contract. Permit at most one recorded native fallback only after authoritative failure/reap, exact restoration and lease release. A live or successful unreconciled attempt blocks fallback. Denied operations must not be retried. Persist fallback completion and required source-wide check receipts; missing or failing checks keep completion blocked.

Destructive cleanup is separate from bookmark deletion. Stop workers, leave the target and move/adopt the harness session to the surviving absolute root first. Verify exact registered name/path, ownership, explicit disposal authorization, integration and recovery refs. Copy and read back evidence outside the target. Inspect tracked/conflicted/ignored/untracked data; never delete unrelated, ambiguous, referenced or non-disposable data. From the surviving root use `jj workspace remove <verified-name>`, never forget plus file deletion. Verify both deregistration and disappearance. Any warning/failure preserves state and recovery path; never force-delete or use a Git fallback. `jj workspace forget` is only unregister-and-preserve-files. Preserve best/archive/recovery bookmarks; deleting another bookmark needs separate authorization.

After every unit, require source-wide verification with durable exit-status receipts. Completed recovery reuses those receipts and never reruns tests merely to reconfirm them. Standalone resumes shipping-workflow only after complete implementation; return-to-caller emits its full result with `standalone_shipping_skipped: true`. Workers inherit neither tail.
