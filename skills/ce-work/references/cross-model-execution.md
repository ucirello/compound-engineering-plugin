# Native cross-model implementation and durable recovery

Use OpenCode's native subagents, never another harness CLI or a dispatch/workspace bridge. `config.yaml`, `config.local.yaml`, and the documented example schema remain authoritative for ordered `work_engine_preferences`, `work_engine_mode` (`off | prefer | require`), model pins, and `work_engine_effort`. Historical harness/provider labels express routing intent, not permission to invoke those harnesses. Resolve exact available model identities with `opencode.models`; preserve an exact pin or report it unavailable. Do not silently substitute a family, tier, effort, or provider. Keep requested route/model and actually observed route/model separate; absent trustworthy served-model evidence, record `unverified`.

## Permission, model selection, and depth

This skill's explicit implementation/reviewer dispatch instructions authorize native delegation under a user-OR-applicable-skill delegation policy. Loading an unrelated skill does not. Unconditional prohibitions and denied tools win: never evade them through shell, another harness, or a parent relaunch. If model override is forbidden without an explicit user model request, omit the optional model argument, use a suitable inherited model when the contract permits, and disclose the unmet configured tier. Same-model execution is not cross-model independence. A required unavailable cross-model route is incomplete, not successful fallback.

Discover effective configuration and actual nesting depth through supported OpenCode configuration discovery. Classify errors separately as permission, missing tool, model rejection, or actual depth/capacity. Correct a pre-launch argument error once; queue capacity-limited work. Inline/parent fallback is allowed only by the implementation or review contract, never as a way around denial or depth. A required independent review cannot be replaced by the author's inline review.

For setup, users must merge `experimental.subagent_depth` >= 3 into their existing `~/.config/opencode/opencode.json` or existing JSONC equivalent. Discover the actual configuration directory using `opencode debug paths` / `opencode debug paths config`; preserve unrelated fields, sibling experimental settings, and higher integer values. Do not create a competing file or replace the document. Plugin installation or shipped package configuration alone does not enable deep delegation, and higher-precedence configuration must not lower the value. Document this requirement; never modify host configuration automatically.

## Native transaction and receipts

Before dispatch, create a private durable run directory under the canonical workspace's `.tmp/rocketclaw/work/<safe-run-id>/`. A safe id matches `^[A-Za-z0-9._-]{1,128}$` with a non-period character. Refuse ambiguous existing state. Copy and read back the source plan or bounded prompt brief, compute SHA-256, and persist source kind/digest, repository identity, absolute canonical root, verified base commit ID, bookmark, pre-work tracked/conflicted/untracked/ignored inventories, exclusions, binding provenance, requested restrictions, route/model/effort, and chosen workspace identity. Record any plan-only checkpoint explicitly; unrelated dirt is not eligible for checkpointing.

Persist each transition before the next action. Keep an append-only attempt history with run/unit/attempt IDs; dependency and wave/base contracts; packet path/digest; exact worker handle; observed status/activity; requested and actual model; authorization and enforcement limits; actual changed paths; transport/recovery bookmark; integration lock and pre-integration commit/tree; authoritative verification command, exit code and evidence digest; canonical commit ID; cleanup status; and recovery path. Read back receipts after writing. A worker statement or process exit is not integration, verification, model-identity, or cleanup evidence.

1. Prepare the bounded packet described in `execution-strategy.md`, including matched pack rules, expected files, exclusions, prototype citations, evidence strategy, inherited restrictions, and the worker result schema. Never send the whole conversation or unrelated secrets. Record its digest before sending it.
2. Initialize the native worker exactly once with the pinned route and verified base. A started attempt locks the unit's authoring route; latency is not unavailability. The worker may author only its assigned files, cannot publish or make canonical changes, and must report its verification evidence. Record the handle immediately. Observe with native status/wait tools, publishing progress between bounded waits (at most 60 seconds). Use a 7200-second hard bound and a 600-second progress-idle bound only when trustworthy incremental activity is available; absence of activity without that capability does not imply failure.
3. On completion, inspect the complete actual workspace delta from the captured base, including binary, uncounted, rename/delete, executable-mode, ignored and untracked changes. Compare to the packet and worker evidence; unexplained scope blocks integration. Pin recoverable output with a recovery bookmark before applying anything. Only the orchestrator integrates.
4. Acquire one durable integration lock; capture exact pre-integration state. In the canonical absolute root, use JJ-native integration of the inspected revision (`jj rebase` onto the verified advancing base, then `jj new` from the accepted result as appropriate). Do not mutate another active workspace's working-copy commit. Resolve conflicts explicitly or stop. Review the actual delta, run authoritative unit checks, capture the exact exit status, and reconcile tracked/conflicted state against the expected integrated tree. Inventory ignored/untracked changes separately: snapshots do not protect them. Verification-created caches remain disclosed, never silently deleted.
5. Compose the canonical description under `implementation-loop.md`, record the exact accepted commit ID and evidence digest, and release the lock only after durable reconciliation. Failure before commit prohibits committing; preserve the pre-integration revision and output. Restore only attributable integration changes with JJ-native operations after proving they contain no user changes. If exact restoration cannot be proven, retain the lock, recovery bookmarks, workspace and receipts and return blocked. A crash after commit is reconciled from recorded commit evidence, never redispatched.
6. Run source-wide Verification Contract gates after unit integration from the captured clean canonical state. Capture exit codes and logs, reconcile tracked state and disclose ignored/untracked divergence, then persist a successful source-wide receipt. Required checks failing blocks completion even if cleanup succeeded.

## Waves, fallback, and recovery

Independent waves follow `execution-strategy.md`; isolated members share one recorded base and exclusive ownership. Integrate in dependency order under the lock, recording each accepted canonical revision as an allowed earlier wave result. Revalidate every remaining output against the advancing base; conflict-free application alone is not compatibility. Retire each handle after its unit, never reuse it for a new unit.

Recovery runs before normal triage. With an explicit run id, read and verify its durable record, repository/source identity, native handle, workspace and receipts; never choose another route or launch fresh work. Plan-based discovery may select only one unfinished exact repository/bookmark/source-digest match. Ambiguity, unsafe state or missing evidence blocks; prompt runs require their disclosed id. Completed recovery is read-only reconciliation of stored unit and source-wide receipts: no test/build/generation rerun or shipping tail.

Loss of contact does not prove termination. Stop/reap only through supported native lifecycle tools and preserve output. After authoritative terminal failure and proven exact restoration plus lock release, record one atomic fallback claim before an allowed `prefer` inline fallback. Never fall back while an attempt is live or successful output is unreconciled. `require` model/independence constraints remain blockers when unavailable. Record fallback completion and verification exactly once; retries retain the scalar run id, use fresh attempt IDs, preserve old receipts, and cannot change recorded dependency/base contracts without renewed planning authority.

Cleanup uses the safe workspace lifecycle in `workspace-setup.md`. Completion alone is not deletion authority. Preserve recovery references and receipts outside the target before removal. Return to the correct standalone or caller-owned tail only after verified integration and source-wide receipts; recovery itself never enters either tail.
