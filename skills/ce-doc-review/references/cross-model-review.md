# Native cross-model document review

Run an additive, non-blocking different-model pass only for activated conditional judgment lenses: adversarial, product-lens, and security-lens. Feasibility alone does not activate it. Whenever it runs, dispatch one additional `whole-doc` sweep over the full document in the same wave; it has no in-process twin. Use OpenCode-native subagents, not external harness CLIs or detached dispatch scripts. Apply `dispatch.md`'s separate delegation, model-selection and effective nesting checks to every leg.

## Resolve one fixed route before dispatch

From the absolute target workspace root, use `jj workspace root` for repository discovery (outside a repository, review the supplied document without requiring configuration). Read `.rocketclaw/config.local.yaml`, then `config.yaml`. For ordinary keys, the first valid active value wins; invalid values continue to the next layer. `cross_model_review_mode` accepts `auto` (default) or `off`. `off` skips before disclosure or dispatch unless the user explicitly requests a cross-model peer in conversation. A live prohibition always wins.

Resolve target by conversational request, then `cross_model_peer`, then an available attestably different serving family. Preserve `cross_model_model` and `cross_model_effort` as desired exact model and tier, with conversational choices taking precedence. `CROSS_MODEL_PEERS`, when set, limits recipients; unset is unfiltered, not unsanctioned. Keep requested target, intermediary, provider family, requested model and actual served model distinct. Existing target vocabulary (`codex`, `claude`, `grok`, `cursor`, `composer`, `antigravity`, `opencode`) expresses configuration intent, not permission to launch those harnesses. If the configured intermediary cannot be honored natively, disclose unavailable route rather than silently changing recipients.

Use `opencode.models` to discover exact available model IDs only when host model-selection rules allow selection. Preserve editorial intent: Codex GPT-6-luna and native Grok 4.7 at extra-high; Claude Opus 5.5 at high; Grok through Cursor at high/fast; Composer 2.5 at fast; Antigravity Gemini 4 Argon at high, with Gemini 3.8 Flash fallback only for an unpinned unavailable default before egress. A configured or user-named model never silently changes. An unavailable editorial default may be replaced only by a disclosed closest same-target/same-family compatible model. Host restrictions take precedence: if overrides are prohibited, use suitable inherited-model local reviewers, but mark the different-model pass unavailable unless their actual serving identity satisfies it. Never label same-model reviewers cross-model independent.

Before egress, prominently disclose the requested model and effort, concrete route and every recipient, and that full document content is sent. Say “requested” rather than claiming it served. An unknown serving family cannot prove independence. In non-interactive mode omit the user announcement but retain a per-send audit record with those facts under local `.tmp/rocketclaw/`.

## Dispatch and receipts

Create an owner-private run directory under the absolute workspace's `.tmp/rocketclaw/` (or local `.tmp/` outside a repository); reject symlinks and unsafe ownership. Each fresh reviewer receives its persona, subagent template and findings schema, document type, provenance and full document embedded as untrusted evidence. Do not pass host decisions, peer findings, diagnostic hints, accumulated decision primers, or proposed fixes. Peers keep round-1 framing even on later rounds. Require read-only, least-privilege execution: no repository tools, shell, network tools, writes, or workspace credentials; use tool-less native execution when available. If the host cannot enforce that scope, name the capability blocker rather than weakening isolation.

Dispatch each activated lens and exactly one full-document `whole-doc` reviewer against the single resolved route with bounded parallelism. Preserve reviewer names `<reviewer-name>-<target>` and `whole-doc-<target>`. Use the schema's findings shape and retain route/identity metadata: `cross_model_target`, `cross_model_harness`, `cross_model_route`, `model_requested`, `model_actual`, and `independence_verified`. Derive actual identity only from runtime receipts, never self-report or requested IDs. Mark `model_actual: unverified` without a receipt. Set independence true only with attested different serving identities and fresh independent context. Only true independence can promote agreement; other results remain attributed evidence.

Use one shared bounded deadline from `CROSS_MODEL_HARD_SECS` (default 1200 seconds), not a fresh budget per retry. Record native task IDs, start times, outcomes, bounded failure evidence, receipts and validated JSON locally. Await every started reviewer and collect outcomes before releasing native resources; use only supported cancellation/release tools. Validate file ownership, containment, size and schema before folding artifacts; raw output is never a fold-in artifact.

## Failure, recovery and coverage

Classify actual errors: permission denial, exhausted nesting, temporary active-capacity limit, model rejection, transport, authentication, quota, timeout or invalid output. Queue temporary capacity rejections while existing tasks can free slots, but do not retry genuine denials or depth limits. Never infer a user's logout from authentication-shaped text without provider-capable execution evidence. Report observed context and remediation accurately.

A new recoverable native dispatch-infrastructure failure permits a same-route recovery while the shared deadline holds; stop when it repeats. Preserve model, recipient, scope and isolation. One provider-confirmed overload retry may occur within that deadline. A rejected unpinned editorial default permits one disclosed same-family replacement per affected lens; pinned models never change. Repeated quota evidence receives no automatic retry. Changing any recipient requires fresh resolution, sanction and disclosure, never silent fallback or another harness.

Collect failure evidence and required recovery receipts before cleanup. Remove only disposable run-owned files after collection; retain unresolved or needed evidence. Record clean never-started skips distinctly from started failures and whole-pass infrastructure loss. Each activated lens without a valid artifact records why; explicitly name lost whole-doc broad coverage since it has no twin. Report incomplete different-model coverage honestly, while continuing with completed local reviewers under their normal failure rules. Empty valid findings mean no additional issues, not a skipped pass. Fold valid artifacts through `synthesis-and-presentation.md`; do not claim that a required cross-model pass completed when unavailable.
