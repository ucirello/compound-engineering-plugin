# Dispatch capabilities and coverage

Apply this contract before every launch: PR triage, persona reviewers, cross-model adversarial review, merge/report leaves, and the validator. This skill explicitly requests those subagents when their selection conditions hold.

1. **Delegation permission.** Read the host's actual rule. If it permits delegation when the user **or an applicable loaded skill** explicitly requests it, this skill's reviewer-dispatch instructions satisfy that exception: proceed without a second approval or a claim that the user did not ask. Loading an unrelated skill with no delegation instruction grants nothing. An unconditional higher-priority prohibition, missing tool, or actual permission denial still blocks dispatch. Never evade it through shell or another harness.
2. **Model-selection permission.** Delegation permission does not authorize a model override. Keep the selected/configured model and tier as intent. Use `opencode.models` to resolve permitted model requests to available exact IDs, not guessed aliases. If the host requires an explicit user model request before overriding, omit the native subagent's optional `model` argument unless that request exists; skill/config tier preferences alone do not qualify. Use a suitable inherited-model reviewer for ordinary personas and disclose unmet tier intent. A required different-model pass or fixed model route that cannot be met remains incomplete; an inherited-model reviewer cannot silently replace it.
3. **Depth and capacity.** Inspect the effective runtime configuration and current session depth before dispatch where exposed. The shipped project's `experimental.subagent_depth` default is not evidence of a consumer's effective setting or remaining depth. Do not launch a probe review during migration or assume permission implies capacity. At runtime classify actual tool errors: exhausted nesting depth, temporary concurrency capacity, permission denial, rejected model argument, and missing tool are different failures. Queue temporary capacity backpressure until active children finish; do not retry a depth/permission denial or escape it through another harness. Correct an invalid optional model argument only when the tool permits an inherited-model invocation, without retrying a denied action.
4. **Fallback and independence.** Use the inline/parent-coordinator fallback only where the relevant depth path permits it. Full-path leaf isolation and required validator/cross-model coverage are not silently waived: if those contexts cannot launch, return the mode's failure result or a clearly incomplete review rather than synthesizing a fully verified result in the dispatch context. Parent-context passes are not independent reviewers. Separate inherited-model children are separate reviewer passes, but not proof of cross-model independence; never use their agreement for cross-model promotion. Verify serving identity from runtime evidence, not the requested model or a self-claim.
5. **Collection.** Use OpenCode-native subagents, in concurrent bounded batches where supported, and await every terminal result in the current turn. Shell is for permitted inspection/validation, not another harness's dispatcher or a permission/depth workaround. Stop/release run-owned children through supported lifecycle tools before returning; preserve useful artifacts and name every missing required pass in Coverage. Never report unavailable cross-model coverage as completed.

All JJ inspection commands run with their working directory set to the target workspace's absolute root, for example `(cd "$workspace_root" && jj diff --from "$BASE" --to @)`. Repository-scoped GitHub CLI commands use `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. Store every temporary artifact, including error/fallback artifacts, under that workspace's ignored `.tmp/`; never fall back to OS temporary storage. See https://docs.jj-vcs.dev/latest/git-experts/ and https://docs.jj-vcs.dev/latest/cli-reference/ .
