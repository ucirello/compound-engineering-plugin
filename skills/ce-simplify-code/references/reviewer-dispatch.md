# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers the reviewers' model, what happens when the harness is full, how review agents are released, and the permission mode.

**Model selection.** Use `opencode.models` to resolve available models for the balanced mid-tier intent. Keep configured role models and tiers authoritative as desired behavior. Model-selection permission is separate from delegation permission: when the host requires an explicit user model request before overriding a model, omit the optional `model` argument unless that request exists. Otherwise inherit the parent model if it can meet the review requirements. Task wording alone does not select a model. Preserve intentional compatibility mappings: the balanced tier in Claude Code is the Sonnet class; Codex requires an explicit supported selector.

If the user's or project's active instructions or the live prompt name a model for this subagent, that is the desired route instead of the default tier above, subject to the host's model-selection permission. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier. Disclose unmet routes or tiers. Same-model reviewers remain separate reviewers, not cross-model independence; an unavailable required different-model pass is incomplete coverage.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Each reviewer starts in a fresh subagent whose context holds only its own rubric and inputs. The one exception is the combined reviewer that `references/single-pass.md` chooses below a size cutoff, which is itself one reviewer. Otherwise do not combine reviewers in one prompt, and do not send a reviewer to an agent that already ran another. Queue the reviewers and launch only as many as the harness accepts at once. When the harness is full, wait for a running reviewer to finish, release it, and launch the next. A full harness is not a reason to run a reviewer inline. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. When a dispatch cannot recover through active work, supported release, or a corrected invocation, run that pass inline using the same prompt asset and disclose the substitution.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.

**Delegation and depth.** Under a host rule permitting delegation when the user OR a loaded skill explicitly requests it, this skill's reviewer-dispatch instructions satisfy that exception; do not ask for a second approval. A genuine higher-priority prohibition, actual denial, or missing tool still applies. Never bypass it using shell dispatch or another harness. Verify effective nesting capacity through the supported OpenCode configuration/debug interface; package-local depth configuration is not proof of the consuming session's effective depth. Classify actual errors separately as permission denial, model-argument rejection, missing tool, nesting-depth exhaustion, or transient concurrency capacity. Do not retry denials or evade depth limits. Where dispatch is unavailable or unrecoverable, this workflow permits the same rubric inline; disclose that substitution and any lost independence. If a caller requires independent coverage that inline work cannot supply, return it as incomplete rather than advancing as fully verified.
