# Cross-model document review

Run the additive pass only for activated `adversarial-document-reviewer`, `product-lens-reviewer`, and `security-lens-reviewer` lenses. Also dispatch exactly one `whole-doc` sweep per document in the same wave, with the full document. Convergent lenses and feasibility do not trigger it. Every peer uses the same persona brief, `subagent-template.md`, and `findings-schema.json` as its local twin; the sweep uses `personas/whole-doc-reviewer.md`. Cross-model prompts retain round-1 framing, without the accumulated decision primer. Synthesis still applies R29/R30 suppression.

## Resolve policy and one fixed native route

Read ordinary YAML keys from the target absolute workspace root's `.rocketclaw/config.local.yaml`, then `config.yaml`: first active supported scalar wins; skip missing files, commented keys, empty values, and invalid values. Discover the root with `jj workspace root` from that workspace. See https://docs.jj-vcs.dev/latest/cli-reference/. Repository-scoped GitHub calls, if needed, use `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`.

Evaluate `cross_model_review_mode` first: `auto` is default; `off` skips before resolution, disclosure, or dispatch unless the user explicitly requests a cross-model peer in conversation. Configured peer preference is not that opt-in. A live user prohibition always applies. Report **disabled by checkout config** distinctly.

Resolve `cross_model_peer` in order: conversational user preference, local then shared config, project instructions, then an available different-family target. `CROSS_MODEL_PEERS` filters sanctioned recipients only when set; unset is unfiltered, not unsanctioned. Do not add recipients, silently alter an explicit choice, or infer a serving family from the host brand. Keep requested target, transport/intermediary, served family, and served model separate. An unattested host family cannot establish automatic different-family exclusion.

Use `opencode.models` to resolve exact available IDs and variants, then OpenCode-native subagents for execution and shell only for local payload/evidence handling. Never invoke another harness's dispatcher. Preserve configured `cross_model_model` and `cross_model_effort`, with conversation outranking configuration. Default model intent is Codex `gpt-6-luna` at extra-high, Claude `claude-opus-5-5` at high, native Grok `grok-4.7` at extra-high; the historical Grok-via-Cursor intent is `grok-4.7[context=256k,reasoning_effort=high,fast=true]`, and Composer is `composer-2.5[fast=true]`. Cursor default/Auto has no fixed model or verified effort. These are desired choices, not permission to launch their old CLIs. A fixed intermediary unavailable natively is unmet routing coverage, not permission to substitute. Only after a default ID is observed unavailable may a compatible same-target/same-family replacement be resolved and disclosed; never replace an explicit model silently.

## Permission, depth, and disclosure

Follow `dispatch.md`'s separate delegation, model-selection, and nesting checks. This skill explicitly requests reviewer delegation and therefore satisfies a host rule allowing user **or loaded-skill** requests; do not demand another approval. An unconditional prohibition, unavailable tool, or actual denial remains binding. If model override requires an explicit user model request, omit `model` absent that request. A suitable inherited-model reviewer may provide ordinary review evidence, but cannot complete a required different-model or fixed-route pass unless the actual model satisfies it. Name unmet tier, route, or independence requirements as incomplete coverage.

Inspect the current project's discovered depth configuration and current nesting position using the host's supported configuration/capability interface. The package default `experimental.subagent_depth: 3` is not automatically inherited by plugin consumers; do not change host configuration or assume remaining depth. Distinguish actual depth/capacity errors, permission denial, model-argument rejection, and missing tools. Queue transient concurrency backpressure until a slot frees; depth exhaustion does not recover that way. Never evade limits through another harness or retry a denied operation.

Before sending document content, prominently disclose an **independent cross-model review** only when different serving families are attested. Otherwise state independence is unverified. Name the requested model as requested, effort, native route, and every recipient receiving full document content. In non-interactive mode keep user-facing prose silent but retain an auditable local send record. No new approval is required for otherwise authorized routing; genuine egress/permission restrictions still apply.

## Dispatch, isolation, receipts, and bounded collection

Resolve one target/route for the whole review and hold it fixed across lenses and the whole-document sweep. Embed full document content for cross-model peers, never truncate it or pass a section slice; skip with a named size/capability reason if the full payload cannot fit. Provide provenance and settled decisions through the normal template. Use fresh contexts that have not seen local findings or peer claims. Peers are read-only leaf reviewers: no writes, web access, further delegation, skills, or unrelated repository reads. Use native least-privilege controls; if the required embedded-document-only scope cannot be enforced, disclose the limitation and skip rather than silently broadening access.

Keep private run state under `<absolute-workspace-root>/.tmp/rocketclaw/doc-review/<run-id>/`, or local `.tmp/rocketclaw/doc-review/` outside a repository. Validate ownership, avoid symlinks and collisions, and do not use global temporary fallback paths. Record native job IDs, requested/actual model, target, route, terminal outcome, timing, and scope. Write fold-in artifacts as `<reviewer-name>-<provider>.json` and `whole-doc-<provider>.json`, validating their schema and trusted ownership before reading. Never infer actual serving identity from a request; absent receipts mean `model_actual: unverified`. Set `independence_verified: true` only with attested different serving families and fresh independent context. Unverified evidence cannot promote agreement.

Use one captured shared deadline for all legs: `CROSS_MODEL_HARD_SECS` defaults to 1200 seconds, with 10 seconds of collection allowance. Poll/await native outcomes in bounded intervals and collect each started job, including failures, before synthesis or cleanup. Stop/release only jobs owned by this run using supported lifecycle tools. Do not assume completion frees capacity or invent cleanup APIs. Preserve evidence before cleaning disposable scratch; never delete an unrelated workspace or required recovery evidence.

## Failure and coverage

The additive pass never blocks local review. Name each lens and whole-doc outcome in Coverage: disabled, never started with reason, completed with no additional issues, failed, timed out, malformed output, or infrastructure loss. Missing artifacts are not proof of completion. A whole-pass infrastructure failure specifically loses the broad whole-doc read and cross-model corroboration; local twins still cover their lenses. If selected local reviewers cannot run, follow the local incomplete-stop contract rather than claim full coverage.

Read bounded native error/log evidence before cleanup. Distinguish quota, authentication, capability, depth, and permission failures. Do not claim the user's account is logged out without provider-capable launch/response evidence; sandbox-context authentication text alone is insufficient. Same-route infrastructure recovery is allowed only for a new plausibly recoverable failure within the original deadline, retaining recipient/model/scope/isolation. Stop when the failure repeats. Permit at most one same-route overload retry when an actual provider HTTP 529 identifies `overloaded`; do not restart a terminal provider no-review outcome, repeat quota failures, or change recipients automatically. Any recipient/route change requires fresh resolution, sanction, and disclosure. Inline or parent-coordinator fallback is allowed only when the contract permits it and must preserve independence; a host inline reread cannot replace independent cross-model coverage.
