# Peer recovery and coverage

Keep permission, model rejection, missing tools, actual depth/capacity exhaustion, provider quota, timeout, malformed output, and infrastructure failure distinct. A permission/model error is not evidence that depth is exhausted. Never evade any denial with shell, another harness, or a sibling session.

- **No successful launch:** one bounded repair of a concrete infrastructure error is allowed before finalizing the local roster. Otherwise run the in-process adversarial reviewer when allowed. Record `peer.outcome: in-process-fallback` and `adversarial lens: in-process fallback (cross-model peer not run: <observed reason>)`. Never call this `harness-native fallback` (that is ce-work's skipped-skill signal).
- **Launch ID returned then failure:** collect terminal error and stop/release it where supported. Retry only the same resolved model/recipient, exact captured endpoints, persona, read-only boundary, and shared deadline while each failure is new and plausibly repairable. A repeated failure or exhausted deadline stops retries. A recovered result is degraded coverage, never a clean independent pass by assertion.
- **Quota/availability requiring another recipient:** resolve and disclose the new route before sending, respecting recipient restrictions and user-explicit target. Never silently switch providers or substitute another ref. When no eligible route exists, use the permitted in-process fallback and report the missing independent corroboration.
- **Forbidden override:** inherit the model if delegation is permitted, explicitly state the requested cross-model condition is unmet; do not claim same-model output is independent.
- **Actual depth/capacity failure:** boundedly release completed owned agents if supported, then retry only when capacity genuinely becomes available. Inline/parent fallback is allowed only where the depth path permits it. Required independent review still missing makes the review incomplete.

Do not promote agreement without a valid independent identity receipt. Partial/malformed artifacts, progress text, and launch acknowledgements are not findings. Fold a successful peer exactly once at merge, never feed it to other reviewers. Record every attempted/recovered/skipped pass and its lens coverage in metadata and final Coverage. Failure must not produce a green completion claim.
