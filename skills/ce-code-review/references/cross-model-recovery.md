# Cross-model recovery — native OpenCode

Use only on an observed launch/collection failure, not to probe or renegotiate permissions. Retain the original captured base/head IDs, fixed recipient/model, read-only boundary, brief and shared deadline from `cross-model-review.md`. Preserve a bounded diagnostic and terminal receipt before releasing owned native agents; no detached jobs or other-harness recovery.

Classify the actual error first:

- **Delegation/tool denial or higher prohibition:** stop the denied operation. No retry, alternate tool, shell dispatcher or harness. This skill satisfies a user-OR-skill delegation exception, but cannot override a real denial.
- **Nesting depth:** separate from permission and models. Do not retry or evade it. Record the actual nesting limitation; refer users to the documented global `experimental.subagent_depth >=3` setup in `subagent-model.md`. Never modify host config.
- **Active-agent capacity:** collect/release owned active agents, keep refused launches queued, and retry only when a slot genuinely becomes available. No reviewer is dropped. If no recoverable capacity remains, use only an allowed degraded path.
- **Model/effort unavailable:** report requested and offered values. A configured/user-pinned peer is never silently swapped. For an unpinned default, at most one same-family replacement may be resolved through `opencode.models` when host model permission allows it, with new disclosure and remaining deadline. Inheriting is allowed only when suitable and not represented as cross-model independence.
- **Correctable invocation/infrastructure:** before a launch receipt, correct one concrete native invocation problem and retry the identical route once within the deadline. After a launch, first collect/stop it before any recovery. Repeating error or deadline exhaustion ends recovery; never retry indefinitely.
- **Provider authentication:** attribute credentials only after provider-capable dispatch is established. Otherwise describe execution-context failure rather than telling the user they are logged out. A no-review authentication outcome permits the local fallback, not a successful peer receipt.
- **Transient provider overload:** at most one same-route retry within the original budget if permitted and diagnostically justified; no recipient/model change. Rate-limit exhaustion or max-turn exhaustion restores local adversarial, not further peer retries.
- **Known no-review (quota, unsupported option, launch failure):** one replacement native recipient is allowed only if the failed recipient was not an explicit live-user preference and another attested-different allowlisted native route is available. Announce every new recipient first. At most one replacement total; then use local adversarial.
- **Ran but malformed/no usable artifact, unknown whether review ran, timeout or crash:** name that exact state, never call it clean not-run or no findings. Do not invent a no-review diagnosis or silently restore coverage. Local evidence may be added only when the review contract permits; independence remains incomplete.

When local fallback is permitted, dispatch generic `adversarial-reviewer` with untouched raw context; never feed candidate findings to it. Record `adversarial lens: in-process fallback (cross-model peer not run: <reason>)` and `peer.outcome: in-process-fallback`, not ce-work's separate `harness-native fallback` signal. A separate same-model context may satisfy focused mode's allowed second reading, but never a mandatory different-model request; record lost cross-model independence. Parent inline evidence is not an independent reading. Any unfulfilled mandatory independence remains incomplete/degraded. Valid peer evidence with unverified independence never earns promotion.
