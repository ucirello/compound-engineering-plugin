# Troubleshooting RocketClaw

`docs/` and `README.md` paths are public pages. `SKILL.md` gives their URLs.

| What the user sees | What to tell them |
|---|---|
| A skill is missing, or behaves the old way after an update | Refresh the marketplace before updating the plugin, because updating alone reads a stale snapshot. Then start a new session. `docs/install/upgrading.md` has the commands for Claude Code, Codex, and Grok Bot. Other hosts' update steps are in `README.md#more-install-options`. |
| An old copy of a skill keeps running after an update | An earlier Bun install may be shadowing the plugin. `docs/install/upgrading.md` has the cleanup command. |
| The agent will not start a skill it recommended | The skill is manual-only, so the user has to type it. `references/skill-map.md` marks these. |
| The slash command is not recognized | OpenCode uses `/skill-name`. Codex uses `$skill-name`. On oh-my-pi, a manual-only skill needs `/skill:<name>`. For other hosts check the documented installed namespace rather than guessing. |
| A skill says a tool is missing | `ce-setup` reports which tools are missing and how to install them. Install only what the workflow needs. |
| A cross-model pass or oracle peer did not run | The run's report says why. `ce-setup` reports missing tools, and the `ce-pov` guide page lists what peers need. Config can also turn the automatic review pass off, so check `docs/guides/configuration.md`. |
| A nested reviewer could not start | Distinguish actual depth, delegation permission, model permission, and tool failures; do not retry a denied operation through another harness or evade nesting limits. See `references/starting-and-running.md` for the global OpenCode depth prerequisite. Use only the review contract's allowed parent/inline fallback, retain bounded recovery and per-review receipts, and report mandatory independent coverage as incomplete when it is missing. |
| Plans or learnings are not where the user expected | `docs_root` in `.rocketclaw/config.yaml` moves every RocketClaw artifact folder. Format options can also change ideation, brainstorm, and plan files from `.md` to `.html`. |
| `ce-compound` wrote nothing | It captures only what the final code, tests, standards, and docs do not already show, so skipping a routine fix is correct. If a lesson was missed, run it again and say what the lesson was. |
| Learnings are captured only when the user asks | A standing instruction fixes this. `ce-setup` offers one when the repo tracks its learnings. |
| New plans ignore past learnings | Check that `<root>/solutions/` holds learnings and that `ce-plan` ran in this repo. A `ce-compound` refresh handles learnings that have gone stale. |
| A hands-off run stopped before merging | That is expected. Merging normally stays with the user. The `lfg` guide page covers where a run ends. |
| The agent's last reply made no sense | `wtf` explains it plainly. |
| A session is out of context, or the work has to move to another agent | `ce-handoff` writes a handoff, and a new session can resume from it. |
| `ce-compound` hit context pressure | An interactive run delegates Full to one fresh native subagent using the actual source session ID, not a parent-written conversation summary. If actual tool denial, unavailable delegation, or depth prevents that, report the lightweight fallback and rerun from the same source session when available; do not recommend a fresh session as a substitute for that source evidence. |
| `ce-babysit-pr` sees an empty working-copy revision | An empty `@` above a pushed PR head is aligned; inspect `@-`, bookmarks, remote and PR before declaring no work. Authorized babysitting includes factual stale-description refresh preserving user content and issue links, clean exact-head alignment, and rearming monitoring without extra approval. Optional rewriting still needs approval, but declining it must not block authorized monitoring. Dirty/conflicted or uncertain state and unknown push authority require a safe stop. |
| Isolated workspace creation or cleanup is blocked | `ce-worktree` owns the harness lifecycle: do not bypass it with direct commands. New workspaces require explicit `jj workspace add --colocate` and `jj git colocation status` from the created absolute root. Unsupported harness naming or colocation is a compatibility blocker. Destructive authorized owned cleanup uses `jj workspace remove <verified-name>` from a surviving absolute root after session relocation, worker shutdown and evidence preservation; `forget` only unregisters while preserving files. Never force-delete after a warning or failure. |
