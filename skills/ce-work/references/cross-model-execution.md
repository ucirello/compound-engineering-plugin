# Native Cross-Model Execution Contract

Use native OpenCode subagents, never an external harness, adapter, detached runner, or shell-launched agent. The host owns scheduling, integration, verification, receipts, and shipping. Model choice changes only the implementation author, not tail ownership.

## Authority and configuration

Resolve current-task intent, still-active session intent, validated typed caller binding with original provenance, project instructions, enabled checkout configuration, then inherited native execution. Narrower, newer intent wins at equal authority; unresolved conflicts block route selection. Incidental quoted model names do not authorize dispatch. A recovery id selects durable state, never fresh dispatch authority.

Read `.rocketclaw/config.local.yaml` then `.rocketclaw/config.yaml` from the absolute root returned by `jj root`. Resolve each key independently: first valid active scalar wins; empty scalar is unset; present lists/maps, including empty ones, replace the entire key. `work_engine_mode: off | prefer | require` controls standing preference only, not live intent. `work_engine_preferences` remains an ordered list of `{harness, model?}` objects; `work_engine_effort` remains a per-harness map. Preserve operational provider/model choices as intent, but do not interpret a harness name as permission to launch that harness. Resolve the requested model through native `opencode.models` (provider, family, exact id, supported variants); never guess provider/model ids, silently replace an explicit pin, or turn effort into a shell command. Configured effort must be supported by the native tool or reported unavailable; actual effort remains unverified absent a receipt. Invalid enabled configuration is disclosed, not guessed.

Skill-requested delegation is authorized by user **or** applicable skill instructions, subject to host policy. Delegation permission and model-override permission are separate. Check available native dispatch tools, depth/capacity, and model-argument support before sending repository content. Prefer an inherited-model worker when suitable. Distinguish permission denial, exhausted depth/capacity, missing dispatch tools, unavailable model, unsupported effort, and model-argument rejection. Never evade any boundary through shell, another harness, or a nested session. Required independent/cross-model coverage that cannot be obtained is a disclosed gap, not a completed cross-model review.

Try authorized candidates in order before dispatch, recording each rejection and evidence. Same-host/default collapses to inherited native execution. `require` fixes the requested identity while viable; once proven unavailable, disclose requested versus actual identity and continue inherited native execution without silently choosing another external recipient. Both preference and requirement fallback remain subject to the original scope and coverage requirements. Do not claim coverage a fallback cannot provide.

## Durable source and dispatch

Create private state under `<workspace-root>/.tmp/ce-work/<run-id>/`, with owned nonsymlink directories and no global-temp fallback. Store a bounded plan excerpt or prompt brief plus SHA-256, repository identity, verified base commit/change id, bookmark, original dirt, binding source, restrictions, and packet digest. A bare brief needs Goal, Scope, Acceptance and verification, Constraints/exclusions, and conservative P-units; missing boundaries return to clarification. Include relevant pack rules and prototype citations, not raw conversation or credentials. Existing dirt never receives an implicit checkpoint. Checkpoint a plan only with exact sole-plan ownership and disclose it.

Before native dispatch, durably record requested/actual route, provider/model, intermediaries (none for native dispatch), source and exposed material, effort, restriction posture, unit/base/dependencies/wave, workspace ownership, and authorization. Native workspace isolation is not an OS sandbox. A restriction the host cannot enforce makes the route unavailable; never weaken it silently. The worker receives one bounded unit, verification criteria, expected files, exclusions, and no shipping, canonical commit, peer scheduling, fallback, or scope-expansion authority.

Use `references/execution-strategy.md` for native scheduling and `references/workspace-setup.md` for any explicit isolated workspace. Preserve harness-owned isolation; do not create an additional workspace merely because another model is requested. Record native task/session id before awaiting results when available. Dispatch all independently ready wave members together, capped at 3–5, only after the Parallel Safety Check proves file, contract, migration, lockfile, generated/config/registry and environment independence. Uncertainty selects serial execution.

## Supervision, inspection and integration

Use native status/result/cancellation tools. Publish unit, model receipt status, elapsed time, meaningful activity, and terminal state. Lack of activity is not failure. A live or unreachable task remains authoritative: no duplicate or fallback author. A timeout is terminal only after native termination/cancellation evidence. Preserve partial output and recovery paths.

Completion text alone is not integration evidence. Inspect the actual `jj status`, `jj diff`, changed paths, binary/mode/rename/delete evidence, scope, and conflicts in the absolute worker workspace. Record a verified immutable output revision and its actual parent/base. Workers must not mutate canonical history. All wave outputs must be terminal and inspected before the first integration. Same paths or semantic interface contention stop the wave even if textual application seems clean.

Integrate serially in dependency order with exclusive host ownership. Record canonical pre-integration revision/tree, output revision and expected paths first; use JJ-native revision transfer/rebase or an inspected patch applied only to owned paths, never Git transport. Verify exact parent/base and preserve unrelated work. A conflict, unexpected path, moved canonical head or uncertain recovery blocks mutation. Run authoritative unit checks against the advancing canonical tree, capture exit status directly, reconcile tracked state, then create a separate host-owned unit commit. Before composing, read `implementation-loop.md`'s full composition contract and apply its runtime guide/history requirements. Record exact earlier integrated wave commits; unknown head movement blocks later members. Repeated collisions disable further waves.

Before checks, inventory ignored/untracked state separately, including local databases and secrets by metadata without copying secret contents into receipts. JJ snapshots do not protect ignored/untracked files. Record created/changed/removed counts and bounded path samples after checks. Do not delete or overwrite such files during restoration. A failed verification forbids the commit; restore only exact host-owned changes when pre-state equality can be proven. Otherwise retain integration ownership, output revisions and workspaces, and return blocked. Never use reset/discard as generic recovery.

Run source-wide authoritative gates after all units complete, preserving command, exit status, evidence digest/log and ignored-state divergence. A failed source-wide gate blocks shipping/return success even if workspace cleanup succeeded.

## Receipts and exactly-once recovery

Store an atomic manifest and append-only transition evidence outside any workspace slated for removal. Preserve `implementation_engine_binding`, requested/actual route/model/effort, model receipt status, fallback reason, source kind/digest, scalar run id, per-unit task ids, packet/base/output revisions, inspection, integration, verification, canonical commit, cleanup, plan checkpoint, blockers and recovery path. Never infer actual served model from requested model or worker prose; use native metadata or `unverified`. Return schema fields remain applicable. Direct and return-to-caller runs retain the same evidence.

Recover a supplied safe run id before input triage. Validate real paths, ownership, repository identity and mode. Without a run id, discover only a single matching unfinished plan-backed run by repository, bookmark and plan digest; ambiguous matches block rather than mint a third run. Prompt-backed recovery requires its disclosed run id. Resume is observation/reconciliation, not redispatch, reapplication, recommit, or either finishing tail. Reconcile a landed commit only against exact recorded parent/tree evidence. Unknown dirt is a blocker. Completed runs with successful source-wide receipts are observation-only: do not rerun tests/build/install/format merely to reconfirm them. Missing required evidence is a recovery blocker.

Record fallback authorization atomically for each unit only after authoritative terminal failure and exact restoration/integration-ownership release. A live task or successful unreconciled output forbids fallback. One claim permits one inherited native implementation; retain prior attempts under the same run id. Record fallback completion only after local verification and canonical commit. A corrected retry needs a fresh attempt id, the same bounded dependency contract, and newly recorded authorization; workers cannot choose recipients. Cleanup failure remains a blocker, not successful completion.

## Tail ownership

Standalone work resumes quality/review/shipping only after implementation and source-wide verification. `mode:return-to-caller` returns implementation/local-verification receipts with `standalone_shipping_skipped: true`, never simplify/review/PR/CI. Recovery never automatically invokes either tail.
