# Stack service boundary for JJ-managed bookmarks

Use latest JJ and `context.md`'s absolute cwd/scoped GitHub environment. `gh stack <command> --help` is the authoritative service-capability reference, not evidence that its Git-backed workspace commands are allowed. Never run its checkout/init/add/top/submit/merge operations when they launch the Git executable; perform local topology, file partitioning, descriptions and pushes through JJ as described in `stack-submit.md`. Do not invoke another harness or a deleted bridge to evade this boundary.

Preserve the distinction between service-side linking and a locally managed stack. `gh stack link` is the external-manager (including JJ) service-side route; inspect `gh stack link --help` and pass its explicit required arguments, never a bare prompting invocation. A service link is not proof that a later manager view/submit/merge owns it. Before registration verify the exact repository, parent relationships and ownership. Do not guess undocumented endpoints or treat a missing tool as successful coverage. If a required managed route cannot operate natively, report a specific residual and preserve existing state/recovery references.

When reading stack metadata, trunk and branch heads/base SHAs describe observed state; a stored base is not necessarily the parent's current tip. Unordered branch arrays do not establish stack order. Verify exact ancestry with JJ and the service's explicit relationship data. Resolve PR heads by repository, bookmark and OID, not by name alone. Shared/ambiguous membership, a non-top explicit parent, or unavailable stack support remain decisions, never permission to pick a different parent.

Draft behavior is consequential: an operation that opens new PRs may also mark existing drafts ready. Preserve existing drafts without explicit opening authorization. A draft-only outcome does not satisfy a ready-stack handoff. Never merge an individual member with `gh pr merge`; stack landing must preserve verified manager semantics under `ce-babysit-pr`'s explicit land authority. `stack-submit.md` owns the native construction/submission phases and residual handling.
