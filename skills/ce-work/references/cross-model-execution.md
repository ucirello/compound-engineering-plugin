# Cross-Model Execution Contract

Read this when `execution-engines.md` selects a configured route or when recovering an existing run. Execute with OpenCode-native `opencode.models`, subagents and shell, not another harness's dispatcher. The host owns scheduling, durable receipts, JJ snapshots, integration, verification, recovery and cleanup. Worker prose or process completion never proves integration or success.

## Configuration-authoritative route selection

Keep the authority order in `execution-engines.md`. Resolve `work_engine_mode` (`off | prefer | require`), `work_engine_preferences` and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `config.yaml`. A present local list/map, including an empty one, replaces the team value. Preserve candidate order, explicit models, configured defaults and requested effort. Invalid non-map effort requests nothing: disclose it once. Enabled mode without valid candidates is unavailable, not guessed.

Compatibility configuration may name `codex`, `claude`, `grok`, `cursor`, `composer` or `opencode`, with optional `model` and harness-keyed effort. These remain intent, not commands or permission to invoke those harnesses. Preserve the requested harness/intermediary identity separately from actual OpenCode execution; a required fixed harness route is unavailable if OpenCode cannot satisfy it. Never silently translate Composer to another model or change a provider/intermediary. Use `opencode.models` to resolve model names to exact available IDs and supported variants; verify requested effort rather than inventing a mapping. Preflight candidates without exposing repository material. An explicit different model on the same harness is distinct; same-host default collapses to native execution.

Delegation permission, model-selection permission and nesting capacity are separate. This skill explicitly requests bounded implementation workers and reviewers. Under a host user-OR-loaded-skill rule, that satisfies the skill exception without another approval; an unconditional prohibition or actual denial still wins. When a model override requires an explicit user model request, configuration alone does not authorize passing `model`: use a suitable inherited model and disclose unmet route/effort intent. Same-model workers are independent contexts, not cross-model evidence. If required different-model coverage cannot run, mark that coverage incomplete. Inspect actual depth/capacity errors separately from missing tools, permission denial and model-argument rejection; do not bypass any through shell or another harness.

Live preference is `prefer` unless its meaning requires a fixed identity (`require`). Before dispatch, traverse only the authorized candidate list. Both modes disclose exhausted candidates and reasons once, then use current-session native execution without broadening host permissions or choosing an unrequested recipient. After start, no fallback or different recipient is eligible until the original attempt is authoritatively terminal or stopped and reconciled. Expected latency or convenience is not unavailability.

## Durable source, authority and receipts

Store private run state under the canonical workspace's ignored `.tmp/rocketclaw/ce-work/<run-id>/`; ensure `.tmp/` is ignored, including fallback/error artifacts. Respect an explicitly configured local run-root override only within workspace-local `.tmp/`. Validate IDs with `^[A-Za-z0-9._-]{1,128}$` and at least one non-period character; refuse foreign/unsafe state. Record repository identity, absolute canonical root, bookmark, base commit/change/tree, source kind/digest, owner, unit dependencies and wave base before mutation.

For a plan, record its SHA-256 and private copy. A sole dirty selected plan may receive a disclosed plan-only JJ checkpoint composed under `implementation-loop.md`; unrelated dirt forbids such a checkpoint. For a bare prompt, first establish Goal, bounded Scope, Acceptance and verification; write a distilled brief in local `.tmp/`, never raw conversation, credentials or unrelated context. Include Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units (one conservative P1 unless evidence establishes more). Record its digest and use the private copy thereafter. Prompt-backed canonical state must already be clean. Recheck source digest, canonical identity and clean baseline before each unit.

Before repository material or mutation authority reaches a worker, durably record the authorizing source, fixed requested and actual route/provider/model/intermediaries, material exposed, requested effort and receipt status, inherited restrictions and enforced-versus-cooperative posture. JJ isolation is not an OS sandbox. Do not claim confinement or served model/effort without runtime evidence; required unenforceable restrictions make a route unavailable. Workers receive one bounded packet and workspace, never commit/push/PR/shipping, fallback, peer scheduling or scope-expansion authority.

Keep `implementation_engine_binding`, requested/actual route and model, model receipt status, requested effort (served effort unverified unless proven), `fallback_reason`, `source_kind`, `source_digest`, scalar `run_id`, `plan_checkpoint`, per-unit attempt receipts, blockers and `recovery_path`. Distinguish dispatch/process terminal state, complete snapshot/scope acceptance, integration, authoritative verification, canonical commit and cleanup. Preserve all earlier attempts. Record intent before each transition and observed evidence afterward, with read-back of durable records; only one orchestrator may hold the integration lock. If a native tool cannot provide required lifecycle evidence, block with inspectable recovery state rather than fabricating a receipt.

## Isolated workspace contract

Detect and reuse existing verified isolation first, under its existing name; never rename/recreate it for naming or colocation. Ordinary synchronous native units stay in the active workspace. Ordinary native worker isolation remains harness-owned: request its supported colocated JJ capability and verify base and `jj git colocation status` from the resulting absolute root. Do not bypass lifecycle authority or silently substitute a Git-only worktree.

For this cross-model protocol's run-owned sibling isolation, preserve the local `.tmp/` parent layout and select a verified base revision. When using `ce-worktree`, capture local creation date once and choose `YYYYMMDD-<task/pr/revision-slug>`; normalize caller names without double-prefixing. Use the same identity as registered workspace name and destination basename, check both registrations and destinations, append `-2`, `-3`, etc. on collision, and persist the chosen identity across retries, resumes and midnight. Preserve PR/source bookmarks. Unsupported harness naming or colocation is a compatibility blocker, not permission to alter existing state.

Creation from source absolute root is `(cd "$workspace_root" && jj workspace add --colocate --name "<persisted-name>" --revision "<verified-base>" "<absolute-owned-destination>")`. Verify `(cd "$destination" && jj git colocation status)` and exact base before editing. Adopt the isolated workspace through the supported harness session move when it becomes the primary workspace. All JJ calls use their target absolute cwd, never `jj -R` as a cwd substitute; path inventories are repository-relative. Repository-scoped GitHub calls use `(cd "$workspace_root" && export GIT_DIR=$(jj git root) && gh ...)`. See https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace and https://docs.jj-vcs.dev/latest/git-command-table/ .

## Serial unit protocol

1. Resolve, preflight and record one fixed binding, restrictions and clean canonical state. After READY, the route is locked for that unit: advance it or return blocked, never reclassify it as trivial for speed.
2. Prepare a private bounded packet with active unit, Goal Capsule, Definition of Done, relevant Verification Contract, cited R/F/AE/KTD excerpts and Product Contract Key Decisions whose `Governs R…` links name its requirements; include expected files, evidence strategy, dependencies and exclusions. Bind run/unit/attempt, base, route and packet SHA-256 before dispatch. Read back the exact packet and authorization; send only that packet, not the entire plan/conversation.
3. Dispatch one fresh native subagent seeded with `agents/implementation-worker.md`, exact absolute workspace and recorded model/variant only when permitted. Record actual handle, invocation arguments and packet digest. No shell wrapper may launch another harness. Worker leaves output uncommitted and returns `implementation-result-schema.json` evidence. Host derives the complete JJ snapshot independently.
4. Observe through native status/wait tools in separate bounded calls (wait at most 60 seconds), reporting unit, route, elapsed time, activity and terminal state. Preserve the 7200-second hard cap and 600-second progress-reset idle window when activity is reliable; otherwise disable idle inference while retaining the hard cap. Stop through supported lifecycle tools only. An unreachable/live attempt remains authoritative; do not duplicate it or infer death from silence. If lifecycle control is unavailable, preserve state and block.
5. On authoritative completion, snapshot the complete worker tree with JJ and pin recovery references. Verify recorded base parent and final tree; inspect actual diff including binary/mode/rename/delete and newly tracked/untracked paths, result, declared scope and scope-expansion request. Unexpected/generated output remains inspectable and blocks integration; worker path lists are hints only.
6. Acquire the host-owned integration lock and record an exact pre-fold snapshot, bookmark, changed-path inventory and allowed advancing head. Recheck base/dependencies and canonical cleanliness. Integrate the accepted delta with native JJ: preserve the pinned source snapshot, duplicate its change with `jj duplicate <snapshot>`, and squash that exact duplicate's delta into the host-owned empty integration change with `jj squash --from <duplicate> --into <integration-change>` after consulting command help. Verify the resulting tree, scope and conflict state; never blindly merge a transport snapshot, alter unrelated files or bypass conflicts. Record expected post-apply tree and paths before proceeding.
7. Run authoritative unit verification from canonical absolute cwd, capturing exit status directly and retaining logs in local `.tmp/`. Direct argv handles simple commands; shell syntax requires an explicit shell with pipe-failure handling. Disable Python bytecode where applicable. Reconcile exact tracked tree/bookmark/state and status-visible paths before marking verified; stdout alone is not a pass. Inventory ignored metadata before/after and record changed/removed/created counts with bounded samples. Ignored caches, local databases and `.env` files are not snapshot-protected: never silently restore/delete them or claim they are protected.
8. On verified exact reconciliation, make one host-owned path-limited JJ canonical commit using the full dynamic message rules in `implementation-loop.md`. Record commit parent/tree, verification evidence and cleanup outcome, then release the lock. A crash after commit is resumable evidence, never permission to redispatch.
9. Any apply, verification, reconciliation or pre-commit failure stops the transition. Restore only proven run-owned tracked changes to the exact pre-fold snapshot; never discard unknown dirt. Prove equality before releasing the lock or permitting retries/fallback/siblings. If restoration cannot be proven, retain lock, workspace, recovery references and blocker. Preserve ignored divergence and logs.
10. After all units, run plan-wide Verification Contract checks under the same host-owned snapshot/exit-status/reconciliation discipline and record durable receipts. Failing checks block completion even if cleanup succeeds. Return/ship only after successful required receipts, never after process exit alone.

## Parallel waves

Use `execution-strategy.md`'s Safety Check, bounded 3–5 workers and fresh contexts. Record one clean common wave base, dependency order and distinct owned workspaces. Start all eligible workers concurrently; terminalize and inspect all complete snapshots before any fold. Same paths or semantic/shared-interface contention stops integration for host resolution. Integrate sequentially under the lock, verify each against the advancing tree, commit and record its exact parent/tree as the only allowed head for later siblings. Textual apply success is not semantic compatibility. Release the reconciled unit before the next; conflicts enter exact restoration. Keep dependents queued, preserve unaffected siblings, and recompute readiness before retrying on the advanced base. Repeated collision, broad edits or unprovable restoration disables further waves.

## Recovery and exactly-once fallback

A supplied run id is authoritative. Recovery reads durable records before classification and never dispatches, changes route, runs either shipping tail or repeats completed checks. Without an id, plan-backed discovery matches exact repository identity, bookmark and selected plan digest; ambiguous matches return ids/recovery paths and block selection, never choose the newest or start a third run. Prompt-backed runs require the disclosed id. Unsafe/foreign manifests block.

Reconcile one recorded/unbound matching native job, live status, terminal snapshot, interrupted restoration or canonical commit only against exact recorded handle/base/parent/tree/digests. Unknown state blocks, never resets. Reuse a recovery reference written before its receipt only when parent and tree match. Successful completed runs are observation-only: return stored unit and plan-wide receipts; missing required receipts are blockers, not permission to improvise verification.

Explicit abandonment requires the exact snapshot revision or terminal handle if no snapshot exists. After authoritative failure/stopping, exact restoration, lock release and safe cleanup, record a single atomic fallback claim under the same run/unit. A live job or successful unreconciled output refuses fallback. Both prefer and require disclose requested-versus-actual route once and allow exactly one current-session native fallback, never a new unrequested recipient. Record its accepted canonical revision, local verification digest and summary; a completed claim is not run again. Corrected retries use a fresh attempt id under the same scalar run id with original dependencies/wave contract and preserved earlier receipts. If exclusive claim/lock ownership cannot be established, block rather than race.

## Safe retirement

Cleanup requires workflow authorization, not merely completion. Stop workers; leave the target workspace and move any active harness session to a verified surviving workspace first. Verify exact registered name, absolute path and run ownership, prove integration when required, and retain recovery/archive/best references. Copy required receipts, logs and evidence outside the target (under surviving workspace-local `.tmp/`) and read them back before deletion. Inspect tracked changes, conflicts, ignored and untracked content: JJ removal snapshots do not protect ignored/untracked files. Preserve unrelated, ambiguous, referenced or non-disposable content and respect harness-owned lifecycle authority.

Remove a disposable run-owned workspace only from the surviving absolute root: `(cd "$surviving_root" && jj workspace remove "<verified-name>")`. Verify deregistration and directory disappearance explicitly, since deletion warnings may accompany successful exit. Failure/incomplete cleanup retains remaining state and reports a blocker; no force-delete, Git removal or permission workaround. `jj workspace forget` is only for unregistering while preserving files. Bookmark deletion is separate; keep needed recovery references. Interrupted cleanup resumes by inspecting both registration and directory, not by blindly retrying or deleting.

## Tail ownership

Standalone execution resumes Phase 3–4 only after implementation/local verification. Return-to-caller returns receipts with `standalone_shipping_skipped: true`; never runs caller-owned simplify/review/PR/CI. Workers inherit neither tail. Report each dispatch, observation, snapshot, scope decision, integration, restoration, verification, commit, cleanup and blocker with recovery path.
