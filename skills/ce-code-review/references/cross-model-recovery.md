# Native peer failure and recovery

Use the permission/model/depth distinctions in `dispatch-capabilities.md` and the native route in `cross-model-review.md`. No removed dispatch helper or cross-harness shell adapter is a fallback.

- **Never eligible / disabled:** retain the selected local adversarial persona where delegation is permitted; record the precise skip reason. Required cross-model coverage is incomplete, even if the same-model lens succeeds.
- **Permission denial / unconditional prohibition:** do not retry, escalate around it, or switch harnesses. Use inline/parent fallback only where the chosen depth contract permits; name lost independent coverage.
- **Nesting limit:** identify the actual depth error; do not treat it as temporary concurrency pressure. A parent coordinator may perform a permitted launch at its own available depth if the workflow allows handoff; otherwise fail/degrade honestly. No second harness or detached shell escape.
- **Temporary concurrency capacity:** queue until active native children finish and supported lifecycle release frees slots. Do not drop selected reviewers or claim failure solely from transient backpressure.
- **Optional model argument rejected:** if no denied action is being retried, correct the invocation by omitting `model` only where inherited-model review is suitable and permitted. A required fixed/different-model route remains unmet; never label the inherited result cross-model.
- **Missing tool or unavailable required model/route:** report that capability precisely. Do not infer a permission denial or silently change provider/model/effort.
- **Provider/authentication/timeout/malformed output:** record the terminal failure and stop/release the native child. Do not loop retries; one supported same-route retry for an explicit transient provider overload/rate limit may retain recipient, model, scope, disclosure, and original deadline, but never retry an actual denial. A changed recipient requires resolution and disclosure before any egress.

When the peer produces no usable result, restore one local adversarial reviewer if permitted and not already run. Collect it before finishing and disclose that it restores the lens, not different-model independence. Findings recovered without trustworthy serving evidence can be attributed evidence, never verified cross-model corroboration. A focused run requiring an independent pass cannot be called complete based on an inline orchestrator read. Preserve the output schema and record all remaining limits in Coverage; in `mode:agent` keep output JSON-only. Full-path merge/report/validator contexts remain subject to the same contract and cannot be silently collapsed into the dispatch context.
