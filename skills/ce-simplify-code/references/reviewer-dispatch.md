# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers what happens when the harness is full, how review agents are released, and the permission mode.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry after a slot frees. Classify actual errors separately as capacity/nesting depth, permission denial, rejected model argument, or missing tool; permission does not guarantee remaining nesting capacity. When a dispatch cannot recover through active work, supported release, or a corrected invocation, run that pass inline using the same prompt asset and disclose the substitution, only where inline execution is allowed. Do not retry a denied operation or evade a prohibition or depth limit through shell or another harness. Record each pass's outcome, failure, and substitution; required independence that inline execution cannot provide remains incomplete and must not be reported as fully verified.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.

**Delegation and model permission.** This skill explicitly requests reviewer delegation, satisfying a host rule that permits either user- or skill-requested subagents without asking again. Respect unconditional prohibitions and actual denials. Permission to delegate is separate from permission to override a model: under a user-only override rule omit the optional `model` argument unless the user requested it, and use a suitable inherited model. Preserve configured routes as intent and disclose unmet requirements. Separate same-model reviewers do not establish cross-model independence; unavailable required independent coverage remains incomplete.
