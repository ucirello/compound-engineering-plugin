# Committing the refresh

Skip if no files changed. Resolve the absolute `workspace_root`, then run every JJ operation from it, for example `(cd "$workspace_root" && jj status)`. Inspect active bookmarks, conflicts, and unrelated work. JJ has no staging area: isolate **only** this refresh's paths (and only its hunks in shared files) in a separate change with `jj split`; preserve all unrelated work and stop for a safe decision if separation is ambiguous. Do not reset or discard changes.

Based on https://go.dev/wiki/CommitMessage and on past commit messages that you can see in `git log`, compose commit messages adherent to the present standards.

Before composing, read the full Go guide and compare several recent subjects AND bodies with `(cd "$workspace_root" && GIT_DIR=$(jj git root) git log -10 --format=%B)`. Determine prefixes/package names, casing, tense, subject/body separation, wrapping, and issue-reference placement at runtime. Project instructions and observed repository syntax always win over differing Go syntax; apply compatible Go quality guidance. With no history, follow project/user instructions and Go guidance without inventing precedent. Describe the maintenance actions and affected learnings, not a fixed message template. Use `(cd "$workspace_root" && jj describe -r "<verified-refresh-change>" -m "<message composed from the standards above>")`.

Non-interactive defaults: resolve the remote-designated default bookmark and the current change's bookmark association rather than relying on Git HEAD. On the default line, create a bookmark named for what was refreshed (e.g., `docs/refresh-auth-learnings`) at the isolated refresh change; on a feature line, advance its verified bookmark to the separate refresh change. Publish with `jj git push --bookmark "<verified-bookmark>"` from the absolute root and attempt a PR. Repository-scoped GitHub operations must run as `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh pr create ...)`. If PR creation fails, report the bookmark; on JJ failures, put recommended commands in the report and continue without discarding work.

Interactive: ask (per Blocking questions), with the recommended option first. On the default line: bookmark+change+PR (recommended; specific bookmark name) / record directly on the current line / don't commit. On a clean feature line: record a separate change on it (recommended) / separate bookmark / don't commit. On a dirty feature line: selectively split and describe only refresh changes / don't commit. Leaving changes uncommitted means leaving them undescribed/unpublished in the working copy, not deleting them.

Command semantics: https://docs.jj-vcs.dev/latest/git-command-table/ and https://docs.jj-vcs.dev/latest/cli-reference/ . Any temporary output belongs under the absolute workspace root's `.tmp/`, never global temporary storage.
