# Cross-model recovery and coverage

Apply the permission, model-selection and effective-depth rules in `cross-model-review.md` to every recovery dispatch. Skill-requested delegation proceeds under a user-or-skill permission rule without another approval; it never overrides an unconditional prohibition. Model overrides forbidden by the host are omitted. Suitable inherited-model reviewers may cover a lens, not a required different-model/fixed-route pass. Record unmet intent. Never retry an actual permission denial or bypass depth with shell or another harness.

Classify actual evidence before recovery:

- Temporary active-agent capacity is backpressure: collect/release live native reviewers, then dispatch queued reviewers within the same deadline. A nesting-depth limit cannot be relieved by freeing a concurrent slot. Use an allowed parent-coordinator handoff only if that coordinator has permission and capacity; inline evidence is not an independent reviewer.
- A model argument rejected by the tool is not a delegation denial. Correct the invocation once if allowed; otherwise omit model for a suitable inherited-model lens and record incomplete cross-model coverage. Missing tool, depth, denied permissions or incompatible required route are named blockers, never successful passes.
- For a new plausibly recoverable invocation/infrastructure error, correct only that error on the same fixed native route within the shared budget. Stop when an error repeats or the budget expires. No exploratory retry of denied operations.
- Authentication attribution requires provider-capable dispatch evidence or a provider response. Login-shaped text alone may reflect execution context; do not claim the user's account is logged out. Either case is a no-review outcome.
- For explicit provider overload HTTP 529, allow one same-route retry within the shared deadline, preserving recipient/model/scope. Other rate-limit/capacity outcomes or max-turn exhaustion restore the local adversarial persona, not a different recipient.
- Valid terminal empty findings is a completed pass. Malformed/absent findings, timeout, failed or interrupted launch is not; name the actual terminal outcome and do not report fully verified coverage.

For the first proven no-review outcome, when the failed recipient was not an explicit user preference and another allowed attested-different native model remains, disclose and bind one replacement recipient within the remaining shared deadline. Preserve configuration intent; never silently change an explicit route or model. No third peer. Otherwise dispatch local `adversarial-reviewer` under `dispatch-reviewers.md`. Record `adversarial lens: in-process fallback (cross-model peer not run: <reason>)` and `peer.outcome: in-process-fallback`; do not call it `harness-native fallback`, which is a different shipping receipt. An unknown diagnostic is named as degraded coverage, not proof that no review happened.

If delegation/depth/tool constraints prevent local fallback, use only the contract's degraded inline path: attribute parent evidence, exclude it from independent reviewers, preserve every missing lens and validation requirement. Focused review with no separately dispatched usable adversarial read is Not ready. Full review names lost independent and cross-model coverage rather than claiming completion. If mandatory finish leaves or validator cannot launch, follow their failed-finish/infrastructure-failure contracts; do not silently synthesize a verified receipt.

Collect terminal results or stop outstanding native work before finish/return. Retain bounded diagnostics and identity receipts in the local run directory until consumed. Remove only disposable run-owned peer scratch, never unrelated content. All evidence/failure paths remain under local `.tmp`; shell is read-only inspection, never a permission/depth workaround. JJ commands run from the target absolute workspace root; repository-scoped GitHub CLI uses `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`.
