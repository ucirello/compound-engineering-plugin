# One tick: fresh facts, feedback, CI, currency

Use the retained `scripts/pr-snapshot` helper for deterministic GitHub snapshots, atomic journal marks, and monitoring; the agent still owns semantic judgment. Use the absolute workspace cwd and `GIT_DIR=$(jj git root)` for every repository-scoped `gh` command. Store snapshots, residual payloads, answers, and logs only under the workspace's ignored `.tmp/rocketclaw/babysit-pr/<host>-<owner>-<repo>-<N>/`, with private permissions, no symlinked or ambiguously owned state, and no global fallback. The helper serializes state with its existing file lock, invocation fencing, atomic replacement, and recovery receipts; do not bypass those mechanisms.

## Direct helper calls

Set `workspace_root` and `SKILL_DIR` to verified absolute paths. Create a private owned `STATE_DIR` under the local path above; re-set variables in every separate shell call. Resolve the PR (including empty-`@` parent discovery) before calling: this helper requires an explicit numeric `--pr` and does not infer a PR from `@`.

```bash
(cd "$workspace_root" && python3 "$SKILL_DIR/scripts/pr-snapshot" snapshot --pr <N> --repo <host>/<owner>/<repo> --state-dir "$STATE_DIR" --start-invocation --invocation-budget-seconds <seconds>)
```

Capture emitted `invocation_id`, `invocation_started_at`, and `invocation_budget_seconds`. Every later snapshot/mark/watch supplies the same tuple as `--invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS"`. Never renew the budget mid-run. Only managed-layer transitions use `--continue-invocation`, carrying prior `invocation_dead_time_seconds` through `--continue-dead-time-seconds` and re-stating posture.

```bash
(cd "$workspace_root" && python3 "$SKILL_DIR/scripts/pr-snapshot" mark --pr <N> --repo <host>/<owner>/<repo> --state-dir "$STATE_DIR" --invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS" --disposition needs-human --residual-file <local-complete-typed-residual-path>)
(cd "$workspace_root" && python3 "$SKILL_DIR/scripts/pr-snapshot" mark --state-dir "$STATE_DIR" --invocation-id "$RUN_INVOCATION_ID" --session-started-at "$RUN_STARTED_AT" --invocation-budget-seconds "$RUN_BUDGET_SECONDS" --answer-decision <decision_id> --answer-file <local-exact-human-response-path>)
```

For ordinary completed work, use `mark --thread <id>` or `--comment <id>` with `--disposition dispatched` and any leaf-returned `--invariant-key`; CI uses `--check <key>`. All these marks include the same state directory and invocation tuple. Residual marks require PR/repo so covered threads are re-read after replies before freezing. Never fabricate an answer, receipt, claim, or confirmation in memory.

1. Read PR state, head repository/ref/OID, base identity, draft, threads with pagination, top-level comments, review bodies, all check rollups, review decision, and chain evidence. A missing page or failed probe is uncertainty, never empty success. Independently read the live base ref and require matching base/head parents in GitHub's generated merge before declaring certain mergeability. Historical base OID drift alone is not a blocker; unknown, racing, deleted, or failed live-ref evidence is. See `watch-loop.md`.
2. Stop on closed/merged, except a just-landed authorized stack transition. Capture the exact remote head SHA, not empty `@`; inspect `@-` for parent PR discovery as specified in `setup.md`. Capture managed pre-push baseline before delegating.
3. Feedback before CI: send all actionable unresolved threads and non-thread candidates to `ce-resolve-pr-feedback mode:pipeline` once. The resolver judges content; never filter solely by author or surface. Record acted-on item IDs and exact observations only after completed action. Save returned stable `invariant_key` values with covered items. Preserve `fixed-differently`, `declined`, and `not-addressing` verdicts for the report.
4. Persist each complete typed needs-human residual in one canonical decision set, with decision ID and frozen source observations. Re-read covered threads after replies before freezing. Leave threads open. Changed/disappeared evidence invalidates the whole grouped decision and reopens surviving sources; it never answers it. Only an exact human response recorded against that decision ID moves it into answered decisions. Apply that answer to matching sources without immediately re-parking unchanged evidence. Continue independent work.
5. Re-read remote head after feedback. If it moved, this snapshot's CI is stale; skip CI and start the next tick with fresh evidence.
6. Aggregate current-head failures in one pass. Flaky/infra: extract exact run ID and host-qualified base repository from the check URL, then `gh run rerun <run-id> --failed -R <host>/<owner>/<repo>`. Never omit the ID and open an unattended picker. Real failures: invoke `ce-debug mode:pipeline` once with job names and log tails. Accept only `fixed-and-pushed`, `fixed-not-pushed`, `flaky-infra`, `diagnosed-no-fix`, or `needs-human`. Record completed actions by check key and head; new heads clear check-dispatch state. Do not weaken tests, rebase, reset, or force-push to clear red checks.
7. Consume only an evidenced branch-currency item after comments and CI, following `branch-currency.md`; never derive maintenance from a clean PR's ordinary base drift. Preserve the exact claim/recovery/confirm protocol and canonical residuals.
8. After a target push, run only verified compatible manager-owned upstack maintenance (`stack.md`). Any mutation requires a fresh snapshot at the next tick, not a second mid-tick CI universe.

Track cross-head trajectory: recurring failures after a clear head (exclude same-SHA flapping), unresolved backlog trend, new threads, CI/review alternation, heads without a new low, and per-invariant unique-head rounds. Route recurrence/oscillation evidence to the relevant leaf before another mutation; a third unique-head pass for one invariant (two completed prior rounds) requires an approach-level assessment. Pass the whole trajectory, not a verdict. Legitimate progressive failure migration is repair, not non-convergence. The leaf distinguishes oscillation from external movement and can assess equivalent sibling sites as one bounded class. A review/CI contradiction becomes one cross-stream residual, not an arbitrary winner. Never claim unavailable independent review coverage.

Factual description refresh with verified run results is already authorized: preserve unrelated user text and issue links, apply without another yes/no or preview approval. If delegating to `ce-commit-push-pr mode:pipeline`, explicitly supply the already-authorized babysitting-maintenance context, verified run results, and those preservation constraints; never route it through standalone description-update/optional-rewrite approval. Optional unrelated rewrites still require approval, and declining one never blocks authorized monitoring. Respect higher-priority restrictions, actual permissions, opt-outs, genuine human choices, and final-merge boundaries.
