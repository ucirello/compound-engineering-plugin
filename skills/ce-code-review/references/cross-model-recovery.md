# Cross-Model Adversarial Pass: recovery branches

Read only from Stage 3d's native launch failure or Step 5's terminal no-usable-artifact branch. A peer that folded successfully never opens this file. Native receipts/collection replace the removed runner; every branch decides whether the adversarial lens is covered and by what.

## Outcomes that need a decision

- **Dispatch-infrastructure failure before launch receipt.** Native launch/preflight could not start. Recover only at Stage 3d before finalizing the local roster. Hold the exact resolved model, tier, provider, read-only boundary, adversarial brief and `jj diff --from <base-ref> --to @` scope fixed. Retry only new, plausibly recoverable failures within the original shared deadline; stop on a repeated failure or expired deadline. Success removes local adversarial from the roster. Exhaustion keeps local fallback and names lost corroboration. Never retry this prelaunch branch at fold-in after local adversarial might already have reviewed the brief.
- **Receipt returned, then infrastructure crash.** Stop/collect the failed native child and classify it before cleanup. At fold-in recover on the identical route, model, tier, scope and brief within the same deadline, only while failures are new/plausibly recoverable. Never broaden scope, substitute family or relax isolation. Repeated failure/deadline stops recovery; the peer was this lens's only cover, so Coverage says the **adversarial lens degraded**, not merely corroboration lost.
- **Ran but produced no usable output.** Terminal launch with missing/unparseable schema artifact differs from never-started. Coverage says `cross-model pass: peer ran, no usable output`. Empty well-shaped findings are valid no-additional-issues output and must not be discarded. On the full path peer failure alone does not fail the review, but coverage remains honest; focused requires a usable independent read or the local fallback, otherwise verdict is Not ready.
- **Failed/timeout/died without result.** Started outcomes are nonblocking but never silent: name target and terminal state in Coverage. Deadline cancellation is timeout, including its reason. A diagnostic proving no review triggers the classifications below.
- **Classify before deleting.** Read bounded native diagnostics/send audit, not a closed phrase list. Attribute account authentication failure only with positive evidence of provider-capable launch or provider response. Otherwise login-shaped text is execution-context evidence, not proof the user's account is logged out; do not prompt a login command. When provider dispatch proves credential failure, report observed failure and appropriate refresh remediation.
  - Session/usage quota or any authentication-shaped failure means no review: never retry the same route; use did-not-run fallback. Attribution changes explanation, not coverage.
  - Transient provider capacity/rate limits: the native supervisor may retry the same route **once only for exact overload 529**, holding all selection and scope plus shared deadline fixed. Once a provider no-review outcome reaches the orchestrator, dispatch local `adversarial-reviewer`; never restart the peer or switch recipients for this branch.
  - Max-turn exhaustion: dispatch local `adversarial-reviewer`; no retry or recipient switch.
  - Other failure: name it, do not automatically invoke did-not-run fallback.
- **Did-not-run fallback** (including first no-review outcome): if no replacement has yet been tried, the failed recipient was not explicitly user-stated, and an attested-different available+allowlisted native model remains, resolve through `opencode.models`, disclose its new recipient/model/tier, then launch a native subagent/shell child with only remaining original deadline. No silent recipient changes inside a child. One replacement only, never a third peer. If that replacement also does not review, or the failed recipient was explicit, or no eligible replacement exists, dispatch local `adversarial-reviewer` and collect it in this turn. Coverage: `adversarial lens: in-process fallback (cross-model peer not run: <reason>)`; outcome `in-process-fallback`. Never call it `harness-native fallback`, which is ce-work's signal for a review that ran without ce-code-review. Config/default preferences are not explicit user preferences.

## Trust boundary

The peer reviews the current tree against `jj diff --from <base-ref> --to @` read-only, with JJ commands run from the target workspace's absolute root. Code/diff is disclosed to the selected model provider (OpenAI, Anthropic, xAI or a configured operational provider); `CROSS_MODEL_PEERS` restricts recipients and intermediaries. All state, diagnostics, fallback/error paths and source exports remain under local `.tmp/`; gh requires `GIT_DIR=$(jj git root)` in the target root.

Unlike self-contained tool-less document review, code review needs surrounding code. Native children can read source but cannot mutate, run arbitrary shell, reach network tools or delegate; reviewed-project configuration/plugins/agents/integrations must not load. Parent-controlled nonmutating JJ inspection or precomputed evidence supplies exact hunks. If isolation cannot enforce this, fail the route rather than loosen it. Preserve compatibility meanings, not foreign dispatches: Codex read-only sandbox, Claude denies mutators/Bash/Task/MCP with Read allowed, Grok/Cursor ask/dontAsk without write/force/yolo, OpenCode isolated operator-owned configuration with edit/bash/webfetch/task denied and Read allowed. Operator-owned global integrations remain a residual boundary distinct from untrusted project tools.

Every transfer has a private one-line audit even in `mode:agent`. Stop and collect every started child, within the original deadline plus at most 10s shutdown, and delete its private job directory after classification/fold. Do not leave processes/sessions outstanding or claim independence/coverage without a receipt and usable result.
