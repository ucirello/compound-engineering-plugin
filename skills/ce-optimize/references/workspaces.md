# Native execution and workspace lifecycle

Use latest JJ (https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace). Never launch Git directly. Every JJ invocation uses the target workspace's absolute root as cwd, including worker commands. For repository-scoped `gh`, first export `GIT_DIR=$(jj git root)` from that root. Temporary prompts, exports, measurement status and scratch files belong under that workspace's `.tmp/`; ensure `.tmp/` is ignored. Never use OS temporary storage.

The explicit worker and judge dispatches in this skill authorize delegation where host policy permits user-or-skill requests. Check actual host restrictions separately from model selection and depth. Read configured choices/tiers and resolve models with `opencode.models`; if model overrides require an explicit user request, omit the optional model argument and use a suitable inherited model. Preserve configured intent and disclose unmet fixed routes. Independent contexts are required for judges and confirmation; same-model contexts are not cross-model independence. A required unavailable independent pass is incomplete, never verified. Classify actual tool errors as permission, unavailable tool, model rejection, depth, or active capacity. Only temporary active capacity is backpressure; do not retry denials or evade depth using shell or another harness. Native subagents/shell replace external harness dispatch while retaining receipts, bounded retries, security intent, and result validation. The legacy `codex` spec token remains accepted as routing intent, not an instruction to execute Codex.

Before creating isolation, detect harness-provided or existing isolation and verify ownership, path, base and lifecycle authority. Reuse existing isolation unchanged, even its older name. Never reset or clean an existing experiment to reuse it. If supported, request harness-native colocated JJ isolation and session adoption. Unsupported required naming or colocation is a compatibility blocker, not a fallback to Git or unowned workspaces.

For a new experiment capture the local creation date once. Derive a meaningful kebab slug from the spec and experiment index; normalize an existing caller date prefix rather than doubling it. Persist `YYYYMMDD-optimize-<spec>-exp-<NNN>` before creation. The JJ name and absolute destination basename are identical, under `<source-root>/.tmp/rocketclaw/optimize/`. Check both registered workspace names and filesystem destinations; choose `-2`, `-3`, etc. on collisions, never timestamps/PIDs/random substitutes. Keep the identity stable across retries, resumes and midnight. PR/source bookmarks remain unchanged. Verify the optimization bookmark resolves to exactly one intended base commit, capture its full ID, then from the source absolute root:

```bash
(cd "$workspace_root" && jj workspace add --colocate --name "$name" --revision "$verified_base" "$absolute_owned_destination")
(cd "$absolute_owned_destination" && jj git colocation status)
```

Verify registration, path, base parent and colocation before dispatch. Adopt/move the harness session through its supported session lifecycle when changing its primary workspace. Never bypass harness ownership. Copy declared shared files only after containment checks: relative sources and real destinations must remain inside their respective roots; reject traversal/symlink escapes. Preserve file/directory hierarchy, copy files and directories without deleting existing unrelated destinations; handle absolute shared sources only when explicitly approved and copy their basenames without collision. Retain configured port parameterization. Count registrations using `jj workspace list` from the source absolute root, not directory glob counts.

For integration preserve the captured base/head: inspect `jj diff --from "$base_sha" --to "$head_sha"` and the exact range for scope, marker-only tip and parent checks. Fetch/push the exact authorized result bookmark with `jj git fetch`/`jj git push`; never substitute a different ref. Integrate only the candidate (not its result-marker child): use native `jj new <current-baseline> <candidate>` for a merge or `jj duplicate <candidate> --onto <current-baseline>` for runner-up replay, inspect conflicts and scope, remeasure the combined snapshot, and move only the optimization bookmark after acceptance. On rejection preserve prior baseline and evidence; discard only verified run-owned experimental changes with explicit workflow authority, never unrelated changes. Before descriptions, read `messages.md` in full. Record full commit IDs in the ledger. Workspace/bookmark cleanup is never implicit integration.

## Retirement

Stop all workers first. Verify cleanup authorization, harness lifecycle authority, exact registered name, absolute path, run ownership, and integration for accepted experiments. Inspect tracked changes, conflicts, ignored and untracked content; JJ's removal snapshot does not protect ignored/untracked files. Preserve unrelated, uncertain, nondisposable or still-referenced content and stop. Copy required metrics, result markers, log, receipts and recovery evidence to the surviving state root outside the target; read back the copies. Create/verify recovery references as needed and preserve best/archive/recovery bookmarks. Leave the target directory and move any active harness session to the surviving workspace before removal.

```bash
(cd "$surviving_workspace_root" && jj workspace remove "$verified_workspace_name")
```

Verify both deregistration with `jj workspace list` and disappearance of the exact directory. A successful exit with deletion warnings is not success. Retain remaining state and report a blocker on any incomplete removal; never force-delete or use Git cleanup. `jj workspace forget` is only for an explicitly authorized unregister-and-preserve-files operation. Bookmark deletion is separate, exact-name and separately authorized; never remove best/archive/recovery or still-needed result refs. Apply this lifecycle to winner, runner-up, failed and batch cleanup alike.
