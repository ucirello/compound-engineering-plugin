# Native model-selected implementation

Read this when live intent, a typed caller binding, or enabled standing configuration selects an implementation route. All execution uses the actual OpenCode host's native subagent tools and shell/JJ operations; never launch another harness CLI or a bundled dispatcher. Model/provider names in configuration are compatibility intent, not executable routes.

## Resolve and lock the route

Preserve layered `.rocketclaw/config.local.yaml`, `config.yaml`, and documented `config.example.yaml` choices. Resolve `work_engine_mode` (`off | prefer | require`), ordered `work_engine_preferences` entries (`harness`, optional `model`), and per-harness `work_engine_effort` without changing their schema or precedence. Preserve configured model tiers and exact model pins. Compatibility targets remain `codex`, `claude`, `grok`, `cursor`, `composer`, `opencode`, and `antigravity`; record the original target separately from the actual OpenCode route. A compatibility name never authorizes launching that harness.

Discover offered models with `opencode.models`, mapping provider/model IDs only from returned data. Preflight ordered candidates without sending task content. Never replace an exact model with a guessed family equivalent. If the native tool cannot enforce requested effort or restrictions, mark that candidate unavailable with evidence. Separate permission to delegate from permission to override a model: when host policy requires an explicit user model request, configuration alone is insufficient. Use an inherited model only where fallback is permitted and disclose the unmet configured route.

These explicit worker instructions request delegation when the actual host permits user-OR-loaded-skill authorization; no second approval is needed in that case. Respect unconditional policy, actual denial, missing tools, and model rejection without bypass or repeated denied calls. Verify delegation depth separately through package and consuming configuration discovery. Setup must merge integer `experimental.subagent_depth >= 3` into the existing global `~/.config/opencode/opencode.json`, or discover the actual global directory using `opencode debug paths` / `opencode debug paths config` and its existing `opencode.json(c)`. Preserve sibling settings, higher depth, and the existing JSON/JSONC document; document this prerequisite, never modify global configuration. Package installation alone does not enable consumer depth; higher-precedence config must not lower it.

Lock authorizing source, requested target/model/effort, actual route/model (or `unverified`), restrictions and rejected candidates in the run receipt before dispatch. A `require` binding that cannot be honored is blocked. A `prefer` binding may fall back to the inherited native route with the observed reason; do not call it cross-model execution or independent coverage. Never silently substitute a recipient after dispatch. Classify actual errors as permission denial, model rejection, depth/capacity, missing tool, or execution failure.

## Durable native unit transaction

1. Resolve the canonical absolute JJ root and exact source/base commit IDs from that root. Record the pre-work inventory, conflicts, untracked and ignored content, plan or prompt digest, owned paths, dependencies, verification contract and run ID under `<canonical-root>/.tmp/rocketclaw/ce-work/<run-id>/`. A configured `CE_WORK_RUNS_ROOT` must be an absolute run parent within the target root's `.tmp`, never an OS temporary directory. Reuse a recovery run without redispatch, changing route, or rerunning completed verification. Recovery requests inspect receipts only unless the user authorizes the named next action.
2. Use the isolation-first protocol in `workspace-setup.md`. Reuse verified harness-owned isolation unchanged. If another isolated workspace is required, use the harness-native capability only when it can enforce the requested dated identity and colocation; otherwise take the safe decision path there. Save exact registered name, absolute path, ownership, source bookmarks and base. For JJ creation use explicit `jj workspace add --colocate`; verify colocation from the new absolute root before writing.
3. Write a minimal unit packet inside the run root: goal, owned paths, approach, patterns, acceptance, cited constraints/settled decisions, verification/evidence strategy, dependency bases and matched pack rules. Do not send the whole conversation or plan by default. Hash the packet; receipt binds run/unit/attempt IDs, exact base, packet path/digest, worker session and requested/actual model. Native session ownership and adoption stay with the harness. Workers edit/test only assigned paths in their absolute workspace and do not publish, integrate or make canonical commits.
4. Dispatch one native subagent seeded with `agents/implementation-worker.md` and the bounded packet. Record tool/session identity, start, terminal outcome, progress and result path. Use native tool lifecycle/waiting rather than a detached runner. Preserve the existing bounded production budget: 7200-second hard limit and 600-second progress-idle window when progress is trustworthy; otherwise report hard-only monitoring. If the tool cannot enforce a budget, disclose that limitation instead of claiming enforcement. Stop on the bound, retaining partial results. At most one retry of a recoverable execution failure is allowed after reconciling exact workspace/session state; never retry denial or an ambiguous still-running worker.
5. Inspect the actual workspace diff and conflicts from its absolute root; reported paths alone are insufficient. Reject out-of-scope edits and stale bases, preserving evidence. Snapshot the exact worker result as a transport revision and retain a run recovery bookmark; record its immutable commit ID and full diff. The orchestrator owns integration. Serialize integration, recheck the recorded canonical base and pre-work inventory, then use native JJ operations such as `jj new <canonical-head> <transport-id>` for a separately inspected merge revision. Never substitute another ref or range, and never overwrite unrelated work to resolve conflicts. Conflicts, dirty collisions or an uncertain source stop integration with recovery state retained.
6. The host runs authoritative verification against the integrated revision with Python bytecode disabled, records commands, exit status and evidence, then makes the owned-path canonical commit using `implementation-loop.md`. A worker's success is not host verification. Record source/packet hashes, dependency/wave position, requested and actual route/model, worker outcome, transport and canonical IDs, integration/verification state, cleanup state and recovery location for every attempt. Read back receipts before reporting completion. Advance dependencies only after the canonical receipt exists; stale or colliding siblings must be revalidated or rerun on the new exact base.
7. Cleanup is optional, separately authorized, and governed by `workspace-setup.md`; completion alone never permits deletion. Preserve archive/best/recovery references and evidence outside the target before any destructive action. An incomplete removal remains an explicit retained-state receipt, not success.

## Result and tail

Keep `implementation-result-schema.json` as the worker-result contract. Preserve complete verification evidence and truthful incomplete coverage. Same-model distinct workers do not establish cross-model independence; if a required distinct-model pass is unavailable, report it incomplete. Inline recovery is allowed only when the caller's independence, coverage and route requirements permit it. Never evade a denied dispatch.

Return requested/actual route, model, effort, fallback reason, run/source digest, per-unit receipts, plan checkpoint (or null), blockers and recovery path using `return-to-caller.md`. Standalone resumes `shipping-workflow.md`; return-to-caller never ships. No engine changes the tail owner.
