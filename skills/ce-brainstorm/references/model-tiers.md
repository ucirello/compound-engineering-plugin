# Model Tiers

Read this when dispatching a sub-agent (the Phase 1.1 grounding scout, the Phase 2.6 claim verifier, or the opt-in Slack researcher). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** — the grounding scout: retrieval and quoting work. Resolve the platform's cheapest capable model with `opencode.models` when model selection is permitted. "Capable" is part of the spec — escalate to the generation tier when the repo is large or the stack obscure.
- **Generation tier** — the claim verifier: evidence-driven mechanical verification. Resolve the platform's mid-tier model with `opencode.models` when model selection is permitted. If model names are unknown or overrides are forbidden, omit the override and inherit rather than guessing; disclose any unmet configured tier.
- **Ceiling tier** — the dialogue itself. Questions, approaches, synthesis, and the requirements-only unified plan run in the main conversation on the orchestrator's model, except the separately activated optional approach elevation in `references/reasoning-elevation.md`.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the scout and verifier on the inherited model and keep their read budgets and output caps — cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, do the topic scan inline at Phase 1.1 — still writing the grounding dossier to the scratch path, because downstream consumers (the Phase 2.6 verifier, the ce-plan handoff) receive that path — and verify claims inline before the Phase 3 write, with the same budgets.

This skill explicitly requests native subagents for the scout, verifier, and opt-in Slack researcher. Under a user-or-loaded-skill delegation rule this satisfies the skill exception; do not ask again solely because the user did not name subagents. Respect an unconditional higher-priority prohibition, tool absence, or actual denial. Delegation permission is separate from model selection: when a user model request is required, do not pass the optional `model` argument based only on a configured tier. Use a capable inherited model and disclose unmet intent. Same-model agents are separate agents, not proof of cross-model independence.

Nesting depth is a separate constraint: inspect the host's configured/effective depth evidence and classify actual failures accurately. Correct an authorized pre-launch argument rejection once; leave capacity-limited work queued where useful, or use the permitted inline degradation above. Never retry a permission denial or bypass depth through another harness or shell. Inline verification is not independent coverage; disclose any independence or required cross-model pass that could not be completed. Preserve read budgets, output caps, dossier paths, and failure evidence.
