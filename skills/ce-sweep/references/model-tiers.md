# Model Tiers

Read this when dispatching a native OpenCode subagent (a source-persona fetch subagent or a media-analyzer subagent). Use `opencode.models` to discover exact available model IDs when a model override is permitted. Subagent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, that is the intended route instead of the default tier above. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier. Pass a model override only if the host permits it; when it requires an explicit user model request, configuration or skill guidance alone is not permission.

**Degradation rule.** This skill explicitly requests subagents in 2b and 2e. Proceed without another approval when the host permits skill-requested delegation; obey higher-priority prohibitions. If per-agent model selection is unavailable or disallowed, use a suitable inherited model and retain the read budgets and output caps; report unmet configured routes. If delegation is unavailable, denied, or blocked by exhausted nesting depth, use the inline source fetch or media analysis only where permitted, with the same budgets and boundaries. Still download media to scratch and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Treat delegation permission, model permission, and effective nesting depth separately. Check the effective OpenCode configuration (including any higher-precedence setting and the `experimental.subagent_depth` limit) and classify failures by the actual error and whether an agent launched. Correct a pre-launch argument rejection once if allowed, without retrying a denial. Leave transient capacity-limited work queued; do not retry an exhausted nesting limit or use another harness or shell to evade it. Apply the inline degradation above or the more specific failure rule in the applicable phase or persona.
