# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers what happens when the harness is full, how review agents are released, and the permission mode.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means the harness is full, not that the reviewer failed: leave the reviewer queued and retry once after a verified slot frees. Classify depth exhaustion separately from capacity, permission denial, model rejection, and missing tools. Do not retry denials or use a different route to evade them. After a failed bounded recovery, use the same prompt asset inline only when the caller permits that coverage; disclose the substitution and any incomplete required independence or model pass.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** This skill's explicit reviewer instructions count as a delegation request where actual host policy permits user- or loaded-skill-requested delegation; no second approval is needed. Unconditional higher policy, actual denials, and unavailable capabilities remain binding. Leave permission settings inherited; do not invent permission parameters or bypass restrictions. Model override permission is separate: use `opencode.models` for discovery, and omit model selection when the host requires a user model request that has not been made. Disclose unmet configured routing.

**Depth prerequisite.** Discover the effective OpenCode configuration before deep delegation. Both package defaults and the consuming configuration must support `experimental.subagent_depth` as an integer at least `3`; a higher-precedence setting must not lower it. For user-level setup, locate the actual global directory via `opencode debug paths` / `opencode debug paths config`, then merge that setting into the existing `opencode.json` or `opencode.jsonc` (normally under `~/.config/opencode/`), preserving siblings, unrelated settings, and any higher depth. Do not create a competing configuration document. Package installation alone does not enable consumer depth. These are setup instructions, not authorization to modify host files during review. Treat actual dispatch depth errors separately from permission or model errors.
