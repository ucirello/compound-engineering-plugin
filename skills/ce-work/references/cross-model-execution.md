# Cross-Model Execution Contract

Read when execution-engines.md selects a configured route or when recovering an existing run. OpenCode-native `opencode.models`, subagents, and shell replace harness dispatch adapters and workspace controllers. Do not invoke another harness, resurrect bridge scripts, or infer a completed transaction from a worker's prose.

## Resolve intent without changing authority

Keep the precedence in execution-engines.md. Resolve `work_engine_mode` (`off | prefer | require`), `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml` then `config.yaml`; a present local list/map, including empty, replaces the team value. Live intent and typed bindings retain provenance. Preferences remain ordered `{harness, model?}` objects; supported intent values remain `codex | claude | grok | cursor | opencode | antigravity`. Model and effort strings are data, never shell commands.

Preserve provider/model intent: Codex requests its configured GPT model; Claude requests its configured Claude model; Grok native versus Grok through Cursor remain distinct requested intermediaries; Cursor default, Composer-family, and explicit Cursor model pins remain distinct. The requested Grok-through-Cursor default is `grok-4.7[context=256k,reasoning_effort=high,fast=true]`; Composer default is `composer-2.5[fast=true]`. Antigravity's unpinned Gemini preference order remains `gemini-4-argon`, then `gemini-3.8-flash`; explicit pins stay exact. Preserve requested reasoning tiers, including Codex `xhigh`, Claude `max`, and Antigravity `low | medium | high`; do not silently translate to an available weaker tier.

Discover available models with `opencode.models`. A provider model may be available natively while its requested harness/intermediary is not: record that distinction and do not claim exact-route coverage. Preflight candidates in order without sending repository content, record unavailable reasons, and select a single authorized native model route. Model aliases require evidence and disclosure; actual served identity remains unverified unless the runtime supplies it. No CLI installation or alternate-harness launch is a preflight fallback.

Delegation permission, model-selection permission, and remaining nesting depth are independent. This skill explicitly requests native implementation subagents; that satisfies a user-OR-skill delegation rule without another approval, not an unconditional prohibition. If model overrides require an explicit user model request, omit the optional model argument and use a suitable inherited model for permitted work. Record unmet pins, effort, or required cross-model independence as incomplete coverage; separate same-model workers do not establish cross-model independence. Classify an actual rejection as permission, model argument, missing capability, or depth/capacity; never evade it through shell or another harness. Correct a prelaunch argument error once; leave capacity-limited work queued. Do not retry denied dispatch.

`prefer` and `require` retain the requested identity while viable. On genuine unavailability, disclose every attempted candidate and reason once and continue on the inherited native route where the implementation contract permits it, without claiming the required model/route was satisfied. Never change to an unrequested external recipient. A live, unreachable, or successful but unreconciled attempt is not unavailable and forbids duplicate work or fallback.

## Durable run and bounded packet

Store run state, packet sources, logs, error paths, and evidence only under the absolute workspace's ignored `.tmp/rocketclaw/work/<run-id>/`. `CE_WORK_RUNS_ROOT`, when used, is a local `.tmp/` parent, not a run id; reject locations outside local `.tmp/`. Check `.tmp` is ignored. Use one scalar stable run id and retain it across retry/resume. Write a JSON manifest atomically with shell/file tools after each transition, then read it back before continuing. Record repository identity, canonical absolute root, bookmark, exact base commit, source kind and SHA-256 digest, binding provenance, requested/actual route and model, intermediaries, requested effort and served-effort receipt (`unverified` without proof), fallback reason, unit/attempt ids, dependencies and wave base, worker handle, packet digest, lifecycle state, blockers, and recovery path. Never fabricate a controller receipt.

For bare prompts write a bounded brief with Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and conservative Units. No concrete goal/scope/verification means return to triage, not dispatch. Preserve a private source copy/digest. For plans, a disclosed plan-only checkpoint is allowed only when that exact plan is the sole working-copy change; unrelated dirt is not implicitly checkpointable. Compose any checkpoint message under implementation-loop.md's runtime standards.

The unit packet includes the Goal Capsule, Definition of Done, active unit, applicable Verification Contract, cited R/F/AE/KTD excerpts, reverse-linked Product Contract Key Decisions (`Governs R…`), prototype citations and availability/authority qualifications, matched Compound Pack rules, expected files, evidence strategy, inherited authority and exclusions. Inspect accessible cited prototypes before affected implementation. Do not send the whole conversation or plan by default. Hash the final packet and record exactly that path/digest before dispatch. Workers may narrow authority, never broaden it; no peers, route changes, canonical commits, pushes, PRs, shipping, or out-of-workspace edits.

## Isolation, authoring, and host integration

Follow workspace-setup.md's isolation contract, including detect/reuse first, explicit `jj workspace add --colocate`, dated stable identity and absolute paths, colocation verification and harness lifecycle. Ordinary synchronous native units may use the active checkout. Concurrent workers require verified isolation or execution-strategy.md's exclusive shared-wave contract. Verify the exact base commit before editing; dirty dependencies cannot be replaced by a default-branch snapshot.

1. Record `prepared` only after canonical identity/base/cleanliness and packet read-back. After preparation, route choice is locked for that attempt; latency or preference for simpler inline work does not authorize bypass.
2. Dispatch one fresh native subagent per unit with the recorded packet, absolute owned workspace, verified base, and `references/agents/implementation-worker.md`. Record its returned handle and actual launch state. Keep the native permission defaults. If the tool has no durable handles or cancellation, disclose that limitation; do not invent process supervision.
3. Observe without steering or duplicate launches. Use supported native wait/status calls in bounded observation intervals (at most 60 seconds when available), report meaningful progress, and retain the existing 7200-second hard supervision budget. An idle limit of 600 seconds applies only to trustworthy incremental activity; otherwise disable idle inference (`hard-only`). Absence of progress alone is not failure. Stop/cancel only with supported lifecycle authority, then verify terminal state; loss of contact preserves the attempt as live.
4. After authoritative terminal completion, inspect the actual JJ diff and all changed paths, binary/mode/rename/deletion evidence, worker result, scope expansion and verification evidence. Record exact base/final commit and recovery bookmark before integration. A completed worker message proves authoring only. Unexpected scope blocks integration; preserve its workspace and evidence.
5. Acquire a host-owned manifest integration lock, recheck canonical identity and expected base, and preserve a pre-integration recovery bookmark and exact tracked/conflict snapshot. Apply only the accepted unit with native JJ (`jj rebase`/`jj squash` as appropriate to the verified graph), never an unreviewed broad restore. Read https://docs.jj-vcs.dev/latest/cli-reference/ for the selected operation. Run every JJ command from the absolute target workspace root, not via `-R` alone.
6. Run the unit's authoritative Verification Contract command in the canonical absolute root, capture its exit code directly and keep its private log. Use explicit `bash -o pipefail -c` for shell syntax, not a quoted expression passed as argv. Compare tracked state and conflicts before/after verification; unexpected tracked mutation fails reconciliation. Inventory ignored/untracked files separately with local filesystem metadata and disclose created/changed/removed counts and bounded paths; do not copy, delete or claim protection of caches, databases or `.env` files. Ignored changes are not tracked-state proof.
7. Only after successful reconciliation compose the host-owned canonical message under implementation-loop.md and record canonical commit identity, parent/tree, authoritative evidence, and read-back receipt. Worker-authored transport descriptions are never canonical messages. On failure, preserve the lock and recovery refs until exact worker-attributed tracked restoration is verified; never discard unrelated or ignored work. If restoration cannot be proved, return blocked with state intact. Release the lock only after verified commit or exact restoration.
8. Before retiring an owned isolated workspace, copy/read back receipts outside it and follow workspace-setup.md's safe `jj workspace remove` lifecycle. Cleanup failure retains state and blocks claims of complete cleanup; bookmark deletion is separate.
9. Run source-wide Verification Contract gates from a clean canonical snapshot, capture command exit and tracked reconciliation plus ignored-state disclosure, and persist a run verification receipt. A failed gate blocks shipping/complete return even when cleanup succeeded.

Use separate tool calls for prepare, dispatch, observe, terminal inspection, integration and verification; never hide the lifecycle in one shell loop. Report each transition, source kind, requested/actual identity, checkpoint, verification, restoration, canonical commit, cleanup and blocker/recovery path.

## Parallel waves

Only execution-strategy.md's Safety Check can authorize a bounded 3–5-worker wave. Record one clean exact wave base and dependency order; every isolated member starts there. Dispatch ready peers together, await and inspect all terminal outputs before the first integration. Same-path or semantic contention blocks blind application. Integrate and verify one result at a time in dependency order, recording each exact host canonical commit as the next permitted base. Revalidate each sibling against that advancing tree. Conflict, scope expansion or test/commit failure freezes dependents until exact restoration and lock release; unaffected siblings may proceed only after readiness is recomputed. Repeated collision or unprovable restoration disables further waves without discarding results.

## Resume and fallback exactly once

Supplied run ids are authoritative. With no id, plan-backed discovery may select only one unfinished manifest matching exact repository/bookmark/source digest; multiple matches block selection. Prompt-backed recovery requires the disclosed id. Unsafe/foreign manifests block rather than silently skip. Recovery does not dispatch new work, change route, select another source, or enter a shipping tail.

Reconcile native handle status, exact parent/tree, packet and evidence digests before advancing an interrupted transition. A recorded live job stays authoritative until terminal proof or supported cancellation. Reuse already-recorded output only when exact base/tree evidence matches; unknown dirt blocks destructive restoration. A commit that landed before receipt persistence may be adopted only with exact pre-fold parent/tree evidence. Completed runs with successful source-wide receipt are observation-only: return stored receipts without rerunning checks, recommitting or shipping. Missing required receipts are recovery blockers.

After exact restoration or explicitly authorized abandonment, lock release and terminal worker proof, record one fallback claim for the unit before inherited-model native implementation. Repeated claim means do not launch it again. A retry uses a fresh attempt under the same run id and unchanged dependency/wave contract, retaining prior receipts. Native fallback completion requires exact accepted commit plus a SHA-256 verification-evidence digest and bounded summary. All units terminal and a successful run verification receipt are required for complete implementation; unavailable required cross-model coverage remains explicitly incomplete.

Standalone resumes quality/shipping only after implementation completes. Return-to-caller returns receipts with `standalone_shipping_skipped: true`; it never runs the caller's finishing tail.
