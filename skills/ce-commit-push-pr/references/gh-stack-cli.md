# Stack metadata and native JJ operations

Use native JJ for all local revision, bookmark, workspace and transport operations; never use another tool's checkout/init/add/top/submit command as a workspace bridge. `gh stack` metadata may describe a managed stack but is not authority to change its topology through Git. Every repository gh call uses `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh <arguments>)`; every JJ call runs with the absolute target workspace root as cwd. See https://docs.jj-vcs.dev/latest/git-experts/ and https://docs.jj-vcs.dev/latest/cli-reference/.

`gh stack view --json` can report trunk, currentBranch, branches with name/head/base/isCurrent/isMerged/needsRebase and PR number/url/state. Its base is the last contained parent SHA, not necessarily the parent's current tip; branch order is not guaranteed. Verify explicit parent relationships from captured commits and PR bases, never infer order from array order. Read command help if its metadata contract differs and report the discrepancy. Missing command or unavailable stack metadata is a classified residual, not evidence that no stack exists.

Resolve parent PRs by explicit number/URL using `gh pr view <ref> --json headRefName,headRefOid,author,baseRefName,headRepositoryOwner,isCrossRepository`. A bare name describes local state only. Match repository, owner, bookmark and exact commit; a stale/colliding name must never be reset. Fetch the exact verified source bookmark using JJ and verify headRefOid; unavailable exact refs stop or use read-only API evidence, never fetch a substitute. Validate names as data and pass via argv/secure quoting, never interpolate untrusted shell syntax.

Native stacks use one feature bookmark and PR per independently reviewable layer. Create/adopt bookmarks only at verified layer tips, push explicitly through `jj git push`, and set each PR base to its immediate parent bookmark. Never adopt another author's standalone PR as a managed bottom layer without authority. Existing externally managed stacks retain their manager and topology: if an authorized JJ-native update cannot preserve its metadata/receipts, stop with a compatibility residual rather than creating a second stack or bypassing its manager.

Do not use `gh stack link` to pretend a locally managed stack was registered: it supplies GitHub links, not local manager tracking. Do not use `gh pr merge` for a managed stack member. Landing remains `ce-babysit-pr` under explicit `posture:stack-land` with a compatible stack-aware landing route, or the user; unavailable routing is a blocker, not a single-PR merge fallback.
