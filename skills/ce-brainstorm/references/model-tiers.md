# Model Tiers

Read this when dispatching a sub-agent (the Phase 1.1 grounding scout, the Phase 2.6 claim verifier, or the opt-in Slack researcher). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** — the grounding scout: retrieval and quoting work. Resolve the cheapest capable OpenCode model with `opencode.models` when model overrides are permitted. "Capable" is part of the spec — escalate to the generation tier when the repo is large or the stack obscure.
- **Generation tier** — the claim verifier: evidence-driven mechanical verification. Resolve a mid-tier model with `opencode.models` when overrides are permitted. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** — the dialogue itself. Questions, approaches, synthesis, and the requirements-only unified plan run in the main conversation on the orchestrator's model; nothing is dispatched for them.

**Permission and capacity.** This skill explicitly requests native OpenCode scout/verifier/researcher subagents; under a user-OR-loaded-skill delegation rule no second approval is needed. Respect unconditional prohibitions, missing tools, and actual denials. Delegation does not authorize optional model arguments: where the host requires an explicit user model request, config tiers alone do not qualify. Use suitable inherited-model reviewers and disclose unmet tier intent. Separate same-model agents are not cross-model independence. Check effective nesting through the runtime configuration-discovery procedure in `reasoning-elevation.md`, independently of permission; a configured depth does not guarantee launch capacity.

**Degradation rule.** When model selection is unavailable or forbidden, dispatch permitted scout and verifier subagents on the inherited model and keep their read budgets and output caps — cost control then comes from structure, not tiering. When native delegation is unavailable, prohibited, or capacity-limited, do the topic scan inline at Phase 1.1 — still writing the grounding dossier to the scratch path, because downstream consumers receive that path — and verify claims inline before the Phase 3 write, with the same budgets. Disclose inline verification; do not claim independent coverage or a required different-model pass that did not run.

Classify actual errors as depth/capacity, permission, model-argument rejection, or missing tool, and record whether an agent launched. Correct an allowed pre-launch argument rejection once; do not retry a denied operation, evade depth through another harness/shell, or silently change a fixed route. Use the permitted inline degradation above if dispatch cannot proceed.
