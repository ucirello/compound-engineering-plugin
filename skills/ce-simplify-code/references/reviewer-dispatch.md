# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers the reviewers' model, what happens when the harness is full, how review agents are released, and the permission mode.

**Delegation permission.** This skill explicitly requests reviewers, satisfying a host rule permitting delegation when the user OR a loaded skill requests it; do not ask for redundant approval. An unconditional higher-priority prohibition, missing tool, or actual permission denial still controls. Never retry a denied call or bypass it through shell or another harness.

**Model selection.** Preserve the balanced mid-tier default and configured role choices as intent; explicit user choices take precedence. Resolve permitted model requests with `opencode.models`. Delegation permission does not grant model-override permission: when the host requires an explicit user model request, omit the optional model argument without one, even if configuration names a model. Use suitable inherited-model reviewers instead and disclose any unmet tier or route. Separate same-model reviewers are not cross-model verification; a required unavailable different-model pass remains incomplete.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Each reviewer starts in a fresh native subagent whose context holds only its own rubric and inputs. The one exception is the combined reviewer that `references/single-pass.md` chooses below a size cutoff, which is itself one reviewer. Otherwise do not combine reviewers in one prompt, and do not send a reviewer to an agent that already ran another. Queue the reviewers and launch only as many as the harness accepts at once. A concurrency or active-agent-limit error means leave the reviewer queued until a running reviewer finishes and supported release frees a slot; it is not an inline-fallback trigger. Classify actual errors separately as nesting-depth exhaustion, permission denial, model-argument rejection, or missing tool. Permission does not guarantee nesting capacity; inspect effective OpenCode configuration rather than assuming it. Do not repeat denied calls or evade depth limits. If permitted dispatch cannot recover, an allowed inline pass may use the same prompt asset, disclosed as non-independent coverage; when independence is required, leave that pass incomplete and report it instead. A forbidden delegation operation never authorizes an alternative dispatch route.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Compatibility mappings (not dispatch routes).** The balanced mid-tier corresponds to the Sonnet class in Claude Code. Claude Code's `Agent`/`Task` and Codex's `spawn_agent` are other hosts' subagent mappings, not tools to invoke from OpenCode; task wording alone does not select a model. Use OpenCode-native dispatch here.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.
