# OpenCode review subagents

This skill explicitly requests native delegation for its trivial-PR check, selected reviewers (including a covered peer), finish leaves and validator. Resolve three distinct constraints before dispatch:

1. **Delegation permission.** Where the host permits delegation at the user's **or** a loaded skill's explicit request, this request qualifies without a second approval. A higher-priority prohibition, actual denial, or absent tool still applies. Never route around it using shell or another harness.
2. **Model-override permission.** A requested tier or configured pin is intent, not permission. If the host allows an override only on an explicit user request and none applies, omit the optional `model` and effort/variant arguments. Use inherited-model reviewers where that meets the review contract. Separate contexts do not prove different models; if a required tier, fixed route, or different-model pass cannot be satisfied, say which part of coverage is incomplete.
3. **Nesting depth.** Query the running session's OpenCode server at `GET /api/config` with `location[directory]` set to the absolute project location (omit only when it is the verified server default). The API returns config sources **from lowest to highest priority**: resolve the last defined `experimental.subagent_depth`, not just the package file's value. OpenCode defaults to `1` when unset; RocketClaw requires a user-level value of at least `3` that higher-precedence config does not lower. Check current nesting against the effective limit. Use the actual launch error to distinguish exhausted depth, temporary slot capacity, missing tool, permission denial, and rejected model/effort. If effective depth cannot be established, do not assume spare capacity. Never evade a depth limit or change config during review. See [OpenCode V2 configuration](https://opencode.ai/v2/docs/config) and its [API](https://opencode.ai/v2/docs/api).

**Model intent.** When overrides are permitted, use the live/user/project named model before the role config, then the tier named at the dispatch site (cheap for triviality, session for core/finish by default, mid-tier for other local personas). Use `opencode.models` to resolve a concrete available `provider/model` and supported variant and the native subagent's actual argument contract. Do not infer a served model from the catalog or use an unrecognized flag. The orchestrator keeps its session model.

**Bounded native collection.** Prefer an advertised bounded native wait. For OpenCode V2's asynchronous subagent receipt, use the same running server's documented `POST /api/experimental/session/{sessionID}/wait`, e.g. `opencode api post "/api/experimental/session/$child_id/wait"` in a foreground shell call with its timeout set to the remaining budget; no new OpenCode session or polling loop.
