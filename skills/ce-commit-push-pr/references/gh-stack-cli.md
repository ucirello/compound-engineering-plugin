# Stack publishing through JJ and GitHub

Do not run Git-backed stack checkout/init/add/submit commands: they invoke the Git executable. Manage local topology with JJ and publish explicit bookmarks. `gh stack link` is GitHub-only and supports externally managed JJ branches; inspect `gh stack link --help` for the installed command's exact arguments before linking verified layers. Never infer successful local tracking from a GitHub link.

Run all JJ commands from the target workspace's absolute root. Before repository-scoped `gh`, export `GIT_DIR=$(jj git root)` there. Read metadata with `gh pr view <ref> --json headRefName,headRefOid,headRepositoryOwner,baseRefName,state,isDraft,author,url,body`. Verify each head repository, bookmark and exact commit, not the name alone. Fetch the exact named remote bookmark with JJ, or the exact PR ref when needed; verify its ID. Missing or ambiguous refs are residuals, never permission to substitute a tip.

Use `gh pr create --head <verified-head> --base <immediate-parent> --title <title> --body-file <local-body-file>` for new layers. For cross-repository heads use the supported owner-qualified head and explicit base repository. Existing PRs retain title/body unless explicitly authorized maintenance or an optional approved rewrite applies. Never mark existing drafts ready unless explicitly requested. Preserve ready/draft state on synchronization.

Read-only GitHub topology or linking capability failures must be distinguished from missing CLI, authentication, ambiguity and unavailable stacked-PR support. If the required hosted stack relationship cannot be expressed or verified, report a residual; do not claim a set of ordinary PRs is a successfully managed stack. Landing remains `gh stack merge` only through the authorized landing workflow; never `gh pr merge` on a managed member. If that command requires prohibited Git execution, report blocked rather than bypassing the repository policy.
