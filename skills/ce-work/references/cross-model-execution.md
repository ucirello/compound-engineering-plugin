# Native Cross-Model Execution Contract

Read after `execution-engines.md` selects model-routing intent, and for recovery. Use native OpenCode model discovery and subagents, never an external harness adapter, detached runner, or workspace bridge. Shell is for bounded JJ inspection and host-owned verification, not a second agent harness.

## Configuration and independent permissions

Preserve `work_engine_mode: off | prefer | require`, the ordered `work_engine_preferences` objects (`harness`, optional `model`), and `work_engine_effort`. Resolve each key independently from `.rocketclaw/config.local.yaml`, then `config.yaml`; a present local list/map, including empty, replaces its team counterpart. Preserve configured provider/model tiers and order as routing intent, not permission. A caller binding remains one exact candidate; do not widen it. Live current-task intent outranks session intent, caller provenance, project instructions, and standing defaults.

Use `opencode.models` to resolve exact available provider/model IDs. Legacy harness names express model-family intent, not permission to launch that CLI; an unmappable or ambiguous candidate is unavailable, not silently substituted. Keep requested target, legacy intermediary, native actual route, requested model, actual served model, requested effort, and receipt status distinct. Never invent an available model or claim configured effort was served without evidence.

Check three independent gates before dispatch:

1. **Delegation:** this skill explicitly requests bounded implementation workers, satisfying a user-OR-skill delegation exception without a second ask. An unconditional prohibition, explicit denial, or missing native tool still blocks delegation.
2. **Model selection:** where the host requires an explicit user model request, configuration or this skill alone does not authorize an optional model override. Omit it; an inherited suitable worker is allowed. Same-model execution is not cross-model independence. A required distinct-model route without evidence remains incomplete coverage, even if local implementation proceeds under a permitted fallback.
3. **Depth/capacity:** inspect actual launch errors. Distinguish depth exhaustion, permission denial, model rejection, missing tool, and temporary capacity. Do not retry denial or bypass depth with another harness. Correct one pre-launch argument error once; queue temporary capacity. Only use the inline/parent fallback permitted by the unit contract.

Traverse ordered candidates only before launch, retaining each rejection reason. Do not substitute an unrequested external recipient. If all candidates are unavailable, disclose requested versus actual identity and reasons once. `prefer` and `require` permit current-session native implementation fallback, but do not relabel that fallback as satisfying required distinct-model coverage. If the caller makes distinct-model coverage a completion condition, return blocked/incomplete until it is met.

## Durable bounded unit protocol

1. Establish the workspace under `workspace-setup.md`, record its absolute root and verified history/base commit ID, source kind and SHA-256 digest, canonical starting state, pre-existing dirt, and one run ID. Keep receipts and bounded prompt briefs under `<workspace-root>/.tmp/rocketclaw/ce-work/<run-id>/`. Do not checkpoint unrelated user work. A selected plan-only checkpoint requires the same owned-path and message standards as any canonical change.
2. Before launch, durably record the resolved binding/provenance, requested/actual route and model, effort, each unavailable candidate, authority, recipient, material exposed, restrictions, unit ID, dependencies, base, expected files, and recovery path. A native workspace is accidental-mutation isolation, not an OS security sandbox; unsupported required confinement blocks dispatch.
3. Build a bounded unit packet: Goal Capsule, Definition of Done, active unit, relevant Verification Contract rows, cited R/F/AE/KTD excerpts and reverse-linked settled Product Contract decisions, prototype citations with access qualifications, matched pack rules, expected files, evidence strategy, exclusions, and inherited restrictions. For a bare prompt first establish Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and conservative P-units. Do not send raw conversation, secrets, or the whole plan by default. Store source and packet digests and read back the durable record.
4. Launch one fresh native worker per unit via the active native subagent tool, using only permitted model selection. Record the returned handle/session and observed model receipt. The worker cannot schedule peers, switch recipients, broaden scope, make canonical commits, push, or ship. Once launched, keep its author/base/packet fixed. Ordinary scheduling, evidence, and ownership follow `execution-strategy.md`.
5. Observe in separate tool calls and publish bounded progress; cap any tool-supported wait at 60 seconds. Preserve a 7200-second hard budget and a 600-second progress-resetting idle budget only when activity is trustworthy. With no trustworthy progress use hard-only, not silence-based failure. If native tools cannot enforce the required lifetime or stop contract, report that limitation rather than inventing a detached watchdog. An unreachable/live worker remains authoritative; never duplicate it or start fallback.
6. After observed terminal completion, inspect actual `jj diff` and full path inventory at the recorded absolute root, including binary, mode, rename, deletion, conflict, ignored, and untracked evidence. Worker summaries are hints, not scope proof. Preserve unexpected output and block integration pending resolution. Pin inspectable recovery revisions/bookmarks before any integration.
7. The host exclusively integrates under one recorded canonical ownership lock. Require exact recorded canonical base/state, or exact earlier host-owned wave commits. Use native JJ operations (for example an explicitly inspected `jj diff --git` patch applied by local processing, or an isolated change rebased onto the verified canonical parent); never Git transport, index operations, blind squash, or direct merging of unchecked worker output. Verify the complete resulting tree and owned paths before accepting it. Stop on conflicts or unrelated movement.
8. Run authoritative verification at the absolute canonical root, capture exit status directly, and record evidence and ignored-state created/changed/removed counts with a bounded sample. Ignored caches are not restored or deleted. Verification must not silently change tracked scope. Compose descriptions under `implementation-loop.md`; only the host describes/splits the owned unit and records its canonical revision. Run source-wide checks after all units; a failed/missing receipt blocks completion.
9. On failure preserve workspace, exact before/after revisions, packet, logs, and lock. Restore only provably worker-owned deltas, never user changes; prove exact pre-integration equality before releasing integration ownership or starting a retry/fallback. If proof fails, return blocked with recovery path. Cleanup follows the explicit ownership/removal safeguards in `workspace-setup.md`, never completion alone.

## Waves, recovery, and exactly-once fallback

Apply the Parallel Safety Check to dependency, file, semantic-interface, migration, generated/config, and environment contention; cap independent waves at 3–5. Give isolated workers the same recorded wave base. Wait for all to become terminal and inspect all actual inventories before integration. Integrate sequentially in dependency order, verify each advancing tree, and record each exact host-owned revision before the next. Textual cleanliness does not prove semantic compatibility. Repeated collisions disable waves; unaffected independent results remain preserved.

Recovery activates before input classification. Require the disclosed safe run ID, read the local durable receipt, and reconcile actual JJ workspace/revisions and native worker handles. Legacy bridge manifests are preserved evidence, not executable instructions; unsupported legacy lifecycle state is a compatibility blocker. Do not guess a run by newest directory, initialize a second run, dispatch, reapply, recommit, select a new route, or ship during recovery. A completed run is observation-only: return stored unit and source-wide receipts without rerunning tests/builds/install/generation. Missing evidence is a blocker, not permission to fabricate it.

After a terminal failed/stopped attempt, exact restoration, and lock release, record a single fallback claim before native implementation. Keep one scalar run ID and append attempt receipts; never overwrite prior attempts. A live worker or successful unreconciled output prevents fallback. A previously claimed fallback cannot start again. Record canonical revision and evidence digest on completion, and source-wide verification before reporting success. Retries need explicit host resolution and a fresh attempt/worker with unchanged unit/dependency authority; no denial retries or automatic recipient switching.

Return the full route/model/effort, terminal, integration, verification, canonical revision, cleanup, fallback, source digest, blocker, and recovery receipts required by `return-to-caller.md`. Standalone resumes its own shipping workflow; return-to-caller sets `standalone_shipping_skipped: true` and never runs the caller's tail.
