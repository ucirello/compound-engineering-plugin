# Native model execution and durable recovery

Use native `opencode.models` discovery and host subagents/shell, never another harness dispatcher. Resolve live intent, typed caller provenance, and existing `work_engine_mode`, ordered `work_engine_preferences`, and `work_engine_effort` configuration as described in execution-engines.md. Preserve exact model pins, ordered candidates, provider intent and requested effort as data. Unsupported harness routes are unavailable, not permission to launch their CLIs. Do not silently translate an exact pin into another model.

This loaded skill requests implementation subagents and satisfies the user-OR-loaded-skill delegation exception. Respect higher prohibitions and actual tool denial. If explicit user model permission is required, omit the optional model argument unless granted; use an appropriate inherited worker and disclose the unmet configured tier. Separate same-model workers are not cross-model independence. Effective capacity/depth is distinct from permission. For consumer setup, merge `experimental.subagent_depth` >= 3 into the existing user-level `~/.config/opencode/opencode.json` (or actual config directory from `opencode debug paths` / `opencode debug paths config`). Preserve higher integers, sibling settings, unrelated configuration and JSONC; do not create competing JSON/JSONC or replace the whole file. Package configuration does not enable consumer depth; higher precedence must not lower it. Never modify host config during work.

## Durable receipt protocol

Before dispatch, create private run evidence below the absolute canonical workspace's `.tmp/rocketclaw/work/<run-id>/`. Resolve a supplied `implementation_run` before ordinary intake, reading its existing receipts without redispatch. Record repository/workspace identity, verified base commit, bookmark, source kind and SHA-256, plan/prompt path, binding provenance, requested/actual route/model, effort (served effort unverified), restrictions, run/unit/attempt ids, dependencies, expected paths, verification contract, fallback reason and recovery path. Unknown served identity stays `unverified`. Preserve existing legacy recovery state read-only; never execute a removed bridge or infer completion from a process exit.

Build a bounded prompt brief only after goal, scope and authoritative verification are concrete. Include the active unit's requirements, applicable settled decisions, cited accessible prototypes, matched pack rules, expected files, evidence strategy and exclusions; omit raw conversation and unrelated source. Record its digest before dispatch and bind each attempt to the immutable packet and verified base. A selected plan-only checkpoint requires explicit ownership of that exact path; unrelated dirt is never checkpointed implicitly.

Use one ready unit at a time unless the Parallel Safety Check proves independence across dependencies, files, interfaces, migrations, lockfiles, generated/registry/config files and environment singletons. Uncertainty is serial; cap a wave at 3–5 isolated workers, all from one recorded base. Workers receive no canonical commit, push, PR, recipient-switch, scheduling, shipping or scope-expansion authority. Isolation is not a security sandbox; required enforced confinement unavailable from the host is a blocker, never silently cooperative.

Reuse verified existing isolation unchanged and respect harness ownership. Any new workspace requires the workspace-setup.md creation and cleanup contract, including explicit colocation, absolute destination, verified base and date-named identity. Harness isolation unable to guarantee these is a compatibility blocker, not a reason to bypass its lifecycle.

Record native job/session id before monitoring. Observe in separate bounded waits <=60 seconds, reporting unit, route, elapsed time, meaningful progress and terminal state. Retain a 7200-second hard cap and, only for trustworthy incremental activity, a 600-second idle window reset by progress; absent trustworthy activity disables idle detection, not the hard cap. A timeout or unreachable session does not prove termination. Stop/reap through host lifecycle and establish authoritative terminal evidence before retry or fallback. Never steer or duplicate a live attempt.

On terminal output, inspect actual complete JJ diff and path inventory, including binary, mode, rename and deletion evidence, against packet scope. Preserve ignored/untracked inventory and worker verification evidence. Unexplained paths or scope expansion block integration. Pin the exact worker revision and recovery bookmark. Only the host integrates into the canonical workspace, sequentially under one run-owned integration lock; verify canonical identity/base and pre-fold snapshot first. Use native JJ operations from the absolute canonical root, inspect semantic compatibility even after clean application, and run authoritative checks with their direct exit status. No worker result substitutes for these checks. Verification must not unexpectedly mutate tracked canonical state. Record ignored-state created/changed/removed counts and a bounded sample without restoring or deleting ignored files; local databases and secrets are not protected by a tracked snapshot.

A failed apply, verification, or host commit preserves the lock and recovery evidence until exact pre-fold tracked equality is proven with native JJ recovery. Never discard unrelated, ignored or untracked work. If equality cannot be proven, block with the workspace, pinned revision and recovery path; do not retry, run siblings, or fallback. After successful verification, compose the full host-owned message using implementation-loop.md, record its exact commit, advance wave evidence by that exact revision, and only then consider guarded cleanup. Every worker must terminalize and pass scope inspection before the first wave integration; collisions stop the wave, dependents remain queued, and repeated collisions disable parallelism.

Resume is reconciliation only: verify packet/base/job/revision/parent/tree evidence and recorded canonical commit before continuing an interrupted transition. Never redispatch, reapply, recommit or run a shipping tail already completed. Ambiguous matching runs require selection; completed runs with successful source-wide receipts are observation-only and must not rerun tests merely to reconfirm them. Missing mandatory evidence blocks completion.

Before egress, traverse configured candidates only while none has started. Record every rejection and reason. `prefer` and unavailable `require` disclose once and may use inherited native execution, never another unrequested recipient. After start, authorize at most one fallback with a durable claim only after authoritative failure/termination, exact restoration and lock release. Successful unreconciled output or a live job forbids fallback. Keep one run id and fresh attempt ids for bounded retries, preserving all prior receipts and dependency/base contracts. Record fallback completion and verification digest; do not claim completion until every unit and the source-wide authoritative checks have successful receipts. Mandatory independent coverage remains incomplete when routes cannot provide it.

Standalone execution resumes shipping-workflow.md after implementation; return-to-caller returns all receipts and `standalone_shipping_skipped: true`. Neither workers nor recovery gain shipping authority.
