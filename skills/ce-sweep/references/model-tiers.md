# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). This skill explicitly requests these reviewers, satisfying a host rule allowing user-OR-loaded-skill delegation without a second approval. Respect any unconditional prohibition, missing tool, or actual denial; never bypass through shell or another harness. Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use OpenCode `opencode.models` to resolve the cheapest capable model only when model overrides are authorized independently of delegation. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Resolve the mid-tier model through `opencode.models` when overrides are authorized. If the host requires an explicit user model request, configuration/tier intent alone does not authorize the optional model argument. Omit it and use a suitable inherited model; disclose unmet tier intent rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Before native OpenCode subagent dispatch, discover project configuration sources and the effective `experimental.subagent_depth`, accounting for precedence and current nesting. A shipped depth default is not proof of remaining capacity. Classify the actual error separately as depth/capacity, permission denial, optional-model rejection, missing tool, or another failure. Correct an ordinary pre-launch argument error once, but never retry a denied operation or evade depth limits through another harness. Leave capacity-limited work queued or use the permitted inline degradation above with identical budgets and coverage. Disclose the fallback and any incomplete coverage; inherited same-model agents are not cross-model independence. Apply a source persona's more specific unavailable-state rule when relevant.
