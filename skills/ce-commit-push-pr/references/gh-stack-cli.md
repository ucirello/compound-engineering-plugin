# JJ-managed stack semantics

Do not invoke `gh stack` checkout/init/add/submit: those routes manage Git working-tree state. Use native JJ bookmarks, changes and `jj git push` as described in `stack-submit.md`, and repository-scoped `gh` for PR metadata and writes, with `GIT_DIR=$(jj git root)` from the absolute workspace root.

Resolve a parent PR by number using `gh pr view <number> --json headRefName,headRefOid,headRepository,headRepositoryOwner,baseRefName,url,author`. Match the actual head repository, owner and exact head, not branch name alone. Verify the head repository URL against `jj git remote list`, then fetch its actual head bookmark using `jj git fetch --remote <verified-head-remote> --branch <verified-head-bookmark>` from the absolute workspace root. `--branch` selects branch names, not arbitrary pull refs. Resolve the fetched remote bookmark to its full commit OID and compare it with the captured `headRefOid` before using it. If the head repository/bookmark is unavailable, no matching remote exists, retrieval fails, or the OID differs, report the exact requested repository, bookmark and OID plus the diagnostic as a residual; never fetch or substitute a different ref, guess a parent, or move the task's history anchor.

Keep parent topology explicit: a new layer descends from its authoritative parent, never a guessed stack top. A name collision at another commit blocks reuse. Preserve existing drafts and other authors' PRs. No automatic landing occurs here; `ce-babysit-pr` owns explicitly authorized stack landing and must support the JJ-managed topology, otherwise report that capability blocker without invoking Git-backed managers.
