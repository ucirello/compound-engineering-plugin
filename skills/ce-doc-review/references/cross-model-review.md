# Native cross-model judgment pass

When any conditional judgment lens (adversarial, product, security) is activated, request a fresh native subagent for each activated lens and one `whole-doc` sweep. Use the same slice as each local twin, and the entire document for the sweep. Use the persona, template, and findings schema in this skill. Peers receive no other reviewers' claims or prior decision primer. Peer-only findings never grant silent edit authority; normalize `safe_auto` to `gated_auto`.

## Policy and route resolution

Resolve the absolute workspace root with `jj root` from the target checkout. Read `.rocketclaw/config.local.yaml`, then `.rocketclaw/config.yaml`: first active valid scalar wins; empty is unset; present lists/maps replace the whole key. `docs_root` remains config.yaml-only. Outside a checkout, review the supplied document without requiring repository config.

Evaluate `cross_model_review_mode` first: `off` disables automatic peers unless the user explicitly requested cross-model review in conversation; invalid values fall through to `auto`. A live prohibition always wins. Preserve route preference order: live user request, `cross_model_peer`, active project instruction, then an available attestably different provider. Preserve `cross_model_model` and `cross_model_effort` as exact routing intent, with live user choices taking precedence. If `CROSS_MODEL_PEERS` is set, restrict every recipient/provider/intermediary accordingly; unset means no additional recipient filter.

Use native `opencode.models` discovery to resolve available exact provider/model IDs and supported variants; never guess IDs or invoke removed CLI dispatch bridges. Keep requested target, intermediary, requested model, actual serving model, and host model separate. Do not silently substitute an explicit model, target, effort, or recipient. Unsupported configured routing is named incomplete coverage, not ignored configuration.

## Three separate gates

1. **Delegation:** this skill explicitly requests reviewers, satisfying a host's user-OR-skill delegation exception without a second ask. An unconditional prohibition, actual denial, or absent native tool still blocks dispatch.
2. **Model override:** delegation permission is not model-selection permission. Where the host requires an explicit user model request, config/tier/skill preference alone does not authorize the optional model override. Omit it and use an inherited suitable reviewer when possible. Such a reviewer supplies local independent-context coverage, not cross-model coverage. If the required different-model route cannot run, report it as missing rather than claiming the cross-model pass completed.
3. **Nesting/capacity:** first follow **Discover effective depth** in `dispatch.md`: consult `ce-setup`'s user-level depth-at-least-3 prerequisite and supported authenticated `opencode api get '/api/config?location%5Bdirectory%5D=<URL-encoded-absolute-target-root>'` discovery. Read the top-level document source entries' `path` and `info.experimental.subagent_depth`, resolving higher precedence rather than assuming package config is effective. Do not mutate config or add a startup gate; report unknown/unmet prerequisites and continue otherwise permitted work. Configured depth does not guarantee actual nesting/concurrency capacity. Inspect actual native-tool errors: temporary concurrency pressure can wait for a released slot; depth exhaustion is not transient capacity. Distinguish depth, delegation denial, model rejection, and missing tool. Do not bypass any limit through shell dispatch, another harness, or repeated denied calls. Local inline fallback may cover a lens but is not independent corroboration and cannot replace the whole-doc cross-model sweep.

## Disclosure, lifecycle, and receipts

Before dispatch disclose the fixed requested model/variant, route and all recipients, and that full document content (or the selected slice) is sent there. In non-interactive mode preserve that disclosure in the run audit evidence. Call a pass cross-model independent only when actual host and serving identities attest different providers/models; requested IDs alone are not receipts. Unknown or inherited identity cannot prove cross-model independence.

Use bounded native parallelism and native wait/collection/cancellation operations actually available. Preserve a per-reviewer receipt: native session/task ID, lens, document/slice, requested target/model/variant, actual serving identity or `unverified`, start/terminal status, error category, and `independence_verified`. Save any necessary evidence only under the absolute workspace's `.tmp/rocketclaw/ce-doc-review/<run-id>/`; validate ownership, containment and no symlink traversal before writing or reading artifacts. No OS temporary directory or detached dispatcher is needed.

Collect every started reviewer before synthesis or return, including failed, timed-out, cancelled and malformed outcomes. Use supported cancellation when a deadline expires; if collection/cancellation is unavailable retain IDs and evidence and report unresolved work. Never claim cleanup without confirmation. Preserve recovery evidence before deleting only owned disposable run files. Do not remove or recreate workspaces for this pass.

The pass remains additive/non-blocking. Keep completed local findings when peers fail, but name each owed lens and the whole-doc sweep that did not fold, including whether it never started or started and failed. Native infrastructure failure is degraded coverage, not a clean policy skip. Do not retry permission denial or silently switch recipients. Correct a genuinely invalid invocation only within the same allowed route and deadline; do not restart provider quota/authentication/model rejection as though it were capacity pressure.

Fold schema-valid findings with reviewer `<lens>-<provider>`, retaining provenance. Set `independence_verified: true` only with positive serving-identity evidence; otherwise false. Only verified independent returns can promote agreement under synthesis rules. No artifact, missing receipt, same-model inheritance, or an inline pass can satisfy cross-model completion. `peer.outcome: folded` requires every owed lens and whole-doc sweep to fold verified different-model evidence; otherwise report the missing cross-model coverage explicitly.
