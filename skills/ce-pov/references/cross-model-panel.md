# Cross-Model POV Panel

Obtain independent read-only peer POVs through native OpenCode subagents. ce-pov remains the decision-maker, not a vote counter. A peer failure never blocks the ordinary grounded POV; requested but unmet coverage is always disclosed.

## 1. Resolve participation and identity

Resolve conversational shorthand to one subject; return essential missing context rather than judge an ambiguous subject. An affirmative request for peers, cross-check, or `oracle` is a summons, including a calling skill's args; a refusal or historical mention is not. Named peers are exact and uncapped, overriding automatic discovery. Bare oracle selects up to two reachable, verified different-family models using conversation preference, configuration, project conventions, then configured defaults. Without a summons, offer only after forming the POV when Tier 2/3 downstream commitment warrants a check; never proactively offer during a warm invocation or Tier 1.

Keep target, requested model, served model, provider, and actual native route separate. Configured model mappings and reasoning tiers remain authoritative selection intent. Codex, Claude, Grok, Composer, Gemini, Cursor default/Auto, and OpenCode auto are distinct requests, not interchangeable brands. A named harness target that cannot be honored natively is unavailable; do not secretly replace Cursor with Composer or invoke another harness. Discover available exact model IDs with `opencode.models` when permitted. Attribute served identity only from runtime receipts, never a request or self-claim; absent evidence is `unverified`. Set independence_verified only when the served peer family is demonstrably different from the served host family. Same-model agents are independent reads, not cross-model corroboration.

Preserve the former adapter defaults as selection intent, subject to current configuration and host permission: Codex `gpt-6.1-sol` high; Claude `claude-opus-5-5` high; native Grok `grok-4.7` xhigh; Grok-through-Cursor `grok-4.7[context=256k,reasoning_effort=high,fast=true]`; Composer `composer-2.5[fast=true]`; Gemini/Antigravity `gemini-4-argon` high with `gemini-3.8-flash` only as the declared account-unavailability fallback when not explicitly user-pinned; Cursor default/Auto and OpenCode auto remain unforced. These historical harness mappings describe intent, never authorize invoking those harnesses. Preserve configured overrides; resolve native equivalents only within the requested family/tier and disclose any unavailable exact harness capability. For an unpinned stale default, an observed capability failure may justify the closest permitted same-family/tier replacement, recorded before dispatch; never silently substitute an explicitly requested model.

Honor `CROSS_MODEL_PEERS` as an optional recipient allowlist, using the original target keys; `antigravity` requires its literal key and Grok-through-Cursor requires both Grok and the sanctioned Cursor/legacy Composer intermediary. Native migration does not expand that allowlist. Preserve `CROSS_MODEL_HARD_SECS` (600 default), the complete-payload size intent `CROSS_MODEL_MAX_PAYLOAD_CHARS` (200000 default), and one finality retry only when at least 60 seconds remain. Native lifecycle tools replace transport-specific heartbeat and process controls, not these bounded coverage rules.

## 2. Check authority separately from capability

This loaded skill explicitly requests native peer delegation and therefore satisfies a host exception allowing explicit user OR loaded-skill delegation; do not demand a second user approval. Respect unconditional delegation bans and tool denials. Separately check model override permission: when the host allows it only for an explicit user model request, configured tiers or skill defaults alone do not authorize an override. Use suitable inherited-model reviewers when overrides are forbidden, preserving configured intent in the record and reporting required cross-model coverage as incomplete. An unavailable explicit model is never silently swapped. If an inherited reviewer would be presented as the named model, mark that requested voice unavailable instead and label the inherited check separately.

Check nesting capacity independently. Distinguish actual exhausted depth/capacity errors from permission rejection, model rejection, missing tools, and authentication/provider failures. Use native subagent dispatch exposed by this host; shell may support bounded evidence reads, not launch another model/harness or evade restrictions. A denied native launch cannot be recovered with another CLI, acpx, detached runner, or external harness. Bundled plugin configuration alone does not grant depth. If setup is relevant, document merging experimental.subagent_depth >=3 into the user's existing OpenCode config while preserving higher values, JSONC, and siblings; never edit host config.

## 3. Freeze scope and prepare independent evidence

Pass the same absolute workspace root and ordered include/exclude patterns to every peer. Default to the repository; never broaden a supplied scope. Patterns and read-only instructions are cooperative, not a filesystem or confidentiality sandbox. Peers inspect existing files directly, never mutate, and never intentionally inspect outside scope. Confirm all actual provider recipients are allowed; ask before adding an unexpected recipient or when an active instruction separately gates external consultation. Announce the selected peers and read-only purpose before dispatch, without noisy lifecycle details.

Capture one repository-scope identity before dispatch: exact committed revision plus a digest of tracked changes and untracked content in scope. Run all JJ reads from the absolute target workspace cwd, e.g. `(cd "$workspace_root" && jj log --no-graph -r @ -T 'commit_id')`, `jj status`, and `jj diff --git`; include scoped untracked file content in the digest without exposing secrets. Do not substitute another revision. Outside JJ, use a scoped content digest. Revalidate before every reconcile round and final fold-in; changed identity requires restarting all voices or an incomplete panel, never folding stale evidence.

Use the absolute private `$SCRATCH_DIR` from grounding.md for payloads and artifacts, with umask 077 and payload mode 600. Never global temporary storage. The common complete payload contains the framed question, subject shape, scope, identity, mode, source paths, necessary conversation-only material labeled by provenance, and `references/agents/pov-peer.md` plus `references/pov-schema.json`. Do not truncate for one peer; a peer that cannot accept the complete payload is unavailable.

For the initial independent round withhold the host's fresh position, other voices' conclusions, advocacy labels, risk rankings, and interpretations. Include source-located facts and the user's goals and strength of preference. Rejecting all supplied options or the framing is valid. A prior position explicitly being judged is the subject: send it intact, withholding only fresh host meta-judgment after the summons. Skeptic mode intentionally includes the host position and does not enter convergence.

## 4. Dispatch, collect, and bounded recovery

Start selected native peers before waiting when capacity permits; retain native task/session IDs and terminal outcomes. Keep a 600-second default aggregate window unless the user configured a longer budget; do not shorten it just to finish sooner. Use native wait/result/cancellation tools and collect completed peers while others run. Do not create detached shell jobs. Cancel only owned tasks on timeout/interruption and confirm settlement before cleanup.

Record target, native route, requested and receipt-supported served model, family, independence, scope identity, round, task ID, failure, and coverage. Validate each result against the schema: nonempty settled position and reasoning, evidence provenance, correct mode, `final: true`, and `movement: initial` for the first round or `moved`/`held` with explanation on reconcile. A settled Blocked answer is usable; an unfinished placeholder is not. Retry a non-final answer once on the same authorized native route within the remaining window, then drop it. Read only owned artifacts. Never infer a provider logout from an ambiguous sandbox error; report observed bounded diagnostics, not invented causes.

Correct one pre-launch argument error once. Recover a transient native infrastructure error on the same permitted route while failures are novel and plausibly recoverable and the aggregate deadline remains; stop on repeat failure or deadline. Missing tool, unconditional denial, model restriction, or actual exhausted depth is not a reason to bypass the host. Drop failed voices and report coverage truthfully. Inline host work can deliver the solo POV but cannot replace independent peer or cross-model coverage.

## 5. Verify dissent and reconcile

Only independent voices enter convergence. Material dissent means different grades, selected approaches, reader actions (proceed/revise-first/reject), or fatal-risk judgments; wording differences are not dissent. Default to the independent initial round plus at most two reconcile exchanges. Honor explicit user limits exactly: one pass means no reconciliation. Initial material dissent requires at least one exchange unless that limit forbids it.

Before each exchange revalidate identity, reconsider every surviving position, and verify only disputed decision-changing claims within scope. Classify claims verified, contradicted, or unverifiable with locations. Send every surviving peer the identical original subject and common evidence delta, with each survivor's full current position/reasoning and up to five succinct source-attributed evidence bullets. Start fresh native tasks using the same permission checks. Drop failed peers rather than pretending their old response participated in a new round.

Stop at the first applicable state: confident (reasoned host judgment after weighing survivors), no-movement (all survivors held and host remains uncertain), or limit-reached (authorized cap reached without confidence). Confidence is not majority agreement. At a cap recommend a specific finite extension only when a named new evidence path could resolve a decision-relevant question; further rounds require authorization, never an open-ended loop.

## 6. Deliver, return, and clean up

Lead with the POV, then a compact panel note. For confidence, say whether voices aligned or explain why the host decided over dissent; distinguish host-added recommendations. For stalemate, report current positions, movement, dropped voices, evidence gaps versus judgment differences, and whether to stop or propose a bounded extension. Partial coverage names survivors and failures. With no survivor, deliver the solo POV and explicitly say cross-model check unavailable or incomplete. Any summons requires a panel-status line even when none ran. No summons means no panel note. Never attribute a position to a model that did not run, or claim cross-model coverage for inherited same-model peers.

Retain receipt and coverage distinctions in the panel record; keep user-facing diagnostics decision-relevant. Skeptic mode folds one attributed critique into the POV and discloses whether it changed it, without convergence rounds. The panel never authorizes implementation. Downstream handoff requires all four: original explicit authorization for that action, non-stalemated result, inherited scope, and otherwise authorized non-destructive work. The caller owns continuation.

After consuming results, clean only this run's owned private scratch payloads, logs, and results on success, failure, interruption, or timeout, after owned workers settle. Never delete outside the verified run root or discard unrelated evidence. Return the judgment even when peer consultation was unavailable.
