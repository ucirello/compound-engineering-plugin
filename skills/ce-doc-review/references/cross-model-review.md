# Cross-Model Judgment Pass

This skill explicitly requests an additive, read-only cross-model review when any conditional judgment lens (`adversarial-document-reviewer`, `product-lens-reviewer`, `security-lens-reviewer`) activates. Feasibility and the convergent lenses do not trigger it. Failures do not block the local review, but missing cross-model or whole-document coverage must be named, never reported as fully verified.

## Resolve policy and one fixed route

Read ordinary keys from the target repository's `.rocketclaw/config.local.yaml`, then `config.yaml`: first active valid scalar wins (empty is unset); a present list or map replaces the whole key. `docs_root` remains config.yaml-only. Obtain the absolute root with `jj workspace root` in the target workspace; outside a repository use local `.tmp/` and do not require irrelevant repository configuration. JJ documentation: https://docs.jj-vcs.dev/latest/cli-reference/ . Any repository-scoped `gh` call runs from that absolute root with `export GIT_DIR=$(jj git root)`.

Evaluate `cross_model_review_mode` first: `off` disables automatic review unless the user explicitly requests it in conversation; `auto` is default, invalid values continue to the next layer. A live user prohibition always wins. Record policy-disabled separately from unavailable or unattested routes.

Resolve the target from conversation, `cross_model_peer`, active project instructions, then the first available attested-different family in `codex → claude → grok → composer`. Cursor-default participates only when explicitly preferred. Preserve compatibility target vocabulary and operational provider references, but execute through native OpenCode model selection and subagents, not another harness's dispatcher. Keep target, intermediary, serving family, requested model, and actual served model separate. Do not infer serving family from a harness brand. An unknown host family cannot establish automatic same-family exclusion.

Read `cross_model_model` and `cross_model_effort` under the ordinary-key rule; conversation overrides configuration. Requested tiers remain high reasoning, except Codex and native Grok extra-high; Cursor Grok uses its high/fast preset and Composer fast is its accepted ceiling. Resolve available exact IDs and variants using `opencode.models` when model selection is permitted. Configuration is authoritative intent, not authorization to pass a model override. Follow `dispatch.md`: user-OR-skill delegation permission is satisfied by this skill's explicit dispatch request, but model permission and effective nesting capacity are independent constraints. When overrides require an explicit user model request, omit `model` without that request and use a suitable inherited reviewer only where it meets the contract. A same-model reviewer cannot fulfill different-model coverage. Report an unavailable fixed route, tier, or required independent pass as incomplete, without silently substituting.

Bind one permitted native route and model for the entire document. `CROSS_MODEL_PEERS`, when set, restricts both target and intermediary; unset means unfiltered, not unsanctioned. Preserve the compatibility alias where cursor or composer sanctions a Cursor intermediary, while a Cursor-default voice requires cursor itself. Never add a recipient silently. Only after an intended ID is observed unavailable may a compatible same-target/family replacement be resolved and disclosed, without changing an explicit user model request. No shell-out to another harness may bypass permission or nesting restrictions.

## Disclosure and dispatch

Before egress, prominently announce the independent cross-model pass, requested model and effort, native route, and every provider/intermediary receiving document content. Use “requested” rather than claiming a served model; call independence verified only with attested different serving families. Cursor default/Auto has an unverified serving model. In non-interactive mode omit user-facing prose but retain an audit receipt of each send and recipient. No resolved peer gets a quiet named skip instead. Do not probe authentication before provider-capable dispatch.

Dispatch generic native reviewers in the same bounded wave as local personas, following `dispatch.md`. Seed the full selected persona and `findings-schema.json`, document type, origin, and embedded document content; supply no peer claims or accumulated round-2 decision primer. Each activated trio peer receives the same reviewer-specific slice as its local twin (full legacy document; unified Product Contract or applicable slice). Also dispatch exactly one `whole-doc-reviewer` with the full document, once per document, on the same fixed route. This broad sweep has no local twin and its loss must be named separately.

Use fresh isolated contexts, read-only/tool restrictions supported by the native primitive, and no project hooks, MCP servers, or unrelated file access. A prompt alone is not enforced isolation: if the native route cannot enforce the required least-privilege embedded-document scope, report it unavailable rather than claim equivalent isolation. If shell is needed for local artifact handling, use only owned private paths under `<absolute-workspace-root>/.tmp/rocketclaw/ce-doc-review/<run-id>` (local `.tmp/` outside JJ); reject symlinks and unsafe ownership. Do not create a Git workspace or dispatch another harness.

## Bounded lifecycle and recovery

Record native task IDs and start time. Idle budget defaults to 480 seconds; shared hard budget uses `CROSS_MODEL_HARD_SECS`, default 1200 seconds. Use bounded native waits/polls, an orchestrator deadline of that budget plus 10 seconds, and any supported supervisor backstop no shorter than `max(1230, budget + 30)`. Do not claim unavailable supervision. Never wait past the remaining deadline. Concurrency backpressure may wait for an actual freed slot; a depth limit, prohibition, missing tool, or model rejection is classified from the actual error, not retried as concurrency. Use an allowed parent-coordinator fallback only if independence and scope remain intact.

A new plausibly recoverable infrastructure failure may receive bounded same-route recovery while the deadline holds; stop when it repeats. A provider-reported HTTP 529 overload may receive one same-route retry within the shared deadline. Do not automatically restart after terminal quota/usage-limit evidence, switch recipients, weaken isolation, or evade denied permissions. Any changed route requires fresh resolution and disclosure. Attribute account authentication failure only after provider-capable dispatch evidence, otherwise describe the execution-context failure without claiming the user's account is logged out.

Before synthesis or return, collect every started task's terminal outcome, cancel unfinished tasks through supported native lifecycle operations at the deadline, and verify termination. If termination or collection cannot be confirmed, preserve evidence and report the blocker. Do not invent cleanup operations or remove live task state.

## Receipts, fold-in, and cleanup

Validate owned, non-symlink result artifacts against `findings-schema.json`; never fold raw or malformed output into findings. Record task ID, outcome, timestamps, target, route/intermediary, requested model/effort, actual served-model receipt (or `unverified`), egress recipients, and `independence_verified`. A request is not evidence of the served model; disclose receipt mismatch without inventing identity. Force `reviewer` to `<reviewer-name>-<provider>` and downgrade peer `safe_auto` to `gated_auto`.

Only `independence_verified: true` can promote merged agreement by one anchor step under synthesis's one-fix test. Otherwise retain attributed evidence without a promotion bonus. Empty findings means no additional issues, not proof of coverage beyond the completed scope. Preserve round-2 suppression through synthesis R29/R30.

Classify each lens and the whole-doc sweep as completed, never-started with reason, failed, timeout, or died-without-result. Distinguish infrastructure-wide loss from a clean policy skip; report lost whole-doc broad read and corroboration explicitly. Required missing different-model coverage remains incomplete even if the local review proceeds. An incomplete local review reports collected peer outcomes without applying findings.

Read back required receipts and outcomes before deleting only consumed, run-owned temporary artifacts after all tasks stop. Preserve unresolved evidence and report cleanup failures; never claim cleanup from a successful request alone. This is artifact cleanup, not authorization to retire a user's JJ workspace.
