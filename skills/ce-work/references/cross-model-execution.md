# Cross-Model Execution Contract

Use this when `references/execution-engines.md` selects a candidate or when recovering an existing run. The OpenCode orchestrator owns routing, receipts, JJ operations, authoritative verification, and delivery. A native subagent authors one bounded unit; neither its report nor a terminal session by itself proves integration or verification.

## Resolve one fixed route

Use the authority order in `references/execution-engines.md`. An ordinary live route request is `prefer`; “must” or “only” is `require` when the intent is unambiguous. Preserve an explicitly ordered preference list; a typed caller binding remains one candidate. Standing configuration is data, not executable syntax. Resolve each key independently using `config.local.yaml` then `config.yaml`, with `config.example.yml` as schema guidance, not an enabled setting. A present list or map, including an empty one, replaces the team value wholesale.

```yaml
work_engine_mode: prefer
work_engine_preferences:
  - harness: cursor
    model: composer
  - harness: codex
    model: gpt-6.1-sol
  - harness: claude
work_engine_effort:
  codex: xhigh
  claude: max
```

- `work_engine_mode`: `off | prefer | require`; `off` disables standing routing, not live authority.
- Standing candidate `harness`: `codex | claude | grok | cursor | opencode | antigravity | pi`, with an optional model selector. A typed `target` also accepts `composer`. Omission means the target's configured default, not any model you happen to find.
- Preserve requested route tokens `codex`, `claude`, `grok-cli`, `cursor`, `composer`, `grok-cursor`, `opencode`, `antigravity`, and `pi` as intent, not as launch commands. `composer` and `grok-cursor` formerly express Cursor as intermediary; record that in requested identity only. Native Grok intent maps to `grok-cli`; Grok via Cursor needs separate authority. Default Composer requests `composer-2.5[fast=true]`; a Grok via Cursor default requests `grok-4.7[context=256k,reasoning_effort=high,fast=true]`. An explicit Cursor preset is one model selector, without separate effort. Antigravity serves only `gemini-*` for this route, and omission tries `gemini-4-argon`, then `gemini-3.8-flash`. Pi may carry a provider/model pin such as `anthropic/claude-opus-5-5`. Preserve exact pins.
- `work_engine_effort` is an optional independently layered map even for a live or caller candidate (Antigravity: `low | medium | high`). A missing entry leaves the candidate's default. An invalid map requests no effort; disclose it once. A requested effort must map to a documented supported native variant; don't silently approximate it. Treat selectors and effort as data, never shell syntax.

Preflight without sending a packet: ask **`opencode.models`** for the exact provider/model and supported variant. Resolve a family/default only from current authoritative configuration and discovery; don't guess from a marketing name. For example, a Codex model request may resolve to its OpenAI model served through OpenCode when the intent is the model, but if the request fixes the Codex harness itself, the route is unavailable. Do not call other harnesses, adapters, or dispatchers; shell is for local JJ, checks and evidence, not to bypass delegation. Record actual route as OpenCode with its verified provider/intermediaries, never as the requested harness unless that is actually OpenCode. An equivalent same-session model is native execution, not an independent cross-model pass. The selected native tool must support the workspace binding and a verifiable hard execution bound (native deadline, or native cancellation with observable termination); unavailable controls are a capability blocker for this route. Log skipped or unavailable candidates and select the first qualified candidate before dispatch; enabled mode with no valid candidates is unavailable.

**Three separate gates:** (1) actual delegation permission (this loaded skill explicitly requests a native subagent for each qualifying cross-model unit, satisfying a user-or-skill permission rule); (2) permission to set its model/variant (omit override when forbidden; inherit only if suitable, and report an unmet fixed or cross-model route as incomplete); (3) available nesting depth. Inspect effective OpenCode V2 configuration and classify actual tool errors as depth/capacity, permission, model/variant rejection, or missing tool. Deep delegation needs `experimental.subagent_depth >= 3`: merge it into user-level `~/.config/opencode/opencode.json` or the existing JSON(C) at the global path from `opencode debug paths` / `opencode debug paths config`, preserving unrelated settings and higher depth. Do not add competing config or allow higher-precedence config to lower depth. Package config alone does not enable consuming projects. Do not change host policy or retry a denied dispatch.

**Sanction before egress:** disclose and persist binding provenance, requested versus actual route, provider and intermediaries, exact model/variant, the bounded material and mutation authority exposed, and requested restrictions (enforced vs cooperative). JJ isolation is not an OS sandbox; do not promise enforcement not present in the native tool. A route that cannot honor a required restriction is unavailable. Report the served model only from trustworthy runtime evidence, otherwise `unverified`; do not infer it from the request. Do not assert verified serving effort from a requested variant alone. Unverified or same-model service is not proof of fixed-route or cross-model coverage.

For either `prefer` or `require`, exhausted preflight permits the session's ordinary native implementation route, with requested versus actual identity and the reason stated once. `require` forbids silently substituting a different external recipient; fallback can complete implementation, not the missing fixed/cross-model coverage. A candidate can be replaced before egress only within the resolved authorization. Once initialized, a run is locked to the fixed route until the evidenced fallback transition below.

## Bound the work and journal the run

Run JJ commands from the applicable workspace's absolute root; see the [JJ workspace reference](https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace). Keep private, ignored `.tmp/rocketclaw/ce-work/<run-id>/` under the canonical workspace for the run manifest, source copy, packets, results and logs. Validate contained, owned, non-symlink paths before writes and recovery. Never include raw conversation, credentials or unrelated context. Bind run id to repository identity, canonical root and feature bookmark, source kind and SHA-256, exact base, binding, restrictions, and the intended tail. Persist the attempt receipt before dispatch; update the journal with atomic local writes and read it back at each transition. Keep one coordinator and one serialized integration owner; if exclusive ownership is uncertain, stop.

Require a clean canonical snapshot, recording `@`, its parent, bookmark target, status, conflict state and pre-existing ignored/untracked inventory. For a repository plan, its exact contents may be the sole dirty, authorized path: record the source digest, make a plan-only checkpoint using the path-limited composition procedure in `references/implementation-loop.md#change-description-standards` (describe why this plan is being checkpointed), verify the checkpoint's exact scope and disclose its commit. Otherwise unrelated dirt or failed checkpoint makes the route unavailable; never checkpoint user WIP. A prompt brief requires an already clean canonical tree. Before applying transport, ensure canonical `@` is an empty unbookmarked change on the accepted committed tip, so working-copy snapshots do not move the feature or unrelated bookmarks.

For a concrete bare prompt, write a private brief with Request, Goal, Scope (including expected files and discovered patterns/tests), Acceptance and verification, Constraints and exclusions, and Units (default bounded `P1`). If goal, bounded scope, or authoritative verification cannot be established, return to triage rather than dispatching. Copy the resolved source into private run state and use its recorded digest thereafter.

For each ready unit write a packet with only relevant Goal Capsule, Definition of Done, unit and Verification Contract rows, cited R/F/AE/KTD excerpts and the Product Contract Key Decisions whose exact `Governs R…` links name its requirements. For prompt work include only the matching P-unit excerpt. Include expected files, evidence strategy, exclusions, inherited restrictions, applicable Compound Pack rule text and citations, and explicitly cited prototype decisions/screens with locality and authority qualifications. The worker must inspect accessible cited sources before editing affected behavior, but write and test only inside the assigned workspace. Keep host-only environment probes authoritative; a sandbox error such as `EPERM` does not prove a host limitation. Send the exact recorded packet, bound to its SHA-256, not a loose paraphrase or full conversation.

## Native unit transaction

1. **Prepare.** Record unit id, unique attempt id, dependency order, exact base, fixed route/model, packet digest, expected outputs and workspace identity. Detect isolation first and follow `references/workspace-setup.md#isolated-workspaces` for verified reuse, colocated creation, dated names and adoption. Use only a dedicated worker workspace, never grant cross-model mutation authority over the canonical workspace. Only this cross-model protocol may provision run-owned workspaces for this engine; ordinary native authoring follows its own isolation rules. A concurrent wave uses distinct verified workspaces and one exact wave base. If the native subagent cannot be bound to the assigned workspace and its limitations, stop; don't invoke another harness.
2. **Dispatch once.** Use the permitted OpenCode subagent tool, seed `references/agents/implementation-worker.md`, and pass only this packet, the verified absolute workspace, and its result contract (`references/implementation-result-schema.json`). Record the actual native session/handle immediately, bound to this run/unit/attempt/path/digest and fixed model. The worker verifies workspace and exact base before editing and has no canonical commit, integration, shipping, push, recipient-switch, fallback, peer-scheduling or scope-expansion authority. The worker leaves changes for the orchestrator to snapshot. Never start a second worker when the original launch state is ambiguous.
3. **Observe without steering.** Use native activity/terminal evidence and await every launched worker. When status/wait is available, use separate updates and waits no longer than 60 seconds. Report unit, route, elapsed time, latest meaningful progress and observed terminal state. Use a 600-second idle budget only for reliable incremental progress (resets on activity); otherwise hard-only, with a 7,200-second ceiling. Request native cancellation at a verified limit only through supported controls. If the tool cannot impose a hard bound or confirm termination, report that limitation and block rather than assuming timeout, starting fallback or duplicating work. No news or temporary loss of contact is not terminal. A nonzero step stops its transition; inspect and reconcile before advancing.
4. **Inspect authoritative output.** Require terminal success and a valid attempt-bound result. Independently capture the complete JJ working-copy commit as a transport revision, verify it has the recorded base as sole parent, and keep a run-owned recovery reference. Compare exact base and transport with `jj diff --from "$base" --to "$transport" --summary` and `jj diff --from "$base" --to "$transport" --git`; inspect actual paths, renames, deletions, modes, binaries, conflicts, and ignored or left-untracked artifacts separately. A scope-expansion request, generated byproduct in the transport, missing result, unexplained path, or mismatch with the expected scope blocks integration; preserve the result and report what is unresolved. Process success alone is not completion.
5. **Verify then commit, one unit at a time.** In a separate transition, under exclusive integration ownership, recheck the exact canonical pre-fold snapshot (including the accepted earlier commits in the wave). `jj duplicate "$transport" -o "$canonical_parent"` creates a candidate on that verified parent; inspect its exact delta, ancestry and conflicts before editing or copying any data into canonical `@`. With a clean, unchanged canonical `@`, apply only the verified candidate tree using `jj restore --from "$candidate" --into @ -- <exact-owned-filesets>` and verify the full post-apply snapshot matches the expected tree. Run authoritative checks in canonical with `PYTHONDONTWRITEBYTECODE=1`, using direct argv unless shell syntax is needed (then use explicit shell with pipe-failure handling). Capture exit status directly and reconcile exact tracked state (revision, parents, feature bookmark, complete tree, all visible dirt and conflicts) against the post-apply snapshot. Before and after, inventory ignored/untracked entries by metadata; record `ignored_state` counts and bounded samples of changed/removed/created entries. Don't copy, restore, or delete those files; ignored caches/databases are not protected by this check. Commit only after checks pass and reconciliation holds, using the full description and exact owned paths from `references/implementation-loop.md#change-description-standards`. Verify exact parent/tree/paths and record canonical SHA, verification summary and evidence digest before advancing the feature bookmark or retiring a workspace.
6. **Fail stop and restore precisely.** On a failed pre-commit step, retain worker/transport, current records and the pre-fold and expected post-apply snapshots. Restore only evidenced run-owned edits back to the pre-fold snapshot, using scoped `jj restore` and verified run-owned references; never undo unrelated concurrent operations or unknown dirt. Prove exact pre-fold equality, including bookmark, parents, conflicts and full tracked tree, before releasing the integration claim or starting a sibling, retry or fallback. Unknown changes or unproven restoration block and preserve all state. After a commit, reconcile the existing result rather than blindly restoring, committing again or redispatching.
7. **Retire and verify the run.** Record integration, verification, commit and cleanup separately. Apply `references/workspace-setup.md#retire-a-run-owned-workspace`, retaining recovery refs/evidence as required. After all required units are terminal with cleanup reconciled under their ownership contract, run source-wide Verification Contract / brief checks from the verified clean canonical snapshot, directly capturing command status, checking exact tracked state, and recording `ignored_state` as above. Restore only attributable tracked side effects and verify equality before proceeding. On failure or missing evidence, retain logs and block completion even if workspace cleanup succeeded. Only a durable successful run-wide receipt allows `complete`.

### Parallel waves

Apply the Safety Check in `references/execution-strategy.md`. Start all ready independent units together on the one recorded wave base. Integrate in dependency order (deterministic order for siblings), accepting only the exact earlier verified canonical commits recorded in the wave. Recheck each transport for path overlap, changed assumptions and compatibility against the advancing tree; a conflict-free duplicate is not proof of independence. A stale/colliding unit needs explicit resolution or a fresh attempt at the newly verified base, without changing its dependency contract. Repeated collisions, broad edits, or failed exact restoration disable further parallel waves. Preserve unaffected siblings; never start dependents early.

## Resume and fallback exactly once

An explicit safe `implementation_run:` or recovery id is authoritative. Otherwise, for a plan, match a single unfinished private manifest by repository, root/bookmark and plan digest; do not guess by latest directory. Multiple matches, unsafe or foreign records, or contradictory receipts block. A prompt run always requires its disclosed id. Resume before ordinary triage and do not start new work or run either tail.

Reconcile recorded attempts against native session status and exact JJ refs, parent, tree and operation evidence. Adopt an unbound attempt only when exactly one matching native handle is independently provable; unknown identity or ambiguous launch blocks. May observe a live job, capture an authoritative done result, finish evidenced restoration or record an already-created exact canonical commit. Reuse an unmatched transport ref only when exact base and final tree match. No reapply/recommit on ambiguous evidence. When all units are cleaned/native-completed with a valid successful run-wide receipt, recover read-only; don't rerun tests, builds, formatters or verification to reconfirm it. Missing expected evidence is a blocker.

Expose status, native cancellation/reap (only if requested and supported), or authorized cleanup as recovery actions. A lost handle is not proof of termination. Explicit abandonment requires the exact transport revision or, with no transport, the terminal native handle. Reconcile both directory and registration on interrupted cleanup. Retrying a corrected unit after a proven restoration, authorized abandonment/cleanup, and release uses the same scalar `run_id` with a fresh `attempt_id` and preserves earlier receipts; no denial retries.

For either strength, post-start native fallback is a separate one-time claim: under the exclusive journal owner record it before any native work, only after authoritative route failure/timeout/no-result (or failed integration with exact recorded restoration and release). Never claim against a live/unknown attempt, successful unreconciled output, or previously claimed fallback. A repeated request recovers the existing claim instead of starting another. Report missing route coverage. Record accepted canonical commit, verification digest/summary and fallback completion separately from cleanup, then require the same run-wide verification gate. If evidence or cleanup is blocked, report the retained recovery path.

Keep `implementation_engine_binding`, `requested_route`, `actual_route`, `requested_model`, `actual_model`, `requested_effort`, `fallback_reason`, `source_kind`, `source_digest`, `run_id`, `unit_receipts`, `plan_checkpoint`, `blockers` and `recovery_path` for direct and return-to-caller runs. Receipt phases distinguish dispatch, terminal output, integration, verification, canonical commit and cleanup. Standalone resumes its shipping workflow; return-to-caller emits the structured result with `standalone_shipping_skipped: true`. No implementation subagent owns either tail.
