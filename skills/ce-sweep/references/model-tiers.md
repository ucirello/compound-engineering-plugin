# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

**Native routing and permissions.** Use `opencode.models` to resolve configured tier intent and OpenCode-native subagents (shell only for permitted supporting commands), never another harness's dispatcher. This skill explicitly requests source and media subagents. Under a host rule allowing user OR loaded-skill requests, that satisfies delegation permission without another approval; unconditional higher-priority prohibitions and actual denials still apply. Delegation permission does not grant model-selection permission: if explicit user model choice is required, omit the optional model argument absent that request and use a suitable inherited model. Preserve configured tiers as intent and disclose unmet requirements. Same-model agents do not establish cross-model independence.

**Degradation rule.** Check effective runtime nesting depth/capacity separately from permission; shipped package depth is not automatically adopted by consuming projects. When overrides are unsupported or forbidden, use suitable inherited-model agents with the same budgets and caps. When delegation is unavailable, prohibited, or depth-limited, perform permitted source fetch/media analysis inline with those budgets; this workflow permits inline analysis, not a claim of independent review. Preserve scratch evidence. If required capability or independence is unavailable, report coverage incomplete. Never evade permission or depth limits through shell or another harness.

Classify failures using the actual error: missing tool, permission denial, rejected model argument, nesting-depth/capacity limit, or post-launch failure. Correct a non-permission pre-launch argument mistake once; never retry a denied operation. Leave capacity-limited work queued or use the allowed inline fallback, noting incomplete work. Preserve the more specific unavailable-state rules in each source persona.
