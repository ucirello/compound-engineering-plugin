# Model Tiers

Read this when dispatching a sub-agent (the Phase 1.1 grounding scout, the Phase 2.6 claim verifier, or the opt-in Slack researcher). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** — the grounding scout: retrieval and quoting work. Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec — escalate to the generation tier when the repo is large or the stack obscure.
- **Generation tier** — the claim verifier: evidence-driven mechanical verification. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** — the dialogue itself. Questions, approaches, synthesis, and the requirements-only unified plan run in the main conversation on the orchestrator's model; nothing is dispatched for them.

**Native dispatch checks.** This skill explicitly requests the scout, verifier, and opted-in Slack researcher. Under a host's user-or-loaded-skill delegation rule this request suffices without another approval; an unconditional prohibition or actual denial still applies. Resolve configured task-shape tiers with `opencode.models`, preserving their intent. Delegation permission is separate from model-override permission: when the latter requires an explicit user model request, do not pass an optional model argument based on configuration alone. Check effective nesting capacity separately; a shipped default is not proof of runtime capacity.

**Degradation rule.** When model overrides are forbidden or unavailable, dispatch permitted scout and verifier work on a suitable inherited model and keep their read budgets and output caps — cost control then comes from structure, not tiering. Disclose any unmet configured tier or fixed route. Same-model agents are separate reviewers, not cross-model independence. When native delegation is prohibited, unavailable, or depth-limited, do the topic scan inline at Phase 1.1 — still writing the grounding dossier to the scratch path, because downstream consumers (the Phase 2.6 verifier, the ce-plan handoff) receive that path — and verify claims inline before the Phase 3 write, with the same budgets. Report any required independence or different-model coverage as incomplete; never evade restrictions through shell or another harness.

Classify a rejected native dispatch using the actual error and whether an agent launched: distinguish permission denial, prohibited model override, nesting/depth or capacity limits, missing tool, and ordinary argument errors. Correct an ordinary pre-launch argument rejection once, leave temporarily capacity-limited work queued when feasible, and otherwise use the permitted inline degradation above. Do not retry a denied operation or evade a depth limit.
