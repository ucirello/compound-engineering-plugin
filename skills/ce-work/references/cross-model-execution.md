# Cross-Model Execution Contract

Read this when `references/execution-engines.md` selects a configured model route or recovery of an existing run. Execute with OpenCode-native `opencode.models`, subagents, and shell for local JJ/verification operations. Do not invoke another harness, a detached CLI model process, or a removed controller/runner/adapter. The host owns the durable run record and canonical integration; worker prose and a terminal tool call alone are not proof of completion.

## Interpret intent and authoritative configuration

A live request such as "use Codex" is preference-strength by default; unambiguous strict intent such as "must use Codex" is requirement-strength. Preserve the resolved `prefer` or `require`, target, model, and binding provenance. A typed caller binding remains one four-field candidate, not a list. A live ordered fallback list retains its order.

Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml`, then `.rocketclaw/config.yaml`. A present local list/map, including `[]`/`{}`, replaces the team key. Configuration remains the source of desired behavior:

```yaml
work_engine_mode: prefer
work_engine_preferences:
  - harness: cursor
    model: composer
  - harness: codex
    model: gpt-6.1-sol
  - harness: claude
work_engine_effort:
  codex: xhigh
  claude: max
```

Mode is `off | prefer | require`; candidates retain `harness: codex | claude | grok | cursor | opencode` and an optional model pin. Omission means the configured default, not permission to invent one. Preserve Composer/Grok-through-Cursor intermediary intent as requested identity, but actual execution is OpenCode. Legacy route tokens `codex`, `claude`, `grok-cli`, `cursor`, `composer`, `grok-cursor`, `opencode` may identify recorded requested routes; they are not executable adapters. Never put CLI commands in configuration.

Use `opencode.models` to resolve each requested family/pin to an available exact provider/model and supported variant. Preserve model tiers and effort choices; unsupported pins, defaults, required intermediaries, or effort make that candidate unavailable, not silently substituted. A non-map effort value requests nothing: disclose that it was ignored. Requested effort is recorded; served effort is `unverified` unless runtime evidence proves it. An explicit pin cannot become a different model. Disclose compatible aliases and distinguish requested identity from actual served identity; catalog availability is not a served-model receipt.

Preflight candidates in order without exposing repository content. Skip equivalent current-session defaults with a reason; a distinct model on OpenCode is still a distinct candidate. Check delegation permission, model override permission, nesting capacity, available tools, workspace capability, and enforceable restrictions separately. This skill explicitly requests bounded implementation subagents; under a user-OR-loaded-skill delegation rule no second approval is needed. An unconditional prohibition or actual denial still applies. If model overrides require an explicit user model request, configuration alone does not authorize the optional `model` argument. A suitable inherited-model worker may execute where allowed, but disclose unmet configured intent; it does not fulfill required different-model coverage.

Discover effective nesting depth from the active runtime configuration sources for the target location and their precedence (OpenCode V2 `/api/config` returns a source-entry array). The shipped package default is 3, but installation does not merge it into a consuming project; inspect actual discovered project settings and current nesting, without mutating config. Configured depth does not prove a launch will succeed. Classify actual errors as depth/capacity, permission, model-argument rejection, or missing tool. Do not retry denied operations, elevate permissions, or evade depth through shell/another harness.

Before launch, unavailable candidates may yield to the next authorized candidate. When the list is exhausted, both `prefer` and `require` disclose attempted routes/reasons once and continue on the current session model, as the original unavailable-route fallback permits. Do not claim the requested fixed route or cross-model requirement was satisfied. After launch, keep one fixed recipient: no recipient change or native fallback until the existing attempt is authoritatively terminal and any integration is reconciled. Cost or latency is not unavailability.

## Sanction and durable source

Before egress, disclose and record authorizing source, requested and actual provider/model/route/intermediaries, bounded material exposed, inherited restrictions, and which restrictions are tool-enforced versus cooperative. A JJ workspace prevents accidental concurrent mutation; it is not an OS security sandbox. An unenforceable required restriction makes the route unavailable.

Store private run state under `<absolute-workspace-root>/.tmp/rocketclaw/ce-work/<safe-run-id>/`, excluded from publication. All brief, packet, message, log, receipt, fallback, and error-path temporary files stay under local `.tmp`; without JJ use the current project's local `.tmp`. Validate ids with `^[A-Za-z0-9._-]{1,128}$` and at least one non-period character, resolve paths inside the owned run root, reject symlink escapes/foreign ownership, and never overwrite another run. Retain a single scalar run id across retries.

Copy the selected plan or a distilled bare-prompt brief into private run state and record its SHA-256. A prompt brief contains Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and Units (one conservative P1 unless discovery proves distinct units). Never include raw conversation, secrets, unrelated context, or speculative scope. If Goal, bounded Scope, or authoritative verification is missing, return to clarification before dispatch.

Record absolute canonical root, repository identity, bookmark/remote, exact base revision and tree, tracked/conflicted state, ignored/untracked inventory, source digest, unit dependencies, wave base, and exclusions. A selected plan that is the sole tracked dirt may receive a disclosed plan-only checkpoint using `implementation-loop.md` message standards; unrelated dirt is never checkpointed. A prompt-backed run requires a clean canonical tracked baseline. Ignored dependencies/caches alone are not route blockers; inventory and preserve them. Lock the selected engine when the durable ready record is written; proceed with that engine or preserve a blocker, never silently reclassify for speed.

## Native unit transaction

1. **Prepare:** Re-read recorded canonical identity/base and source digest. Persist unit/attempt ids, packet bytes and SHA-256, expected scope, dependencies, restrictions, activity kind, and workspace ownership. Include only the Goal Capsule, Definition of Done, active unit, relevant Verification Contract rows, cited R/F/AE/KTD excerpts, and Key Decisions whose `Governs R…` links name the unit's Rs, or the matching prompt unit. Never send the entire source by default. Use `workspace-setup.md` isolation-first creation/adoption rules and verify the worker's exact base before any edit.
2. **Dispatch:** Create one fresh OpenCode subagent, bound to this unit/attempt, fixed model when authorized, bounded packet, digest, workspace, and result schema. Record the returned handle and runtime identity separately from requested identity. The worker may edit only its owned workspace and run its focused checks; no canonical commits, push, PR, shipping, fallback, peer scheduling, scope expansion, or recipient switching. No shared-workspace worker may run JJ state-changing commands. The host snapshots isolated output. Verify handle/attempt/packet correspondence before accepting evidence.
3. **Supervise:** Dispatch returns before supervision; use separate tool calls for transitions. Where native status/wait exists, bound each wait to 60 seconds, report unit, route, elapsed time, activity, and terminal state. Retain a 7200-second hard cap and a progress-resetting 600-second idle window only for trustworthy incremental activity; terminal-only routes use hard-only supervision with no idle timeout. If the tool cannot expose/enforce required lifecycle bounds, disclose that limitation and use an allowed fallback before launch, not an unsupervised substitute. An unreachable/live attempt remains authoritative. Stop/reap only through exposed lifecycle authority, retain its workspace, and record termination evidence before retry.
4. **Terminalize and inspect:** Require authoritative terminal evidence and validate the result against `implementation-result-schema.json`. Inspect the full actual JJ diff and inventory, including binary/mode/rename/delete and untracked evidence, not only reported paths. From the worker's absolute root snapshot its complete tracked result and pin a recovery bookmark; record exact base, final revision/tree, parent relationship, and changed paths. Unexpected generated output, unexplained differences, or scope expansion blocks integration. Preserve all evidence.
5. **Integrate:** Serialize canonical integration under a host-owned durable lock. Record pre-fold revision/tree, tracked state and ignored/untracked inventory, expected result and unit paths. From the absolute canonical root use JJ changes (for example `jj new <recorded-canonical-base> <verified-worker-result>` for inspected isolated-parent integration), inspect the resulting diff/conflicts, and separate only the accepted unit into a canonical change. A clean textual merge is not semantic compatibility. Never merge unrelated worker history or publish transport/recovery bookmarks. Keep unrelated user state out; unknown canonical movement blocks.
6. **Verify and describe:** Execute the authoritative unit command from the absolute canonical root, capturing exit status directly and durable logs (`PYTHONDONTWRITEBYTECODE=1` for Python). Shell syntax needs an explicit shell with pipe-failure handling, not quoted argv that never expands. Compare tracked revision/tree/paths before and after verification; unexpected tracked mutation fails reconciliation. Inventory ignored entries by metadata and disclose changed/removed/created counts and bounded samples as `ignored_state`; ignored caches/databases and `.env` files are not protected by a JJ snapshot. Do not copy, restore, or delete them automatically. Only after successful checks and exact reconciliation does the host describe the unit using `implementation-loop.md` runtime standards and record the canonical revision/tree, message, and evidence digest.
7. **Failure:** A failed apply/check/describe stops this transition. Retain the pre-fold recovery bookmark, workspace, logs and lock. Undo only proven run-owned changes when authorized and prove exact pre-fold tracked equality; never reset/discard unknown user work. If safe restoration cannot be proved, retain the lock and return blocked. No sibling, retry, or fallback begins until reconciliation and lock release. A crash after a canonical change is reconciled by exact parent/tree/message evidence, never duplicated.
8. **Finish:** Persist integration, authoritative verification, canonical revision and cleanup receipts separately. Cleanup follows the retirement contract below and never follows merely from completion. After all units, run source-wide Verification Contract gates with the same direct exit-status, tracked reconciliation and ignored-state disclosure rules, retaining private logs and durable receipts. A failing source-wide gate blocks shipping/return even when units succeeded.

## Independent parallel waves

Use `execution-strategy.md`'s Parallel Safety Check across files, shared contracts, generated/config surfaces, migrations, lockfiles, singleton resources and merge cost. Uncertainty selects serial work for affected units; cap waves at 3-5. Record one clean wave base, dependency order and distinct isolated workspaces. Start all ready fixed-route workers together, but integrate none until every worker is terminal and all actual inventories are inspected. Same-path or semantic contention stops the wave. Fold sequentially, verify and create each host-owned change, recording its exact parent/tree for later siblings. Revalidate each sibling against only recorded advancing canonical changes; unknown movement blocks. Repeated collisions disable further waves. Preserve unaffected outputs, but never start dependents early or blindly integrate stale results.

## Recovery and exactly-once fallback

Recovery precedes input classification, accepts the supplied run id as authoritative, and performs no fresh dispatch, route choice, reimplementation, or shipping tail. Without an id, only a plan-backed run may be discovered by exact repository/bookmark/source-digest match in the owned run root; multiple unfinished matches require selection, never a guessed id. Prompt runs require their disclosed id. Unsafe/foreign records block.

Reconcile recorded handles, terminal receipts, workspace registration, recovery bookmarks, base/tree and canonical evidence. Adopt at most one exactly matching unbound native job; ambiguous/live/unreachable jobs cannot be duplicated. A complete run is observation-only: report stored unit and source-wide receipts without rerunning test/build/format/install/generation. Missing receipts are blockers. Reconcile interrupted snapshot/integration/description by exact recorded parent/tree evidence; unknown dirt blocks. Explicit abandonment requires the exact recorded terminal handle or preserved result revision and lifecycle authorization.

Retry only after authoritative termination and safe restoration/lock release, using the same run id with a fresh attempt id; preserve earlier receipts and dependency/wave/base contracts. Post-start native fallback requires a durable exactly-once claim after failure/timeout/no-result, no live or unreconciled successful output, and proven pre-fold equality. Record the claim before work; an existing claim/completion forbids duplicate execution. Preserve requested identity and disclose actual current-session fallback. Record its canonical revision and verification digest; then source-wide gates must pass before complete. Shell cannot make this claim a permission/depth bypass.

## Authorized workspace retirement

Stop workers; leave the target and move any active OpenCode session to a surviving workspace before removal. Verify exact registered name, absolute path and run ownership; prove integration or explicitly authorized abandonment, preserve recovery/archive/best bookmarks, and copy/read back required evidence outside the target. Inspect tracked changes/conflicts and ignored/untracked/non-disposable content: snapshots do not protect ignored/untracked files. Completion is not deletion permission; respect harness lifecycle and existing cleanup authorization. Never remove unclear, unrelated or still-referenced content.

From a surviving absolute root run `(cd "$surviving_workspace_root" && jj workspace remove "<verified-name>")`. Verify both deregistration and directory disappearance; warning-only deletion failures are incomplete cleanup. Preserve remaining state and report the blocker, no force deletion or Git cleanup fallback. `jj workspace forget` is only unregistering while retaining files. Bookmark deletion is separate and must not remove recovery references still needed.

## Receipts and tail ownership

Record binding source/mode/target/model, requested and actual route/intermediaries/model, trustworthy served-model receipt status, requested effort and served-effort status, fallback reason, source kind/digest, scalar run id, plan checkpoint, unit/attempt/handle/base/result/canonical revisions, terminal/integration/verification/cleanup states, blockers and recovery path. Distinguish authoring completion from canonical completion. Report transitions in commentary or the structured return; never claim missing independence/coverage or fabricate observations.

Standalone runs resume `shipping-workflow.md` only after verified implementation. Return-to-Caller Mode returns implementation/local verification receipts and `standalone_shipping_skipped: true`; it never enters simplify/review/PR/CI/babysitting owned by the caller. Workers inherit neither tail.
