# Native Cross-Model Implementation

This reference replaces the former dispatch/controller/workspace bridges. Implementation uses OpenCode native subagents or shell-supported OpenCode APIs only, never another harness. The host remains canonical integration and verification authority; changing the author never changes the shipping owner.

## Resolve intent and capability separately

Preserve the binding's provenance, mode (`prefer` / `require`), target family, model, intermediary mapping and effort, and the configured ordered `work_engine_preferences` and `work_engine_effort` tiers. Read enabled `.rocketclaw/config.local.yaml` before `config.yaml`; a lower layer fills omissions, never overrides higher intent. Use `opencode.models` to resolve exact available provider/model IDs. Do not silently replace a pinned model, equate same-model execution with cross-model independence, or dispatch another harness to satisfy a legacy target. Disclose unsupported targets and unmet configured intent.

Permission, model permission, and depth are separate checks. A host exception allowing explicit user OR loaded-skill delegation is satisfied by this skill's bounded worker instructions: do not seek a second approval. An unconditional delegation ban or tool denial still wins. If the host allows model overrides only for an explicit user model request, configuration/skill intent alone does not authorize an override: use a suitable inherited model when the contract permits, disclose unmet cross-model independence, otherwise block. Depth/capacity errors do not imply permission or model rejection. Never evade any rejection with shell or another harness.

Preflight without sending source: inspect available native tools, resolve the intended model, and check permission/capacity. Walk ordered candidates only on observed unavailability, preserving each rejection reason. With no qualifying independent route, report requested versus actual route/model and use inline/inherited fallback only when the task's independence contract allows; required independence remains incomplete otherwise. Record actual served model as `unverified` without a trustworthy receipt. Never claim a configured request was served from the request alone.

## Durable bounded-unit protocol

1. Before dispatch, create an owner-private run directory beneath the absolute canonical workspace `.tmp/rocketclaw/ce-work/<safe-run-id>/`. No OS temp, host caches, random discovery of other runs, or global state. Write a durable manifest containing absolute repository/workspace identity, verified bookmark/base commit IDs, source kind and SHA-256, binding provenance, route/model/effort, task dependencies, declared files/exclusions, and run ownership. Copy the source and read it back; never overwrite a conflicting existing run.
2. A plan-only checkpoint is allowed only for the exact selected dirty plan and disclosed to the caller. Unrelated tracked/ignored/untracked work stays untouched. A prompt brief requires bounded goal, scope, acceptance, verification and exclusions; do not send a vague prompt or ask a worker to invent scope.
3. Persist one packet per unit/attempt and its digest before dispatch. Include only Goal Capsule, Definition of Done, active unit, relevant Verification Contract entries, cited requirements/findings/key decisions and reverse-linked governing Product Contract decisions, qualified prototype citations, matched pack rules, expected files, evidence strategy and exclusions. Include the implementation-loop's Build what was asked and Plan IDs stay out of written files rules verbatim. Give the worker no canonical commit, publish, integration or route-selection authority.
4. Dispatch a fresh generic native subagent for exactly that unit, with the packet path/digest and absolute verified workspace/base. Record the returned session/handle immediately. No retasking across units. Apply `execution-strategy.md` isolation and shared-wave constraints. Independent required reviews must use independent fresh contexts; missing independence cannot become complete coverage.
5. Persist observations and receipts: unit/attempt, exact packet digest, requested/actual route and model, handle, activity, terminal status, changed paths, scope-expansion requests, tests/evidence, and any error classification. A missing result, lost contact or inactivity is not success or authoritative termination. Use bounded status calls, retain a 7200-second hard deadline and a 600-second progress-idle window only when progress is trustworthy; otherwise disable idle termination. At a deadline request native cancellation if supported and confirm termination. No fallback/duplicate while the attempt is live or uncertain.
6. Inspect the actual JJ changes including binary, mode, rename and deletion evidence, not merely the summary. Pin a recovery bookmark to the accepted worker commit and preserve complete output. Unexpected/generated paths require host scope resolution before integration. One canonical integration at a time: record the exact pre-integration commit, parent/bookmarks, tracked status/conflicts, and ignored/untracked inventory, acquire a run-owned lock exclusively, and revalidate prerequisites against the current canonical base.
7. Integrate an isolated unit with native JJ (`jj rebase -r <verified-worker-commit> -d <verified-canonical-base>` in its absolute workspace, then inspect conflicts and the full exact diff); do not move canonical bookmarks until the host accepts it. Shared units are already in the canonical working copy: inspect only their owned files. Run authoritative verification in the absolute canonical target workspace, capture exit status directly and retain logs. If verification changes tracked state unexpectedly, fail reconciliation. Disclose ignored-state created/changed/removed counts and a bounded path sample; ignored local databases/secrets are not protected by JJ snapshots.
8. Only after successful verification and reconciliation may the host compose and create the path-limited canonical commit under `implementation-loop.md`, then record exact commit ID and verified evidence. A crash after commit is recovered by checking the recorded commit and parents, never redispatching blindly. On failure preserve output, recovery refs, logs and lock; restore only run-owned tracked changes from the verified pre-integration revision, never ignored/untracked or user work. Release the lock only after exact equality is proven. Unproven restoration blocks fallback, retry and dependent work.
9. For parallel siblings, integrate in dependency order and record each earlier canonical commit. Revalidate every remaining sibling against the advancing base; a conflict-free merge is not evidence of semantic compatibility. Stale/colliding work is explicitly resolved or rerun only after the old attempt is terminal. Run source-wide Verification Contract checks after all units; capture status/logs and reconcile tracked state as above. Failed final checks block completion even if unit cleanup succeeded.

## Isolation and retirement

Detect an existing harness-owned isolated workspace first and verify its registered name/path and exact base. Reuse it without renaming/recreating; respect harness lifecycle. Native isolation must support colocation and the requested name, otherwise report a compatibility blocker rather than bypass the harness. For skill-owned new workspaces delegate naming/setup to `ce-worktree`: capture local YYYYMMDD once, meaningful kebab task slug without double date, stable name matching destination basename beneath the absolute local `.tmp` parent; check both registry and path collisions and append `-2`, `-3`. Preserve PR/source bookmarks.

Creation is explicit: `(cd "$workspace_root" && jj workspace add --colocate --name "<name>" --revision "<verified-base>" "<absolute-owned-destination>")`; verify `(cd "$created_root" && jj git colocation status)` and the full commit ID before any edits. Every JJ call runs from the absolute target workspace cwd, never merely `-R`.

Completion is not removal authorization. Before authorized retirement stop workers, leave the target and move the harness session to a surviving absolute workspace. Verify registry name/path/run ownership, integration and recovery refs; copy evidence outside target and read it back. Inspect tracked/conflicted AND ignored/untracked content; snapshots do not protect ignored/untracked files. Do not remove unrelated, ambiguous, referenced or non-disposable content. From the surviving absolute root use `jj workspace remove <verified-name>`, then verify both deregistration and directory absence. Failure retains/reports state, never force-deletes or falls back to Git. `jj workspace forget` is only unregister-and-preserve-files. Bookmark cleanup is separate and preserves best/archive/recovery refs.

## Recovery and fallback

Recovery activation precedes triage and never dispatches or ships. Require the supplied safe run ID (prompt-backed runs cannot be rediscovered); plan discovery may select only one unfinished manifest matching absolute repository identity, bookmark and source digest. Ambiguity, unsafe ownership or foreign state blocks selection. Read the durable manifest and receipts, inspect native handle state and JJ identities; do not rerun completed verification or infer completion from a clean tree. Return preserved paths and exact next recovery action.

After authoritative terminal failure and proven restoration/lock release, persist an exclusive fallback claim before any inline work. Exactly one fallback is eligible; no recipient substitution while a route is viable, no duplicate after a completed claim. A `require` binding never authorizes falsely claiming independent execution. Preserve requested/actual differences and blocked independence. Record fallback canonical commit and verification digest, then final source-wide check receipt. Return-to-caller never enters standalone simplify/review/PR/CI; standalone resumes its original shipping tail only after complete verification.
