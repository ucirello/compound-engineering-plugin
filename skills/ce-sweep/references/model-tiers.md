# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

Use native OpenCode subagents and `opencode.models` discovery to resolve available model IDs, never a helper dispatcher or guessed model name. If the user's or project's active instructions or the live prompt name a model for this subagent, use that permitted model instead of the default tier above. They can name it by tier, prompt-asset name, or the subagents being dispatched. Otherwise a configured role model takes precedence over the default tier only when host policy permits model selection. Where model overrides require an explicit user request, omit the override and inherit; disclose the unmet configured route. Delegation permission is not model-override permission.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

This skill explicitly requests source-fetch and media-analysis delegation: actual host user-OR-loaded-skill permission permits it without another approval. Respect unconditional higher policy, actual denial, and missing tools. Never retry a denial or evade it through another dispatcher. Verify nesting depth separately by configuration discovery: the package default and consuming OpenCode configuration must provide integer `experimental.subagent_depth >= 3`. Distinguish depth/capacity errors, policy denial, model rejection, missing tools, and pre-launch argument errors in the report. Correct a pre-launch argument error once when not a denial; leave capacity-limited work queued. If dispatch is unavailable or denied, the explicitly permitted inline degradation above may perform only the same bounded read-only analysis; do not bypass a restriction that also forbids the underlying work. Retain receipts with requested/effective model, whether an agent launched, outcome, and uncovered items. These extraction tasks do not claim cross-model review independence.

Setup prerequisite (documentation only): locate the actual user-level configuration via `opencode debug paths` / `opencode debug paths config`, normally `~/.config/opencode/opencode.json`. Merge integer `experimental.subagent_depth` of at least 3 into the existing JSON or JSONC document, preserving sibling/unrelated settings and any higher value; do not create a competing document. Package installation alone does not enable consumer depth, and higher-precedence settings must not lower it. Do not modify global files automatically.
