# Native model execution contract

Read this when `execution-engines.md` selects a configured model route or when recovering a run. Implement the protocol with `opencode.models`, native subagents and shell, not harness adapters or workspace controllers. Independently inspected JJ state and native tool results are evidence; worker assertions alone are not receipts.

## Intent, selection and authority

Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml` then `config.yaml`. A present local list/map, including an empty one, replaces its team counterpart. Preserve ordered candidates, exact model pins, provider intent and reasoning tiers. Modes remain `off | prefer | require`; live intent wins over defaults and a typed caller binding fixes one candidate. Preserve configured harness identities (`codex`, `claude`, `grok`, `cursor`, `composer`, `opencode`, `antigravity`) as requested intent, not routes to launch another harness. An omitted Antigravity model preserves its ordered Gemini intent (`gemini-4-argon`, then `gemini-3.8-flash`); explicit models/presets stay exact. Selectors are data, never shell syntax.

Preflight candidates in order with `opencode.models` without sending repository content; resolve exact provider/model IDs and supported effort variants. Never silently substitute a pin, effort or intermediary. An unavailable harness-specific requirement is unavailable in OpenCode, not satisfied by a similar model name. Record target, requested route/intermediaries, actual route, requested/actual model, served-model receipt status, requested effort and actual effort evidence separately; unknown served identity/effort is `unverified`. Host-equivalent defaults collapse to native execution with the requested/actual difference disclosed.

This skill explicitly requests bounded workers where scheduling calls for them, satisfying a host rule permitting delegation on user OR skill request. It cannot override an unconditional prohibition or actual denial. Model permission is separate: when host policy requires an explicit user model request, config alone never authorizes a subagent `model` argument. Use a suitable inherited-model worker if adequate and disclose unmet intent. Same-model workers are separate workers, not cross-model independence. Required distinct-model/route coverage that cannot run remains incomplete. Classify actual errors as permission denial, missing tool, model-argument rejection or depth/capacity exhaustion. Never repeatedly retry denied operations or evade restrictions via shell/another harness.

Both `prefer` and `require` fix a viable recipient. Exhaust preflight candidates with reasons recorded, then fall back once to this session model without broadening permissions, prompting or choosing an unrequested recipient. Latency/cost is not unavailability. After dispatch starts, no substitution or fallback until authoritative terminal/reaped evidence and exact restoration if integration began.

## Durable source and receipts

Create private records under the canonical absolute workspace root's `.tmp/rocketclaw/ce-work/<run-id>/`. Packets, logs, errors, briefs and recovery copies all stay in local `.tmp/`; ensure it is ignored. `CE_WORK_RUNS_ROOT`, when used, is a local `.tmp/` parent of runs, not an individual run. Never include credentials or raw conversation by default.

Write/read back a manifest containing repository identity, canonical absolute root, bookmark, exact base commit, source kind/digest, fixed route/model/effort, authorizing source, exposed material and restrictions. A plan-only dirty path may receive a disclosed owned checkpoint; unrelated dirt makes this isolated route unavailable. Prompt work requires a clean baseline and a bounded durable brief: Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, Units (one P1 unless evidence supports more). Missing bounded scope/acceptance returns to clarification. The durable source copy/digest remains authoritative thereafter.

Before egress disclose recipient/provider/intermediaries, bounded repository/unit/prototype material and enforced versus cooperative restrictions. Isolation is not an OS sandbox. Never auto-approve permissions; unmet required confinement makes a route unavailable. Workers receive only inherited authority: no canonical commit, push, PR, shipping, recipient switch, fallback scheduling, peer scheduling or scope expansion.

Each attempt binds run/unit/fresh attempt ID, native job/session ID, exact workspace/base, packet path/SHA-256 and result directory to one fixed recipient. Write authorization before dispatch and record the returned native ID immediately. Reconcile at most one exact matching unbound job after a crash; duplicate/mismatched binding blocks. Packets contain only active Goal Capsule/DoD/unit, relevant Verification Contract rows, cited R/F/AE/KTD excerpts, governing Product Contract decisions, prototype citations with locality/availability qualifications, expected files, evidence strategy, exclusions, inherited restrictions and applicable Pack rules. Prompt packets contain only the matching P-unit. Require inspection of accessible cited prototypes/screens before relevant edits, even when stored in another workspace. Never expose the entire plan/conversation by default.

Receipts distinguish process terminal state, complete output snapshot, scope inspection, integration, authoritative verification, host canonical commit and cleanup. Preserve binding, requested/actual identities, fallback reason, source kind/digest, plan checkpoint, blockers, recovery path, ignored-state divergence and all attempts in `unit_receipts`; use `implementation-result-schema.json` for worker results. Process completion alone is never implementation completion.

## Isolation

Detect isolation first; reuse existing verified names unchanged and preserve PR/source bookmarks. Synchronous native units stay in the active workspace. Harness-provided isolation remains harness-owned: request supported colocated JJ capability and verify intended base/name/colocation without bypassing lifecycle authority. Unsupported required new naming/colocation is a blocker, never a Git fallback.

When authorized to create isolation, capture local creation date once and normalize a meaningful task/PR/revision slug as `YYYYMMDD-meaningful-kebab-slug`, without double-prefixing a caller's dated name. Persist the selected name across retries/resumes/midnight. Use that same identity for workspace name and destination basename under an absolute local `.tmp/` parent. Check registrations and paths; suffix collisions `-2`, `-3`, never overwrite. From the source absolute root run `(cd "$workspace_root" && jj workspace add --colocate --name "$name" --revision "$verified_base" "$absolute_destination")`; from the destination verify `jj git colocation status` and exact base commit before editing. Do not recreate existing isolation just to impose naming. See https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace .

Every JJ command runs with cwd at the target absolute workspace root, never `-R` alone. Repository GitHub calls use `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. Never directly execute Git.

## Serial unit transaction

1. Re-read canonical identity/bookmark/base, source digest and clean state. Persist one authorization/attempt, then dispatch one fixed native worker. After authorization, no canonical authoring until accepted integration or recorded fallback. Worker edits/tests only its workspace and leaves canonical operations to host.
2. Observe in separate native tool calls, not a shell loop spanning dispatch through integration. Dispatch returns before supervision. Bound individual waits to 60 seconds where supported; report unit, route, elapsed time, meaningful activity, activity kind and terminal state. Preserve a 7200-second hard cap and a 600-second reset-on-progress idle window only for reliable incremental activity; otherwise `hard-only` disables idle timeout. Missing activity does not prove failure. If required supervision cannot be enforced, disclose unavailable capability before dispatch. Live/unreachable attempts remain authoritative: no duplicate or fallback. Stop/reap through authorized native lifecycle tools and retain output.
3. On authoritative completion, host snapshots complete JJ output and pins a recovery bookmark. Verify sole parent equals recorded base. Inspect exact base-to-result range via `jj diff --from <base> --to <result> --git`, actual changed paths, tracked/untracked content, binaries, modes, renames and deletions. Compare expected scope, worker evidence and expansion requests; unexplained byproducts block before integration.
4. Acquire a durable single-writer lock by exclusive local file creation. Revalidate exact canonical baseline/bookmark; record pre-fold revision/tree/path inventory and recovery reference. Only host applies accepted output, using native JJ rebase of the isolated result onto the verified advancing revision and `jj squash --from <accepted-result> --into <canonical-change>` as appropriate to recorded topology. Inspect conflicts before proceeding; never guess targets or overwrite unrelated work. A clean apply is not semantic compatibility; transport snapshots are not canonical commits. Stop visibly on any failed transition.
5. Run authoritative Verification Contract commands in canonical absolute cwd with actual exit status/logs and Python bytecode disabled where applicable. Simple commands use direct argv; shell syntax requires explicit shell with pipefail from the first attempt. Record expected post-apply tracked tree/identity before verification; tracked/content/bookmark/revision movement by checks fails reconciliation. Inventory ignored entries by metadata before/after and report created/removed/changed counts plus bounded path samples. Never copy/restore/delete ignored files; empty ignored directories are excluded, `.env` and databases are not protected from misbehaving checks.
6. Only after scope, verification and exact reconciliation succeed, compose full messages under `implementation-loop.md`, create the host-owned path-scoped canonical commit and record exact parent/tree/id before releasing the lock. Failure forbids committing. Restore only run-owned tracked integration changes to the exact pre-fold snapshot through JJ recovery, prove equality and release before next unit/retry/fallback. Preserve unknown dirt. If equality cannot be proven retain lock, workspace, recovery refs and evidence and return blocked. A crash after commit reconciles exact parent/tree rather than recommitting.
7. After every unit is accepted, run source-wide gates with the same clean-snapshot, reconciliation and ignored-state receipts. Failed gates retain logs and block shipping/return despite successful cleanup. Record `RUN_VERIFIED` only from actual successful receipts.

## Parallel waves

Require the Parallel Safety Check across dependencies, files, contracts/interfaces, migrations, lockfiles, generated registries/config, environment singletons and merge cost; uncertainty selects serial. Cap waves at 3–5 workers. Record one clean wave base and dependency order, prepare distinct isolated workspaces from it and terminalize/inspect every output before integrating any. Same-path or semantic collisions stop the wave. Integrate sequentially under lock; later preflights accept only exact earlier host-owned canonical commits recorded for this wave, never unknown head movement. Recheck scope/semantic compatibility and authoritative verification each time. Failure requires exact restoration and lock release before unaffected siblings proceed; dependents remain queued. Preserve unaffected output. Repeated collisions/broad edits/unprovable restoration disable more waves. Workers cannot schedule peers or alter dependencies.

## Recovery, fallback and cleanup

Recover before ordinary triage; never start new work. Explicit `implementation_run:<safe-id>` is authoritative. Otherwise discover a plan run only by exact repository identity/bookmark/plan digest, not shared-root guesses. Prompt runs require their disclosed ID. Multiple unfinished matches, unsafe/foreign manifests block selection. Reconcile native job evidence, pinned output, expected post-apply tree/path set and exact canonical parent/tree; do not redispatch/reapply/recommit. Snapshots written before receipts are reusable only after exact proof. Unknown dirt blocks without destructive restoration.

Completed runs are observation-only: return stored receipts, do not rerun tests/build/format/install/generation or either shipping tail. Missing required evidence is a blocker. Lost contact remains live until authoritative termination. Explicit abandonment requires exact output revision or terminal job ID when no output exists, plus existing cleanup authorization.

After authoritative failure/timeout/death, or exact restoration and lock release, exclusively persist one fallback claim before native authoring. Live or successful unreconciled output refuses fallback. Both modes may fall back once to current session model with reason/requested identity disclosed. Record claimed/completed state, accepted canonical revision and verification digest; an existing claim never starts duplicate work. Corrected retries retain the scalar run ID/dependency/wave/base contract, use fresh attempt IDs and preserve earlier receipts. Uncertain restoration forbids fallback/retry.

Completion does not authorize workspace deletion. Stop workers, leave target cwd and move any active session through the native session tool to a surviving workspace. Prove exact registered name/path/run ownership, authorization and required integration. Preserve recovery references; copy/read back evidence outside target. Inspect tracked changes/conflicts and ignored/untracked content: removal snapshots do not protect ignored/untracked files. Never remove ambiguous, unrelated, still-referenced or non-disposable content; respect harness lifecycle authority. From a surviving absolute root use `jj workspace remove <verified-name>` only for authorized disposable run-owned retirement. Verify deregistration AND directory disappearance; warnings/remaining paths are blockers, retain/report state without force deletion or Git fallback. `jj workspace forget` is unregister-only preserving files. Bookmark deletion is separate; retain best/archive/recovery references still needed.

The engine changes implementation authorship only. Standalone work resumes its owned shipping workflow after verified implementation; return-to-caller returns receipts with `standalone_shipping_skipped: true` without the caller's final simplify/review/PR/CI tail. Workers inherit neither tail.
