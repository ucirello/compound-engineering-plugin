# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

Configured model choices and tiers remain authoritative intent: user/project/live role selections take precedence over default tiers. Resolve exact available IDs using native `opencode.models`; dispatch through native subagents (or a documented native shell/API primitive), never another harness. Apply a model override only when the host permits it, including any explicit-user-model-request condition. A configured model does not itself grant override permission. If an override is not permitted or available, inherit a suitable model, retain budgets, and disclose the unmet tier/model intent; do not guess IDs or bypass rejection.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

**Permission and capacity are separate.** These loaded skill instructions explicitly request delegation, satisfying a host user-OR-loaded-skill delegation exception without asking the user again. Respect unconditional delegation bans and tool denials. Distinguish delegation permission, model permission, missing tools, and actual nesting-depth/capacity errors. Correct a pre-launch argument error once; leave transient capacity-limited work queued. Only classify an explicit depth/capacity error as exhausted depth. Never evade a restriction through shell or another harness. If native dispatch is unavailable or denied, this skill permits the inline degradation above, with the same read/output limits and a truthful coverage/failure summary; unavailable required independent analysis remains incomplete. Same-model workers are not cross-model independence.

**Depth setup (documentation only).** For nested runs, merge `experimental.subagent_depth` as an integer at least `3` into the user's existing `~/.config/opencode/opencode.json`, locating the active path with `opencode debug paths` or `opencode debug paths config` when needed. Preserve any higher integer, JSONC, siblings, and unrelated settings; do not create a competing config file. Bundled config/plugin installation alone does not configure a consuming project, and higher-precedence config must not lower depth. Never edit host configuration during a sweep. Depth does not grant delegation or model permissions.
