# Reviewer Dispatch

Read this before dispatching the Step 2 reviewers. It covers the reviewers' model, what happens when the harness is full, how review agents are released, and the permission mode.

**Delegation permission.** Step 2 explicitly requests reviewer subagents. When the host permits delegation requested by the user or a loaded skill, this instruction qualifies; no second approval is needed. An unconditional prohibition, actual permission denial, or missing native tool still applies. Do not invoke another harness or shell to emulate delegation.

**Model selection.** The desired model comes from the user's or project's active instructions or live prompt, which may name a model by tier, prompt-asset name, or reviewer role. Otherwise use the role's configured model from the effective project configuration, falling back to the balanced mid-tier (Sonnet class). When an override is permitted and available, use `opencode.models` to resolve the model to an exact available ID, and use the native subagent model argument. Task wording alone does not select a different model.

Permission to delegate is not permission to override the model. If the host requires an explicit user model request and there is none, omit the model argument. Also inherit when selection is unavailable, provided the inherited model satisfies the review requirements; disclose any unmet model preference. If inheritance cannot satisfy a fixed-model or required cross-model pass, report that pass as incomplete. Same-model subagents provide separate reviews, not cross-model independence.

A generic subagent is one whose whole brief is the prompt you send it. When the host's subagent tool makes you name an agent, use only a name you have seen the host list, and list its agents before the first dispatch if you have not. Pick the plain one that adds no role of its own, which still counts as a generic subagent. Never pick a specialist, such as a reviewer or worker agent, whose own role prompt, output format, or tool limits would replace or narrow your prompt.

**Bounded dispatch.** Each reviewer starts in a fresh subagent whose context holds only its own rubric and inputs. The one exception is the combined reviewer that `references/single-pass.md` chooses below a size cutoff, which is itself one reviewer. Otherwise do not combine reviewers in one prompt, and do not send a reviewer to an agent that already ran another. Queue the reviewers and launch only as many as OpenCode accepts at once. A concurrency or active-agent-limit error means OpenCode is full, not that the reviewer failed: leave the reviewer queued, wait for a running reviewer to finish and release its slot if needed, and retry after a slot frees. A temporarily full queue is not a reason to run a reviewer inline.

**Depth and fallback.** Check the effective `experimental.subagent_depth` for the target location. To inspect the active service's configuration documents in precedence order, use `opencode api GET /api/config --param "location[directory]=$workspace_root"` with the absolute workspace root; the bundled default alone does not establish the running session's remaining depth. Use the actual error to distinguish nesting depth exhaustion from a full queue, a permission denial, a model-argument rejection, or a missing tool. Correct an invalid invocation if supported; omit an unsupported model argument only when inheritance satisfies the pass. Never retry a denied operation or bypass a depth limit. If native dispatch is unavailable or cannot recover, run each feasible pass inline using the same prompt asset and disclose the substitution and its cause. An inline pass is not independent delegation and cannot satisfy a fixed-model or independence requirement it does not meet; report those passes as incomplete. A prohibition on the review work itself also rules out inline fallback.

**Agent lifecycle.** Collect terminal outcomes, including failures, before cleanup. Close or release review-owned agents when the harness provides caller-owned cleanup, before refilling slots, advancing stages, or returning. Do not message completed agents with no remaining work. Do not infer released capacity from completion or interruption, or invent cleanup operations.

**Permission mode.** Omit the `mode` parameter on the dispatch call so the user's configured permission settings apply.
