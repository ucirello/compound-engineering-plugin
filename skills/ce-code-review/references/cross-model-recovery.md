# Native peer recovery and coverage

Classify the observed native dispatch error before recovery: permission denial,
model-argument rejection, missing tool/route, nesting-depth exhaustion, transient
capacity, provider failure, timeout, malformed output, or artifact trust failure.
Do not infer account logout from login-shaped text without provider-capable
dispatch evidence. Report the actual diagnostic and supported remediation.

Never retry a denied operation or bypass a nesting limit through shell or another
harness. Capacity can queue behind active work; depth is not concurrency. Ask the
parent coordinator to dispatch only when that allowed route preserves the same
read-only brief and independent reviewer contract; an inline pass is attributed
parent evidence, not an independent pass.

Before local dispatch, a no-launch failure retains the local adversarial persona.
After a launched peer fails, stop/release it before restoring the local reviewer.
Keep one adversarial cover; do not double-dispatch the same brief accidentally.
Recover only the same disclosed fixed route, model, criteria, exact captured
base/head range, and trust boundary, within the original shared deadline.
Stop on a repeated infrastructure failure. A provider overload allows at most
one same-route retry; ordinary no-review, exhausted budget, or timeout restores
the local fallback without restarting a provider loop. A changed recipient
requires fresh route resolution and disclosure and must remain within policy.

Validate normalized artifacts through a bounded, non-symlink, run-owned file
read; corruption or trust failure is degraded coverage, not a clean skip. Keep
receipt facts needed for the final report before removing only run-owned
transient material. Collect terminal outcomes and stop/release native agents on
all exits; never abandon running work or delete its evidence while it is live.

Coverage distinguishes disabled/not-started peers from started failures, and
names `adversarial lens: in-process fallback (cross-model peer not run: <reason>)`
when appropriate (`peer.outcome: in-process-fallback`). Do not call this a
`harness-native fallback`, which means ce-code-review itself did not run.
Local fallback may cover the lens but cannot fulfill a required cross-model
pass. Report that requirement incomplete, never fully verified. Preserve every
requested/actual model, effort, route, and independence receipt field.
