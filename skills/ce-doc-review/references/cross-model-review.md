# Cross-Model Judgment Pass

An additive, read-only judgment pass on one fixed OpenCode route. Run it only when `adversarial-document-reviewer`, `product-lens-reviewer`, or `security-lens-reviewer` activates in ordinary persona selection. Review each activated lens and **one** whole-document sweep on the same route. Feasibility, coherence, scope-guardian, and lite review do not activate the pass. The readability check in Phase 1 still applies.

**Check egress policy first.** `cross_model_review_mode` accepts `auto` (default) or `off`. In `off`, skip before lookup or disclosure unless the user explicitly requested a cross-model peer for this run in conversation. Configured preferences do not opt in. A live prohibition takes precedence. Record **disabled by checkout config** separately from permission, capability, and independence failures.

**Separate target, route, recipient, and serving identity.** Attest the parent model family from the running session's native model metadata (e.g. a runtime-published model ID mapped to its known family). A harness name, configured model, catalog entry, or model's self-report is not proof of what is serving. An unknown parent family cannot satisfy automatic same-family exclusion; skip the automatic pass. An explicitly requested, otherwise eligible route can return supplemental evidence with independence unverified. For the automatic pass, exclude a same-family target before dispatch. After dispatch, a same-family or unverifiable result never establishes cross-model independence.

**Choose target in order:** live conversation, `cross_model_peer` in layered config, preference in active project instructions, then the first eligible family in `codex → claude → grok → antigravity`. Recognize the existing target vocabulary; use `opencode.models` to discover the exact provider/model IDs and advertised variants available natively. In a native pass the family labels name model intent, not commands. A specifically requested intermediary or configured route pin is binding: if the native route cannot honor it, report the route unavailable instead of substituting. Cursor default and Composer are opt-in targets, not automatic fallbacks.

| --- | --- |
| `codex` | GPT-6.1 Terra (`gpt-6.1-terra`) at `high`; GPT-6.1 Sol (`gpt-6.1-sol`) is the editorial alternate when Terra is unavailable. |
| `claude` | Opus (`claude-opus-5-5`) at `high`. |

| `composer` | Composer 2.5 at its fast preset. |

Live model/effort choices outrank `cross_model_model` / `cross_model_effort` in the same workspace config. A pin must be supported on the chosen route and satisfy its family requirement. A configured or explicitly stated choice runs exactly, or the peer is not run. Only an unavailable **editorial** default may be replaced by its documented alternate or closest advertised same-family model on the same route, without adding a recipient; resolve and disclose the result. A family or model that is visible in the catalog may still be refused at dispatch.

**Authorize the native dispatch under `references/dispatch.md`.** This skill explicitly requests these reviewers where a user-or-skill delegation rule permits them. That does not authorize choosing a model when the host requires an explicit user model request. Do not pass `model` or effort overrides when forbidden; an inherited model is not a substitute for a required different-model leg. A genuine denial, nesting limit, or missing native tool remains in force. Never work around one with shell, another harness, an alternate agent definition, or another recipient. If the selected model and variant cannot be bound with the native tool under active permissions, name the unmet requirement in Coverage.

**Bind and sanction one route.** Before sending content, establish the exact target, OpenCode route, recipient(s), requested model, and requested reasoning. When `CROSS_MODEL_PEERS` is set and not empty, it must sanction the target and every actual recipient/intermediary. Preserve the aliases: `cursor` or `composer` sanctions Cursor as an intermediary, but `grok` alone does not sanction Grok through Cursor; `antigravity`, not `gemini`, sanctions the Antigravity target. Unset/empty means no allowlist filter, not permission to ignore egress policy. When no allowlist filters the route, this invocation (or the caller's non-interactive request) and the pre-dispatch disclosure provide the sanction, subject to the actual host policy. Do not probe credentials by sending review content.

## 2. Disclose egress and dispatch

- **Interactive:** prominently announce the cross-model pass before dispatch, with the requested model and reasoning, concrete route, and all recipients. Say that the full document is sent to the stated recipient(s) for the sweep, even though unified-artifact lenses are sliced. Name the model as **requested**, not as what served; qualify actual serving only when a receipt differs or the route requested no model. Describe the pass as intended to be independent only when the parent and intended target families are attestably different. If no route is eligible, give one quiet skip line with the reason.
- **Non-interactive:** no user-facing announcement. Before each authorized dispatch record a one-line egress audit in the native tool trace or private local run record, naming the lens, route, requested model/effort, recipients, and whether the payload is a slice or the whole document; record whether dispatch actually started. Never include document text or credentials in the audit line.

Dispatch each leg as a fresh generic OpenCode subagent in the same bounded dispatch wave as the ordinary reviewers. The peer must have no repository context or tool access: use the native host's supported restricted/read-only context with no project file access, shell, writes, web, extensions/MCP, or further delegation. Use an empty private local run directory if a native dispatch context needs a working directory; never create an alternate JJ workspace for it. A prompt asking the peer not to use tools is not enforcement. If the host cannot enforce the needed isolation or cannot bind the disclosed route, skip affected legs and record the coverage gap. Do not change permissions for unrelated operations.

- **Activated trio lenses:** embed the full selected persona asset, output rubric and schema from `references/subagent-template.md` and `references/findings-schema.json`, and the same reviewer-specific slice as its ordinary twin for a unified artifact; use the full legacy document. No project paths to read and no absolute document path. Supply the document basename, Phase 1 type and origin, and the round-1 primer, even on later rounds. Synthesis handles previously rejected or resolved findings as usual.
- **Whole-document sweep:** dispatch **one** `whole-doc` leg using `references/personas/whole-doc-reviewer.md`, with the same route, classification and origin, but embed the full document, never a slice. It has no in-process twin and can corroborate any merged finding it independently reaches.

Ask for one object matching the findings schema, not a file write. Keep run-owned dispatch IDs, status, and trusted receipts in the private local run directory defined in `references/synthesis-and-presentation.md`; stage any slices or intermediate results only there.

## 3. Bound recovery and collect every outcome

Use one wall-clock budget for the peer wave (`CROSS_MODEL_HARD_SECS`, default 1200 seconds; reject a non-positive or malformed value visibly). Once dispatch begins, track one shared deadline including queueing, waiting, and retries; stop waiting when it expires. If the runtime reports peer activity, time out an idle child after 480 seconds, or at the shared deadline if earlier; a quiet tool trace alone is not proof of idleness. Use bounded native waits/status and terminal notifications; do not issue a blocking call longer than the remaining budget. Cancel overdue work or release completed run-owned children through supported native lifecycle operations only. If the host cannot confirm a terminal state or cleanup, preserve evidence and name the unresolved child and blocker before returning. Never claim it stopped based only on requesting cancellation.

- **Concurrency backpressure:** queue and retry when a slot frees, within the shared deadline. Nesting exhaustion is not transient slot pressure. A permission denial, missing capability, or forbidden model override is not a retryable transport error.
- **Recoverable infrastructure failure:** fix the native invocation and retry the same approved route and scope once while the deadline holds. Stop on repeat failure. If this removes the whole pass, name the loss of both corroboration and the whole-document sweep; do not relabel it a clean skip.
- **Overload:** retry the exact same model, effort, recipients, and scope once for a positively identified transient provider overload (HTTP 529 or the native equivalent). A refused editorial-default model may be retried once on the same route with the documented alternate or closest same-family advertised replacement, after updated disclosure. Never swap a pin. A refused optional editorial effort may be omitted only if the route supports that fallback and it does not violate the requirements; disclose the effort as unverified. Do not retry an authentication, quota, or usage-limit failure as an overload, and do not fall through to another recipient. Any authorized route/recipient change needs new resolution, sanction, and disclosure before sending content.
- **Classify from evidence:** distinguish no dispatch or a proven pre-egress failure from a started dispatch that failed, timed out, died without a result, or returned unusable output. Only an actual provider-capable launch or provider response establishes an account authentication failure; without it, report the observed context failure, not that the user logged out. Read available native diagnostics before cleanup. Empty, valid findings are a real result: report no additional issues, not missing coverage.

Validate each native return against `findings-schema.json` and match it to this run's child ID and expected lens. Discard raw, malformed, or unowned results; a missing file or unsupported receipt is not a successful verification. The orchestrator forces the reviewer ID to `<reviewer-name>-<provider>` and changes peer `safe_auto` to `gated_auto` before writing `<reviewer-name>-<provider>.json`. Record `cross_model_target`, `cross_model_harness`, `cross_model_route`, `model_requested`, `model_actual`, and `independence_verified` from the bound request and trusted native evidence. Use the native return metadata or the authorized session API (`opencode api get /api/session/<child-session-id>/message`) to inspect runtime-published serving identity, not internal storage. `model_actual` is `unverified` if there is no served-model record; never derive it from the requested model or peer prose. Set `independence_verified: true` only when actual peer and parent serving families are verified different and the authorized recipient/route and any fixed pins were satisfied. A valid in-scope return with insufficient independence evidence may inform synthesis without promotion; an unauthorized route or recipient is not usable.

Collect and classify every started child before synthesis or return, even if ordinary dispatch stopped incomplete. Remove only consumed run-owned transient files after preserving required results and receipts; leave and report unresolved state. If the review proceeds to synthesis, only verified independent evidence can promote merged agreement, by the one-fix test in `references/synthesis-and-presentation.md`; corroboration never by itself authorizes an edit. Report incomplete cross-model coverage in both modes, with each missing required peer and specifically the uncovered whole-document sweep when it did not qualify. Base reviewers can still return their ordinary coverage and findings.
