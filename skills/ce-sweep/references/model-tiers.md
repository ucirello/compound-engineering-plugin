# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). This skill explicitly requests these native OpenCode subagents. Under a user-or-loaded-skill delegation rule this request suffices without another approval; an unconditional higher-priority prohibition, missing tool, or actual denial still applies. Never bypass these restrictions via shell or another harness. Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes a known, permitted override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes a known, permitted override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, prefer that model over the default tier above only when model-selection permission allows it. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier, subject to the same host permission checks.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Use `opencode.models` to discover available model IDs rather than another harness's dispatcher. Configured role choices and tiers remain authoritative intent, subject to actual host permissions. Delegation permission is distinct from model-selection permission: if an override requires an explicit user model request, omit the optional model argument otherwise and use a suitable inherited model. Report unmet route/tier requirements, and never call same-model agents cross-model independent verification.

Verify effective runtime nesting depth separately from permission using the host's supported configuration inspection; do not assume available capacity from a package-local default. Classify actual dispatch errors as permission denial, model-argument rejection, depth/capacity limit, or missing tool. Correct a harmless pre-launch argument error once only when allowed; do not retry a denial or evade depth through another harness. Leave capacity-limited work queued, or use the permitted inline degradation above with the same budgets and artifacts. Report unavailable work and any unmet independence/coverage requirements rather than claiming completion.
