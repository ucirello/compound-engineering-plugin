# Cross-Model Judgment Pass

This additive, non-blocking pass reviews each activated conditional judgment lens (`adversarial-document-reviewer`, `product-lens-reviewer`, `security-lens-reviewer`) with one fixed different-model target, plus exactly one `whole-doc` sweep. Coherence, scope, and feasibility do not independently activate it. A failed or unavailable pass never blocks ordinary persona synthesis, but Coverage must identify unmet cross-model corroboration and whole-document coverage; never call the complete review fully verified when a required different-model pass is unavailable.

## Resolve policy and one fixed native route

Use the separate delegation, model-selection, and depth checks in `dispatch.md`. This skill explicitly requests these reviewers, satisfying a host user-OR-loaded-skill exception, not an unconditional prohibition. If model overrides require an explicit user model request, config preferences do not authorize the optional `model` argument. Suitable inherited-model ordinary reviewers may still run; same-model reviewers cannot satisfy this pass. Do not bypass denied operations, missing tools, or exhausted nesting via shell or another harness.

Attest the host's serving family and model from runtime evidence, not harness branding. Unknown host family cannot establish automatic different-family independence. Keep requested target, intermediary/harness, serving provider/family, and actual served model distinct.

Locate the enclosing `.jj` workspace by ancestor discovery, set its absolute root as `workspace_root`, and confirm with `(cd "$workspace_root" && jj workspace root)`. Ordinary RocketClaw configuration resolves `.rocketclaw/config.local.yaml` before `config.yaml`: first active valid scalar wins, empty is unset, invalid falls through to default; a present list/map replaces the whole key. Missing files are skipped regardless of ignore status. `docs_root` remains `config.yaml` only. Outside a repository use defaults without inventing project config.

Evaluate `cross_model_review_mode` first: `auto` is default, `off` disables automatic egress unless the user explicitly requests this run's cross-model peer in conversation. A configured peer or project preference is not that opt-in. A live prohibition always wins. Name `disabled by checkout config` separately from capability or independence skips.

Resolve target preference in this order: conversational request, `cross_model_peer` under the ordinary-layer rule, active project instructions already in context, then first available attested-different target in `codex → claude → grok → composer`. Cursor-default is explicit-preference only. Preserve provider compatibility vocabulary, but resolve executable routes exclusively using `opencode.models` and native OpenCode subagents: do not launch Codex, Claude, Grok, Cursor, or another OpenCode CLI dispatcher. A configured intermediary/fixed route unavailable natively is an unmet route, not permission to substitute silently.

`CROSS_MODEL_PEERS`, when set and nonempty, restricts every recipient including intermediaries; unset/empty means unfiltered, not unsanctioned. The skill request and pre-egress disclosure sanction the eligible pass subject to actual permissions. Compatibility alias rule: `cursor` or `composer` sanctions Cursor as intermediary, but Cursor-default requires target `cursor`, and `grok` alone does not sanction Cursor. Native routing must not invent an intermediary. Fix one concrete provider/model/variant route for all lenses and the sweep; no internal failover. Changing any recipient requires renewed resolution and disclosure.

Conversation model/effort requests outrank `cross_model_model` and `cross_model_effort`. Preserve configured target/family and tier intent; validate exact available model IDs and supported variants through `opencode.models` when overrides are allowed. Incompatible or unauthorized requirements get a named skip, never a silent substitution. Preferred editorial mappings are GPT-6-luna (`gpt-6-luna`) extra-high for Codex/OpenAI, Opus 5.5 (`claude-opus-5-5`) high for Claude/Anthropic, Grok 4.7 (`grok-4.7`) extra-high for native Grok/xAI; compatibility Grok-via-Cursor requested `grok-4.7-xhigh`, and Composer `composer-2.5-fast` at its fast ceiling. These are preferences, not guaranteed availability or authorization. Only after the preferred ID is observed unavailable/obsolete/incompatible may a closest same-target/same-family replacement be resolved and disclosed; never silently replace an explicit user model. Cursor-default has no requested model and cannot establish serving identity without a receipt.

## Disclosure and isolation

Interactive mode: prominently announce an independent cross-model judgment review, requested model and reasoning level, fixed native route, and every provider/intermediary receiving document content. Say `requested <model>`, not that the model served. Call it independent only with attested different serving families. Add a serving caveat when a receipt disagrees, or no model was requested (`serving model unverified`); absence of a receipt for a requested ID is not evidence of substitution. If no peer resolves, one quiet skip line names why. Non-interactive mode emits no user-facing prose; record a bounded send audit in local run evidence naming recipients and data scope.

Create private, owned, nonsymlink scratch under `<absolute-workspace-root>/.tmp/rocketclaw/ce-doc-review/<run-id>`; outside JJ use local `.tmp` under the absolute working directory. All fallback/error paths remain local. Verify ownership and restrictive permissions before writing; never fall back to OS-global temporary storage. Embed only the document slice and persona/schema in the native payload. Request tool-less, read-only leaf reviewers, no writes, network tools, MCP, further subagents, or unrelated project context. Enforce available native tool permissions, not just a prompt; unavailable required isolation is a named capability failure. Do not claim isolation the host cannot enforce. Accepted read-only residual access must be disclosed and limited to the maintainer-owned document threat model, with no mutation authority.

## Dispatch, bounded recovery, and collection

Launch in the same bounded parallel wave as ordinary reviewers. Activated trio peers get the same reviewer-specific slice as their in-process twin on unified artifacts, full document on legacy documents. Launch `whole-doc` once with the full document, never a slice, using `references/personas/whole-doc-reviewer.md`. Only allowlisted persona names select prompt assets; no caller-controlled brief path. Pass the classification and origin unchanged and round-1 framing even on later rounds; do not pass accumulated decision primers to these peers. Synthesis suppresses already-resolved/rejected findings normally.

Track native job/session IDs and outcomes. Use one shared `CROSS_MODEL_HARD_SECS` budget (default 1200 seconds), orchestrator deadline budget + 10 from the final start, and supported bounded waits that do not cross it. Where progress telemetry is available, enforce the existing 480-second idle bound; no streaming telemetry means hard-bound only, not invented liveness. Do not inherit a stale unrelated supervisor cap that undercuts this budget. On deadline cancel only review-owned outstanding work with supported native lifecycle operations, then collect terminal records with bounded grace; if cancellation/collection is unavailable preserve state and report unresolved jobs. Never return claiming cleanup while jobs are unresolved.

Transient active-agent capacity queues work until a slot frees; permanent nesting exhaustion is not transient backpressure. Distinguish permission, model-argument, missing-tool, infrastructure, provider, and timeout failures using actual errors. For a new plausibly recoverable infrastructure failure, correct the invocation and retry the same fixed route within the deadline, retaining recipient, model, isolation, and scope. Stop on repeated failure. Never retry denial or evade depth. One exact provider-overload 529 permits one same-route retry within the original deadline; quota/usage-limit no-review outcomes are not automatic retry or failover authorization. Repeated quota evidence ends retries. No authentication probes are prerequisites; diagnose account authentication only from provider-capable dispatch/response, not sandbox-shaped text. Report observed remediation without guessing account logout.

Collect each started outcome before synthesis/return. Validate schema-shaped JSON against `findings-schema.json`, reject unparseable/trust-failed outputs, ignore raw leftovers, force `reviewer` to `<reviewer-name>-<provider>`, and downgrade peer `safe_auto` to `gated_auto`. Record `cross_model_target`, `cross_model_harness`, `cross_model_route`, `model_requested`, `model_actual`, and `independence_verified`; derive actual model from runtime receipts only. Missing receipt means unverified, never infer it from request. Only attested different serving families with verified receipts set independence true; same-model separate reviewers do not. Only true independence can promote a merged finding by one anchor step under the one-fix test.

Coverage distinguishes never-started policy/capability skips, started failures/timeouts, malformed results, no additional issues, and whole-pass infrastructure loss. Always name loss of the whole-doc broad read (it has no twin) and cross-model corroboration. The trio's ordinary twins remain coverage, not replacements for cross-model independence. Preserve collected evidence on incomplete ordinary dispatch without applying findings. After reading back and classifying outcomes, release review-owned agents with supported native operations and remove only consumed run-owned scratch authorized for cleanup. Preserve unresolved evidence and report blockers; never invent lifecycle operations or delete unrelated state.
