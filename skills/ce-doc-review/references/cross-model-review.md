# Cross-Model Judgment Pass

Run this additive, non-blocking pass only when a conditional judgment lens (`adversarial-document-reviewer`, `product-lens-reviewer`, or `security-lens-reviewer`) is activated. Each peer uses the same persona, template, schema and reviewer-specific slice as its in-process twin. Also dispatch exactly one `whole-doc` reviewer using `personas/whole-doc-reviewer.md` and the full document, once per document. The sweep has no in-process twin: its loss must be named in Coverage.

## Policy and native routing

Follow the separate delegation, model-permission and depth rules in `dispatch.md`. This skill explicitly requests these reviewers where host policy permits user-or-skill-requested delegation. No shell or other harness may bypass a prohibition or exhausted depth. If model overrides require an explicit user request, omit the optional model argument; inherited-model work is permissible evidence but is not cross-model independence. An unavailable required independent pass remains incomplete coverage even though this additive pass does not block the underlying document review.

Resolve ordinary configuration from `<absolute-workspace-root>/.rocketclaw/config.local.yaml`, then `config.yaml`: first active valid scalar wins; empty scalars are unset; present lists/maps replace the entire key, including empty values. `docs_root` remains config.yaml-only. Discover the root with `jj workspace root` using an absolute cwd, then run JJ from that absolute root. Outside a repository use local `.tmp` and no repository config.

Evaluate `cross_model_review_mode` first (`auto` default, `off` skips unless the user explicitly requests a cross-model pass this run). Report `disabled by checkout config`, not an authentication or capability failure. A live prohibition always wins.

Resolve target preference in order: user conversation, valid `cross_model_peer` config, active project-instruction preference, then first available attested-different target in `codex → claude → grok → antigravity`. Explicit `cursor` and `composer` preferences remain intent, not permission to launch another harness. Preserve requested targets and intermediaries as route requirements: if native OpenCode cannot represent an exact route, report it unavailable rather than silently changing recipients.

Use `opencode.models` to discover exact native provider/model IDs and supported reasoning variants, then native subagents for dispatch. Shell is for bounded local preparation, receipt storage and validation only, not alternate-harness model dispatch. Resolve one target/model/route for all activated lenses and the whole-doc sweep. Preserve `cross_model_model` and `cross_model_effort` (user values outrank config), and retain these editorial defaults when permitted: Codex GPT-6-luna extra-high; Claude Opus high; native Grok 4.7 extra-high; Cursor Grok high/fast preset; Composer 2.5-fast ceiling; Antigravity Gemini 4 Argon high, with one pre-egress Flash fallback only if Argon is unavailable and no explicit model was supplied. Discover exact IDs rather than guessing aliases. Other default editorial IDs may be replaced only after observed unavailability by a closest same-target/same-family supported model. Never replace a configured/user-named model, change family, add a recipient or silently lower effort.

The preserved editorial model IDs are `gpt-6-luna`, `claude-opus-5-5`, `grok-4.7`, `grok-4.7[context=256k,reasoning_effort=high,fast=true]`, `composer-2.5[fast=true]`, `gemini-4-argon`, and its sole unconfigured fallback `gemini-3.8-flash`. Cursor default/Auto and OpenCode auto have no pinned model. These source IDs and preset semantics are intent to resolve through the native catalog, not invented OpenCode IDs or permission to use a forbidden model argument. Preserve unsupported fixed-route/preset requirements as incomplete coverage.

`CROSS_MODEL_PEERS`, when nonempty, restricts every provider and intermediary. Unset means unfiltered, not unsanctioned. `cursor` or `composer` sanctions Cursor as intermediary; `grok` alone does not. Only literal `antigravity`, not `gemini`, admits that recipient. Preserve these restrictions when translating config into native routes; unavailable intermediary-specific routes are named skips.

Attest host family and actual peer model only from runtime-published identity, not product branding, inherited environment markers, requested IDs or the model's self-report. Unknown host identity cannot establish automatic different-family selection: skip with the reason. Same-family/same-model reviewers are separate reviewers, not independent cross-model corroboration.

## Disclosure, scope and dispatch

Before sending content, announce the requested model, reasoning level, concrete native route and every recipient; state that document content is sent to that provider. Say `requested <model>`, never claim the requested model actually served. Say independent only when host and target families are attested different. Unknown identity means independence unverified. Non-interactive mode stores the same disclosure in the local audit receipt rather than announcing it.

Use private, owned, nonsymlink run directories under `<absolute-workspace-root>/.tmp/rocketclaw/ce-doc-review/<run-id>` (or local `.tmp` outside a repository). Dispatch with bounded parallelism alongside the primary reviewers. Give peers embedded document text and the full persona/template/schema, no accumulated round-2 decision primer. Use round-1 framing. Require read-only least privilege: no edits, shell, network tools, further delegation or unrelated project reads. Use native isolation/tool restrictions where available; disclose unenforceable residual scope and do not pretend prompt instructions are a sandbox. A mandatory isolation requirement that cannot be enforced is unavailable coverage, not a reason to launch an unrestricted alternative harness.

Trio peers receive the same slices as their twins; whole-doc receives the full document. Do not truncate silently. Validate returned JSON against `findings-schema.json`, force reviewer `<reviewer-name>-<target>`, and downgrade peer `safe_auto` to `gated_auto`. Store only validated fold-in artifacts as `<reviewer-name>-<target>.json`. Ignore raw/partial artifacts during synthesis.

## Bounded recovery, receipts and completion

Capture dispatch time and one shared deadline from `CROSS_MODEL_HARD_SECS` (default 1200 seconds), with bounded native waits; retain an idle limit of 480 seconds where observable. Never start a wait beyond remaining budget. Concurrency rejection is backpressure: collect/release finished native agents, then retry queued work only while capacity can recover and the deadline remains. Actual depth exhaustion is not transient concurrency pressure. Classify permission denial, unavailable tool, model-argument rejection, depth/capacity, authentication, quota, timeout and infrastructure errors separately from observed evidence.

One same-route retry is allowed for an explicit overload response within the same deadline. For infrastructure failure, retry the same fixed scope/route only for a new plausibly recoverable error; stop when an error repeats or budget expires. A default editorial model refusal permits at most one same-family supported replacement per lens; explicit pins never change. Do not restart a provider no-review outcome otherwise, and never automatically retry repeated quota/usage-limit evidence. Do not diagnose the user's account as logged out without a provider-capable launch/response proving authentication failure.

For every owed leg retain a receipt with native task/session ID when started, lens, scope, start/end/deadline, target, route, recipients, requested model/effort, actual model from runtime or `unverified`, host identity evidence, `independence_verified`, state and reason. Preserve compatible result fields `cross_model_target`, `cross_model_harness` (`opencode`), `cross_model_route`, `model_requested`, and `model_actual`. Set independence true only when actual runtime identities establish different serving families; requested IDs alone are insufficient.

Before synthesis or return, collect/classify every started task. Cancel expired/unneeded tasks through supported native lifecycle operations, wait boundedly for terminal state, and release only this run's agents when supported. Do not invent cancellation or claim unresolved tasks stopped. Preserve evidence and report blockers if collection or cleanup fails. Never delete run artifacts before reading and classifying outcomes; remove only consumed, verified run-owned disposable files after collection, preserving receipts needed by the report.

Coverage distinguishes never-started skips, failed, timeout, malformed/untrusted result and unresolved tasks. An infrastructure crash that voids the whole pass is named whole-pass loss including the broad whole-doc read, not a quiet per-lens skip. Each trio lens keeps its primary twin. Non-interactive results record every owed leg that did not fold using `synthesis-and-presentation.md`; interactive Coverage names failures and skip reasons. Empty findings means no additional issues, not missing review. Underlying review may continue after peer failure, but never claim full independent coverage.

Fold validated findings only when the underlying review proceeds to synthesis. Agreement promotion is at most one anchor step and only for `independence_verified: true`; ordinary one-fix merging still decides whether findings agree. Round-2 suppression in synthesis still rejects already-resolved/rejected findings.
