# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Prefer the platform's cheapest capable model only when the host permits the model override and exposes it. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Prefer the platform's mid-tier model only when the host permits the model override and exposes it. If model names are unknown or selection is not authorized, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

Use OpenCode-native subagents; resolve permitted model identities through `opencode.models`, not a harness dispatcher or shell workaround. User/project instructions and role-specific configuration in `.rocketclaw/config.local.yaml` then `config.yaml` take precedence over the default tiers as desired behavior. All tier/override preferences above are conditional on model-selection permission. Preserve configured choices and tiers, but treat delegation permission, model-selection permission, and available nesting depth separately.

This skill explicitly requests source-fetch and media-analysis subagents. If the host permits delegation when the user OR a loaded skill requests it, this request satisfies that exception without another approval. Respect an unconditional higher-priority prohibition, missing tool, or actual denial. A configured tier does not authorize a model override: if the host requires an explicit user model request, omit the optional `model` argument and use a suitable inherited model. Disclose unmet configured requirements; same-model agents do not establish cross-model independence.

**Degradation rule.** When the platform's subagent primitive does not support per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on the inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When the platform has no subagent primitive at all, run the source fetch and the media analysis inline in the orchestrator with the same budgets. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Verify effective delegation depth from runtime configuration discovery and higher-precedence sources; do not assume the bundled package setting applies to consumers or that permission guarantees capacity. Classify an actual failure as depth/capacity, permission denial, model-argument rejection, or missing tool using its error. Correct a non-denial pre-launch argument error once; never retry a denial or evade a depth limit via shell or another harness. Leave capacity-limited work queued, or use the inline degradation above where permitted, preserving budgets and artifacts. Report skipped or incomplete analysis honestly; never claim an unmet independence or fixed-model requirement completed. Apply a source persona's more specific unavailable-state rule when present.
