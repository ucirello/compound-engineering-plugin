# Cross-Model Execution Contract

Read this when execution-engines.md selects a configured route or when recovering a recorded run. Execute with OpenCode-native `opencode.models`, subagents, and shell for JJ and verification; never invoke another harness, adapter, detached runner, or deleted workspace controller. The orchestrator owns durable state and receipts, not the worker's claims.

## Resolve authoritative intent

Keep live intent, typed caller provenance, and standing configuration precedence from execution-engines.md. Resolve `work_engine_mode`, `work_engine_preferences`, and `work_engine_effort` independently from `.rocketclaw/config.local.yaml` then `config.yaml`. A present local list or map, including empty, replaces the whole team key. Modes remain `off | prefer | require`; off disables standing preferences only. Preserve ordered candidates, explicit model pins, and harness-specific effort intent. Configuration is data, never executable shell text.

Retain configured `harness: codex | claude | grok | cursor | opencode`, optional `model`, and effort map as requested intent. Use `opencode.models` to resolve exact available provider/model IDs and supported variants. A named harness/intermediary is not interchangeable with a provider: report an unsupported fixed route unavailable rather than silently translate it. Do not replace Composer or Cursor model selectors with an unrelated model. A required effort unsupported by native execution makes that candidate unavailable; do not silently reduce effort. Omitted model means the configured default only when verifiable. A same-host default collapses to inline native execution with requested versus actual disclosed.

Preflight ordered candidates without exposing source. Record every unavailable candidate and observed reason. The first qualified candidate is fixed for that attempt. Both prefer and require retain that identity while viable; if all candidates are unavailable, disclose once and continue on the current OpenCode session model without another approval or an unrequested external recipient. Record unmet configured route/effort requirements rather than claim they were met.

## Delegation, selection, and depth are separate

This skill explicitly requests native workers. Under a user-or-loaded-skill delegation rule that satisfies the skill exception; no redundant user approval is needed. An unconditional higher-priority prohibition, denied permission, or missing tool still applies. Delegation permission does not authorize a model override: when the host requires an explicit user model request, omit the optional model argument and use a suitable inherited-model worker. Report required different-model coverage incomplete; separate same-model workers are not cross-model independence. Inspect effective runtime nesting capacity separately; classify actual errors as depth/capacity, permission, model-argument rejection, or missing capability. Correct a pre-launch argument error once, queue capacity-limited work, and use inline/parent fallback only when the unit contract allows it. Never evade a denial or depth limit with another harness or shell dispatch.

## Durable source, isolation, and authorization

Create a private run record under the canonical absolute root's ignored `.tmp/rocketclaw/ce-work/<run-id>/`. All packets, message files, logs, error/fallback files, and recovery state stay under local `.tmp/`. Record one scalar run id, repository/workspace identity, selected bookmark, exact base revision, source kind and SHA-256, binding provenance, requested/actual route/model/effort, receipt status, restrictions, dependencies, wave base, and per-unit attempts. Keep actual served-model identity unverified unless native runtime evidence proves it; served effort is unverified unless independently evidenced.

For bare prompts, build a bounded brief with Request, Goal, Scope, Acceptance and verification, Constraints and exclusions, and conservative P-units. Never include raw conversation, credentials, or unrelated context. Missing goal/scope/verification returns to clarification before dispatch. Freeze the source digest and copy/read back the packet in private state. For a plan, include only the Goal Capsule, Definition of Done, active unit, relevant Verification Contract, cited R/F/AE/KTD excerpts and Product Contract Key Decisions whose Governs links name its R-IDs. Preserve caller restrictions; a worker may narrow but never broaden them.

Disclose route/provider/intermediaries, material exposed, and enforced versus cooperative restrictions before dispatch. JJ isolation is not an OS sandbox; never grant broader permissions to make a route reachable. Required enforced confinement unavailable in the native capability makes the route unavailable. The selected plan alone may receive a disclosed path-limited checkpoint; unrelated canonical dirt blocks isolated cross-model preparation. Inventory ignored content by metadata, not by copying secrets; dependency/cache size alone does not invalidate preparation.

Detect existing isolation first and preserve its verified existing name/bookmarks. Use harness-owned supported colocated JJ isolation and its lifecycle where available. Verify exact base from the resulting absolute root and `jj git colocation status` before editing. Never rename/recreate existing isolation to enforce new naming or colocation. Unsupported required new-workspace naming/colocation is a compatibility blocker, not a Git fallback or permission workaround.

When caller-owned creation is authorized, use `ce-worktree`: capture local `YYYYMMDD` once, derive a meaningful task/PR/revision kebab slug, normalize a supplied dated name without double-prefixing, and use the same dated identity for workspace name and absolute destination basename under the existing local `.tmp/` parent. Check registrations and destinations; use `-2`, `-3` collision suffixes without overwriting, and persist the selection across retries/resumes/midnight. Preserve PR/source bookmarks. From the source absolute root:

```bash
(cd "$workspace_root" && jj workspace add --colocate --name "$selected_name" --revision "$verified_base" "$absolute_owned_destination")
(cd "$absolute_owned_destination" && jj git colocation status)
```

JJ commands always run from the target absolute root, including Python `subprocess.run(["jj", ...], cwd=workspace_root)`. `-R` alone is insufficient; changed paths remain repo-relative. Repository-scoped GitHub calls use `(cd "$workspace_root" && GIT_DIR=$(jj git root) gh ...)`. References: https://docs.jj-vcs.dev/latest/git-experts/ , https://docs.jj-vcs.dev/latest/git-command-table/ , https://docs.jj-vcs.dev/latest/cli-reference/#jj-workspace .

## Serial unit transaction

1. Record a clean canonical snapshot, exact base, source digest, bounded packet digest, unique attempt id and fixed recipient before starting. A successful prepared attempt locks engine choice; latency or convenience never justifies duplicate native authoring.
2. Dispatch one fresh native worker bound to that packet and isolated root. It edits only its unit, verifies its base before writes, and leaves changes for host inspection. No canonical commit, push, PR, shipping, peer scheduling, recipient switch, or scope expansion authority is delegated. Bind the native handle to run/unit/attempt/packet digest; reject mismatched evidence.
3. Observe through native status/wait capabilities in separate calls, waits at most 60 seconds. Record elapsed time, latest meaningful activity and terminal state. Preserve a 7200-second hard cap, a 600-second progress-reset idle window only when progress is trustworthy, otherwise hard-only with idle disabled. If native supervision cannot enforce required bounds, report unavailable before dispatch. Loss of contact is live/unknown, not failure: never duplicate, fallback, or clean up until native terminal or authorized cancellation evidence proves workers stopped.
4. On authoritative completion, pin the complete JJ result and recovery reference with recorded base as sole parent. Inspect actual `jj status` and `jj diff` including binary/mode/rename/delete and all tracked/untracked changes; compare to expected scope and worker result schema. Unexplained byproducts or scope expansion preserve state and block integration.
5. Acquire a single durable host integration lock. Re-read canonical root/bookmark/base/digest/cleanliness; unknown movement blocks. Record pre-fold snapshot, expected applied tree and changed paths. Apply the verified result using native JJ change integration (for example a verified base-parented result via `jj rebase` and `jj squash --from <verified-result> --into <host-owned-change>`), never blindly merge or use a transport description as the canonical message. Preserve recovery references before mutation.
6. Run the unit's authoritative Verification Contract command, capture its actual exit status and log directly, and reconcile tracked tree/revision/bookmark/paths before recording verified. Invoke shell syntax through explicit `bash -o pipefail -c`, not literal unexpanded argv. Inventory ignored entries before/after and disclose changed/removed/created counts with bounded samples as `ignored_state`. Ignored caches, `.env`, and databases are not protected by JJ snapshots; never copy, restore, or delete them implicitly.
7. Only after scope, verification and reconciliation pass, create the host-owned canonical description/change using implementation-loop.md's runtime message standards. Record canonical revision, parent/tree, verification digest and unit receipt; canonical completion, integration, verification, terminal authoring and cleanup are distinct states.
8. A failed verification or pre-commit integration step forbids canonical completion. Restore only proved run-owned tracked mutations to the recorded exact pre-fold state using preserved JJ recovery revisions, never discard unknown/user state. Prove exact equality before releasing the lock. If equality is unprovable, retain lock, result reference, workspace and recovery path, and stop retry/fallback/siblings. A crash after canonical completion reconciles receipts, never redispatches.
9. After all units complete, run source-wide Verification Contract checks from a clean canonical snapshot, capture status/log/digest and ignored-state divergence, and prove tracked-state reconciliation. A failed check retains logs and blocks returning success/shipping even if cleanup succeeded. Never infer success from stdout or worker exit alone.

## Parallel waves

Use execution-strategy.md's full Parallel Safety Check, cap 3–5 workers, record one clean wave base and dependencies, and isolate each concurrent cross-model worker. Terminalize and inspect every result before the first fold. Actual same-path or semantic contention blocks the affected wave even with clean textual application. Integrate sequentially in dependency order under the lock, revalidate each result against the exact advancing host-owned canonical revision, verify and record one unit before the next. Unknown head movement blocks. Conflicts/failures require exact restoration and lock release before retry/siblings/fallback. Recompute readiness; do not discard unaffected work or start dependents early. Repeated collision, scope expansion or unprovable restoration disables further waves.

## Recovery and exactly-once fallback

An explicitly supplied safe run id (`^[A-Za-z0-9._-]{1,128}$`, at least one non-period character) is authoritative. Otherwise discover only a single unfinished plan-backed record matching repository, bookmark and selected plan digest; prompt runs require their disclosed id. Multiple matches return ids/recovery paths and block selection; unsafe/foreign records block rather than get skipped. Recovery reconciles recorded native handles, terminal results, exact apply tree or canonical parent/tree. Never redispatch, reapply, recommit or run either shipping tail merely to recover. Complete runs with successful stored unit/source-wide receipts are observation-only: do not rerun tests/build/install/generation. Missing evidence is a blocker.

Record retry/fallback claims under the durable integration lock. A retry preserves scalar run id, earlier receipts, unit dependencies and wave/base contract, but gets a fresh attempt id. At most one corrected retry before reporting a persistent blocker; no automatic retry of permission denial. Fallback is eligible only after authoritative failure/timeout/cancellation, any exact restoration, abandonment evidence, and lock release; never while live or with successful unreconciled output. Record exactly one native fallback authorization before execution. An existing authorization/completion cannot launch another fallback. Preserve requested identity and unavailable reason in prefer and require modes; no unrequested external recipient substitution. Complete fallback with canonical revision and local verification digest; all units still require a successful source-wide receipt.

## Cleanup and tail ownership

Cleanup requires existing authorization and lifecycle ownership, not completion alone. Stop workers; leave the target and move any active harness session to a surviving workspace before deletion. Verify exact registration name, absolute path and run ownership; prove required integration and preserve best/archive/recovery references. Copy and read back receipts/logs/packets outside the target. Inspect conflicts, tracked changes, ignored/untracked content and still-needed references. JJ removal snapshots tracked state but does not protect ignored/untracked files; unrelated, ambiguous or non-disposable content blocks cleanup.

From the surviving absolute root use `jj workspace remove <verified-workspace-name>` only for authorized retirement plus file deletion. `jj workspace forget` is unregister-only and preserves files. Colocated metadata follows JJ lifecycle, never separate Git removal. Verify deregistration AND directory disappearance; deletion warnings/nonzero/incomplete cleanup retain remaining state and report the blocker, never force-delete or fall back to Git. Bookmark deletion is separate and must preserve recovery/still-used references.

Store binding, requested/actual identity, source kind/digest, run id, unit receipts, disclosed plan checkpoint, blockers and recovery path for direct and return-to-caller runs. A receipt is observed host evidence, not inferred success. Standalone execution resumes quality/shipping; return-to-caller returns implementation/local verification with `standalone_shipping_skipped: true`. Workers inherit neither tail.
