# Model Tiers

Read this when dispatching a sub-agent (a source-persona fetch subagent or a media-analyzer subagent). Use OpenCode-native subagents for dispatch, `opencode.models` to discover available model IDs, and shell for local mechanical work, never another harness's dispatcher. Sub-agent dispatch is tiered by task shape, never hardcoded to a model name:

- **Extraction tier** is for the source-persona fetch subagents. This is retrieval and quoting work (pulling items and their media paths out of a source connector). Use the platform's cheapest capable model when the current harness exposes and permits a known override. "Capable" is part of the spec. Escalate to the generation tier when the source is large or the connector obscure.
- **Generation tier** is for the media-analyzer subagents. This is evidence-driven mechanical work that turns downloaded frames and transcripts into a bug-report-shaped finding. Use the platform's mid-tier model when the current harness exposes and permits a known override. If model names are unknown, omit the override and inherit rather than guessing.
- **Ceiling tier** is the orchestrator's judgment. The decision round and plan reconciliation run in the main conversation on the orchestrator's model. Nothing is dispatched for them.

If the user's or project's active instructions or the live prompt name a model for this subagent, preserve that choice instead of the default tier above, subject to host model-selection permission. They can name it by the subagent's tier, by its prompt-asset name, or for the subagents being dispatched. Without such an instruction, a model configured for this subagent's role takes precedence over the default tier.

This skill explicitly requests source and media delegation. Under a host user-or-skill delegation rule, that satisfies the skill-requested exception without a second approval; it does not override an unconditional prohibition. Delegation permission, model-selection permission, and remaining nesting capacity are separate. If model overrides require an explicit user model request, omit the optional model argument absent that request; use a suitable inherited model and disclose unmet configured tiers/routes. Verify effective `experimental.subagent_depth` from supported OpenCode configuration inspection and remaining capacity; do not assume the package default applies. Classify actual errors as permission denial, missing tool, model-argument rejection, or depth/capacity exhaustion. Do not retry denied operations or evade limits through shell/another harness. The inline fallback below is allowed for this extraction/analysis contract; report that it was inline, not independently delegated. Same-model agents do not establish cross-model independence, and any required unavailable different-model pass remains incomplete.

**Degradation rule.** When the platform's subagent primitive does not support or permit per-agent model selection, dispatch the source-persona fetch and media-analyzer subagents (Phase 2b, 2e) on a suitable inherited model and keep their read budgets and output caps. Cost control then comes from structure, not tiering. When delegation is unavailable, prohibited, or blocked by exhausted depth, run the source fetch and the media analysis inline in the orchestrator with the same budgets and disclose the actual reason. Still download media to the scratch path and write each analysis finding to its scratch artifact, because the wrap-up summary and plan reconciliation read those paths.

Classify a rejected native dispatch by whether an agent launched. Correct a pre-launch argument rejection once. Leave capacity-limited work queued. Send any other failure to the inline degradation above, or to the more specific unavailable-state rule in the persona file for that source.
