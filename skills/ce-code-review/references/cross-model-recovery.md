# Native cross-model recovery and coverage

Apply `references/subagent-model.md` to every active route and fallback.
Classify from the actual error before cleanup:

- **Delegation denied, missing tool, depth exhausted:** name the exact class.
  Skill-requested dispatch is allowed under a user-OR-skill rule, but never
  overrides an unconditional prohibition. Do not retry denied operations or
  evade nesting depth with shell or another harness.
- **Model/effort rejected:** preserve the configured/user route as intent.
  If override permission is absent, omit model arguments for an allowed,
  suitable inherited-model reviewer; it does not prove cross-model independence.
  Never silently swap a user/configured fixed model. A default-only rejected
  model permits one disclosed same-family replacement chosen from native
  discovery, only when selection permission and the review contract allow it.
- **Capacity:** wait for existing native work to finish/release and retry the
  queued reviewer within the shared deadline. A nesting limit is not temporary
  slot backpressure.
- **Infrastructure failure before launch:** one corrected same-route attempt
  is allowed for an actual recoverable invocation error, within the deadline.
  No retry for repeated failure, denial, or depth exhaustion.
- **Provider overload:** at most one same-route retry within the shared
  deadline; exhausted quota, max-turn exhaustion, or authentication no-review
  outcomes do not repeatedly restart that route. Attribute an account login
  failure only when provider-capable launch/response evidence supports it;
  otherwise report an execution-context authentication failure, not a guessed
  user logout.
- **Started but failed/timeout/no usable output:** name the terminal outcome,
  distinguish from never-started, and never report it as clean findings.
  An unknown outcome remains unknown; no invented receipt.
- **Trust/read failure:** do not fold the artifact or classify it as a clean
  skip; retain the diagnostic and degraded coverage.

A first proven no-review outcome may use one disclosed different eligible
native recipient only if the failed recipient was not the user's explicit
preference, configuration does not fix the route, permission allows model
selection, and the allowlist and shared deadline permit it. Never switch inside
the child or start a third peer. Otherwise dispatch one native local
`adversarial-reviewer` if allowed. This skill requests that fallback too; omit
model overrides when forbidden. Stop/release the failed live worker first and
do not duplicate a usable independent review on the same brief.

Record `adversarial lens: in-process fallback (cross-model peer not run:
<actual reason>)` when that independent native reviewer completes. It is
separate-context coverage, not different-model proof. Inline parent analysis
can add evidence but never covers an independent-read requirement. Focused
mode without the required independent read is Not ready. Any required fixed-
route/different-model pass remains **incomplete**, including when a same-model
fallback succeeds; never call the review fully verified. An optional peer
failure alone need not fail the whole review when the lens is independently
covered and no required cross-model contract remains unmet.

Maintain the original exact captured endpoints, persona brief, constraints,
read-only boundary, bounded native collection, identity receipts and lifecycle
cleanup in every recovery. Copy required diagnostic evidence before removing
consumed disposable logs; never delete the persisted report artifact.
